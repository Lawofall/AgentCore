# 后端架构

> 目标模块体系与分层约定。目录树 → [项目结构](/docs/02-架构/项目结构.md)；契约 → [核心接口](/docs/02-架构/核心接口定义.md)。

## 一、五层分层

`models → schemas → repository → service → router`，单向不可反转。

| 层 | 职责 |
|----|------|
| models | ORM（约定 → [核心接口 §6.2](/docs/02-架构/核心接口定义.md)） |
| schemas | request / detail / list 分层 |
| repository | 纯数据访问，无业务逻辑 |
| service | 多 repo / 编排 / 外部副作用时才设 |
| router | 薄层；**简单 CRUD 可直接注入 repository**（避免空透传） |

### 1.1 事务边界（谁 commit）

**约定**：调用方拥有 unit-of-work。仓库写方法默认 `commit=True`（单步 CRUD / 薄路由）；**组合写**必须逐步 `commit=False`，最后由 service / 编排层 `session.commit()` 一次。共享助手 → `db/repositories/_base.commit_or_flush`。

**例外（须注释）**：有意立即落盘且不与同 session 其它写混用的单步（如登录失败计数 `increment_failure`）；或已标明「Does not commit — caller owns the txn」的纯 flush 级联（如 `RunSessionRepository.delete_for_conversation`）。

**未全仓迁移**：多数仓库仍为「方法内 commit」遗留默认；新组合路径与已改高频路径（auth 注册/改密/注销、handoff 建作业、regenerate 截断）按上约定。勿在同一次请求里对已 `commit=True` 的方法再叠 service 层 `commit`。

#### 抄对范例（事务）

| 场景 | 抄这个 | 勿抄这个 |
|---|---|---|
| 单步 CRUD / 薄路由 | repo 默认 `commit=True`（经 `commit_or_flush`） | — |
| 组合写（同 session 多步） | `auth/service.py`（注册/改密/注销）；`conversation/handoff_jobs.py`（建作业）；`conversation/turns.py` regenerate 截断：逐步 `commit=False` → 调用方一次 `session.commit()` | 任意「方法内已 commit」的旧 repo 用法再叠一层 service `commit`（双提交） |
| 共享助手 | `db/repositories/_base.commit_or_flush` | 在组合路径里绕过助手直接 `session.commit()` 中间步 |

| 面 | 现状 |
|---|---|

## 五、评估体系

立场：以**任务结果**为中心，否决「把轨迹手段当门禁」。L0 契约硬门 ✅ · L1 结果质量主轴 ✅。未定义的 L2/L3 编号废弃，勿再加层。轨迹形状 check 仅诊断（`gating=False`）。**合成 evals ≠ 真实数据**——优化前须声明证据性质（合成 L1 / R 真仓 / dogfood 金标三档 → [`evals/dogfood/README.md`](/evals/dogfood/README.md)）。夹具必须 `copytree` 隔离。

**贡献者边界**：PR / `release:gate` 只认 L0 用例结构（`seed_lint` / `python -m agentcore.evals lint`）与合成主轴的零 LLM 单测。真模型（`run routing` / `run core` / `run compare` / MAST 标签 / 文风）= **本地自愿观察**，不挡合并。dogfood 三维分仍人工。→ `agentcore/evals/`；跑法 → [本地开发 · evals](/docs/02-架构/本地开发.md)；门禁 → [发布与门禁 §二](/docs/05-平台与运维/发布与门禁.md)。
