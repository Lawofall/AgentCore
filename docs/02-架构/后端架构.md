# 后端架构

> 目标模块体系与分层约定。目录树 → [项目结构](/docs/02-架构/项目结构.md)；契约 → [核心接口](/docs/02-架构/核心接口定义.md)。

## 一、五层分层

`models → schemas → repository → service → router`，单向不可反转。

| 层 | 职责 |
|----|------|
| models | ORM（约定 → [核心接口 §6.2](/docs/02-架构/核心接口定义.md)） |
| schemas | request / detail / list 分层 |
| repository | 纯数据访问，无业务逻辑 |
| service | 多 repo / 编排 / 外部副作用时才设 |
| router | 薄层；**简单 CRUD 可直接注入 repository**（避免空透传） |

### 1.1 事务边界（谁 commit）

**约定**：调用方拥有 unit-of-work。仓库写方法默认 `commit=True`（单步 CRUD / 薄路由）；**组合写**必须逐步 `commit=False`，最后由 service / 编排层 `session.commit()` 一次。共享助手 → `db/repositories/_base.commit_or_flush`。

**例外（须注释）**：有意立即落盘且不与同 session 其它写混用的单步（如登录失败计数 `increment_failure`）；或已标明「Does not commit — caller owns the txn」的纯 flush 级联（如 `RunSessionRepository.delete_for_conversation`）。

**未全仓迁移**：多数仓库仍为「方法内 commit」遗留默认；新组合路径与已改高频路径（auth 注册/改密/注销、handoff 建作业、regenerate 截断）按上约定。勿在同一次请求里对已 `commit=True` 的方法再叠 service 层 `commit`。

#### 抄对范例（事务）

| 场景 | 抄这个 | 勿抄这个 |
|---|---|---|
| 单步 CRUD / 薄路由 | repo 默认 `commit=True`（经 `commit_or_flush`） | — |
| 组合写（同 session 多步） | `auth/service.py`（注册/改密/注销）；`conversation/handoff_jobs.py`（建作业）；`workflows/runner.py`（代跑新开对话 create+attach）；`conversation/turns.py` regenerate 截断：逐步 `commit=False` → 调用方一次 `session.commit()` | 任意「方法内已 commit」的旧 repo 用法再叠一层 service `commit`（双提交） |
| 共享助手 | `db/repositories/_base.commit_or_flush` | 在组合路径里绕过助手直接 `session.commit()` 中间步 |

### 工作流触发（定时 / Webhook） {#工作流触发}

> **主循环归属**：[组](/docs/01-产品/产品定位与品牌.md)——钟是工作流怎么开跑，不是新种类。画布 / 槽位 / 复跑 → [工作流固化与复跑](/docs/02-架构/工作流固化与复跑.md)。

| 面 | 现状 |
|---|---|
| L1 定时 | cron 挂在这张图上；周期到点 → 代跑 |
| L2a Webhook | 有信号才跑；挂在同一张图上；无预制连接器 |
| 一图一钟 | 一张工作流最多一口钟（定时或 Webhook，不是两个触发器叠在一张图上） |
| 代跑 | 与手点「跑一次」同构：新开对话、按图、锁拓扑、无 CEO |
| cron 语义 | 自实现 5 段解析（不引 croniter）。**日 / 周两段都非 `*` 时取或**，遵 Vixie cron：`0 9 1 * 1` = 每月 1 号**或**每周一 09:00。`*/n` 与 `*` 同属星号段（Vixie DOM_STAR），故 `*/10 * 1` 仍取与 |
| 漏跑可见 | 两处会静默少跑一次：调度器先推进 `next_run_at` 再派发，派发抛错即丢本周期；webhook 抢不到图级租约直接 409。两处都写工作流行 `last_error`（不重试、不补跑）——用户决定要不要手点「跑一次」。手点「跑一次」不走触发租约、不写 `last_error` |
| 无收件箱 | 代跑结果落在新开的那轮对话；失败看工作流行，不另立审阅面 |
| 无系统模板 | 钟只触发用户自己的图，不预置系统任务 |
| 端覆盖 | **后端 + 桌面 ✅**；**mobile / admin 有意未接**（非遗漏） |
| 边界 | ≠ 产品公告 Notice；≠ IM 官方号推送 |

→ 见代码：`workflows/` · 桌面 Toolbox 工作流

### 后台派活（工作流 / 交接）{#后台派活}

审计里「工作流镜像 handoff」多半是**假镜像**：二者都是「建作业 → `spawn_background` → 后台跑」，但表、凭据、pause、结果物刻意分叉。**不抽统一 job 框架**；共享原语只有 `conversation/background.spawn_background`。定时 / Webhook 是工作流图上的属性，不是第三张作业表。`handoff_jobs` = 本机文件夹「后台云端」产品入口（云拷贝跑完 → Diff 显式合回本机）→ [双模式 · §7.6](/docs/02-架构/双模式工作区.md)。

| 维度 | workflows | handoff_jobs |
|---|---|---|
| 产品 | ✅ **工作流**：主入口是工具箱画布（新建 / 官方模板）；`mode=workflow` 直起（按图、锁拓扑、**无 CEO**）；可挂一口钟。槽位 / `definition` 所有权 → [工作流固化与复跑](/docs/02-架构/工作流固化与复跑.md)；触发 → [工作流触发](#工作流触发) | Local→云快照交接 |
| 表 / 状态 | 用户工作流表 + 对话 `mode=workflow`（无独立 job 表）；漏跑见行上 `last_error` | `handoff_jobs`（pending→running→succeeded\|failed） |
| 已共享 | `spawn_background` | 同左 |
| 凭据 | `preflight_resolved_llm_credentials`（选型 + 计费门 + platform 覆盖） | **薄路径** `resolve_user_llm_credentials`（不升级 preflight） |
| pause | 走普通挂起（`paused_turns`） | **禁止** pause / 不读 `paused_turns` |
| 结果物 | 对话回合落盘 | `persist_job_turn` + result snapshot |
| 端覆盖 | **桌面 ✅**；mobile/admin 有意未接 | 桌面 |

→ 见代码：`workflows/` · 桌面 `pages/toolbox/workflows/` · `conversation/handoff_jobs.py` · `billing/gate.py::preflight_resolved_llm_credentials`

## 五、评估体系

立场：以**任务结果**为中心，否决「把轨迹手段当门禁」。L0 契约硬门 ✅ · L1 结果质量主轴 ✅ · L2/L3 ⏳。轨迹形状 check 仅诊断（`gating=False`）。**合成 evals ≠ 真实数据**——优化前须声明证据性质（合成 L1 / R 真仓 / dogfood 金标三档 → [`evals/dogfood/README.md`](/evals/dogfood/README.md)）。夹具必须 `copytree` 隔离。

**贡献者边界**：PR / `release:gate` 只认 L0–L1 契约与合成主轴；真模型对比 / MAST pass_rate / style 违规率 / 路由混淆矩阵 = **观察-only**（nightly 软门，不挡合并）。dogfood 三维分仍人工。→ `agentcore/evals/`；跑法 → [本地开发 · evals](/docs/02-架构/本地开发.md)；门禁 → [发布与门禁 §九](/docs/05-平台与运维/发布与门禁.md)。
