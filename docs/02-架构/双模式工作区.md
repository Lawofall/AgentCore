# 工作区（云端权威）

> **定位**：给每次协作一个持久的文件夹空间。**双通道观察期**——**云协作**为推荐默认（云桌权威 + 全云执行；本机落点经导入 / Diff 合回 / ZIP / 连接 Git）；**本机传统**为桌面可选入口（打开本机文件夹 = 本机权威工作区 + 本地引擎）。≠ 两平级「云/本地模式」开关；≠ 离线 /「数据不出本机」。
>
> **代码现状**：云桌主路径已落地；**本机传统入口 ✅**（Composer / 命令面板 / Ask 三件套履约 + `mode=local` 默认同侧 sidecar）。旧 `mode=local` 仍可开。**拒 Dropbox 式实时双向同步**不变。余项：⏳ 合回开 PR（**狗粮观察后再排**）；本机通道取消条件见 §7.2（暂不排死线）。导入硬顶见下「现行默认」。
>
> **边界**：Backend / 绑定 / Sidecar / 协作桌（文件夹成员） / 约定文档目录。记忆注入 → [记忆系统](/docs/03-AI核心/Agent记忆与知识系统.md)；文件树 UX → [前端 UX §九](/docs/04-前端/前端UX设计.md)。
>
> → 见代码: `apps/server/agentcore/workspace/`；桌面入口 `ComposerWorkspaceChip` · `importToCloud` · `mergeLandingDiff` · `cloudDeskExit`

## 一、云端权威（✅ 推荐主路径）+ 本机传统（观察期通道）

- **内核**：多 Agent 在同一张「桌子」上靠文件协作。
- **云协作（推荐）**：桌子 = **云桌**（打开即用、多端同一份、可隔离协作）；执行全云（引擎与盘同侧）。本机 = **碰盘动作**：导入到云、连接 Git（云 clone）、Diff 合回落点、下载 ZIP。
- **本机传统（观察期 · 桌面）**：打开本机文件夹 = **本机权威工作区** + **本地引擎**（sidecar；引擎与盘同侧）。适合已有大仓 / 必须碰本机环境；改动直接进本机目录。入口文案与差异 → §7.1–7.2、[前端 UX](/docs/04-前端/前端UX设计.md)。
- **默认与记忆**：新用户 / 无记忆 → 云；**可记上次通道**（本机用户不被每次推回云）。推荐徽标只给云。
- **云端远程**：云工作区可从产品 UI 浅克隆任意 http(s) 仓（SSRF 闸；私仓用账户级 PAT）。工具 `git clone` 仅 GitHub http(s)，与 UI 不是同一策略。→ [工具 · Git 闭环](/docs/03-AI核心/工具与能力系统.md#git-闭环)

**仍成立**：❌ 拒绝实时双向同步（Dropbox 式）。❌ 不把本机传统卖成离线或「数据不出本机」（推理仍多经云代理；对话回写云）。

**合流**：旧 `mode=local` 与「本机传统」同通道——侧栏图标语义为「本机传统」，无「请迁移」债务徽标；⋯ / ModeControl 可安静「导入到云」（可选转换）。过桥仅机制兜底（§7.2）。

**否决（回潮）**：把本机传统标成与云**平级推荐/默认**；Composer 并排「本地引擎 / 云端过桥」实现词；过桥当新云桌或新本机入口的默认；把过桥当「关电脑还能改本机原件」；用本机通道冒充完全离线。

## 二、三正交轴与拒绝实时同步

| 轴 | 取值 |
|---|---|
| 轴1 执行位置 | server（云协作）/ local·sidecar（本机传统）（机制见 §七） |
| 轴2 文件源头 | server dir（云桌权威）/ local dir（本机传统权威） |
| 轴3 持久化 | S3 快照 / 合回本机 / 下载 ZIP / ~~实时同步~~ |

推荐日常 = **server + server**；本机传统 = **local + sidecar**；云桌本机落点仅经显式合回/ZIP。

- ✅ 接受快照 / 交接（git-push 式）与 **显式合回**（§7.6 云桌→本机标准出口）。
- ✅ **导入到云**（本机文件夹 → 云桌权威）+ ignore / 密钥尽力排除。**现行硬顶（实现默认，可调）**：archive 约 100 MiB / 2 万文件；单文件 PUT 50 MiB（超限跳过并提示部分导入）。
- ❌ **拒绝实时双向同步**（Dropbox 式）：双真相源 + 冲突，在并行 Agent 并发写下尤其致命。
- ❌ **首期不做**：「整仓永不上传」大众例外；整树静默覆盖本机。

## 三、`WorkspaceBackend` 抽象原则

沿用 Protocol + 实现 + 工厂（同 `LLMProvider` / `SandboxProvider`）。引擎与工具只对接口编程。

- **护栏·瘦接口**：持久化（snapshot/restore）**不进 backend**——属轴3，归独立 `StorageProvider`。backend 只管「文件 + 执行」这对必须同源的能力。
- **为何 P0 引入**：本地是已承诺路线；接口先行使加 `LocalWorkspace` 时工具/引擎零改动。
- **唯一接缝**：`ToolContext.workspace_dir` → `backend: WorkspaceBackend`；`run` 短执行收编进 `backend.execute`（与文件同目录）。
- **列举有界且诚实（✅）**：`list` 收 `cap` 形参、返回 `DirListing(entries, truncated)`。**两道上限各有其理，不许统一**：AI 面沿用 100 是**上下文预算**（一次目录转储已挤占模型窗口）；文件浏览面另给 `WORKSPACE_BROWSE_LIST_MAX = 2000`，因为浏览**不是**上下文预算——导入了一个仓的用户必须够得着自己的文件。遍历**边下降边剪忽略目录 + 广度优先**，避免预算花在 `.git` / `node_modules` 上、或深子树把顶层兄弟挤出预算。`truncated` **必须一路送到 UI**：文件树上的静默截断读作「我的文件没了」，这是文件视图唯一不许暗示的事。条目另带**软元信息** `size_bytes` / `mtime_ms`（stat 失败只留空，绝不因此让整次列举失败）→ 用户面呈现见 [前端 UX §九](/docs/04-前端/前端UX设计.md)。
- **按目录列举（✅）**：REST 两个 `/files` 端点（`/v1/workspaces/{ws_id}/files`、`/v1/conversations/{id}/workspace/files`）收 `path` 查询参数（工作区相对，`.` = 根）、回 `truncated`。按目录展开后上限只在单个超大目录（或显式整树拉取）上才咬得着。

→ 见代码: `apps/server/agentcore/workspace/`

`ServerWorkspace`：服务端目录 + 云桌 guest（gVisor）。✅ 执行面独立于 API 进程（独立 `sandboxd`，不留同容器回落）；⏳ 第二刀用户预览（产品按钮 + sandboxd 反代）→ [安全 · 五、代码执行沙箱](/docs/05-平台与运维/安全权限与治理.md)。`LocalWorkspace`：用户真实本地目录 + 桌面执行；传输不另造——把审批门「挂起 + HTTP 回填」泛化为 `WorkspaceChannel`。Sidecar 文件 op 直连本机（不经 channel），但后台进程仍交主进程代持（sidecar 生命周期短于 dev server）。

## 四、约定文档目录约定

多幕协作副产物落工作区约定目录。**否决**另建「会话级团队约定文档」实体——复用既有文件夹 / 工作区文件心智。全部挂在 `AgentCore/文档/`（**不**进 `<设定>` 注入）。

**产品心智：过程材料在 `.agentcore` 抽屉里**：用户平时不必打开；打开入口是终稿路径可点与工作区树。用户要拿走的文件在派单时用 `form=workspace` / 显式 `artifacts` 直接写入工作区（`promote_product` 收口再搬 **已撤销**）→ [术语表 · 成品归位](/docs/01-产品/术语表.md)。呈现与存储分工见本节末。

| 目录 | 谁写 | 谁读 |
|---|---|---|
| `AgentCore/文档/工作稿/` | 裸文件名；不知放哪的过程稿 | 后续回合按需读；用户从终稿路径或工作区树打开 |
| `AgentCore/文档/research/` | 调研 / 竞品笔记（`form=files`）——须 research playbook 或**显式**指定 | 后续辩论 + 主持人索引 |
| `AgentCore/文档/debate/` | 辩论收场机制 | 用户 / 后续回合按需读 |
| `AgentCore/文档/reviews/` | 审查类 `form=files` | CEO 汇总 / 用户按需 |

**`research/` 不是兜底去处**：它有机器语义——辩手被要求读它取证（`runtime/debate/prompt.py`），杂物灌入即污染取证面。**否决**「非 review 即 research」的正则兜底：入闸词表比出闸到 reviews 的词表宽，没有专属常量的成品会躺进调研抽屉。`工作稿/` 接住裸文件名与不知放哪的过程稿后，`research/` 只进 playbook 常量与显式声明。

落盘与 handoff 摘要正交：结构化 handoff 走委派通道；完整报告叠加写文件。`<工作区>` 只陈述短事实，不注入正文。约定文档出口**非空才**出现「现有：文件名」行（空抽屉不写）；布局 HOW → `team_delivery_env`。读历史报告以该清单或 `file_list` 为准，勿按话题拼接 `{主题}审计.md`。CEO 全树稀疏索引是同一 `<工作区>` 末节 `文件：`（工人不加；空盘 `文件：空`）；项目共享树**不**列 mtime 抽样（已撤「最近触达」），只报附件 +「另有 N 个」；有 `AGENTS.md` / `CLAUDE.md` 只留文件名指针，不摘正文。不另开标签。→ `runtime/context/outlet_inventory.py` · `runtime/context/workspace_overview.py`

✅ **落点不由运行时猜**：`artifact_dir` 只认显式来源（`deliverable.artifact_dir`、已声明 artifacts 推导出的目录、playbook 常量）；**裸文件名** join 进 `工作稿/`；空 `artifacts` 不钉目录。旧的「扫 role·task 自由文正则决定落 research 还是 reviews」整链**已净删除**。✅ **写码类用 `form=workspace`**（吞 playbook 内部 `workspace_native`；无约定文档落点，路径未知也能填）。`form=files` 不再兼「改工程」。`文档/` 无 `项目/`——厚背景资料走 `记忆/主题/` 按需条目，不再落盘。

**`form=workspace` 与 leftover `artifact_dir`**：workspace 节点 leftover 目录一律清掉，**不**把裸名 join 进约定文档路径（含 `{reviews}/{裸名}`）。裸名由 worker 自己定位。点名的具体 `artifacts` 未命中仍可 warning / `missing_declared`（对账观测），不挡正式完成。**仅 `artifact_dir` 未命中且已有落盘：不提醒、不催搬，收口认实际路径。** `form=files` 的裸文件名仍 join（无路径 → 工作稿；有显式目录 → 该目录）。空 `artifacts` 不钉目录。**否决**「验收层给 `artifact_dir` 兜底」。声明路径已落盘时备份不进卡；声明未命中则实际落盘进卡。仍不打「未通过」。路径验收 HOW → [执行引擎](/docs/03-AI核心/执行引擎架构设计.md)。

**向用户报路径（✅ 提示约束）**：收口列出落盘文件时，须用工作区相对完整路径（与上表约定文档前缀一致），以 `file_write` 回执 / `artifacts` / 交付对账为准；禁止裸写 `reviews/…` 或同一清单混用两套前缀。→ `team_delivery_env` 【产物路径】

**约定文档文件命名（✅）**：柜名 / 抽屉目录不动；规范柜内文件名。

| 规则 | 约定 |
|---|---|
| 类型前缀 | 英文小写 + 连字符（机器友好）；可读短名可中文 |
| 权威默认名 | 只在一处常量；playbook 文案 / 验收 / 技能须引用，禁第三种默认名 |
| `reviews/` 审查报告 | 工人自起名（默认省略 `artifacts`）；不规定套餐文件名或配套台账 |
| `reviews/` 日复盘 | `{YYYY-MM-DD}.md`（保持） |
| `research/` 成篇主文件 | 权威默认 `报告.md`（`output_path` 可覆盖；验收只认主路径） |
| `research/` 单角调研中间产物 | `调研要点.md`（**勿**与主文件抢名） |
| `research/` 多角 / 透镜 | `{短名}调研报告.md` / `{短名}透镜报告.md`；汇总 `汇总与命题卡.md`（辩论依赖，保持） |
| `research/` 审校 | `AgentCore/文档/reviews/审校报告.md`（保持中文名） |
| `debate/` | 机制落盘名保持 |

旧 dogfood 产物不自动迁移。生成端 → `research_quality.DEFAULT_RESEARCH_REPORT_ARTIFACT` · `playbooks/research.py`。

**写路径扁平（✅）**：上表各约定文档前缀下（含 `工作稿/`），写工具（含 `file_batch`）把前缀之后的嵌套 `/` `\` 压成 `_` 成单文件名（例 `reviews/audit-ai/01.md` → `reviews/audit-ai_01.md`）；派 `artifacts` / 约定路径时用平铺名，勿再 move「改回」斜杠子路径。进任务书前 `apply_artifact_dir_defaults` 把具体文件声明压成落地名；对账（声明 vs 已落盘）与下游前置路径按落地名认，嵌套旧写法仍能对上扁平文件。→ `workspace/_paths.sanitize_write_relpath` · `runtime/runs/file_acceptance.py` · `runtime/runs/fidelity.py`

同树旁路（仍系统噪音，对 AI / 用户文件 UI 都隐藏；**不**注入）：`AgentCore/{index,trash,baselines}/`（code_search · 软删 · 回合基线）。与可见 `规则/` · `记忆/` · `文档/` 同根；路径感知忽略（禁止全局忽略裸名 `index` 等）。**勿与**容器路径 `~/Documents/AgentCore/` 混淆。常量 → `stage_dirs.{INDEX,TRASH,BASELINES}_REL`。

**否决（存储层 · 仍成立）**：约定文档与 `AgentCore/{规则,记忆}` 在盘上「两根并存」——统一挂 `AgentCore/`；规则/记忆仍仅 documents 注入。否决独立隐藏根 `.agentcore/`（已并入约定根旁路）。

**呈现层：一个 `.agentcore` 抽屉，存储与注入仍拆开**：记忆侧是扁平条目（DB · 占配额 · 进 prompt），产物侧是盘上文件（可下载 / 合回 / `file_read`），两者不同构——**配额条不得画到过程稿上**。**否决**把 documents 虚拟根与盘上 `AgentCore/` 渲成两个同名平级节点。用户面合成一个钉顶节点 **`.agentcore`**（默认折叠）：条目 + 摊平后的 `工作稿/` `research/` `debate/` `reviews/`（不露 `文档/` 壳，不露 `已迁入记忆/`）。全局仍单独叫「全局设定」。磁盘路径**不迁移**——`AgentCore/` 这名字在本机传统模式下是准的，**不改成真点目录**。

**`文档/项目/`**：厚约定已迁为按需 `记忆/主题/` 条目；`文档/` 只留运行产物（`工作稿`/`research`/`debate`/`reviews`）。盘上原件归档、本机绑定未迁、一次性 pass 须晚于 `migrate_workspace_tree.py` → [记忆 · 文档/项目 归位](/docs/03-AI核心/Agent记忆与知识系统.md#文档项目-归位)。

## 五、绑定：文件夹即工作区 · 双通道入口

### 5.1 产品主路径（✅）

- **两通道（观察期）**：
  - **云协作（推荐）**：新建 / 导入到云 / 连接 Git → 文件夹权威在云；执行全云。
  - **本机传统（桌面）**：打开本机文件夹 → 本机权威工作区 + 本地引擎。✅ Composer / Ask / 命令面板入口已加回。
- **Composer 入口（✅）**：草稿弹层**第一屏只选这次聊哪**：快速对话 + 已有文件夹（筛选；通道用云/硬盘图标区分，顶层无「我的文件 / 本机文件夹」副标题；嵌套 hint 只写之上那段路径，不加通道名前缀）。点**云文件夹**即定；点**本机文件夹**进与「从本机加入」相同的三选。「新建或加入…」进二级面：新建文件夹、从 Git 克隆、从本机加入（桌面；无本机盘时第一屏直接「新建文件夹」，不套二级）。本机目录**先选定夹，再三选一**——**直接改这个文件夹**（本机权威 + 本地引擎；列表已有的只改草稿意图，新路径才打开会话；可标「上次」）/ **复制到云上当新家**（导入；原件不再跟着变）/ **先在云上做，原件先不动**（借用；做完再决定写不写回）。三选短 hint 只说互斥后果，不是通道课；点导入 / 借用先弹轻量确认（文件夹名 + 互斥后果，无改名 / 重选夹），确认后开传（默认本机名）。弱链「了解区别」对着这两问写，不把六条动词平铺回第一屏。默认云；可记上次通道。手机无本机盘 → 无本机三选。弹层无「在哪工作 / 云协作推荐」说明壳。**否决**：常驻第二枚「跑在哪」chip / 云·本机平级分段开关；对云文件夹再问怎么用（通道已在云上）；把导入 / 借用 / 打开本机再铺回第一屏。命令面板 / Ask / 文件中枢仍可用长名直达（「打开本机文件夹」「导入到「我的文件」」「云上做完再写入」），不经 Composer 两步；后两条仍弹完整确认框（选夹 + 可改云上名）。文件夹行通道看图标；有祖先才写路径 hint（本机只说之上那段，免「白板」底下再写「白板」）。→ §7.1 · §7.8。
- **合回与 ZIP（✅）**：云桌 ModeControl **只留 Diff 勾选合回**本机落点（冲突默认留本地，禁静默覆盖；**首次合回询问落点**，已登记可更换）。**导出 ZIP / 导出到本机文件夹**收进工作区工具条导出菜单（不必先登记落点）。合回落点登记 ≠ 打开「本机传统」文件夹。✅ 快捷「只合回产物」挂工作区工具条导出菜单。⏳ **PR/推远程** = 二级出口，**狗粮观察后再排**（不替代 Diff 默认）。整树覆盖不做主路径。
- **本机触点**：合回落点登记 ≠ 本机传统文件夹；Host / 区外挂载仍可与云桌正交（桌面在线）。
- **执行**：云协作 → **全云**（不默认过桥）。本机传统 → **本地引擎（sidecar）**。过桥 **不当**新入口（§7.2）。

### 5.2 会话归属与可达多桌

- **会话归属中途不改挂**：创建时绑定文件夹或明确不绑；**禁止**事后改写本会话 `folder_id`。要换心智 → 新开对话。
- **可达多桌（✅）**：归属不改 ≠ 手只能碰默认桌。分两档：
  - **CEO 只读跨桌（轻量认桌）**：通用 `file_*` **只绑出生桌**（当前桌列目录 / 读文件走 `file_list` / `file_read`，不必先 `list_folders`）。`list_folder_dir` / `read_folder_file` 仅派单前轻量认**另一张桌**/抽样；**不**改会话挂载、**不**写入目标桌记忆；**禁止**当跨文件夹摸底主通道。
  - **派工换桌（读写通吃）**：跨已登记文件夹的只读摸底与改盘/推进，一律 `delegate` 带已解析 `target_folder_id`（=该队员坐哪张桌；写不写盘由 write_scope/grant 正交）。**裸聊未点名**：纯对话/只读（非名册目标）可派（worker 坐 `conv:` scratch，`write_scope=none` 禁写）；写盘 deliverable（`form=files` / 非空 `artifacts`）或名册目标未点名 → **禁默写 scratch**。**裸聊写盘自动建云桌（✅）**：无出生且缺有效目标、且无唯一 `turn_target_desk` 时，派工前运行时 `POST` 云 Folder 并写入 `turn_target_desk`（命名：只采**形状像文件夹名**的短标题——显示宽度 ≤16（约 8 个汉字）、无截断标记，否则一律「云文件夹」（重名交 `unique_sibling_name`）。**像文件夹名 ≠ 像会话标题**：标题模型预算约 16 字，当目录名过宽。**用户原话不参与命名**：它没有形状保证、常含身份证 / 电话 / 住址，而这个名字会成为磁盘真实目录段；铸题失败不再把 `fallback_title` 写入会话 `title`（空则走通用名），但用户手改与 `_sanitize_title` 仍只留下一个字符串，故目录名只做形状判断、失败方向退通用名。这也是 `fallback_title` **只要丢了原文就必留省略号**的原因（后续行被丢弃也算）：省略号是形状判断唯一能读到的「这是用户原话的一截」信号。**建成即发 `auto_folder_created`**（journal / 投影仍有；对话内不再画落点条，文件夹进「我的文件」，改名走文件页）——仍不问 `ask_user`、不挂起回合，复用旧桌与竞态输家静默；同回合至多一次；**不**改会话出生 `folder_id`）。首次建桌持久化 `Conversation.auto_desk_folder_id`（与归属正交），后续回合复用同一张桌；CEO 文件视野（`file_*` / 工作区索引）坐落地桌，侧栏分组与记忆作用域仍为裸聊。**一会话一 root（✅）**：建桌瞬间把 `conv:` scratch 整树搬进落地桌（同名不覆盖；`AgentCore/{index,trash,baselines}` 这类 root 作用域派生态不跟随），且用户侧会话工作区接口与 AI 侧共用 `resolve_turn_file_workspace` 同一份解析——否则同一会话分裂成两个物理目录：上传的附件下属读不到、AI 产出用户看不见、建桌后再传的附件仍落 scratch。存量会话由 `scripts/backfill_auto_desk_scratch.py` 回填。换根靠 `ToolContext` 共享工作区槽生效（`replace` 快照跟随同一槽，故 CEO 与下属同回合永不分裂）；**故意**坐别的桌的路径（`apply_target_desktop` / `folder_fs`）须 `fork_workspace_slot` 显式分叉——禁止给 `replace` 传 `backend=`，那会让快照停在换根前。多文件夹同回合 hint 已清空 → 仍须各 task 显式点名（不自动建第三桌）。**裸聊单目标捷径（✅）**：同回合唯一 `create_folder` / `resolve_folder` / 自动建桌 成功后，缺省 `delegate` 可省略 `target_folder_id`。写权账本按桌×路径分区（见 [Agent协作模式 · 交接式写权](/docs/03-AI核心/Agent协作模式.md)）。
  - **产物完整预览跟落地桌（✅）**：归属不改挂 ≠ 预览只读出生桌。`delivery_status.artifacts[].workspace_id`（有 `target_folder_id` 时为 `folder:{id}`）→ 桌面 `workspace://{folder|conv}.{id}/…` 取 `/v1/workspaces/{ws_id}/files`；无该字段则回退会话出生桌。禁止改挂会话冒充、禁止拷贝进 scratch 假预览。→ [前端技术 §9.12](/docs/04-前端/前端技术与架构.md)
  - 同指挥面：写盘缺桌优先靠**运行时自动建云桌**；`create_folder` 仅用户明确「新建名为…」或显式多线先建。导入 / 连接 Git 后再 `resolve`；本机传统走 `open_local_project` / `register_local_project` / `bind_local_folder`（✅ 合法产品路径，非推荐默认）。Composer 弱提示：写文件时可自动建云文件夹，也可先在「我的文件」里新建。→ 见代码: `ensure_bare_chat_auto_cloud_desk` · `tools/builtin/folders.py` · 桌面 `ComposerWorkspaceChip`
- **空桌禁止工程壳（✅）**：不变量权威在 §5.4。落地规格：
  - **回合作用域，不是「当时盘空才剥一次」**：可见顶层尚空时，第一次写入的未知顶层段登记为本回合 `stripped_slug`，此后本回合对该前缀的写 / 读 / `mkdir` / `artifacts` / 写权声明一律剥。首写后桌不再空，只剥一次会套回来。
  - **空桌谓词不可复用 `path_has_non_internal_entries`**：必须忽略全部 `AgentCore/`（含可见 `文档/`）、`attachments/`、声明潜伏目录。谓词只看盘；DB 里尚未落盘的子 Folder **不算**「桌上已有结构」（否则嵌套桌会让整桌不再剥身份壳）。登记 `stripped_slug` 时跳过这些子 Folder 名，避免 `课题A/…` 被剥到父桌根。裸聊建桌会把 scratch（含附件）迁入落地桌，复用现成 `has_files` 则主路径永不剥。
  - **入口是带工作区+回合态的改写**：包在写工具外层。**禁止**塞进无盘纯函数 `sanitize_write_relpath`。独立 `mkdir` 必须走同一改写。本回合 `file_read` / `file_list` 对已登记 slug 同样改写，避免写剥读不剥软空转。
  - **约定工程目录单一常量**：建站锁死 `site/`；绿场软件固定 `app/`（**禁止**再派生应用名 slug 当工程根；与工程壳同构）；另含 `src/` `docs/` `design/` `game/` `AgentCore/` 等。
  - 已有用户结构不剥、不自动拍平存量。CEO `artifacts` 经同一函数改写后再声明写权。`<工作区>` 陈述「本文件夹根即工作区根」（事实句，不是禁令）；空桌（同一剥壳谓词）再加一句操作事实：可见顶层空、工程入口写在根上。when-to-use 在 `mkdir` description（套应用名/话题名当工程根 ≠ 本工具）。仍不是意图分类器、不是 `mkdir` 硬闸；HOW 不进 CEO-only skill。工具成功 `output` 与用户过程卡同源：剥壳只报路径事实（「slug/ 即工作区根」），不写空桌/工程壳/无需创建。
- **裸聊**：默认云 `conv:<id>` scratch；桌面新建默认云（可记上次为本地则跟记忆）。亦可作跨文件夹指挥面（自动建桌 / 点名 / 显式 `create_folder` 后再派）。
- **用户心智（云）**：「文件在云上；要进本机就合回或下 ZIP。」**用户心智（本机传统）**：「打开的就是本机文件夹；Agent 直接改这里——仍要联网跑模型。」

### 5.3 遗留与观察

| 路径 | 状态 |
|---|---|
| 旧 `mode=local` 文件夹 | ✅ 仍可打开；侧栏「本机传统」语义；可选「导入到云」，非催迁 |
| `bind_local_folder` / `open_local` / `register_local` | ✅ 本机传统入口已恢复履约 |
| 「打开文件夹 = 本机传统文件夹」 | ✅ Composer / 命令面板 / Ask；文案用「本机传统」非「本地模式」 |
| 多 Folder 共享本机容器根 + `local_subpath` | 机制仍见代码；不推广 |

**裸聊默认云的理由**（仍成立）：① 关桌面任务停是 Multi-Agent 硬伤；② 大众交付 = 云预览 + 导出/合回；③ 多端可见；④ 对话正文回写云，隐私不支持 local-first 冒充「数据不出本机」。

**否决**：auto-promote 裸聊为 Folder（**≠** 写盘时静默建云桌 + `auto_desk_folder_id` 跨回合复用——建桌/复用**不**改会话归属；CEO 文件视野可坐落地桌）；会话中途改 folder；本机传统与云**平级推荐/默认**；Composer 并排「本地引擎 / 云端过桥」；用改会话挂载冒充跨文件夹；给通用 `file_*` 加换桌参数；只读跨桌写入目标桌记忆；过桥当新入口默认；「整仓永不上传」大众例外（私有化/离线另案）；本机传统冒充完全离线；扫用户原文硬拦发送「先建文件夹」；拦 `mkdir` 当工程壳闸；扫用户原文猜「该不该套目录」；空桌再问「要不要再套一层」（与自动建桌不问用户冲突）；已有用户结构的文件夹静默拍平；把剥壳塞进 `sanitize_write_relpath` 纯函数；空桌只剥首写一次；复用 `path_has_non_internal_entries` 当空桌谓词；绿场软件再造一层应用名 slug 当工程根。

云 scratch / 云文件夹产物 = 预览 + **ZIP 导出** + **Diff 合回**（单向，与拒双向同步对称）。平台代付**不为云执行新增配额维**——推理 `quota_*` 天然封顶；真实负载后再议。

### 5.4 去「项目」概念 · 容器统一为文件夹

**容器统一为文件夹。** 撤掉用户面的「项目」概念。`Folder` 实体保留但降级为内部稳定引用——用户不再「新建项目」，只在云盘里建文件夹、或打开本机文件夹。

**为什么**：① 容器三词（项目 / 工作区 / 文件夹）需要专节治理（[术语表 · 命名约定](/docs/01-产品/术语表.md)）本身就是概念冗余的证据；② 云项目**不对应任何用户可见文件夹**——物理目录名即 `folder_id`，路径由 id 派生而非相反，用户起的名字只活在 DB，与「项目即工作区」的心智错位；③ 大众心智里容器只有一种，就是文件夹。

| 项 | 形态 |
|---|---|
| 界面 | 只剩「我的文件」（云端目录树，用户起名、可嵌套）+「本机文件夹」（最近打开列表）+「与我共享」（别人邀请你加入的云文件夹，同一 `folder:` 树、不是第三种容器）。**无**「新建项目」入口、**无**「项目」一词；会话仍按文件夹分组，组名即文件夹名。**文件中枢不列**裸聊 `conv:` scratch（写盘进自动建桌，落「我的文件」）；「快速对话」只留 Composer / 侧栏对话入口 |
| 云端存储 | 从平铺 `workspaces/<user>/<folder_id>/` 重排为**真目录树** `workspaces/<user>/tree/<可见路径>/`；scratch 仍在 `conv/`。用户树**必须单占一段**——否则用户把文件夹命名为 `conv` / `shared` 就撞上同级顶层段 |
| 嵌套语义 | 真嵌套：AI 活动范围 = 用户选中那一层**及以下**（外层能读写里层子树），同「编辑器打开一个文件夹」 |
| 规则 / 记忆 | ✅ 沿树**由外向里继承**——外层定的约定，里层自动适用。注入按「全局 → 祖先（外→内）→ 当前」排序，**近的覆盖远的**靠这个顺序 + 层标签措辞兜（无硬覆盖结构，同全局 vs 文件夹那道缝）；`consult` 取正文与之相反，从最近层往外找、第一命中即止。**存储不搬家**：条目仍按 `folder_id` 分区、id 不变即不失忆，改的只有读侧。祖先链由 `rel_path` 段前缀解析（`ancestor_chain` 纯函数）；桌面本机引擎没有 folders 表，链与祖先层由云在 `/v1/account/rules/list` 一并算好、随 prepare 快照下来，**快照缺链就退回「只当前层」而非猜链**。**例外**：`记忆/导航.md` **不继承**、只注当前层。它是**工作区根相对路径**的路由表，而外层文件按嵌套语义本就不在里层的活动范围内（范围 = 选中层及以下），重基也够不着——继承等于注一堆不可达路由。规则与记忆之所以能继承，是因为它们是**内容**不是路由；这条边界即「内容继承、路由不继承」 |
| 稳定引用 | `Folder` id 保留且用户不可见；职责从「充当物理目录名」改为「记住该文件夹当前位置」，故改名 / 移动**不断**站立任务 · 记忆 · 白板归属。**快照与工作区锁的 key 仍由 id 派生、不再镜像盘上布局**——否则改名即孤儿化整段快照历史，且改名事务与并发回合会拿到两把不同的锁 |
| 命名约束 | 同层禁重名（今天云项目允许重名）；过滤文件系统非法字符 |
| 删除 | 软删**把目录移出用户树**到按 id 命名的墓碑区；同层禁重名只看活文件夹。可见名下若不移走，软删目录会占名整个保留期，用户重建同名即坐在已删文件上、并被保留期清理连带 rmtree（id 命名时不存在此洞，是本形态引入的）。软删因此从纯 DB 变带盘操作、须走工作区锁。这张桌的设定（documents 按 `folder_id` 分区）**退出注入、行仍留着**，恢复桌子时一起回来；彻底删除 / 过保留期才物理清。全局设定不陪葬。**三条同源约束**（都会真丢文件）：保留期清理只按 id 走墓碑区，**禁**照软删行记的旧槽位 rmtree（那个名字当场就释放了，删的是用户新建的同名文件夹）；恢复必须把解删与写新槽位放进**同一条 UPDATE**，否则一解删就撞活唯一索引；嵌套子文件夹标 `cascade` 不单独成条，回收站只显一条、由父级带回整棵子树（否则单独恢复只得一个空壳） |
| 系统旁路 | `AgentCore/{index,trash,baselines}` 三个隐藏 zone **移出用户树**、按 `folder_id` 存；可见的 `规则/` · `记忆/` · `文档/` 仍随工作区根。否则外层回合会把里层的回收区原文 / 基线 zip / 索引当普通用户文件去 grep 与索引。派生：删除落**当前工作区根**的回收区（谁执行删除落谁的）；每层文件夹各有自己的 `文档/` |
| 裸聊 | 保留「不选文件夹直接聊」。写盘自动建桌**对话内不再画落点告知**（产出卡只列文件；找桌走「我的文件」）。**否决**轻提示 + 当场改名并进产出卡头（与产出叠音）。`auto_folder_created` 仍发。命名见 §5.2；仍不问 `ask_user`、仍不改会话归属 |

**文件夹根即工作区根**：用户打开的那一层就是工作区根——撤掉用户面「项目」之后必须守住的落盘不变量。空文件夹里的成品直接落在这一层（及约定工程子目录）；禁止再套一层与文件夹身份重复的「工程壳」（队员用 `file_write` 父路径撑出的 `court-game/` 这类）。`create_folder` 建的是「我的文件」里另一张可派工的桌；工作区内的 `docs/` / `site/` / `src/` 是桌内结构。把工程壳再造成内部顶层目录，等于在文件夹里复活「项目」。空桌写入剥壳与命名阈值 → §5.2。

**否决**：

- **真删 `folders` 表 · 一切以路径为主键**——站立任务（调度器在无会话上下文时解析目标）、记忆分区、软删墓碑与保留期、工作区 desk 维度均需跨会话可 join 的稳定标识；且改名 / 移动会打断全部引用。
- **整个云盘单容器（不分文件夹）**——等于取消 FS 隔离轴（§六；[安全 · 隔离轴](/docs/05-平台与运维/安全权限与治理.md)）。多 Agent 并发写盘边界是磁盘短串行 + 整篇 CAS，不是长期写权台账；并肩可写同一路径。 → [Agent 协作 · 冲突与文件写权](/docs/03-AI核心/Agent协作模式.md#三冲突与文件写权)
- **每对话一独立盘**——放弃「多对话围同一张桌子」这一内核（§一）。
- **物理目录保持 id 名 · 树仅界面呈现**——真嵌套要求 AI 面对真目录树，否则外层读不到里层。
- **只统一术语、保留「项目」实体形态**——不解决「云项目不对应任何文件夹」的心智错位。
- **在文件夹内再造一层「项目」目录当工程根**——与撤掉用户面「项目」同根因：用户看见两层容器（自动建的文件夹 + 队员撑的 `court-game/`）。
- **文件页单独「快速对话」区列 `conv:` scratch**——写盘已自动建桌进「我的文件」，该区空态是假承诺；内测不留兼容层。

**仍成立**：会话归属中途不改挂（§5.2）；auto-promote 裸聊为 Folder 仍否决（自动建文件夹 ≠ 改归属）；多人围桌走协作桌（§八），不是第三种容器。

**工具面（✅）**：名册不进 CEO 常驻（当前桌只在 `<工作区>`）；跨桌先 `list_folders`。`list_folders` / `resolve_folder`（按路径解析，同名多层返歧义候选而非静默猜）/ `create_folder`（`parent_path` 挂层）/ `delete_folder`（**只认 id**——跨层同名合法，按名删必然误删；审批卡由服务端名册补完整路径而非末段名）/ `list_folder_dir` / `read_folder_file`。`target_folder_id` 字段名不动（本就是 folder 口径，改它只白冲击向量与快照）。

**存量迁移（✅）**：alembic 回填 `rel_path` + 幂等脚本 `scripts/migrate_workspace_tree.py`（`--dry-run`；重名加序号、非法字符替换、目标已存在只报告绝不合并）。**跑在部署链的停-api 窗口内**（`deploy/scripts/finish-server.sh` / `deploy-server.sh`，alembic 之后、起 api 之前），不是手工步骤——`resolve_workspace_root` 是 mkdir-on-resolve，api 先接流量就会把空目录建在迁移目标上，而「绝不合并」意味着此后补跑一律判 skipped、存量永久停在旧平铺目录。同窗口内 `migrate_project_docs.py` 必须**晚于**本脚本（它读迁移后的 `tree/` 落点；跑反了会静默扫到 0 个，故自带顺序探测与非零退出）。扫描面是 **DB 用户 ∪ 盘上用户**：从没建过文件夹的纯裸聊用户没有 `folders` 行，但其 `conv/<cid>/AgentCore/{index,trash,baselines}` 同样要搬（索引能自愈，回收区与基线不能）。

**收尾**：`AgentCore/文档/项目/` 已随[文档/项目 归位](/docs/03-AI核心/Agent记忆与知识系统.md#文档项目-归位) 撤除，而非改名：该目录定位曾是「项目级厚文档」，容器改称文件夹后存在理由一并消失。厚背景资料走 `记忆/主题/` 按需条目。

→ 见代码: `workspace/locate.py`（盘上布局唯一定义处）· `workspace/layout.py`（反向问题「盘上现有哪些目录、分别是什么」的唯一判据，供扫盘运维脚本用：用户目录必须是 UUID 形状的**白名单**——`im/` 与用户目录平级，黑名单漏一项就是删数据）· `folders/placement.py`（id → rel_path 唯一异步入口）· `memory/scope_chain.py`（祖先链）· 桌面 `lib/folderTree.ts`

## 六、关键边界

| 项 | 约束 |
|---|---|
| 路径 | 相对工作区根 POSIX；裸 `/` 与 `\` → `.`；其它绝对路径拒。禁止工具私有 `if path=="/"`。空桌禁止工程壳前缀（§5.2 / §5.4） |
| 归属变更 | **不支持**事后改挂本会话到另一个文件夹（要换心智→新开对话）。同对话：跨已登记文件夹（读写通吃）须委派 worker（`target_folder_id`）；CEO `list_folder_dir` / `read_folder_file` 仅派前轻量认桌。文件搬运仍是显式动作 |
| 删除 | 软删可逆分轨：云端/sidecar → `AgentCore/trash/`（`GET|POST …/trash` 一键 list/restore，保留期对齐 `workspace_retention_days`）；本地默认 → 系统回收站（**不**承诺产品一键还原）。无系统回收站时桌面兜底仍写 `AgentCore/trash`，可由桌面 IPC 还原。硬删旁路仅针对同树内部区 `AgentCore/{index,trash,baselines}`。删**含 trash 的祖先**（含裸 `AgentCore`）→ **按子项展开**（先硬清三 zone，再逐项软删可见子树），禁止整树移入自身回收区；`WorkspaceIOError` → API 422。删规则/记忆/文档仍可逆 |
| 脚本/shell 破坏可回滚 | Local：`run`/`host(action=shell)` 命中破坏性删启发时，须有本回合 zip 基线（`AgentCore/baselines/`）否则 `FORCE_APPROVAL`；顶层整棵工作区树另窄闸（白名单清 `node_modules`/`.venv` 等不误拦）。桌面通道 Local 经 `ensure_turn_baseline` 落盘/探测非空 zip（gate 问 ready，不给服务端假 `Path.root`）；Sidecar `ServerWorkspace(location=local)` 仍走 Path zip。普通回合基线仍 best-effort、失败不阻断。基线区按**数量上限 ∧ TTL** 清理（对齐云端 D+C；捕获后顺带做，两条写盘分轨各一份实现，清理失败同样只打日志）：一回合一份整树 zip，不清就在用户盘上永久堆积；老回合被清后自然失去恢复入口（面板本就扫盘决定给不给），用户命名版本区 `AgentCore/versions` 永不自动清（sidecar API 仍在；**产品不再提供本机创建 / 列表 / 恢复 UI**，已留下的 zip 不删，持久历史走 Git）。还原 = overlay 尽力（有体积/忽略目录门），非完整镜像。UI：有基线即可进「改动」恢复，不依赖 `file_*` 产物。事实层只报根有无 Git，不软提示 `init_baseline`。→ `destructive_fs` · `turn_baseline` · `safety_breaker` |
| 本地并行团队 | 同回合多本地根（不同 `root_id`）✅ 经每目标一 `WorkspaceChannel` 并行；sidecar 进程内多根仍 ⏳ C2。单通道容量有限时仍可 snapshot 交接云端放大并行 |
| 引用区外文件 | 单文件仍优先复制进 `attachments/`。对话级区外目录挂载（`external/<别名>/…`）与绑定 / 打开文件夹 **正交**：桌面在线即可（云 scratch 亦可），不改 binding。**产品主轴**：**AI（+桌面解析）负责定位文件夹；用户只做允许/拒绝**——与行业「指明目标再授权」一致。**否决**区外链失败时弹系统选文件夹作主修复；**否决**「先在文件树看见未授权目录再点授权」。**只读**：工具 `external_mount_readonly`（`approval=never`）按 path 与/或 `well_known`+`target_name` **静默挂载为主**（无授权决策卡；Ask 面无只读授权 action；敏感整盘/用户目录根是否改轻确认另议）。grant 链**无**系统选文件夹；成功后同回合热挂载（云 backend）；模型面日常仍走 `external/`，**禁止**把 abs 当 `file_*` 日常路径。**整理/交付（云协作 + organize）**：`ask_user`+`grant_organize_folder` 仍须用户确认（卡上展示 `display_label`，非完整 abs）；只读挂过 ≠ 已授写；授权对象必须是**具体文件夹**（可读标签），禁止空心「请授权本机」。授权面 = `move`/`copy`/`mkdir`/回收站删除，**直接 `write` 区外仍拒**。产出交付走两步：先写工作区，再 `file_copy` 到 `external/<别名>/…`——单向（工作区 → 授权目录），**目标已存在即失败、不覆盖**，反向 copy 与跨根 move 仍拒。云 scratch 源在服务端盘、整理目录在用户机时，COPY 携带源字节过桥（单文件上限对齐 `workspace_upload_max_bytes`），**不开** organize `write`。**否决**给 organize 补 `write`：`copy` 本就在授权面内，只需解除跨根一层，不必往外部根加新 op；且「不覆盖」把最坏后果限到「多几个可删的文件」，低于已放行的 move/delete。→ 见代码: `cross_root_copy_error` · `copy_from_bytes`。**歧义（✅）**：定位到 2～3 个候选时，卡上让人选「是 A 还是 B」（各一 `grant_organize_folder` + 不同 well_known/target_name/path；仍非系统选文件夹）。→ 见代码: `prompt` / `skills` / `ask_user`。**失败分型（✅）**：对人区分「没定位到」(`not_found`) vs「定位到了但本机不让读」(`permission_denied`)；解析侧 `EACCES`/`EPERM` 不再压成「找不到该目录」。失败后引导用户补充线索或处理系统权限后再说「继续」，**不**改走选文件夹。→ 见代码: `resolveGrantAbsPath`。**口头同意闭环（✅）**：用户已明确「可以整理 / 允许」→ 须立刻发确认卡并履约；卡上「其他…」短允许表同走真 grant；成功或失败都要可见反馈，禁止空泡 / 空心再等确认。→ 见代码: `AskDecisionBody` · `isOrganizeOralConsent` · prompt/skills。**登记**：服务端只存 alias/root_id/mode；持久 abs 只在桌面（`fs-session-grants.json`）；mount 工具参数可含 path（运输例外，与用户原文同级）。**可见/可撤**：工作区面板列本对话挂载并可撤销（成功后须有「本对话已授权：…」锚点，避免人去错侧栏找）。⏳ 本地引擎（sidecar）mid-turn 热推 `externalMounts` 未齐——下回合/resume 注入仍可用 |
| 本机附加可写根 | **本机传统**对话可将旁边文件夹经 `ask_user`+`grant_attach_folder` 加入本对话为 `attach_rw`：可读写、可覆盖、该根下 `run` / `host(action=shell)` cwd。**分轨**：云协作不得选 rw；云→本机整理仍走上行 organize（copy 不覆盖）。保护路径 / fuse / 永久删始终在。→ 见代码: `external_mounts` · `grant_attach_folder` |
| ✅ 本机 Host | 与工作区绑定**正交**的第三能力面（单一 `host` 工具按 action 分流）；运输同属桌面回填通道族；云 scratch 亦可装配。GUI 面 → [Computer Use ⏳](/docs/03-AI核心/工具与能力系统.md#computer-use)。→ [工具与能力 · Host](/docs/03-AI核心/工具与能力系统.md) |
| 多 worker | 锁/审批门/通道/handoff 现为进程内态。现状一律拒启；放开前置 ⏳ → [部署拓扑 · API 进程约束：多 worker 一律拒启](/docs/05-平台与运维/部署拓扑与环境.md#api-进程约束多-worker-一律拒启) |

HTTP / `ws_id`（`folder:` / `conv:`）→ 见代码: OpenAPI + `workspace/locate.py`。本地 `location=="local"` 时 REST 写/索引返回 409；只读 snapshot list/download 放行。

## 七、Sidecar（本地引擎）与执行路径

比 `LocalWorkspace`（云端引擎 + `WorkspaceChannel` 遥控桌面）更深一层：引擎本体可搬到桌面子进程跑同一 `run_chat_pipeline`，工作区直连本地盘。**产品心智上须与「工作区是否本地」对齐本机传统、与「过桥」拆开**——见下。

### 7.1 三层勿混（已确认）

| 层 | 用户在选什么 | 示例文案 |
|---|---|---|
| **工作区 / 通道** | 云协作 vs 本机传统（观察期双入口） | 「云协作（推荐）」= 云桌权威；「本机传统」= 打开本机文件夹 |
| **执行路径** | Agent 循环跑在哪 | 云协作 = 全云；本机传统 = 本地引擎；过桥 = 仅机制兜底，不当选项 |
| **模型 / 计费** | 推理从哪出 | 推理仍多经云代理；**不得**把「本机传统 / 本地引擎」卖成离线或「数据不出本机」 |

Composer：草稿第一屏选**地方**（快速对话 / 已有文件夹 / 新建或加入）；点本机文件夹或「从本机加入」后再问怎么用（直接改 / 复制到云上当新家 / 先在云上做，原件先不动）。差异须在三选上写清。**否决**并排「本地引擎 / 云端过桥」实现词；**否决**常驻「跑在哪」第二控件；**否决**对云文件夹再问怎么用。→ [前端 UX · 模型与自主度](/docs/04-前端/前端UX设计.md)

**用户面用词**：`云协作` / `本机传统` / `云桌` / `过桥` / `sidecar` / `合回` / `通道` / `遗留` 是**内部口径词**——只在本文、术语表与代码注释里用，**界面一律不出现**。界面只说「我的文件」「打开本机文件夹」「导出到某个文件夹 / 导出 ZIP」；Composer 草稿另说「新建或加入」「从本机加入」与本机三选（直接改这个文件夹 / 复制到云上当新家 / 先在云上做，原件先不动）。同理禁止把 `ModeControl` / `Composer` 这类**代码符号**写进用户可见文案（照抄本文段落会把内部防回潮写法漏进弹窗）。用户面也**不再出现「项目」**，连口语义（「大项目」）一并避开——刚退役的实体名再冒头会被读回成实体。→ 桌面 `WorkspaceChannelGuideDialog` 由同名测试扫这批禁用词守着。

**入口差异（须露出）**：

| 入口 | 一句话 | 配套短注 |
|---|---|---|
| **云协作（推荐）** | 文件在云桌，多端同一份；要落本机用合回 / ZIP | 不直接改你电脑上的原文件夹 |
| **云上做完再写入**（桌面） | 先在云上做，原件先不动 | 关电脑也能做；做完再决定写不写回。≠ 直接改本机、≠ 复制到云上当新家 |
| **本机传统** | 直接改这个文件夹；Agent 立刻改该目录 | ≠ 离线；模型调用仍走网络 |

### 7.2 产品路由（双通道观察期）

| 项 | 定案 |
|---|---|
| **云协作（推荐）** | 文件权威云桌；执行 **全云**（`ServerWorkspace`）；**永不默认过桥** |
| **本机传统（桌面）** | 打开本机文件夹 = 本机权威 + **本地引擎（sidecar）**；入口级可见，非设置高级隐藏开关 |
| **默认** | 新用户 / 无记忆 → 云；**可记上次通道**（三选「直接改这个文件夹」可标「上次」；「从本机加入」不打） |
| **过桥** | 仅未走 sidecar 的旧 local / 机制兜底；**不当**新入口选项；**不当**「关电脑还能改本机文件夹」的方案（电脑必须在线履约）。静默降级 ≠ 正式能力。行业「云上循环、本机干活」是云任务的执行落点，≠「打开本机文件夹」第三引擎。细通道（host / MCP / 整理到文件夹）仍可存在——那是云桌碰本机的手，不是本机工作区回合。物理与导入的关系 → §7.8 |
| **产品面** | 文案「云协作」「本机传统」；取消「本地引擎」作独立第三选项名；禁止卖成离线 |
| **代码 / 落地** | ✅ Composer/Ask/open·register；`mode=local` 默认同侧 sidecar（显式强制关除外）。显式强制关走通用·进阶「允许本机执行」（独立开关；有本机引擎才出现） |
| **手机** | 无本机盘 → 无本机传统入口 |
| **取消本机通道（观察）** | 云路径在目标用户上无稳定「大仓痛 / 本机工具链刚需」差评，且合回/导入够用 → 再收入口；**暂不排死线** |
| **续跑** | **路由意向 ≠ 恢复事实**：已有 `origin=sidecar` / 本机活回合续跑跟本地事实 |
| **Toast** | 默认云路径静默；本机传统启动失败可诊断，禁止常态「本地引擎已关闭」吓大众 |
| **否决** | 两平级「云/本地模式」无推荐；过桥当新默认；过桥当关电脑方案；静默过桥当正式能力；静默默认 sidecar 冒充「已取消本机」；本机传统冒充离线 |

过桥下 `browser_*` 跟执行走云：无本机 Bridge 时装配 gVisor Sandbox（右坞 SSE 直播）；有健康 Bridge 的真·本地引擎仍走 Local 真页。→ [工具与能力 · browser](/docs/03-AI核心/工具与能力系统.md)

机制能力（stdio JSON-RPC、降级规则、窄票、outbox 等）仍以下文为准。

### 7.3 本地引擎相对过桥：不可等价替代什么

- **不可被过桥「做成一样」的**：引擎与本机盘同侧 → 文件工具循环无「云下指令 → 桌面再读盘」往返；重读盘/多工具更不易把 `WorkspaceChannel` 挤死。过桥只能少跳、跳得稳，不能变零跳（除非引擎也在本机，或盘改到云上）。
- **今天并不交付的**：真正离线、数据不出本机（对话回写云、推理出网）。断线产品档仍是 **断线只读**（不能发送/改文件/跑 AI）。
- **本机传统为何用本地引擎而非过桥**：大仓 + 多 Agent 狂读写时差别可以很大；观察期用「真·同侧」验证需求，而不是用过桥冒充本机通道。

### 7.4 与完全离线 / 私有化

- **完全离线** ⏳（本机推理 + 本机消息库 + 本机执行）：需要「本机运行时」形态；**打开今天的 sidecar / 本机传统 ≠ 离线**。保留代码资产降低以后重做成本；详细提案不在公开仓。
- **私有化**：私有云只部署服务端 → **不依赖**桌面 sidecar；本机/内网一体、断网可用 → 依赖本机（或内网）运行时，与 sidecar 同类而非必须原开关。

### 7.5 同 folder 多对话（云端）

**同文件夹多对话**：应可并行跑 prepare / LLM / 读；**写盘与 snapshot manifest RMW 单层串行**（`workspace_lock`，禁止同 key 嵌套）。**否决**云端整回合握锁（第二对话会静默排队、假「思考中」）。写锁短等须诚实等待态（如「等待工作区…」），禁止空 Thinking 冒充。Sidecar 路径本就不握该整回合锁。→ 见代码: `workspace/locks.py` · `ServerWorkspace` mutation / `execute` · `workspace/snapshots.py`

### 7.6 显式合回（✅ 云桌→本机标准出口）

云桌 → 本机的出口：

1. **遗留「后台云端」handoff**：本机快照 → 云上改 → Diff 合回（`handoff_jobs` · `BackgroundTaskReview`）。**不是**一场可续聊的云对话：用户仍在源本机会话；干活的是隐藏 `mode=handoff` 会话（空历史、一轮 pipeline、禁止 pause）；apply / discard 后收 host。**否决**升格为 Composer 一等入口或「一单=一场对话」的骨架。**否决**芯片武装入口（与 §7.8 双入口互斥）；后端作业暂留。
2. **云桌标准出口**：ModeControl **Diff 勾选合回**（首次询问落点；已登记可更换）；工作区工具条 **导出 ZIP / 导出到本机 / 只合回产物**（纯桌面 zip↔落点 · `mergeLandingDiff` · `MergeLandingReview`；冲突默认留本地；不经 `applyHandoffJob`）。

| 项 | 定案 |
|---|---|
| 与过桥 / 本机传统 | 云桌 **不**靠过桥；本机传统文件夹 **不**经合回当主写盘（已在本机权威上直写）。合回 = 云桌→本机单向出口 |
| 副本 / 云桌 | 日常权威在云桌；合回是单向写出。**否决**文件夹级 Dropbox 镜像 |
| 只读副本打开 | ✅「用本机默认应用打开」落 temp **只读**副本供查看（Office / PDF 等面板内看不了的类型），**不是**写出口：副本只读 + 不回写 + 不登记落点，故不动摇「点了才进本机」。要改仍走面板内编辑或合回 → [前端 UX §九](/docs/04-前端/前端UX设计.md) |
| 写回默认 | **Diff 合入本机**（勾选 / 全部接受；冲突须提示） |
| 写回旁路 | **只合回产物**（快捷）；⏳ **合回=开 PR**（二级；**观察后再排**，不挡大众 Diff） |
| 用户心智 | 「点了才进本机」——禁止暗示已自动双向同步 |
| 入口 | ✅ 云桌 ModeControl **只留合回**；ZIP / 到本机文件夹在工作区工具条导出菜单；只合回产物在导出菜单；**导出 ZIP 另挂「我的文件」云端工作区根**（从文件页进来的用户手里没有会话，只能绕回某个对话才够得着，那是缺口不是设计）——实现即「建一份快照再下载」，**不**新增第四种出口。文件树对文件夹点「下载」是另一条路：当前子树 zip（选中目录为根），独立 archive 端点，容量对齐面板上传/下载，**不是**整桌快照；协作桌与所有者云桌同一 `folder:` 树，能下单文件则子树 zip 同样走（勿套快照 409）→ [前端 UX §九](/docs/04-前端/前端UX设计.md)。Git 浅克隆进本桌在文件树工具条（与文件中枢根右键「克隆仓库」同活）。遗留 handoff 芯片武装入口已撤；手机无本机盘 → 无合回面、可 ZIP |

### 7.7 机制约束（实现）

- **路由（机制；以 §7.2 为准）**：云协作全云；本机传统 sidecar；过桥不当新默认。**贴文件不改场地**——区内引用原路径、区外才复制进 `attachments/`，本机绑定仍走 sidecar。启动失败（出输出前）可降级云；中途失败不降级。**生成中再发**跟占槽引擎：本机 live 走 sidecar `deliverMessage`（插队/排队），**禁止**打云 `/messages`——云 `turn_runs` 是另一进程，会当成空闲新回合。产品语义 → [运行时三模型 · 同对话再发](/docs/03-AI核心/运行时三模型与挂起.md#同对话再发steer--queue)。
- **健康 ≠ 绑定判定**：健康只决定「要不要拉起」，**不掺进绑定判定**——否则污染续跑 / 列暂停帧。
- **履约通道 ⊥ 展示通道**：本机 CLIENT_TOOL（workspace / host / mcp / board / board_read / notify / external_mount）不搭对话 SSE 投递，走**设备级履约流** `GET /v1/fulfill`（`device_id` + caps + roots；根变更 `POST /v1/fulfill/roots` 重声明，不重连）。空 `roots: []` 与「暂时读不出来」在 HTTP 上不可区分——桌面读失败不 POST（不清空）；残留窗口仅首连且首读失败，靠 `fulfill.no_fulfiller{reason}` 观察。**不改**公开 roots 契约。**为什么**：对话 SSE 是**展示**流——寿命跟着「谁在看」走（关掉页面就断），而「能干活的那台机器在不在」是另一回事；用展示流投递时服务端只能靠超时反推，每个本地 op 都熬满通道 deadline。多端同权跟播之后更不能用「谁在看」推断「谁能干活」。分离后有 `root_id` 时按根定位设备，同账号多机各履约自己声明的根（无根 op 的选机见下条）。
- **无根 op 钉发起设备**：`root_id` 缺席时（`host` / 本地 mcp / 区外目录挂载 / 通知 / 白板），旧选机取「最近注册的那台」会让同账号两台桌面在线时随机挑一台跑用户的 shell。跟随**发起本回合的设备**：桌面每请求带 `X-Client-Device`，纯 ASGI 中间件（`middleware/origin_device.py`）绑在请求任务上，回合任务 `create_task` 复制上下文即继承（`fulfill/origin.py`）。**分档**：动这台机器本身的四类（workspace / host / mcp / external_mount，见 `ORIGIN_PINNED_CHANNELS`）钉死原机，原机离线即**诚实报错、不转投**——把用户的命令跑到另一台装机上是答错了，不是降级；board / board_read / notify 属展示面（画布可能就开在另一台上），仍可另选。**为什么不记进会话表**：换台笔记本继续昨天的对话必须跟到新笔记本。**跨回合寿命**：rehang（履约方重连）与 cancel（用户停止）跑在回合上下文之外，读 pending CLIENT_TOOL payload 上盖的那份拷贝；延后回合（会话队列 / steer 提升 / 冷续跑）在载具上快照、drain 时重绑，否则会继承上一回合的设备。手机 / Web 不发该头、也不是履约方，选机行为与钉机出现前一致。**否决**新增「选哪台」交互卡：契约成本远大于收益。
- **本机引擎自带履约方**：sidecar 与云 API 是**两个进程、各有各的进程内履约中枢**，云端那条 `GET /v1/fulfill` 到不了 sidecar。本机回合因此由 sidecar 在自己的中枢里注册**一个**会话（caps 全开；roots 跟回合 `localRootId` 声明），帧经既有 stdio JSON-RPC `fulfill/frame` 通知交主进程，按会话找到活回合窗口后投给渲染层**同一个** `clientToolIngress`（云/本机两源一个消费口，`origin` 决定回哪条结算）。**为什么不让 sidecar 退回 sink 投递**：两模式共用一个投递口，才不会出现「云走中枢、本机走展示流」的双真相源。sidecar 自己的文件 op 仍直连 `Path`、根本不发帧。履约帧**不入** `SidecarEventBuffer`（attach 重放会让同一 op 再执行一遍）。**开发期**：各进程各自 `import` runtime/prompt，重启 API ≠ 本机引擎加载新代码；哪边要重启 → [本地开发 · 改代码后哪边会加载](/docs/02-架构/本地开发.md#改代码后哪边会加载)。**否决**让 API 清树顺带杀 sidecar、或给 sidecar 开 WatchFiles 跟 API 热更新（掐断桌面 stdio / 残杀长 SSE，与双中枢切分冲突）。
- **本机引擎坐云文件夹不跑 gVisor**：`create_folder` / 派工换桌可以让 sidecar 回合的队员坐到**无 `local_binding` 的云文件夹**（`ServerWorkspace(location=server)`）。隔离执行仍只属于**云执行面**（独立 `sandboxd`，不回落到 sidecar）。sidecar 对该桌 **不装配** `run`（换桌从出生桌注册表卸下，不是只改 prompt）；失败若仍撞上 gVisor 健康检查，码是 `exec_env_not_linux` / `exec_env_sandbox_unavailable`，**禁止**说「本机执行环境不可用」。拷工程走 `file_copy` / `file_write`。**否决** sidecar 用本机 subprocess 冒充云隔离。云协作 Linux 回合不受影响。装配谓词 → [工具与能力 · 沙箱](/docs/03-AI核心/工具与能力系统.md)；拓扑 → [安全 · 五、代码执行沙箱](/docs/05-平台与运维/安全权限与治理.md)。⏳ sidecar 对云桌的文件 op 仍写本机 `data_dir/workspaces`：与云 API 同机同盘时碰巧是同一份；生产两盘不一致则「拷到云文件夹」不会落进云卷——远程 `WorkspaceBackend`（`/v1/workspaces/{id}/files`）另案，窄票不对文件 CRUD 敞开。
- **在场闸（回合前，毫秒级）**：起回合前查履约中枢有无「持 workspace 能力 **且** 声明了本会话绑定根」的在线设备，缺则**立即**三档诚实拒绝——桌面未连接 / 桌面在线但未持该根 / **发起本回合的设备离线**（仅钉机档，别的机器在线也不转投）——并指引「点重新生成」（勿重发，免出两条用户消息）。**否决**用超时反推在场。回合中文件工具卸除 / 拒写盘派工也只认履约在场（桌面重新连上即恢复）；单次 settle 超时只失败该 op。履约流断开时，桌面**已经在跑**的文件通道 op 立刻失败（「桌面在重连，请再试这一下」），不空等通道 deadline、不算连不上；尚未投到桌面的仍走 reconnect grace/rehang。用户停止仍 `client_tool_cancelled`、不结算。准备段本地 IO 预算耗尽仍用通道无响应文案中止准备（尚未开跑）。闸问中枢的问题必须与投递时**逐参数一致**（含来源设备），否则会出现「闸放行、第一个 op 却报无机可投」。
- **取消要先于回合任务收尾**：用户点停止时，先把在飞 CLIENT_TOOL 的 `client_tool_cancelled` 帧投给履约方，**再**取消回合任务——任务一旦 unwind，`InteractionRegistry.suspend` 的 `finally` 就丢了登记，设备会继续跑完一个没人等的 op（`host(action=shell)` 这类尤其伤）。云端停止路由与 sidecar 停止 handler 两条路都要发；离线设备收不到属尽力而为。
- **prepare 本地 IO 总预算**：baseline + `probe_exec` + `exists` 等 prepare 期本地 IO 共享一个总时钟（`prepare_local_io_budget_seconds`，默认 20s），超支即 case-3 收口；**否决**逐 op 各自 deadline 无界相加。执行期工具 IO 不受此闸——回合级 deadline 只是「绑定」，**必须由 prepare 段显式开 span 才生效**：若绑定即全程生效，跨桌派工在执行期重探**目标桌**也会被算进 prepare 预算，目标桌一次探测超时就打掉整回合，还报「本机工作区通道无响应」这条指向出生桌的文案。
- **结算按来源路由**：桌面 `resolveInteraction` 显式带 `origin`（`cloud` | `sidecar`），**不**由「本机是否有活跃 sidecar 回合」反推——双模式并存时该反推会把云回合的结算误投给 sidecar。
- **迁移（clean）**：旧桌面不连履约流 = 在场闸判定「无履约者」，本地回合直接拒并提示升级；**不**为旧客户端保留对话 SSE 投递回退（双投递 = 双真相源）。
- **Office 文档能力（云 = 本地）**：附件分流预解析与工作区 `file_read` **透明抽取**共用一核：`.docx` 主路径 python-docx（段落+表，不经 markitdown）；pdf 按 `start_page` 开窗（每窗约 40 页）pdfminer，仅第 1 页窗抽失败才 markitdown；pptx/odt/rtf 走 markitdown。抽取在可杀子进程内，墙钟约 12s；超时/扫描/OLE `.doc`/抽失败 = **成功观察信封**（≠ 通道活性挂起，≠ `contract_failure`）。sidecar / 云盘父进程只 stat，子进程按路径打开文件（磁盘摄入 100 MiB）；过桥 `LocalWorkspace` 仍通道 `read_bytes`（IPC 摄入 25 MiB；桌面无 Python 抽取栈）。上传顶 50 MiB，与过桥抽取顶不是同一闸。嗅探误后缀 / OLE 取 size 走 `read_head`（头字节 + 总大小），不走整文件闸。读时默认不写旁路，若已有 `path.md` 可优先读（`start_page>1` 当场抽取、不读旁路）。确定性 `md_to_docx` / `md_to_pdf` 仍云=本地。xlsx/csv 等不抽全文（成功信封）。权威口径 → [工具与能力 · 工作区 Office/PDF 读](/docs/03-AI核心/工具与能力系统.md)。依赖在 `pyproject` 主依赖与 sidecar extra 对齐；`bundle:sidecar` 冒烟校验 `docx` / 抽取栈 / md→docx。**否决**为瘦身砍掉 Office 却仍跑同一管线。预解析失败仍不阻塞回合（路径提示回落；office/PDF 勿一律教 `run`）。
- **岔路 B（否决 A）**：平台 key 不下放；推理经云代理；计费权威在云、不从客户端上报。名册同构：桌面铸 **folders 窄票**（`POST /v1/folders/token`）注入 sidecar；`list_folders` / `resolve_folder` / `create_folder` 与换桌 binding 问云 `GET/POST /v1/folders`（及 `GET /{id}`），`delete_folder` 走 `DELETE /{id}`（**仅软删**；`/permanent` 不进窄票），**不**打本机 PG、**不**把 access 塞进引擎。对话日志 + 规则/记忆同构：桌面铸 **account 窄票**（`POST /v1/account/token`）注入 `accountAuth: {baseUrl, apiKey}`（`baseUrl`=`…/v1/account`）；`search_conversations` / `read_conversation` 问云 `POST …/conversations/search|read`；`assemble_turn_rules` / `remember` / `DocumentMemoryStore`（consult / update_folder_profile 经同一 store）问云 `POST …/rules/*` 与 `…/memory/*`——仅 account（或 access）可调、引擎最小面，**不**把 UI 对话/文档/记忆编辑器 CRUD 对窄票敞开。无票仍走本机 DB。开回合另注入 `folderId` + 本地绑定（`localRootId`/`localSubpath`）供记忆 workspace key，避免为归属/钥匙硬连本机库。
- **持久化**：sidecar → 本机 outbox → 主进程回写云；Renderer 退出回写职责。用户回合同走 `bind_turn` → `OutboxStore.finalize(local)` → `POST /local-turns` → 云 `turn_journal`（可选 `agent_mentions` 落 `messages.agent_mentions`，旧客户端省略）；本机禁止 `MessageRepository` 直写 PG。混合态下对话正文全量回写云——**不得承诺「数据不出本机」**。大众不装 Docker/本机 PG；开发 compose 仅开发者联调。**outbox journal 发射序**：磁盘仍是扁平 `seq(str) → {kind,payload,ts}`（overflow 键继续占 `1e6` 带，不迁客户端形状）；每条事实另盖整型 `ord`（首次写入分配、前缀重写按 occupancy 保留，对标 Postgres `created_at`）。Python 与桌面崩溃打捞都只按 `ord` 读序——`band` 不够（overflow 夹在封盘前缀与 resume live 尾之间），`ts` 可 null，JS `JSON.parse` 会把整数样键按数值重排故不能信 map 插入序。老文件缺 `ord` 保持旧行为（live-then-overflow / 整数键序）。**回合历史**：sidecar 无消息库，窗口由云端 `load_chat_context` 经 account `chat-context` 下发（与云回合同源：摘要 + 近窗；历史 harvest 注记仍折进窗）；桌面不再从本地切片拼全量原文。桌面 cookie 拉到则 sidecar 不再打云（同一 ``chat-context``）；省略时 sidecar 用窄票拉并重试 5xx。拉窗失败不得用空窗开跑，仍失败则回合明确失败。
- **投影同寿命（渐进写云）**：本机传统活态经 owner Bearer 薄写 `POST …/local-turns/begin`（幂等插 user + `CloudStore.begin_turn` running 占位 + 本机 occupy 的云 TurnLease）· `…/heartbeat`（桌面 ~20s 续租，owner 由 message_id 决定、跨 API worker 可心跳）· `…/journal`（`append_journal(seq=int)`；中途只送未确认增量，live / overflow 两档内存水位；失败指数退避、成功后密写，同一波失败只记一次；水位不写回 sidecar 拥有的 OPEN 文件，进程重启可整本再送——云端幂等。**否决**把抄云失败并进文件通道或弹用户同步横幅）· `…/stream-segments`（`upsert_stream_segments`，未变则跳过，不改 `messages.content`）· `…/abort`（仍 running 则双删助手+user 并放 lease；已 settle 为 no-op 仍放 lease）。不走 `POST /messages`、不铸题、不 compaction、不扩窄票；sidecar 不直写 PG。终局仍 `POST …/local-turns`（缺省 `complete`，挂起/取消/完成都放 lease）。GET overlay 叠 `running` + segments。本机 FIFO 出队与点发送同一条 `startTurn`：先 `begin` 再开跑（`queue/needStart`）；OPEN 文件只投影 journal/segments，**不再**从文件补占位。过期的本机 lease **不**走云 `recover_turn`（桌面 salvage 才是权威）。
- **挂起帧**：settlement 预写即消费帧（决策即事实，不还帧）。**否决**：保留帧 + journal 对账改写 paused[]（双真相源对账 = 补丁绊线禁止形态）。挂起帧与 outbox **不并同一状态机**。
- **恢复面**：默认路由变更须重估双面恢复；路由意向 ≠ 恢复事实——刷新后无条件并行查本地+云。
- **契约 α（本地回合恢复）**：刷新 = **双面恢复**（云消息投影 ∥ 本地 recovery/attach）。**云投影从开跑起即是权威**（`begin` 占位 → 中途 `journal` / `stream-segments` → 终局 `local-turns` settle 同一行）；outbox 是 sidecar 落盘与 POST 失败重试缓冲，**不是** hydrate 主源——同 id 仅当 unsynced **严格更厚** 时覆盖云薄壳（禁止无条件 skip、禁止整窗替换）。resume / 刷新后的活 SSE 仍靠本地 attach，**勿只信云薄壳**（GET overlay 是快照，不是 live 泵；冷水合 `isGenerating` ≠ 本端占用）。冷 GET 空窗且非确定空会话：overlay 等 recovery 投影后再揭，空数组不得写入 opened 缓存。列表 `GET …/messages` 可瘦 `runs.events`（`events_complete=false`）；全量 journal 走 `GET …/messages/{id}`，不把千级事件塞进开窗。sidecar 被杀：可 salvage 的 OPEN 走封盘写回，**不** abort 未 settle 的 running 占位；仅 begin-only 空壳 abort。终态已投递则 `await_live_detached_drive` 有界等待（grace 超时仍 flush + settle，不 cancel drive）；工人仍跑时无界等。不冲 β；不放宽 hydrate、不透传 unsynced journal（掉帧/审计员另案）。→ `projection.ts` / `local_turn.py`；水合 → [前端技术 · 打开对话水合](/docs/04-前端/前端技术与架构.md)。
- **回写 id 契约 ⏳**：`local-turns` 的 `user_message_id` / `message_id` 就是 `messages.id`（PG UUID 列），schema 须按 UUID 收口——非法值判 **422**：桌面把 4xx（除 401/408/429）当永久失败搬死信，5xx 则无限退避、卡住的 outbox 每 6min 刷一次 500 永不自愈。sidecar resume 缺 id 时铸真 UUID（`resolve_resume_user_message_id`），**禁止**派生 `resume-{turn_id}` 这类 43 字符 token。⏳ 收紧须**等** 0.6.5 的 `get_by_id` 容错把可配对的存量 outbox 自救完再发，早收会把还能上云的一并切掉。代价：切掉的存量回合只留本机、云端永无此回合；死信仍显示「待同步」是既有死信面的诚实缺口，另案。**否决**：服务端把 `resume-*` 收成合法句柄；`uuid5` 洗成合法 id 再落盘（自愈 + 派生主键，破「按 client-minted umid 去重」的回写幂等）；桌面单独改写存量文件（旧客户端吃不到）；只改 500 文案。
- **产品对外（档 A · 断线只读）**：断网/服务不可用时可浏览已缓存对话与本机文件（只读）；不能发送、改文件、跑 AI。完全离线 ⏳ 见 §7.4。
- **断线只读 = 未验证会话（恢复即补正）**：只读壳是用**缓存身份**进的，服务端从未确认过这条会话，握手期才下发的东西（首当其冲 CSRF 令牌）一概没有 → 读请求全通、写请求全 403，用户看到「点了没反应」。恢复联通**必须重跑同一条 bootstrap** 把握手补完才算在线；每个 online 边沿至多一次，补正失败落回只读等下一个边沿。**否决**：只补单个令牌；只翻连接状态位当恢复；给各写入点分别加自愈兜底（补丁绊线禁止形态）。→ 见代码: `AuthGate` 会话补正

### 7.8 关电脑、导入与「云上做完再写入」

> 主循环归属：收（产物落哪张桌子）+ 看（换设备还能否跟）。

**物理（✅）**：关电脑还能让 Agent 改文件 = 跑的时候那些文件**已经在云上**。没有第三种可能：过桥要电脑在线履约；打开本机直改要引擎与盘同侧。故「从本机导入、在云上做」与「先抄一份到云上再关电脑」在**团队怎么改文件**上是同一件事。

**产品差（「电脑当家」）**：不是另一种存储。差在家仍在原文件夹、原件点了才动、云拷贝默认不是新家（进行中标明「原件尚未改动」；「留在云上接着用」才搬家）。用户面须与导入「复制一份、原件不再跟着变」互斥。

**过桥**：不当「在哪工作」选项；不当关电脑方案；不把 sidecar 失败静默走过桥当正式能力。行业云任务选「在这台机器上执行」是另一产品槽（异步任务的执行落点），≠ 打开本机文件夹的第三引擎。

**Composer 入口（✅）**：桌面在「从本机加入」选完路径后给 **「先在云上做，原件先不动」**，与「直接改这个文件夹」「复制到云上当新家」互斥，不打推荐、不回第一屏。Composer 点导入 / 借用先弹轻量确认（无改名 / 重选夹），确认后开传（默认本机名）；命令面板 / 文件中枢直达仍用完整确认对话框（标题「云上做完再写入」）。手机无出发、可跟播已建云对话。骨架 = 导入同款快照进云文件夹（硬顶同导入）+ 预登记原文件夹为写回落点 + 普通云对话接着聊；**禁止**走遗留 `handoff_jobs` 隐藏会话。写回走既有 Diff 合回（冲突留本机）；芯片另给「留在云上接着用」。不自动写回、不每句重新抄原件。进行中标明「原件尚未改动」。

**遗留后台云端** → §7.6 第 1 条：芯片武装入口一并撤掉，避免双入口。后端作业可暂留，不再从产品面武装。

## 八、协作桌（文件夹成员）

> 主循环归属：收（同一张云文件夹上的文件）+ 看（成员跟播桌上对话）。

几个人围**同一张云文件夹**：文件 + 这张桌的设定 + 桌上对话。成员看见的就是这张桌，不是第三种容器、也不是挂进对话的第二根。与「公开分享」（对话只读快照 `/shared/<id>`）是两回事。词条 → [术语表 · 协作桌](/docs/01-产品/术语表.md)。

| 项 | 现状 |
|---|---|
| 身份 | `Folder.user_id` 仍是所有者；成员走 `folder_members`（加法式，不在 owner-scope 开洞）。外人 404，不泄漏存在性 |
| 角色 | `owner` / `editor` 可写（续跑 / 跟播 / 审批 / 停止）；`viewer` 只看。角色即授权，不加第二道门。成员吃同一张桌的**已有**文件夹层设定；账号级记忆仍私有 |
| 入口 | 所有者「我的文件」里**有名册的桌根用人图标标协作**（含待接受；不写「已共享」），动作是「成员 / 邀请成员」。被邀请的人在文件中枢「与我共享」（扁平根，同一 `folder:`） |
| 邀请 | 仅定向（好友多选 + 精确搜用户名/ID；非好友仍可搜邀；已成员/待接受灰显；所有者可取消 pending）。拉黑挡新邀请，不自动移除已成员。注销级联 |
| 配额 | 每桌 20 人（含所有者 + pending）；邀请 20/h。→ `folders/limits.py` |
| 盘 | 成员读写的是所有者那张云桌。`ws_id` 只有 `folder:` / `conv:`。文件夹对话 CEO `<工作区>` 文件节可点名本对话写/改/导出（上限 8，不含只读；工人不加） |

**否决**：独立文件盘 + 会话级第二根 `shared/<别名>/`（废名「共享空间」，已删表、不做兼容层；`/v1/shared-spaces` 404；盘上 `workspaces/shared/` 遗留目录不迁移、不 rmtree，扫盘跳过该段）；链接加入；共享账号级记忆；本地共享 / 双向同步；实时协同编辑；组织概念；公开文件链接（对话快照 `/shared/<id>` 仍是另一条）。
