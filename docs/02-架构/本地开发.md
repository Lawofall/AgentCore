## 2. 启动后端

```bash
cd apps/server
cp .env.example .env
# 必填：生成 ENCRYPTION_KEY（.env.example 中为占位符，勿用于生产）
#   python -c "import secrets; print(secrets.token_hex(32))"
# platform 模式再填 PLATFORM_API_KEY 等；BYOK 默认模式登录后在设置页配 key
uv sync                       # 仅运行依赖；跑测试/lint 需 uv sync --extra dev
uv run alembic upgrade head   # 应用数据库迁移（DEBUG=true 时启动会自动执行，此步可跳过）
```

**Windows 推荐**用清树脚本启动（先按命令行白名单杀掉旧的 `python -m agentcore` / `uv run …` 整棵进程树，确认端口无 LISTEN 再起新实例）：

```powershell
powershell -File apps/server/scripts/start-dev-server.ps1
```

**并行 Agent 纪律**：重启脚本自带真跑保护——杀树前读 `logs/dev.jsonl` 末行时间戳，活跃期内（默认 120s）拒绝重启（非零退出）；`-Force` 强杀须知情。`AGENTCORE_RELOAD=false` 只防 WatchFiles，防不了本脚本的主动清树。

手动启动（端口空闲时）：

```bash
uv run python -m agentcore
```

`python -m agentcore` 从 dotenv 读取 `HOST` / `PORT` / `DEBUG`（默认 `0.0.0.0:8000`，`DEBUG=true` 时热重载）。进程环境变量 `AGENTCORE_ENV`（默认 `development`）选文件：`development` → `apps/server/.env`；其它值优先 `.env.{env}`，不存在则回退 `.env`。与 VS Code 自动启动任务一致。启动前会预检目标端口：若已被占用则立即报错退出（非零码），避免 Windows 上多实例静默共存、孤儿 worker 继续服务旧代码。**dev（`DEBUG=true`）启动时自动 `alembic upgrade head`**（`db/migration_check.py`；成功升级打 `db.migrations_upgraded`，失败不阻断启动、回落 drift 告警）——多 worktree 并行下别的分支合入迁移后，本地重启即对齐，无需手动跑；prod 不自动动 schema，迁移仍是显式部署步骤。

**长时间真跑协作场景前，先关热重载**：`.env` 加 `AGENTCORE_RELOAD=false`（独立开关，不必动 `DEBUG`，缺省沿用 `DEBUG` 原逻辑）。WatchFiles 检测到任意 `agentcore/` 文件保存就会重启 worker（宽限期仅 2s），会打断正在跑的多 Agent 回合——多 Agent 并行改码 + 同一台 reload 后端真跑 = 互相残杀。恢复热重载：删掉该行（或改 `true`）再重启。启停均打 `server.started` / `server.shutdown` jsonl 事件，可在 `logs/dev.jsonl` 复盘重启时刻。graceful lifespan 关停会按 `/stop` 语义抢救收口（已有产出落盘、lease 显式释放）；真硬杀 / 崩溃仍走 orphan / sweeper（见 [`执行引擎 · 边界与硬杀韧性`](/docs/03-AI核心/执行引擎架构设计.md)）。

**DEMO_TAPE 与热更新**：开磁带回放 / 录制相关开关时同样会关掉或干扰 WatchFiles 热更新路径——真跑验收前勿与热重载叠开；配方与磁带用法见 [`demos/README.md`](/demos/README.md)。

**手动重启必须杀整棵树**：`taskkill /F /T /PID <pid>`（`/T` 必带）。只杀子进程会留下幽灵 reload worker 继续占端口、跑旧代码；只杀父进程同理。Windows 上旧 server 杀不干净会导致双进程打架（端口看似占用、请求打到旧代码）。清理后应只剩一个 LISTEN 在目标端口上的健康实例。

### 改代码后哪边会加载

桌面 **本机传统** 回合跑在 sidecar（`python -m agentcore.sidecar`，桌面主进程 stdio 拉起），**不是** 8000 上的 API。两边各 `import` 一份 runtime/prompt，寿命跟进程走。这是 [双模式工作区](/docs/02-架构/双模式工作区.md) §7.7 的既定切分（两个履约中枢），不是热更新漏了。

| 你在测什么 | 加载新代码要重启 |
|---|---|
| 本机传统（桌面打开了本机文件夹） | **完全退出并重开桌面**（只重载渲染层不够）。对账：新一条 `sidecar.ready`，本场 `cost.prompt_assembled` 的 `ceo_prompt` / `assembly_hash` 相对改前应变 |
| 云协作 / 浏览器 / 通用·进阶关掉「允许本机执行」 | 重启 API（`start-dev-server.ps1`）。对账：新一条 `server.started` |

`start-dev-server.ps1` **故意不杀** sidecar：命令行白名单只匹配 `-m agentcore`。API 清树若误杀 sidecar，会掐断 Electron 的 JSON-RPC、把活着的本机回合打死——与上面真跑保护同一类伤害。也**不要**给 sidecar 开 WatchFiles 来「跟 API 一起热更新」：长 SSE / 多 Agent 真跑会被 2s 宽限杀掉，这正是 `AGENTCORE_RELOAD=false` 的理由。

`GET /version` 的 `git_sha` 是 HEAD 短 SHA，**不含**未提交改动；不能用来判断工作区里的 prompt 有没有进进程。

## 黄金场验收（LV 案两幕）

常备端到端场：幕1 MLR 调研落盘 → 综述收场（**不**出阶段推进卡，也不把调研员续进辩论当证人）。用户点名开辩才另开一场（独立图，不链幕1）。真跑走产品对话；**验收权威** = 离线六环 `uv run python scripts/mlr_golden_rings_check.py <conversation_id>`（`agentcore/conformance/mlr_golden_rings.py`，只读 DB+工作区、零 LLM）。旧磁带若含推进卡 / 证人，检查器仍能判历史场。

**判据决策**：① 环3 以 **journal 为权威**（SSE 全绿 ≠ 落库）→ [运行时三模型](/docs/03-AI核心/运行时三模型与挂起.md)；② 环4 = 机制对齐（单辩手成功检索超预算即 FAIL；被拒超发起不占槽）。真跑窗口禁重启后端 / 改 `agentcore/`；勿与 evals 并行争限速。

## evals 评测跑法

`apps/server/agentcore/evals/`。**合成 evals ≠ 真实用户数据**；dogfood = `logs/dev.jsonl` ⋈ Postgres → [对话日志分析指南](/docs/05-平台与运维/对话日志分析指南.md) / `conversation-logs.mdc`。优化前须声明证据性质。决策闭环金标（routing / deliverable / citation，观察-only）→ [`evals/dogfood/README.md`](/evals/dogfood/README.md)。

本地真跑凭据：优先测试账号（`dev` / `DEV_USERNAME`）已配的 OpenCode Zen BYOK（与桌面 / `probe_turn` 同路）；`EVAL_DEEPSEEK_*` 显式覆盖；勿默认依赖 `PLATFORM_API_KEY`（见 `evals/harness.py` · `.cursor/rules/local-llm-dogfood.mdc`）。

防崩：会话内设 `EVAL_JUDGE_MODEL` / `EVAL_DEBATE_MODEL` / `EVAL_DELIVERABLE_FORM_MODEL`（缺省易撞中转拒名）。跑序便宜→重：`--lint-only` → probe L1 → core L1 → `--calibrate`（kappa≥0.6）→ L2 → 诊断子命令 → `--compare`（最重）。先校准再 `--update-baseline`。相对基线观测（`--baseline` / `--diff-reports`）是报告型、不卡门禁：看共享用例翻转方向，不用固定容差。夜跑（`evals-nightly.yml`）把 `--baseline` 挂在 routing / style / compare / probe（以及功能 / MAST）的既有真跑上，对着 `eval-out/*-latest.json`；`*-baseline.json` 仍只升。夹具必须 `copytree` 隔离（禁挂源目录）→ `evals/harness.py`。长跑用分离进程；小时级限流窗宜等不宜硬重试。

**playbook 路由回归**（报告型，不进 PR / `release:gate`）：提示词改完要看「普通人说法会落到哪」时跑。真跑 LLM，dev BYOK（禁默认踩 `PLATFORM_API_KEY`），不许 mock 模型。默认 9 场景 × 3 采样；口语 6 条 + 教科书对照 3 条。产出 `eval-out/playbook-routing-*.json`，`--update-baseline` 写下次对比用的落点指纹。

```bash
cd apps/server
uv run python -m agentcore.evals --playbook-routing --lint-only
uv run python -m agentcore.evals --playbook-routing
uv run python -m agentcore.evals --playbook-routing --update-baseline
uv run python -m agentcore.evals --playbook-routing --samples 5 --keys audit_check_bugs_save_file
```

花费量级（economy / `deepseek-v4-flash`，约 9×1）：全套约 43 万 input / 0.9 万 output tokens，审计场景因探路最贵。默认 `samples=3` 约 ×3；`samples=5` 约 ×5。免费档连跑可能撞小时限流。与 `--routing`（Delegated/NotDelegated 准确率门）不是同一条命令。

路由探针 `probe_routing_think.py`：打转只计第一动前思考。其余探针入口 → `apps/server/scripts/archive/probe_*.py`（不在 CI 硬门禁，易腐化；见该目录 README）。

## 排障：本机代理 fake-IP 导致 `read_url` / `web_search` 全失败

**根因**：Clash 等 fake-IP（`198.18.0.0/16`）让 SSRF 守卫（`core/net.py`）正确拦截——非产品缺陷；生产无此代理。诊断：`uv run python scripts/archive/probe_egress.py` 看 `fake-IP 检出`。解决：代理改 `redir-host` / 关 FakeDNS，或临时不劫持 DNS。SSRF 不为 dev 放宽 → [安全 §一](/docs/05-平台与运维/安全权限与治理.md)。
