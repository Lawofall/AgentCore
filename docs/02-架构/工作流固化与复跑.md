# 工作流固化与复跑

> **主循环归属**：[组](/docs/01-产品/产品定位与品牌.md)——在工具箱里把拆法锁成可复跑的图。复跑时不再由 CEO 判轻重组队，改按图组。
>
> 站立任务 / Webhook 怎么触发它 → [后端架构 · 站立任务](/docs/02-架构/后端架构.md#站立任务--webhook)。

本文只写代码看不出来的那部分：入口为什么在工具箱、复跑到什么程度算「同一件事」、哪些形态有意不接、`definition` 归谁所有。

## 一、主入口在工具箱，不在对话

要一张可复跑、可绑站立的固定图，去工具箱新建或套官方模板，在画布上设计。日常聊天仍是 CEO 即兴组队——两件事不混。

**否决：从刚跑完的一轮对话固化（完成态「存为工作流」）。** 要固定拆法的人会去工具箱；聊天里的组队是临场分工，不该在收工时推销「锁成死图」。编排税由选择「要一张图」的人承担，不摊到每轮协作的完成条上。对话不再写入 `source.kind=turn`；已有历史行仍认、仍可抽槽。

**否决：把「从某次对话导入」搬进工具箱。** 那仍是固化，只是换了个门。

## 二、复跑 ≠ 原轮，这是结构性的

工作流走 mechanism-direct，**CEO 不在场**（不是被 `topology_lock` 挡住——没有 react 循环，`replan` 永远不会被调用；锁只是给仍可能摸到 plan 的旁路兜底）。所以复跑拿到的是画布上那张**静态图**：同样输入若跑出不同的中间产物，没有任何机制能再改拓扑，用户只能在 `human_gate` 处做文本 steer——**能改内容，改不了拆法**。

### 为什么不让 CEO 回到复跑现场

**否决：复跑时带 CEO，让工作流当「起手建议」而非死图。** 否决理由是它误解了需求。用户说「按这张图再来一次」，真正要的是**换个输入还这么拆**，不是复现临场判断的随机性——如果每次跑出来结构都不一样，那反而不叫「再来一次」。

这里有两种动机，产品上要分清：

| 动机 | 用户要什么 | 谁服务它 |
|---|---|---|
| 「这个流程固定下来」（每周一出简报） | 确定性：结构一致、成本可预期 | 锁拓扑 + 无 CEO，正对 |
| 「再来一次那样的协作」 | 换个输入还这么拆 | **参数化**（§三），不是 CEO |

把第二种动机误读成「要自适应」，就会得出「该带 CEO」的错误结论。

## 三、参数化：槽位与它的时机

没有参数化，任务描述里写死的具体主题（「调研 Notion 的协作功能定价」）会逼用户下次进画布逐个节点手改。

**槽位的默认值就是抽出时的原值**（历史固化行 = 当年那一轮的原文；官方模板 = 作者写的默认）。所以「原样再跑」与「换个主题跑」是同一套机制：跑一次时预填默认值，不动就是逐字复现，改了才带覆盖值；站立任务用默认值跑，正对「每周同一主题出简报」。

### 抽槽挂在「跑一次」，不在保存路径

**否决：保存时同步抽槽。** 用户点保存时的心智是「先把这张图存下来」，还没想到换主题；真正需要槽位的时刻是第二次要用它、看到任务里写死着具体主题的时候。抽槽按需做一次：参数表当场摆出来预填原值让他过目，抽错能改，失败就退化成按原文直接跑、下次还能再试。

只对历史固化来源抽——官方模板复制来的本来就带槽位，手画的由用户在画布上自己管。对话不再产生新的固化来源。

### 模型只有指认权，没有改写权

抽槽是唯一让模型碰用户任务文本的地方，所以它被约束成：模型只能报**原文里逐字出现的片段**，代码自己去找那段做替换，找不到就丢掉这个槽位；替换完还要用默认值正向展开一遍与原文逐字比对，对不上整份作废。

这保证了「不填任何覆盖值地跑一次」必然复现抽出前的任务——参数化不会悄悄改写用户的图。

## 四、辩论有意不进画布

**否决：支持把一场辩论固化成工作流。** 对话固化入口已撤，这条仍然成立：辩论天然绑定一个具体命题，没有人每周辩同一个命题。辩论里真正可复用的是**形态**（红队 / 正反 / 圆桌、轮次、取证要求），正确载体是带命题槽位的官方模板。

技术层三条各自独立，补任何一条都不够：辩论不写 `plan_snapshot`、辩手 `depth = 2`、身份在 `DebateConfig` 不在 plan 层。

## 五、`definition` 归谁所有

同一个形状栽过四次——**有人拿一份多方共享的 JSON 文档，按自己知道的字段把它重建了一遍**，别人加的字段就被静默抹掉，且没有任何信号。所以所有权必须写下来：

| 内容 | 归属 | 规则 |
|---|---|---|
| 来源标记 | 服务端权威 | 独立列，只在创建时写一次；更新路径不收这个参数。今日产品路径不再写入 `kind=turn` |
| `nodes` / `edges` / `slots` | 用户画布内容 | 服务端**只校验不重建**，未知字段原样透传 |

来源不放在 `definition` 里，除了防丢，更因为客户端整份覆盖那份 JSON——放里面它既能被删，也能被**伪造**，让手画的工作流冒充固化来源去骗抽槽。

推论：给画布加字段不需要改服务端白名单；给工作流加服务端权威元数据则必须走独立列，不许塞进 `definition`。

任务描述里的占位符字符集是**前后端逐字一致**的契约。认得比服务端多，画布上就会把字面量画成变量胶囊而跑出来不替换。

## 六、跨端

工作流整组面**有意只做桌面**（画布、CRUD、直跑、槽位）。窄屏按黑名单不上（产品页单树）；parity 登记表已清，不再要求手机对等裁决。
