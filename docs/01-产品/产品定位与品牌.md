# 产品定位与品牌

> **状态**：✅ 已确定。术语 → [术语表](/docs/01-产品/术语表.md)；已知方向 → [路线图摘要](/docs/01-产品/产品路线图摘要.md)。

## 一、定位

**Multi-Agent AI 工作台**——对标 Cursor / Codex / Claude / Coze，核心差异是**真正的 Agent 团队协作**（非「单 Agent + 子任务派发」）。

用户心智：「**掌管一支由 AI CEO 带队的 Agent 团队**」——你是老板，定目标、拍板；团队替你跑。理念：**协作，是更高级的智能。**

**解决的真实问题**：一件事大到单个 AI 一轮做不完、做不好——要广度、要交叉验证、要多步产出——而用户不愿自己拆任务、盯进度、当项目经理，却必须能看见、能拦下来。

### 用户与场景口径（写文档、做取舍时按此）

- **不切目标人群**：底座是通用大模型，能力面也通用，切人群等于把工具做小。文档禁止出现「目标用户 = ×× 人群」式表述。
- **用主循环代替人群做判据** → §二。
- 场景只作**代表性例子**出现（调研成稿、代码改动与验收、资料整理、方案对抗评审…），不写成人群画像，不暗示其它场景不支持。
- **形态口径统一**：一律写「Multi-Agent AI 工作台」。「协作智能」是品牌层品类主张（§三），不替代形态表述；**禁用「生态平台」**描述本产品（生态市场暂不启动 → §四）。

## 二、产品主循环（功能取舍与文档写作的判据）

**说 → 组 → 看 → 拍 → 收**，外加一条「记」的回路。

| 拍 | 是什么 | 用户得到什么 |
|---|---|---|
| **说** | 一句话说目标 | 不配角色、不选流程、不填表单 |
| **组** | 系统判轻重、自动组队 | 轻问直答不加编排税；重活才 `delegate` / `debate` |
| **看** | 协作过程可见 | 协作图、过程时间线、便签墙、辩论室 |
| **拍** | 只在真决策点停下来问 | 检查点 / 审批 / 升级；其余自己跑（组队与开辩不先确认编制） |
| **收** | 产物落到工作区 | 文件 · 文档 · PDF · 代码 · PR，且交付诚实对账 |
| **记**（回路） | 跨会话记住偏好、文件夹事实与导航 | 下一轮的「说」更短 |

**判据**：新增功能先问「它服务哪一拍」。答得上来 = 产品功能，产品文档要写、首屏要有位置；答不上来 = 工程内务或实验项目，只进 `02`–`05` 技术文档，**不进产品叙事、不进路线图产品方向**。

不服务任何一拍、但主循环跑不起来的（认证 / 计费 / 安全 / 部署 / 协议对账）= **平台底座** → [平台地图](/docs/05-平台与运维/平台地图.md)。

不服务主循环、也不支撑它的 = **实验项目**（如 [AI 小镇](/docs/04-前端/AgentTown客户端.md)），只在自己的专题里说明，不进核心能力清单。

## 三、品牌用语

| 层级 | 内容 |
|------|------|
| 品牌理念 | 协作，是更高级的智能 |
| 品类定义（品牌层） | 协作智能平台——产品形态仍一律写「Multi-Agent AI 工作台」 |
| 产品标语 | AI 的下一步不是更聪明的个体，而是更好的协作 |
| 功能标语 | 多 Agent 协作 · 全程可见 · 你是领导者 |

用户角色：从「提示者 / 指令者」升级为**领导者 / 老板 / 决策者**。

## 四、差异化（交叉壁垒）

| 壁垒 | 说明 |
|---|---|
| Multi-Agent 原生 | 委派一等公民、层级编排、单 Agent 与 Team 同一执行路径 |
| 场景连续 | 一个工作台 + 多 Agent 团队跟随同一用户跨编码与研究/写作/分析 |
| 生态闭环（⏳ 暂不启动） | Tool / Skill / Rule / Memory / Team 五类资产为**远期方向**，代码无市场实体与安装绑定，**当前不作为壁垒**。Agent 始终是运行时参与者，不是可上架资产 |

以 Multi-Agent 协作为核心差异，走 **Codex/Devin 的运行时深度**；不在「更强单体模型」赛道正面对抗。生态位对标（Coze/GPTs）随生态启动再谈。

**已知差距**：模型能力靠 Gateway 可换；沙箱与跨进程挂起余项见路线图与 [执行引擎](/docs/03-AI核心/执行引擎架构设计.md)。**Git 闭环**已落地 → [工具 · Git 闭环](/docs/03-AI核心/工具与能力系统.md#git-闭环)。

## 五、Agent 角色策略

不做预制角色；采用「**动态角色分配 + 用户可选行为模板**」。

| 原则 | 说明 |
|------|------|
| 无预制身份 | 无固定「代码 Agent / 写作 Agent」 |
| 动态专精 | CEO 按任务为 worker 分配临时角色 / 工具集 |
| 行为模板（可选） | 用户可保存可复用工作流配置（非固定角色） |

**否决预制角色**：把路由推给用户、跨域任务边界僵硬、专精会随模型过时、竞品无因预制角色胜出。

## 六、决策理由（一行）

「协作智能」新品类避开「更强模型」正面战；与真实 Multi-Agent 能力对齐；中英双语可扩展。**不切人群**：能力面通用，用主循环（§二）而非人群画像做取舍判据。

## 七、演进原则

渐进兼容、复用基建、Multi-Agent 优势最大化、先跑通再优化。Day 2+ 迭代方向只在 [路线图摘要](/docs/01-产品/产品路线图摘要.md) 与各专题 ⏳ 维护，本文不列功能清单。
