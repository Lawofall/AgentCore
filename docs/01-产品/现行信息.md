# 现行信息

> **定位**：什么信息可以留在「以后还会当现状来用」的通道里。对象是**所有内容**——产品 AI 输出、设计文档、规则、注释、记忆条目、对用户说的话——不限作者是人还是模型。提示词怎么写 → [上下文工程 · 提示词设计原则](/docs/03-AI核心/上下文工程.md#提示词设计原则)；提示词出门检验 → `.cursor/rules/prompt-design.mdc`；文档 How（含出门检验）→ `.cursor/rules/doc-governance.mdc`。
>
> **主循环归属**：跨拍约束——「说」「收」「记」里凡会被当成现行事实再用的内容都受本原则约束；同时约束工程内务（设计文档 / 规则 / 注释）。不进产品叙事、不进路线图产品方向表 → [主循环](/docs/01-产品/产品定位与品牌.md)。

## 一、原则

只保留会改变以后行动的信息。过程、废选项、已完成步骤，用过就离开现行通道。

检验：这句话会不会改变以后怎么做（人改代码、模型选工具、用户理解现状）。不会，就不该还留在现行通道。

不是「写短」，也不是「写全」。短而全的施工日记对以后仍是噪声。

## 二、通道

| 通道 | 放什么 | 例子 |
|---|---|---|
| **现行** | 以后还会被当成现在怎么做来读 | 现状文档、常驻提示、规则、对用户的结论、还在生效的注释、记忆里的现行事实 |
| **历程** | 当时有用、以后不该再当现状 | git、当时的对话、已替代的决策记录 |

历程可以存在。错误是占了现行通道。

## 三、三类残留

现行通道里的噪声，形态只有这三种：

1. **已完成过程当现状**——施工顺序、已勾完的阶梯、排查经过。
2. **已死机制还当活选项**——废名、已撤销的二选一，读起来还要选。
3. **防回潮写成编年史**——「怎么走到今天」代替「现在怎么做」。

## 四、该留的负知识

仍可能被再提出来的否决：一行「方案 + 为何否」。这会改变以后的行动。

没人会再发明的机制名、已走完的步号：不留。代码里已经唯一的现状：只写现在怎么做；「不另立 X」只在 X 仍是真实诱惑时才留。

## 五、对照

同一条原则在不同行当里的名字，便于检索，不在本文展开：

- 决策论：信息价值（VoI）——不改变以后行动分布的句子，值为 0。
- 文档：evergreen vs 决策当时记录（历程单独立档，现行文只写现在）。
- 模型上下文：高信号 token；旧名与新现状同时在场是冲突，不是对照。

提示词层的宪法非法例是本原则在常驻提示上的特化 → [上下文工程 · 提示词设计原则](/docs/03-AI核心/上下文工程.md#提示词设计原则)。

## 否决

| 方案 | 理由 |
|---|---|
| 用「写全」当现行通道的质量标准 | 全的是当时过程，不是以后决策 |
| 把完成阶梯留在权威现状文里当验收清单 | 历程；现行只留仍要守的原则 |
| 废机制仍写成二选一「以示对照」 | 读者当活选项；对照放历程或一行否决 |
| 只把本原则用在设计文档或产品提示词 | 对象是所有现行通道上的信息 |
