# 术语表

> 项目术语的**单一真相源**（勿在他处重复定义）。命名约定与判定表偏长属故意——跨文档禁再抄定义。

## 核心术语

| 术语 | 定义 |
|------|------|
| **AgentCore** | 产品名，**Multi-Agent AI 工作台**。不设中文名；**禁用「生态平台」**作形态口径（生态市场暂不启动）→ [定位 §一](/docs/01-产品/产品定位与品牌.md) |
| **主循环（说·组·看·拍·收 + 记）** | 产品的单一主路径，也是**功能取舍与文档写作的判据**：说目标 → 系统判轻重自动组队 → 协作可见 → 关口用户拍板 → 产物落工作区；「记」为跨会话回路。答不出「服务哪一拍」的 = 工程内务或实验项目，不进产品叙事。→ [定位 §二](/docs/01-产品/产品定位与品牌.md) |
| **现行信息 / 现行通道** | 以后还会被当成「现在怎么做」来读的文本所在的通道。只留会改变以后行动的信息；过程、废选项、已完成步骤用过就离开，改放历程（git / 当时对话 / 已替代的决策记录）。对象是所有内容，不限作者。→ [现行信息](/docs/01-产品/现行信息.md) |
| **勿增实体** | 过主循环拍之后，还须现有原语盖不住才另立名词 / 面板 / kind / 工具 / 具名 playbook / `consult` 名。正交 WHEN 的 skill 不合本减名。叙事一等、规格附属 = 心智税。→ [定位 §二](/docs/01-产品/产品定位与品牌.md) |
| **更新通道（稳定 / 测试）** | ✅ 桌面对外两轨：稳定版（默认）与测试版（「AgentCore 测试版」并列安装）。通道 = 独立 `appId` + 独立 updater feed，**不是**再开源码仓、也不是长期 Git 分支。同生产 API；userdata 默认隔离。→ [发布与门禁 §7.6c](/docs/05-平台与运维/发布与门禁.md) |
| **约定文档** | `AgentCore/文档/` 下协作副产物目录（`工作稿/` · `research/` · `debate/` · `reviews/`）；多幕协作落盘，**不**进 `<rules>` 注入。区别于同根 `规则/` · `记忆/`（documents 注入）。✅ 厚背景资料已并入 `记忆/主题/` 按需条目。✅ `工作稿/` = 无显式路径产物的默认落点，取代旧的「兜底进 `research/`」——`research/` 有机器语义（辩手读它取证），杂物灌入会污染取证面。→ [`双模式工作区 §四`](/docs/02-架构/双模式工作区.md#四约定文档目录约定) |
| **`AgentCore/` 约定目录** | 全局或文件夹下的约定根夹。**UI 呈现名 `.agentcore`**（次要样式、钉同级最前、默认折叠）：里面是文件夹设定条目（DB · 占常驻配额 · 常驻进 prompt / 按需 `consult`）+ 过程稿（盘上 `AgentCore/文档/{工作稿,research,debate,reviews}`，**不**进 `<rules>`，UI 摊平掉 `文档/` 这一层）。全局条目仍单独叫**「全局设定」**。过程稿默认留在这里；用户要拿走的文件在派单时用 `form=workspace` / 显式 `artifacts` 路径直接写入工作区，否则从终稿路径或工作区树打开。存储仍拆开（条目 ≠ 盘上文件），配额条只计量条目、不画到过程稿上。旁路 `index/` · `trash/` · `baselines/` 为机读系统噪音，**已移出用户树**按 id 存。文件夹层另含 `记忆/导航.md`（短入口 always）；厚背景资料走 `记忆/主题/` 按需条目（无 `文档/项目/`）。**勿与**本地盘默认路径 `~/Documents/AgentCore/`（工作区容器）混淆——磁盘上这个名字是准的（本机模式下一眼可辨出自哪个工具），冗余只发生在应用 UI 内，故**只改呈现、不迁移磁盘路径**（不改成真点目录）。否决「`知识/` + 目录注入」、否决写用户仓根 `AGENTS.md`。文件页已取消「记忆 / 规则 / 文档」三夹（与落点正交，勿混）。⏳ 取消 `role` 三分、市场 Skill 入基座。→ [`记忆 · 目标形态`](/docs/03-AI核心/Agent记忆与知识系统.md)、[`双模式工作区 §四`](/docs/02-架构/双模式工作区.md#四约定文档目录约定) |
| **成品归位** | **已撤销**：收口不把过程稿再搬进工作区。过程稿默认 `工作稿/`；用户要拿走的文件在派单时用 `form=workspace` / 显式 `artifacts` 钉路径。`delivery_status.promoted` 仅兼容历史事件。**否决**由路径推断 / 派单预判 / worker 自判产物地位。→ [`双模式工作区 §四`](/docs/02-架构/双模式工作区.md#四约定文档目录约定) |
| **文件夹导航（`记忆/导航.md`）** | ✅ 仅文件夹层 · always 短入口：一句话定位 +「我要…→先读/先查」路由表；厚内容不进本文件，指到 `主题/`。由探索幕维护。**不沿树继承**——它是工作区根相对路径的路由表，外层文件本就不在里层活动范围内（「内容继承、路由不继承」）。→ [`记忆`](/docs/03-AI核心/Agent记忆与知识系统.md)、[`工作区` §5.4](/docs/02-架构/双模式工作区.md) |
| **冷启动探索幕** | ✅ 软硬分层：仅空画像 → **软幕不挡**（可直接域外调研）；换绑 / 点名刷新 / 空画像+工程点名短语 → **硬挡**先摸仓写画像与 `导航.md`。硬挡 pending 时用 `write_scope=explore_memory`（可 `form=files`，不可写出约定记忆根），**不再**用禁 `form=files` 代理。本回合新建的空云文件夹被点名为写盘目标时改用 `project`（填新桌 ≠ 改出生仓）。指纹漂移仍不挡。**勿与**「记忆巩固冷启动」混淆。→ [`编排器`](/docs/03-AI核心/编排器与CEO主Agent.md)、[`记忆`](/docs/03-AI核心/Agent记忆与知识系统.md) |
| **写范围（`write_scope`）** | ✅ worker 本批可写盘范围：`none` / `explore_memory` / `project`。与 `deliverable.form` 正交（form=形态，scope=安全边界）。✅ 派活单 `form` 已收成三档 `prose` / `files` / `workspace`（漏填=`files`）→ [`编排器`](/docs/03-AI核心/编排器与CEO主Agent.md) |
| **协作停止（Stop）** | ✅ 显式 Stop = 整回合取消（`user_stop`）；状态条 / 图呈「停止 / 已停止」（聊天时间线不另占「已停止」行）；**否决** Stop→pause。与 Interaction 挂起、冷卡次要键「取消」正交——**禁止**把「已停止」gloss 成「取消」。细则 → [执行引擎](/docs/03-AI核心/执行引擎架构设计.md) |
| **冷卡次要键「取消」** | ✅ `ask_user` / `plan_review` / `browser_login` 冷卡次要 CTA 文案一律「取消」（拒答 / 拒续跑 → 冷路 `resume` `decision=stop`；`ask_user` 取消回灌 CEO 短续，非空 continue「按默认」）。中途协调已启动时 ask 取消不重派未完成 worker、不转后台。桌面 `ask_user` 取消/确认/超时都占时间线真话存根；缺决策不猜超时。与上条协作停止正交。→ [检查点与开工卡 · §一](/docs/03-AI核心/检查点与开工卡.md) |
| **记忆巩固冷启动** | 巩固抽取侧：当**全局** `偏好.md` 与 `画像.md` **均为空**时降低抽取门槛、主动挖信号（代码 `_is_cold_start`）。与「冷启动探索幕」正交。→ 见 [`Agent记忆与知识系统.md` §1.5](/docs/03-AI核心/Agent记忆与知识系统.md) |
| **文件夹（Folder）** | ✅ 用户面**唯一的容器概念**——会话分组 + 记忆作用域 + 文件工作区三合一（代码符号沿用 `Folder`）。云端 = 「我的文件」下**可嵌套的真目录树**（`tree/<rel_path>`，同层禁重名）；本机 = 打开本机文件夹（最近打开列表）。`Folder` id **用户不可见**，只作稳定引用——改名 / 移动不断站立任务 · 记忆 · 白板归属。AI 活动范围 = 选中层**及以下**；规则与记忆沿树由外向里继承（路由表 `记忆/导航.md` 不继承）。会话**归属中途不改挂**；可 `target_folder_id` 跨文件夹派工；裸聊默认云 scratch，写盘时自动建文件夹（落「我的文件」，对话内不另告知）。**该文件夹的根即工作区根**（空桌成品落在这一层，不套工程壳）。共享空间不是第三种容器（多人文件盘，挂进对话）。**弃用「项目」**作该实体的中文 gloss。→ [`工作区` §五 · §5.4](/docs/02-架构/双模式工作区.md) · [§八](/docs/02-架构/双模式工作区.md) |
| **工作区（Workspace）** | 文件可寻址空间，`ws_id = folder:` / `conv:` / `shared:`；**寻址口径，非用户面容器名**。对用户说文件夹 / 「我的文件」 / 「本机文件夹」 / 「共享空间」；右坞 tab「工作区」= 本对话文件树（铬条），不是第三种容器。双通道：云协作 = 云桌权威（本机经合回 / ZIP / 导入触达）；本机传统 = 本机文件夹权威。≠ 两平级「云/本地模式」。→ [`工作区`](/docs/02-架构/双模式工作区.md) |
| **附加可写根（`attach_rw`）** | 本机传统对话级把旁边文件夹加入本对话的可读写世界（含覆盖、该根下执行 cwd）。工具 `grant_attach_folder`。**≠** 云协作 `organize`（整理/交付：`move`/`copy`/`mkdir`/回收站删除，copy 不覆盖）。云对话不得选 rw。保护路径与熔断仍在。→ [`工作区` §六、关键边界](/docs/02-架构/双模式工作区.md#六关键边界) |
| **导入到云** | ✅ 选本机文件夹 → ignore 打包上传进云端文件夹；之后权威在云桌。与**本机传统**（打开本机文件夹）并存，非取代。**用户面文案**：Composer「在哪工作」本机三选叫**「复制到云上当新家」**；其余入口（本机文件夹 ⋯ 菜单 / 命令面板 / 对话框标题）仍用长名「导入到「我的文件」」——同一动作，长名用于脱离三选语境。**弃用「上传」**作其 gloss：产品里「上传」已固定指「把文件放进当前位置」（文件树 / 共享空间工具栏 / 附件），同词双义会误导。→ 桌面 `importToCloud` |
| **合回落点** | ✅ 本机目录登记，供 Diff 合回写入；**≠** 打开本机传统文件夹。冲突默认留本地，禁静默覆盖。→ `mergeLandingPreference` / `MergeLandingReview` |
| **从 Git 克隆（产品入口）** | ✅ Composer「新建或加入」二级面与新建文件夹并列：云 clone remote 得到云桌（G3）。合回默认文件夹 Diff；⏳ PR/推远程二级（观察后再排）。中文展示固定**「从 Git 克隆」**；**弃用「连接 Git」**作其 gloss——这是一次性浅克隆，「连接」会被读成持续同步关系。代码符号 `openConnectGit` / `ConnectGitDialog` 保留。 |
| **PermissionAxes（权限轴）** | 会话级权限真相源（`file_write` / `command` / `host`）。配方与非法组合细则 → [安全权限与治理 §三](/docs/05-平台与运维/安全权限与治理.md) |
| **Host（本机协助）** | ✅ 桌面第三能力面：结构化观测/打开系统面板/受控动作本机 OS（非工作区文件执行）。与 folder/bind 正交；运输=桌面回填通道（非 BrowserBridge loopback）。CEO 仅持只读 L1；L2/L3 仅 worker。→ [工具与能力 · Host](/docs/03-AI核心/工具与能力系统.md) |
| **共享空间（Shared Space）** | 多人云端**文件盘**——只有「文件」一个面，不是容器（容器只有文件夹）。成员三档（所有者/可编辑/只读），定向邀请 + 接受制（好友多选或精确搜用户名/ID；不做链接加入）；可编辑成员的 Agent 经会话**挂载**直写（仅云执行对话）。文件中枢第三区是这个盘的入口。UI 定名「共享空间」。**勿与「文件夹内多会话共用一份盘」混**——后者是单人 `folder:<id>`，无多人成员概念。否决 Folder+成员 → [`双模式工作区.md` §八](/docs/02-架构/双模式工作区.md) |
| **Agent** | **运行时参与者**——一次执行中由 CEO 动态分配临时角色与工具集的 Run；不做预制角色 → [定位 §五](/docs/01-产品/产品定位与品牌.md)。**不是**可上架、可复用的市场产品单元（生态暂不启动） |
| **Skill** | Agent 的领域能力——工作流指引、约束、输出格式，绑定后注入 Prompt。单一来源（无内联）。现状 = 代码内 6 个系统薄技能；**市场 Skill ⏳ 暂不启动** |
| **Tool** | 确定性动作执行器——无推理；内置函数或市场工具经声明式连接器执行。分两个家族：**动作工具**（执行确定性动作、不留可编辑产物，如 file/grep/web/exec）与**创作工具**（产出可持久编辑的产物类型，见下） |
| **创作工具（Creation Tool）** | 面向用户的工具，每个对应一种**产物类型**（思维导图/画布/多维表格/文档）；有「用户编辑器（人）+ Agent 工具（AI）」两副面孔，共编同一份产物。同属「工具」，故 Agent 也能用。**现状**：仅白板部分落地（手绘 ✅ / AI 指挥 ⏳）；文档 / 思维导图 / 多维表格 / 幻灯片 / 可运行产物 **⏳ 未开工**，工具箱占位卡已撤下 → [路线图 · 交付物形态扩展](/docs/01-产品/产品路线图摘要.md) |
| **产物（Artifact）** | 创作工具产出的可持久化、可反复编辑结果；进统一文件/产物体系，可被对话 `@` 引用、分享、重开。⏳ 随创作工具未开工——当前交付物形态是工作区文件（md / docx / pdf / 代码） |
| **AI 选区改写（assist / rewrite）** | 创作工具（文件编辑器）的 AI 原语，做成**无状态文本进/文本出**：服务端**从不读写文件本身**（本地文件在桌面 fs 桥后、云端在工作区 API 后），只收「选区 + 指令 + 前后文（只读）」、调 `LLMProvider` 返回改写后的选区文本，由前端套 `@codemirror/merge` 逐块评审（人接受/拒绝）。`scenario="file.rewrite"` 归因花费，60s 交互超时；当前仅 L1 选区改写。→ 见代码 `agentcore/assist/rewrite.py` / `services/rewrite.ts` |
| **Rule** | 可复用规则——约束 Agent 行为的指令片段。用户自定义规则（`AgentCore/规则/`）✅；跨用户安装 / 共享 **⏳ 暂不启动** |
| **Memory（记忆）** | 跨会话可沉淀的偏好、画像与文件夹上下文（`AgentCore/记忆/` 等）✅；沿文件夹树由外向里继承（路由表除外）；≠ 运行时「会话内工作记忆」。作为「五类资产」之一的市场形态 ⏳ 暂不启动。→ [`记忆与知识`](/docs/03-AI核心/Agent记忆与知识系统.md) |
| **Team** | Agent 团队——多个 Agent 的编排组合，有 captain 和 members。**⏳ 一等实体未落地**：现状是每回合临时 `delegate` 组队，不可保存复用。用户叙事不出现可保存的「团队库」 |
| **五类资产（生态）** | Tool / Skill / Rule / Memory / Team——**⏳ 远期市场闭环，暂不启动**（无市场实体表、无安装绑定）。**Agent 不在此列**：Agent 是运行时参与者，不是可沉淀分享的资产。→ [定位 §四](/docs/01-产品/产品定位与品牌.md) |
| **AgentVersion** | ⏳ 生态字段（未启用）：Agent 版本快照——system_prompt、model、tools、delegations |
| **Fork** | ⏳ 生态字段（未启用）：复制他人 Agent 并独立改进，类似 GitHub Fork |
| **Delegation** | Agent 委派——一个 Agent 将子任务交给另一个 Agent 处理 |
| **Arena** | 竞技场——多个 Agent 围绕同一主题进行多轮对抗/讨论（多轮辩论）。✅ 已落地为**主持人（Moderator）驱动**的逐轮交锋 → 决策简报 + 交锋叙事线双产物（见 [`辩论编排设计.md`](/docs/03-AI核心/辩论编排设计.md)）；底层仍是普通 AGENT DAG、**非独立执行子系统**（独立子系统仍否决）；≠ best-of-N 择优，见下 |
| **Moderator（主持人）** | 辩论的有状态编排角色（主持 + 裁判 + 书记三合一），落成 CEO `debate` 工具内的确定性循环（非 LLM 委派角色）、辩手为 `depth+2` 叶子。逐轮流程（定议题 → 派辩手 → 判交锋 → 收敛出简报）见 [`辩论编排设计.md` §二](/docs/03-AI核心/辩论编排设计.md) |
| **best-of-N 择优** | 行业术语：同一任务并行跑 N 个候选再择优。**已否决**——N 倍开销而用户看不到协作过程；「高不确定环节要多视角」的需求由 Arena 逐轮交锋覆盖得更好（同样并行投入，但产出可看的交锋与结论）；且择优者难定（AI 评判可靠性存疑；让用户挑属另一功能「多方案对比」）。若重提，须从「有客观裁判」的场景（如修码以测试判定）重新设计，勿复用旧策略位形状 |
| **MCP** | Model Context Protocol（行业 Agent↔Tool 标准） |
| **A2A** | Agent-to-Agent Protocol（行业 Agent↔Agent 通信标准） |
| **ReAct** | Reasoning + Acting 循环，Agent 的推理-执行模式 |
| **SSE** | Server-Sent Events，对话流式输出的传输协议 |
| **Turn** | 交互聚合层——一次用户消息触发的完整 ReAct + 委派过程 |
| **Run** | 执行单元——一次被调度的 Agent 工作（委派的 worker / DAG 节点）；一个 Turn 含一棵 Run 树。生命周期见 `RunPhase`。代码层统一称 Run（旧称 Step 已废弃），用户展示用「任务 / 子任务」 |

> CEO 组团、挂起、续跑等执行层名词的精确定义；与上表 **Delegation**（泛化委派概念）区分。**delegate** 专指 CEO 工具原语。

## 命名约定（代码符号 ↔ 展示文案）

统一术语、消除「同义多词」。代码符号（标识符 / 字段 / 事件 key）用规范名，面向用户的中文展示用展示文案；二者不混淆。开发期无兼容层，旧词直接废弃。

### 执行单元：Run（弃用 Step）

- 代码层一律 `run`：`run_id` / `RunPhase`（后端权威生命周期：queued·running·completed·failed·skipped·cancelled·retrying）/ `RunStatus`·`RunNode`（前端投影态）/ `runs`；图节点高亮由 SidePanel **焦点面板**的 run 派生（`focusSurface` / `sidePanelFocusTabId`；早期 `selectedRunId`/`selectRun` 跨 store 选中态已弃用）。→ [前端UX · §十](/docs/04-前端/前端UX设计.md)。
- 旧的 `step` 词汇（`step_id` / `StepStatus` / `steps` / `stepId` …）全部废弃。
- 用户展示文案仍用「任务 / 子任务」（展示语，非代码符号）。
- 例外：与 Run 无关的通用「step」保留——如 React Flow 的阶梯边 `StepEdge`、CSS 缓动 `step-end`、时间轴步进 `STEP_INTERVAL`。

### 终止：状态 cancelled，动作 stop（与冷卡「取消」正交）

- 数据层（状态值 / `FinishReason` / 投影态）= `cancelled`。
- 动作层（协作硬停按钮 / handler / 动词）= `stop`（如 `stopGeneration`）。
- 协作硬停 / 状态条 / 图 `cancelled`：中文展示统一「停止 / 已停止」；弃用「中止」作其 gloss；**禁止**把「已停止」gloss 成「取消」——「取消」专指冷卡次要键（见上表「冷卡次要键「取消」」）。例外：`AbortController` 机制本身、部署/进程「终止」、DB 状态值「已取消」、执行引擎「协作取消」语义标签各有所指，保留。

### 重跑：regenerate（整轮）vs retry（重试）

- `regenerate` = 从某条用户消息整轮重新执行的原语（后端 `/regenerate`、`regenerate_chat`；前端 `runRegenerate`）。两种入口：直接重新生成、改输入后重发。用户可见入口在助手气泡**底栏**，文案固定 **重新生成**；底栏点击须**二次确认**（截断其后历史 + 新贵回合，不可逆）。改输入后「调整后重发」不经此确认（用户已主动编辑）。**否决**红错误卡上再挂「重新生成」（失败救火改再说/改发）。
- `retry` = **无节点级自动重试**：引擎不重跑失败节点——`on_failure="retry"` 与 `skip` 走同一条级联跳过，失败节点由 CEO 以 `replaces_run_id` 换人接手；`RunPhase.RETRYING` 全仓无写入点。勿据这些名字推断存在重试机制。AI 错误条（`RetryBanner`）只展示文案 + 关闭（可选「去配置」），**否决**「重试」「重连」一键再打。
- 中文展示固定两词：**重新生成**（要个新答案）/ **调整后重发**（改了输入）。弃用游离的「重跑」；弃用错误条上的「重试」「重连」按钮。
- 例外：「重跑」作通用 rerun 动词保留——CI / 工作流重跑、`alembic` 重跑、`react_loop` 重跑、布局重跑等与「整轮重答」无关的场景。

### 团队角色：队员 / captain / 主 Agent

- **worker 的中文展示 = 队员**：被 `delegate` 委派的 worker Run，中文一律「队员」（计费 role / UI / 文档同）。弃用「组员」；prompt 里指代被委派 worker 的「成员」亦收敛为「队员」。
- **保留「成员」的合法所指**：① Team 结构成员（`captain + 成员`）；② IM 群成员 / 设置页「成员」（人类用户）；③ 嵌套委派的「子成员」。
- **CEO = 主 Agent**（产品名 / 对话者）；**协调者** = CEO 的角色描述（只读边界、产出全委派）；**captain** = 指挥 Run（英文保留、不译；CEO 为根 captain，`depth < 3` 默认带子队的 worker 为子 captain）。弃用「队长」「协调官」作上述任一的 gloss（测试角色串等任意输入不在此列）。

### 模型相关：场景画像 / 思考开关

- **ModelProfile 的中文 = 场景画像**（内部参数包，不外露用户）。弃用「模型档位配置」指代 ModelProfile。
- **已删除**：旧 worker 模型**档位**（`ModelTier{fast,strong}` / `model_preference`）与 per-agent 思考强度（reasoning effort）。worker 回合预算统一为单一上限，「力度」仍由委派协作结构表达。**Per-run 显式模型身份 ✅**（非 fast/strong 档）→ [编排器 · Per-worker 模型覆盖](/docs/03-AI核心/编排器与CEO主Agent.md#per-worker-模型覆盖abc-同一功能)。
- **思考模式**（DeepSeek API `thinking` 开关）保留：仅区分思考 / 非思考，无强度档。

### 对话实体：对话（AI 实体）vs 会话（作用域 / session / IM）

- **AI 对话实体 = 对话**：用户与团队的一通会话单元（`Conversation`）。中文一律「对话」——对话页 / 对话行（`ConversationItem`）/ 对话列表（`对话列表设计`）/ 对话管理页（`/conversations`）/ 新建对话 / 旧对话 / 上次对话。弃用「会话列表 / 旧会话 / 上次会话」作 AI 实体 gloss。
- **保留「会话」的合法所指**：① 作用域限定词（`会话级` vs `turn 级`、当前会话、本会话、跨会话、会话内、每会话、切会话）；② 认证 session（`认证与会话`、Cookie / refresh）；③ IM 域会话（`ChatList` 会话列表 / 静音会话 / 每会话未读，人对人线程）；④ 记忆域 session（会话内工作记忆、~~会话摘要~~）。

### 容器两词：文件夹（Folder 实体 = 目录）/ 工作区（文件空间）

- **✅ 「项目」已退役**：容器只剩「文件夹」一个用户面词。`folders` 实体、云端目录树的一层、本机 OS 目录，中文一律「文件夹」——新建文件夹 / 删除文件夹 / 按文件夹筛选 / 本文件夹记忆。**弃用「项目」**作该实体 gloss。用户界面**连口语义也避开**（「适合已经在电脑上的大项目」→「适合东西本来就在电脑上」）：实体刚退役，界面再冒出这两个字就会被读回成实体。**例外**：命令面板的搜索关键词别名（`project` / `xiangmu`）保留——老用户搜「项目」仍要能找到入口。
- **代码符号一律 `Folder`**（`/v1/folders` / `FolderMeta`）。实体 id 用户不可见，可见的是名字与 `rel_path`。
- **工作区 = 文件可寻址空间**（见核心术语词条）：SidePanel「工作区」tab、`ws_id`。它是**寻址口径**，不是用户面容器名——对用户说文件夹；右坞「工作区」只是本对话文件树。
- **共享空间不是容器**：多人文件盘，挂进对话；文件中枢第三区是入口。权威 → [工作区 §八](/docs/02-架构/双模式工作区.md)。
- 例外保留：`project*` 作投影动词（`projectExecution` / `projectFlowGraph`）、pnpm workspace 等 monorepo 工程用语；`write_scope="project"` 是 delegate 的安全范围枚举（另一概念面）；记忆条目的 wire 值 `scope="project"`（**上 wire 的契约值，不动**；展示层已中文化为「本文件夹」）。渲染层表示「容器」的符号则已清退（`DraftWorkspaceIntent.kind` / `AgentCoreScope` / `EntryScope` 一律 `folder`，`openLocalFolder.ts` / `registerLocalFolder.ts`）。

### 消息气泡：对话气泡（AI）

- **AI 消息气泡 = 对话气泡**（`MessageBubble`，用户提问 + CEO 流式作答同栈）。弃用「聊天气泡」作其 gloss。
- 保留：IM 域人对人气泡（`ChatBubble`，自身文案区别于「AI 对话气泡」）。

### 审批动词：放行（门）/ 允许（用户按钮）

- **门动作 = 放行**（`ApprovalGate` 放过、检查点 continue、fail-open、CORS、并行批量放行）；**用户按钮 = 允许**（「允许一次 / 本轮内都允许」）；**名词 = 审批**（审批卡 / 审批门 / 审批三态）。弃用「批准」作「放行」的游离同义词。
- 保留不同所指：**授权**（`授权根` / 授权语义「这类操作我信任」）、代码符号 `approve`（`autoApproveSiblings` 等，英文保留）。

### 凭据 vs 凭证（credentials）

- **credentials 的中文 = 凭据**（`LLM 凭据` / BYOK 凭据 / 凭据加密〔安全 §七〕/ 凭据来源）。弃用「凭证」作 credentials gloss。
- 保留不同所指：**凭证式 CORS**（`credentialed` 标准术语，不译「凭据式」）、**防幻觉凭据**（= 证据 / 依据，另一义）。

### 交互不答语义：timed_out（拼写）/ 已失效（orphaned）

- **escalation 结算的超时态 = `timed_out`**（单一拼写）；弃用 `timeout` 作该状态值（`CheckpointDecision.timeout` / debate 决策 `timeout` 是另一语义——「引擎按默认推进」的决策值，保留）。
- **「已失效」= orphaned**（见运行时协作术语表）；弃用「过期 / 作废」作其 gloss。中文展示「已失效（回合已结束或服务已重启）」。

## Agent-Skill-Tool 三层概念模型

### 不可违反的边界

| 维度 | Agent（专家） | Skill（技能） | Tool（工具） |
|------|--------------|--------------|-------------|
| 本质 | 有独立推理的参与者 | Agent 的内在能力（Prompt 注入） | 确定性原子能力 |
| LLM | 有独立画像与系统提示 | 无独立 LLM；知识注入宿主 Agent | 无；由当前 Agent 发起调用 |
| 执行 | 占轮次，参与共享上下文 | Prompt 组装时注入 system prompt | 步骤层内调用，不占轮次 |
| 调度 | 由委派或路由触发 | 绑定后始终注入（超阈值转目录 + 按需取） | Agent 推理决定调用 |
| 前端表现 | 独立气泡/身份标识 | 随「AI 提示词」层公开（工具进阶用法 / 薄技能）+ 运行时「查阅能力」卡；不与工具并列 | 折叠在宿主消息下 |

**核心原则：Agent 与 Tool 概念不相交**——需要 LLM 综合与表达的归入 Agent 轮次；输入输出确定的归入 Tool。不承认「会思考的工具」中间形态。

> **系统 Skill 的归位（能力图鉴）**：当前的系统 Skill（团队编排进阶 / 辩论与交叉审查 / 向用户发问…）本质是「某个内置工具的进阶用法指引」，即 **Prompt 注入**，故在「能力图鉴」里归入 **「AI 提示词」层**（作为"工具进阶用法（薄技能）"一节公开），**不**与「工具」并列成独立目录——能力图鉴只分**工具（确定性代码）+ AI 提示词**两类。拉取它们的 `consult` 是 CEO **编排原语**（`ToolCategory.ORCHESTRATION`），非「技能」类目工具。等真正的**市场域 Skill**（合同审查 / 数据分析等独立于工具的领域能力）出现，再为其立独立技能目录。决策与否决项见 [`前端UX设计.md` §十二](/docs/04-前端/前端UX设计.md)。

### 技能光谱：单工具薄技能 ↔ 多工具域级技能

「技能」不是单一物种，而是一段**光谱**。行业共识（Anthropic Agent Skills 渐进披露、SoK: Agentic Skills）：技能与工具的真正分界**不是「代码 vs 文字」**——技能里也可含脚本、工具也带自然语言描述——而是 **「原子动作」 vs 「按需加载的多步流程知识」**。本项目的「技能」落在这条光谱的两端：

| 维度 | 单工具薄技能（当前 6 个系统 Skill） | 多工具域级技能（市场 Skill，⏳ 未落地） |
|------|--------------------------------|----------------------------------|
| 实质 | 「**某一个**内置工具的进阶用法」——从工具描述里拆出的"怎么用好它" | 独立于任何单个工具的**领域 SOP**（合同审查 / 数据分析等） |
| 与工具关系 | 一对一贴着某工具（delegate / debate / ask_user） | 自带领域知识 + **编排一组工具**完成成果级流程 |
| 形态 | ≈ 加长版工具说明书；纯 Prompt 注入 | Prompt 指引 + 工具绑定（可含脚本） |
| 能力图鉴归类 | 并入「AI 提示词」层、作「工具进阶用法（薄技能）」一节，不与工具并列 | 出现时立**独立技能目录** |

**为何当前这 6 个读起来像工具描述**：它们就在薄端——本质是「单个工具的进阶用法」、为省常驻 prompt 预算才挪成按需 `consult`。等多工具域级技能出现，「自带领域知识 + 编排多工具」一眼就与「某工具的用法」区分开，独立技能目录才名正言顺。

### 判定标准

- 需要 LLM 推理（有 ReAct 循环）→ **Agent**
- 描述一类任务的 SOP 工作流（Prompt 指引 + 工具绑定）→ **Skill**
- 不需要推理、给参数固定执行返回结果 → **Tool**

### Skill 与 Rule 的区分

| 维度 | Skill | Rule |
|------|-------|------|
| 职责 | 「怎么做」— 多步操作模板、领域指引 | 「不能做什么」— 行为约束、质控合规 |
| 粒度 | 域级（如"合同审查"、"数据分析"） | 原子级（如"中文优先"、"禁止虚构") |
| 加载方式 | 绑定加载；超阈值转 `<按需目录>` + `consult` 按需取 | 对外 always 常驻；on_demand 进同一 `<按需目录>` + `consult`；`conditional` 仅 DB reserved（无触发底） |

**加载方式已合一**：Skill 与 Rule 的按需侧走同一 `<按需目录>` 与同一 `consult`。读侧二者都是带 `description` 的 md 条目。⏳ 取消 `role` 三分。**存储不合一**：系统 Skill 真源留代码（随产品发布走），只有市场 Skill ⏳ 与用户 / AI 条目进 DB 基座。→ [记忆 · 目标形态](/docs/03-AI核心/Agent记忆与知识系统.md)

### Agent→Skill 降级判定

当某个 Agent 满足以下全部条件时，应降级为 Skill：

1. 其**每次判断都依赖领域上下文**（不具备独立完成推理的能力）
2. 领域 Agent 挂载对应 Skill 后**可独立完成同等质量输出**
3. 该 Agent 的存在**增加调度歧义**（委派路由难以区分）
