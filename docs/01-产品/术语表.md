# 术语表

> 项目术语的**单一真相源**（勿在他处重复定义）。命名约定与判定表偏长属故意——跨文档禁再抄定义。

## 核心术语

| 术语 | 定义 |
|------|------|
| **AgentCore** | 产品名，**Multi-Agent AI 工作台**。不设中文名；**禁用「生态平台」**作形态口径（能力商店是工具箱功能，不改形态）→ [定位 §一](/docs/01-产品/产品定位与品牌.md) |
| **主循环（说·组·看·拍·收）** | 产品的单一主路径，也是**功能取舍与文档写作的判据**：说目标（过往可查旧对话）→ 系统按信息结构决定要不要组队（开辩不主动启动、仅推荐；用户规则进设定）→ 协作可见 → 关口用户拍板 → 产物落工作区。答不出「服务哪一拍」的 = 工程内务或实验项目，不进产品叙事。→ [定位 §二](/docs/01-产品/产品定位与品牌.md) |
| **现行信息 / 现行通道** | 以后还会被当成「现在怎么做」来读的文本所在的通道。只留会改变以后行动的信息；过程、废选项、已完成步骤用过就离开，改放历程（git / 当时对话 / 已替代的决策记录）。对象是所有内容，不限作者。→ [现行信息](/docs/01-产品/现行信息.md) |
| **勿增实体** | 过主循环拍之后，还须现有原语盖不住才另立名词 / 面板 / kind / 工具 / `consult` 名。正交 WHEN 的 skill 不合本减名。叙事一等、规格附属 = 心智税。→ [定位 §二](/docs/01-产品/产品定位与品牌.md) |
| **瞥或读** | 过程可见只有两档：瞥 = 已有概览上的结构与进度；读 = 已有详情里的叙事与全文。把读再贴到瞥上的摘要壳是伪需求。同一面展开/折叠仍是这一档。→ [协作图 UX](/docs/04-前端/协作图与双视图UX.md) |
| **更新通道（稳定 / 测试）** | ✅ 桌面对外两轨：稳定版（默认）与测试版（「AgentCore 测试版」并列安装）。通道 = 独立 `appId` + 独立 updater feed，**不是**再开源码仓、也不是长期 Git 分支。同生产 API；userdata 默认隔离。→ [发布与门禁 §1.6c](/docs/05-平台与运维/发布与门禁.md) |
| **约定文档** | **已卸**。曾为 `AgentCore/文档/` 下四格活柜（`工作稿/` · `research/` · `debate/` · `reviews/`）。存量盘路径当普通文件，不进 `<设定>`，不扫、不空柜广告。落点只认显式 `artifacts` / leftover `artifact_dir`；裸文件名不发明柜。→ [`工作区 §四`](/docs/02-架构/工作区.md#四约定文档目录约定) |
| **`AgentCore/` 约定目录** | 全局或文件夹下的约定根夹。**UI 呈现名 `.agentcore`**（钉同级最前、默认折叠）；磁盘仍是 `AgentCore/`，勿与本机容器 `~/Documents/AgentCore/` 混淆（只改呈现、不迁盘）。活柜是用户规则（DB · 常驻/按需；对话内写入走 `rules/`）。存量 `记忆/` · `文档/` 若在盘上当普通子项，不进模型。文件页已取消「记忆 / 规则 / 文档」三夹。落点 → [记忆 · 用户规则](/docs/03-AI核心/Agent记忆与知识系统.md#用户规则)、[工作区 §四](/docs/02-架构/工作区.md#四约定文档目录约定) |
| **成品归位** | **已撤销**：收口不把过程稿再搬进工作区。用户点名拿走的文件在派单时用显式 `artifacts` 钉路径。经理默认不发明路径；收工认盘。仅 `artifact_dir` 未命中不发软待办、不催搬。**否决**由路径推断 / 派单预判 / worker 自判产物地位。→ [`工作区 §四`](/docs/02-架构/工作区.md#四约定文档目录约定) · [执行引擎](/docs/03-AI核心/执行引擎架构设计.md) |
| **文件夹导航（`记忆/导航.md`）** | **已撤销**。现状：存量当普通稿、不进模型；因探索幕已停写。→ [记忆 · 否决](/docs/03-AI核心/Agent记忆与知识系统.md#否决) |
| **冷启动探索幕** | **已撤销**。现状：点名「先了解」当普通干活（读文件）；因系统不擅自写画像 / 导航 / 主题。→ [记忆 · 否决](/docs/03-AI核心/Agent记忆与知识系统.md#否决) |
| **写范围（`write_scope`）** | ✅ worker 本批可写盘范围：`none` / `project`。与派活单正交（scope=安全边界；催写只认非空 `artifacts` / `artifact_dir`）。已删 `explore_memory` 与 `deliverable.form` 三档 → [`编排器 · 交付物：钉路径才催写`](/docs/03-AI核心/编排器与CEO主Agent.md#交付物钉路径才催写) |
| **协作停止（Stop）** | ✅ 显式 Stop = 整回合取消（`user_stop`）；点击即冻图，状态条 / 图呈「停止 / 已停止」（聊天时间线不另占「已停止」行）。**否决** Stop→pause；**否决**图画布「停止任务」（整队留 CEO）。与 Interaction 挂起、冷卡次要键「取消」正交——**禁止**把「已停止」gloss 成「取消」。细则 → [执行引擎](/docs/03-AI核心/执行引擎架构设计.md) |
| **冷卡次要键「取消」** | ✅ `ask_user` 冷卡次要 CTA 文案一律「取消」（拒答 / 拒续跑 → 冷路 `resume` `decision=stop`；`ask_user` 取消回灌 CEO 短续，非空 continue「按默认」）。中途协调已启动时 ask 取消不重派未完成 worker、不转后台。桌面 `ask_user` 取消/确认/超时都占时间线真话存根；缺决策不猜超时。与上条协作停止正交。→ [检查点 · §一](/docs/03-AI核心/检查点.md) |
| **记忆巩固冷启动** | **已撤销**。现状：闲聊收尾不写常驻。→ [记忆 · 否决](/docs/03-AI核心/Agent记忆与知识系统.md#否决) |
| **文件夹（Folder）** | ✅ 用户面**唯一的容器概念**（会话分组 + 用户规则作用域 + 文件工作区）。代码符号 `Folder`，id 用户不可见。**弃用「项目」**作 gloss。绑定 / 嵌套 / 跨桌 / 协作桌 → [工作区 §五 · §5.4](/docs/02-架构/工作区.md) · [§八、协作桌（文件夹成员）](/docs/02-架构/工作区.md) |
| **工作区（Workspace）** | 文件可寻址空间，`ws_id = folder:` / `conv:`；**寻址口径，非用户面容器名**。对用户说文件夹 / 「我的文件」 / 「本机文件夹」。右坞 tab「工作区」= 本对话文件树，不是第三种容器。桌面默认本机、云端并列 → [工作区](/docs/02-架构/工作区.md)。**废名「双模式工作区」**：文件现名 `工作区.md`；不是两平级模式开关 |
| **附加可写根（`attach_rw`）** | 本机传统对话级把旁边文件夹加入本对话的可读写世界（含覆盖、该根下执行 cwd）。模型对已挂 `external/` 路径或该本机路径 `write`（`file_path`）/ `file_batch` copy，运行时请用户确认。**≠** 云协作 `organize`（整理/交付：`move`/`copy`/`mkdir`/回收站删除，copy 不覆盖）。云对话不得选 rw。保护路径与熔断仍在。→ [`工作区` §六、关键边界](/docs/02-架构/工作区.md#六关键边界) |
| **云上做完再写入** | ✅ 选本机文件夹 → ignore 打包上传进云端文件夹；原件先不动。做完 Diff 合回，或芯片「留在云上接着用」搬家。Composer「从本机加入」后不再两选：点本机文件夹或「从本机加入」即直接改。命令面板长名「云上做完再写入」。**否决**并列第三动词「导入到云 / 复制到云上当新家」（同一快照骨架，出发时预测终局）。**弃用「上传」**作其 gloss：产品里「上传」已固定指「把文件放进当前位置」（文件树 / 附件）。→ [工作区 · §7.8 关电脑与「云上做完再写入」](/docs/02-架构/工作区.md) · 桌面 `borrowToCloudJob` |
| **合回落点** | ✅ 本机目录登记，供 Diff 合回写入；**≠** 打开本机传统文件夹。冲突默认留本地，禁静默覆盖。→ `mergeLandingPreference` / `MergeLandingReview` |
| **从 Git 克隆（产品入口）** | ✅ Composer「新建或加入」二级面与新建文件夹并列：云 clone remote 得到云桌（G3）。合回默认文件夹 Diff；⏳ PR/推远程二级（观察后再排）。中文展示固定**「从 Git 克隆」**；**弃用「连接 Git」**作其 gloss——这是一次性浅克隆，「连接」会被读成持续同步关系。代码符号 `openConnectGit` / `ConnectGitDialog` 保留。 |
| **对话边界** | 会话级权限真相源，三档：`read` 只看 / `folder` 这个文件夹（默认）/ `computer` 这台电脑。列名仍是 `permission_axes`，形状只有 `{"boundary":...}`。→ [安全权限与治理 §二](/docs/05-平台与运维/安全权限与治理.md) |
| **Host（本机协助）** | ✅ 桌面第三能力面：结构化观测/打开系统面板/受控动作本机 OS（非工作区文件执行）。与 folder/bind 正交；运输=桌面回填通道（非 BrowserBridge loopback）。CEO+worker 同形（含 action）；审批走轴 / 恒确认。分集 → [编排器 · 核心定位](/docs/03-AI核心/编排器与CEO主Agent.md)；动作表 → [工具 · Host](/docs/03-AI核心/工具与能力系统.md) |
| **协作桌** | ✅ 云文件夹成员制：几个人围同一张桌，文件 + 这张桌的设定 + 桌上对话互看互改（可编辑续跑/跟播/审批/停止；只读只看）。账号级用户规则不共享。入口：所有者「我的文件」里**有名册的桌根用人图标标协作**（含待接受；不写「已共享」），动作是「成员 / 邀请成员」；被邀请的人在「与我共享」。**废名「共享空间」**：曾是独立文件盘 + 挂载第二根，已删除、不做兼容层。→ [工作区 · §八、协作桌（文件夹成员）](/docs/02-架构/工作区.md) |
| **Agent** | **运行时参与者**——一次执行中由 CEO 动态分配临时角色与工具集的 Run；不做预制角色 → [定位 §五](/docs/01-产品/产品定位与品牌.md)。**不是**可上架 SKU（能力商店只卖 Skill） |
| **Skill** | Agent 的领域能力——可复现的 SOP / 编制指引（过程、形状、产品合同下次还对得上），按名 `consult`。出厂可留强吸引子原则（如页面预训练默认脸），**不**写质量菜谱。现状 = 代码内系统薄技能（官方 HOW 只读）。✅ **用户技能**：基座 `on_demand` 条目，可加成目录行（可写编制，CEO 对照执行）。✅ **能力商店**：跨用户上架 / 一键安装同一类条目 → [工具与能力 · 能力商店](/docs/03-AI核心/工具与能力系统.md#能力商店)。出厂正文过[内容闸](/docs/03-AI核心/上下文工程.md#内容闸可复现不服务更好) |
| **Tool** | 确定性动作执行器——无推理；内置函数或本机 MCP 连接器执行。分两个家族：**动作工具**（执行确定性动作、不留可编辑产物，如 file/grep/web/exec）与**创作工具**（产出可持久编辑的产物类型，见下）。**否决**货架卖 Tool（第三方只走 MCP） |
| **创作工具（Creation Tool）** | **已卸**。曾设想每种产物「人编辑器 + Agent 工具」两副面孔。白板 / 文档活稿 / 多维表格均已卸（内测硬切，无兼容层）。思维导图 / 幻灯片观察不排期，不为它们预留画布引擎。交付走工作区文件。**否决**可运行产物作为创作工具。→ [AI 协作白板](/docs/04-前端/AI协作白板.md) · [多维表格](/docs/04-前端/多维表格.md) · [路线图](/docs/01-产品/产品路线图摘要.md) |
| **产物（Artifact）** | 工作区里可反复打开的文件结果。曾绑定创作工具物种的活产物面已卸。→ [工作区](/docs/02-架构/工作区.md) |
| **AI 选区改写（assist / rewrite）** | 创作工具（文件编辑器）的 AI 原语，做成**无状态文本进/文本出**：服务端**从不读写文件本身**（本地文件在桌面 fs 桥后、云端在工作区 API 后），只收「选区 + 指令 + 前后文（只读）」、调 `LLMProvider` 返回改写后的选区文本，由前端套 `@codemirror/merge` 逐块评审（人接受/拒绝）。`scenario="file.rewrite"` 归因花费，60s 交互超时；当前仅 L1 选区改写。→ 见代码 `agentcore/assist/rewrite.py` / `services/rewrite.ts` |
| **Rule** | 可复用规则——约束 Agent 行为的指令片段。用户自定义规则（`.agentcore/rules/` 提示词条目）✅；跨用户上架 **否决**（常驻污染）→ [工具与能力 · 能力商店](/docs/03-AI核心/工具与能力系统.md#能力商店) |
| **Memory（记忆）** | **已撤产品面**。现状：用户规则进 `<设定>` / `consult`；过往事实走 `search_conversations`；AI 笔记停写停注入。≠ 运行时「会话内工作记忆」。跨用户记忆包 **否决**。→ [`记忆与知识`](/docs/03-AI核心/Agent记忆与知识系统.md) |
| **Team** | Agent 团队——一次执行里多个 Agent 的编排组合（captain + members）。**否决**一等实体 / 可保存团队库：组队是每回合 `delegate`；可保存拆法写进用户技能。用户叙事不出现团队库 |
| **五类资产（生态）** | 曾用货架物种表（Tool / Skill / Rule / Memory / Team）。**否决**按其做远期：现行货架只有 Skill；Tool 不卖（第三方走 MCP）；Rule / Memory / Team 不上架。**Agent 不在此列**。→ [定位 §四](/docs/01-产品/产品定位与品牌.md)、[工具与能力 · 能力商店](/docs/03-AI核心/工具与能力系统.md#能力商店) |
| **能力商店** | 工具箱市场货架：开放上架 + 一键安装。只卖 Skill（快照复制进「我的」，徽标「市场」）✅。≠ 本账号自己写的提示词。壳：顶栏「市场」栏 → [前端 UX · 工具箱](/docs/04-前端/前端UX设计.md)、[工具与能力 · 能力商店](/docs/03-AI核心/工具与能力系统.md#能力商店) |
| **AgentVersion** | **否决**当货架 SKU（Agent 不上架）。商店版本快照属于 Skill listing，不是 Agent 实体 |
| **Fork** | 安装是复制进目录、来源仍是市场；**不**另立 Fork 实体，也**不**改姓成「我的」 |
| **Delegation** | Agent 委派——一个 Agent 将子任务交给另一个 Agent 处理 |
| **Arena** | 竞技场——多个 Agent 围绕同一主题进行多轮对抗/讨论（多轮辩论）。✅ 已落地为**主持人（Moderator）驱动**的逐轮交锋 → 决策简报 + 交锋叙事线双产物（见 [`辩论编排设计.md`](/docs/03-AI核心/辩论编排设计.md)）；底层仍是普通 AGENT DAG、**非独立执行子系统**（独立子系统仍否决）；≠ best-of-N 择优，见下 |
| **Moderator（主持人）** | 辩论的有状态编排角色（主持 + 裁判 + 书记三合一），落成 CEO `debate` 工具内的确定性循环（非 LLM 委派角色）、辩手为 `depth+2` 叶子。逐轮流程（定议题 → 派辩手 → 判交锋 → 收敛出简报）见 [`辩论编排设计.md` §二](/docs/03-AI核心/辩论编排设计.md) |
| **best-of-N 择优** | 行业术语：同一任务并行跑 N 个候选再择优。**已否决**——N 倍开销而用户看不到协作过程；「高不确定环节要多视角」的需求由 Arena 逐轮交锋覆盖得更好（同样并行投入，但产出可看的交锋与结论）；且择优者难定（AI 评判可靠性存疑；让用户挑属另一功能「多方案对比」）。若重提，须从「有客观裁判」的场景（如修码以测试判定）重新设计，勿复用旧策略位形状 |
| **MCP** | Model Context Protocol（行业 Agent↔Tool 标准） |
| **A2A** | Agent-to-Agent Protocol（行业 Agent↔Agent 通信标准） |
| **ReAct** | Reasoning + Acting 循环，Agent 的推理-执行模式 |
| **SSE** | Server-Sent Events，对话流式输出的传输协议 |
| **Turn** | 交互聚合层——一次用户消息触发的完整 ReAct + 委派过程 |
| **Run** | 执行单元——一次被调度的 Agent 工作（委派的 worker / DAG 节点）；一个 Turn 含一棵 Run 树。生命周期见 `RunPhase`。代码层统一称 Run（旧称 Step 已废弃），用户展示用「任务 / 子任务」 |
| **CostEvent** | 成本事件——记录单次 LLM 调用的 token 用量和 CNY 成本 |
| **Approval** | 工具执行审批——安全门禁，按 tool_call_id 独立等待 |
| **Checkpoint（引擎快照）** | 运行时状态快照——回合级落盘（`paused_turns`）+ 进程内挂起帧，供断点续跑与调试。**≠「用户检查点」**（产品层拍板卡，见运行时协作术语表） |
| **AgentCard** | Agent 能力声明——capabilities, input/output_modes, endpoint |
| **TaskRequest** | 标准化委派信封——instruction, context, constraints |

## 运行时协作术语

> CEO 组团、挂起、续跑等执行层名词的精确定义；与上表 **Delegation**（泛化委派概念）区分。**delegate** 专指 CEO 工具原语。

| 术语 | 定义 |
|------|------|
| **CEO** | 主 Agent——本回合对话 + 按需组团 + 收尾汇报的 captain。**身份层级**：用户是老板，CEO 受雇于用户、替其掌管按需组建的专家 Agent 团队并对其负责；**用户才是最终决策者**——CEO 关键岔路向用户请示、收尾向用户汇报（与「用户检查点」心智「团队请示领导」一致）。**实现 = captain 根 Run**（`react_loop` 即 `CAPTAIN` 根节点；content/reasoning 走气泡级 delta，非 run 级）。→ 见 [`编排器与CEO主Agent.md`](/docs/03-AI核心/编排器与CEO主Agent.md)、[`运行时三模型与挂起.md`](/docs/03-AI核心/运行时三模型与挂起.md) |
| **worker** | 被 CEO `delegate` 委派的队员 Run。`depth < MAX_DELEGATION_DEPTH` 的 worker 默认获 `delegate`（委派默认开、无 opt-in 开关；`replan` 在已有子计划后挂上）；depth=3 sub-worker 为叶子；单 lead 最多 4 个 sub-worker。**硬上限 `depth ≤ 3`**。→ 见 [`编排器与CEO主Agent.md` §2.4](/docs/03-AI核心/编排器与CEO主Agent.md) |
| **delegate** | CEO 持有的**内置工具原语**——在 ReAct 内调用来下达子任务、`depends_on` 定形 DAG。≠ 上表 **Delegation**（Agent 间委派的一般概念） |
| **带现场续派（同人接续）** | `delegate.tasks[].continue_from_run_id`——唤回刚干完活的同一队员，带完整 ReAct 现场（transcript）接着干：改自己的稿或接强相关新任务（同一动作，task 内容区分；旧独立工具 `revise` 已退役）。wire `continues_run_id` 恒指现场根；图上同一座位（角标「续 ×N」），各版在右坞往下接。**否决**全屏画布「对比」透镜、状态条「接续 N 次」。现场保留 =「对话在，现场就在」（随删对话级联清理）；现场不在则明确拒绝，回落冷 `delegate`。同一作者链不设唤回次数上限。→ 见 [`多轮编排与同人续派.md`](/docs/03-AI核心/多轮编排与同人续派.md) |

## 命名约定（代码符号 ↔ 展示文案）

统一术语、消除「同义多词」。代码符号（标识符 / 字段 / 事件 key）用规范名，面向用户的中文展示用展示文案；二者不混淆。开发期无兼容层，旧词直接废弃。LLM 工具 schema / journal 的 `name`（如 `web_fetch`）与过程线人话（如「Read page」）同此纪律；定名对照哪家官方表、哪些假朋友不改 → [工具与能力 · 模型面工具名](/docs/03-AI核心/工具与能力系统.md#模型面工具名)。

### 执行单元：Run（弃用 Step）

- 代码层一律 `run`：`run_id` / `RunPhase`（后端权威生命周期：queued·running·completed·failed·skipped·cancelled·retrying）/ `RunStatus`·`RunNode`（前端投影态）/ `runs`；图节点高亮由 SidePanel **焦点面板**的 run 派生（`focusSurface` / `sidePanelFocusTabId`；早期 `selectedRunId`/`selectRun` 跨 store 选中态已弃用）。→ [前端UX · §十](/docs/04-前端/前端UX设计.md)。
- 旧的 `step` 词汇（`step_id` / `StepStatus` / `steps` / `stepId` …）全部废弃。
- 用户展示文案仍用「任务 / 子任务」（展示语，非代码符号）。
- 例外：与 Run 无关的通用「step」保留——如 React Flow 的阶梯边 `StepEdge`、CSS 缓动 `step-end`、时间轴步进 `STEP_INTERVAL`。

### 终止：状态 cancelled，动作 stop（与冷卡「取消」正交）

- 数据层（状态值 / `FinishReason` / 投影态）= `cancelled`。
- 动作层（协作硬停按钮 / handler / 动词）= `stop`（如 `stopGeneration`）。
- 协作硬停 / 状态条 / 图 `cancelled`：中文展示统一「停止 / 已停止」；弃用「中止」作其 gloss；**禁止**把「已停止」gloss 成「取消」——「取消」专指冷卡次要键（见上表「冷卡次要键「取消」」）。例外：`AbortController` 机制本身、部署/进程「终止」、DB 状态值「已取消」、执行引擎「协作取消」语义标签各有所指，保留。

### 重跑：regenerate（整轮）vs retry（重试）

- `regenerate` = 从某条用户消息整轮重新执行的原语（后端 `/regenerate`、`regenerate_chat`；前端 `runRegenerate`）。两种入口：直接重新生成、改输入后重发。用户可见入口在助手气泡**底栏**，文案固定 **重新生成**；底栏点击须**二次确认**（截断其后历史 + 新贵回合，不可逆）。改输入后「调整后重发」不经此确认（用户已主动编辑）。**否决**红错误卡上再挂「重新生成」（失败救火改再说/改发）。
- `retry` = **无节点级自动重试**：引擎不重跑失败节点——`on_failure="retry"` 与 `skip` 走同一条级联跳过，失败节点由 CEO 以 `replaces_run_id` 换人接手；`RunPhase.RETRYING` 全仓无写入点。勿据这些名字推断存在重试机制。AI 错误横幅（输入框上方）只展示文案 + 关闭（可选「去配置」），**否决**「重试」「重连」一键再打。
- 中文展示固定两词：**重新生成**（要个新答案）/ **调整后重发**（改了输入）。弃用游离的「重跑」；弃用错误条上的「重试」「重连」按钮。
- 例外：「重跑」作通用 rerun 动词保留——CI / `alembic` 重跑、`react_loop` 重跑、布局重跑等与「整轮重答」无关的场景。

### 克隆对话（截到这条）

- 克隆对话 = 从某条助手回复把**本条及之前**的消息拷进新对话（`POST …/duplicate`，必带 `until_message_id`）。原对话不动。入口在助手气泡底栏。最后一条上点 = 整段拷贝。拷正文，不拷 `turn_journal`（克隆后无团队图回放）；仍坐源那张桌。新对话标题 = 源标题词干 + ` (n)`（n 从 1 起，在该用户未归档、未进最近删除的对话里找空号）；原标题不动。空标题用侧栏兜底展示，再空则 `新对话 (n)`。旧的「… 副本」存量不改写，再克隆时剥后缀进新规则。**否决**叠「副本 副本」；**否决**文件夹那套从 `(2)` 起的同层唯一名（对话标题本就不唯一，`(n)` 只标分叉）。
- **否决**对话列表 / 标题右键整段克隆（截止点不在消息上，已撤）。进行中的气泡 409。

### 团队角色：队员 / captain / 主 Agent

- **worker 的中文展示 = 队员**：被 `delegate` 委派的 worker Run，中文一律「队员」（计费 role / UI / 文档同）。弃用「组员」；prompt 里指代被委派 worker 的「成员」亦收敛为「队员」。
- **保留「成员」的合法所指**：① Team 结构成员（`captain + 成员`）；② IM 群成员 / 设置页「成员」（人类用户）；③ 嵌套委派的「子成员」。
- **CEO = 主 Agent**（产品名 / 对话者）；**协调者** = CEO 的角色描述（唯一对话入口与声音；干活面与工人同形；要不要派看信息判据）；**captain** = 指挥 Run（英文保留、不译；CEO 为根 captain，`depth < 3` 默认带子队的 worker 为子 captain）。弃用「队长」「协调官」作上述任一的 gloss（测试角色串等任意输入不在此列）。

### 模型相关：场景画像 / 思考开关

- **ModelProfile 的中文 = 场景画像**（内部参数包，不外露用户）。弃用「模型档位配置」指代 ModelProfile。
- **已删除**：旧 worker 模型**档位**（`ModelTier{fast,strong}` / `model_preference`）与 **per-agent** 思考强度（reasoning effort）。worker 回合预算统一为单一上限，「力度」仍由委派协作结构表达。组合级厂商 `reasoning_effort` 不是档位矩阵。**Per-run 显式模型身份 ✅**（非 fast/strong 档）→ [编排器 · Per-worker 模型覆盖](/docs/03-AI核心/编排器与CEO主Agent.md#per-worker-模型覆盖abc-同一功能)。
- **思考模式**（DeepSeek API `thinking` 开关）保留：仅区分思考 / 非思考，无强度档。

### 对话实体：对话（AI 实体）vs 会话（作用域 / session / IM）

- **AI 对话实体 = 对话**：用户与团队的一通会话单元（`Conversation`）。中文一律「对话」——对话页 / 对话行（`ConversationItem`）/ 对话列表（`对话列表设计`）/ 对话管理页（`/conversations`）/ 新建对话 / 旧对话 / 上次对话。弃用「会话列表 / 旧会话 / 上次会话」作 AI 实体 gloss。
- **保留「会话」的合法所指**：① 作用域限定词（`会话级` vs `turn 级`、当前会话、本会话、跨会话、会话内、每会话、切会话）；② 认证 session（`认证与会话`、Cookie / refresh）；③ IM 域会话（`ChatList` 会话列表 / 静音会话 / 每会话未读，人对人线程）；④ 记忆域 session（会话内工作记忆、~~会话摘要~~）。

### 容器两词：文件夹（Folder 实体 = 目录）/ 工作区（文件空间）

- **✅ 「项目」已退役**：容器只剩「文件夹」一个用户面词。`folders` 实体、云端目录树的一层、本机 OS 目录，中文一律「文件夹」——新建文件夹 / 删除文件夹 / 按文件夹筛选 / 本文件夹规则。**弃用「项目」**作该实体 gloss。用户界面**连口语义也避开**（「适合已经在电脑上的大项目」→「适合东西本来就在电脑上」）：实体刚退役，界面再冒出这两个字就会被读回成实体。**例外**：命令面板的搜索关键词别名（`project` / `xiangmu`）保留——老用户搜「项目」仍要能找到入口。
- **代码符号一律 `Folder`**（`/v1/folders` / `FolderMeta`）。实体 id 用户不可见，可见的是名字与 `rel_path`。
- **工作区 = 文件可寻址空间**（见核心术语词条）：SidePanel「工作区」tab、`ws_id`。它是**寻址口径**，不是用户面容器名——对用户说文件夹；右坞「工作区」只是本对话文件树。
- **协作桌不是第三种容器**：成员看见的是同一张云文件夹。废名「共享空间」（独立盘 + 挂载）。权威 → [工作区 · §八、协作桌（文件夹成员）](/docs/02-架构/工作区.md)。
- 例外保留：`project*` 作投影动词（`projectExecution` / `projectFlowGraph`）、pnpm workspace 等 monorepo 工程用语；`write_scope="project"` 是 delegate 的安全范围枚举（另一概念面）；用户规则条目的 wire 值 `scope="project"`（**上 wire 的契约值，不动**；展示层已中文化为「本文件夹」）。渲染层表示「容器」的符号则已清退（`DraftWorkspaceIntent.kind` / `AgentCoreScope` / `EntryScope` 一律 `folder`，`openLocalFolder.ts` / `registerLocalFolder.ts`）。

### 消息气泡：对话气泡（AI）

- **AI 消息气泡 = 对话气泡**（`MessageBubble`，用户提问 + CEO 流式作答同栈）。弃用「聊天气泡」作其 gloss。
- 保留：IM 域人对人气泡（`ChatBubble`，自身文案区别于「AI 对话气泡」）。

### 审批动词：放行（门）/ 允许（用户按钮）

- **门动作 = 放行**（`ApprovalGate` 放过、检查点 continue、fail-open、CORS、并行批量放行）；**用户按钮 = 允许**（「允许一次 / 本轮内都允许」）；**名词 = 审批**（审批卡 / 审批门 / 审批三态）。弃用「批准」作「放行」的游离同义词。
- 保留不同所指：**授权**（`授权根` / 授权语义「这类操作我信任」）、代码符号 `approve`（`autoApproveSiblings` 等，英文保留）。

### 凭据 vs 凭证（credentials）

- **credentials 的中文 = 凭据**（`LLM 凭据` / BYOK 凭据 / 凭据加密〔安全 §四〕/ 凭据来源）。弃用「凭证」作 credentials gloss。
- 保留不同所指：**凭证式 CORS**（`credentialed` 标准术语，不译「凭据式」）、**防幻觉凭据**（= 证据 / 依据，另一义）。

### 交互不答语义：timed_out（拼写）/ 已失效（orphaned）

- **escalation 结算的超时态 = `timed_out`**（单一拼写）；弃用 `timeout` 作该状态值（`CheckpointDecision.timeout` / debate 决策 `timeout` 是另一语义——「引擎按默认推进」的决策值，保留）。
- **「已失效」= orphaned**（见运行时协作术语表）；弃用「过期 / 作废」作其 gloss。中文展示「已失效（回合已结束或服务已重启）」。

## Agent-Skill-Tool 三层概念模型

### 不可违反的边界

| 维度 | Agent（专家） | Skill（技能） | Tool（工具） |
|------|--------------|--------------|-------------|
| 本质 | 有独立推理的参与者 | Agent 的内在能力（Prompt 注入） | 确定性原子能力 |
| LLM | 有独立画像与系统提示 | 无独立 LLM；知识注入宿主 Agent | 无；由当前 Agent 发起调用 |
| 执行 | 占轮次，参与共享上下文 | Prompt 组装时注入 system prompt | 步骤层内调用，不占轮次 |
| 调度 | 由委派或路由触发 | 按名 `consult`；常驻/按需是人侧档位，超阈值走 `<按需目录>` | Agent 推理决定调用 |
| 前端表现 | 独立气泡/身份标识 | 随工具箱「官方」公开（工具进阶用法 / 薄技能）+ 运行时「查阅能力」卡；不与工具并列 | 折叠在宿主消息下 |

**核心原则：Agent 与 Tool 概念不相交**——需要 LLM 综合与表达的归入 Agent 轮次；输入输出确定的归入 Tool。不承认「会思考的工具」中间形态。

> **系统 Skill 的归位**：当前的系统 Skill（整理表 / 页面观感…）本质是「某个内置工具的进阶用法指引」，即 **Prompt 注入**，故在工具箱 **官方**「提示词」货架公开（准则在前），**不**另开技能种类、也**不**另开工具种类 tab、**不**另做一套卡。拉取它们的 `consult` 是 CEO **编排原语**（`ToolFace.ORCHESTRATION`），非「技能」类目工具。名与目录行 → [工具与能力 · 系统 Skill 按需目录](/docs/03-AI核心/工具与能力系统.md#系统-skill-按需目录)。域级 Skill 走用户自建 ✅，跨用户上架走能力商店 ✅。决策与否决项见 [`前端UX设计.md` §六、工具箱](/docs/04-前端/前端UX设计.md)、[工具与能力 · 用户技能](/docs/03-AI核心/工具与能力系统.md#用户技能与可编目录)、[能力商店](/docs/03-AI核心/工具与能力系统.md#能力商店)。

### 技能光谱：单工具薄技能 ↔ 多工具域级技能

「技能」不是单一物种，而是一段**光谱**。行业共识（Anthropic Agent Skills 渐进披露、SoK: Agentic Skills）：技能与工具的真正分界**不是「代码 vs 文字」**——技能里也可含脚本、工具也带自然语言描述——而是 **「原子动作」 vs 「按需加载的多步流程知识」**。本项目的「技能」落在这条光谱的两端：

| 维度 | 单工具薄技能（当前系统 Skill） | 多工具域级技能（用户技能 ✅；能力商店 ✅ 上架同一类） |
|------|--------------------------------|----------------------------------|
| 实质 | 「**某一个**内置工具的进阶用法」——从工具描述里拆出的"怎么用好它" | 独立于任何单个工具的**领域 SOP**（合同审查 / 数据分析等） |
| 与工具关系 | 一对一贴着某工具（`ask_user`→提问两本 / `run`）；`debate` 入口合同在工具 description，无独立系统 Skill | 自带领域知识；工具开场就在，不因查阅才启用 |
| 形态 | ≈ 加长版工具说明书；纯 Prompt 注入 | Prompt 指引（不含脚本、不卖 Tool SKU） |
| 提示词目录归类 | 出厂说明书从组装页工具矮卡打开，不另开种类 | 并进组装页「交代」（自写 / 市场装来的）；**否决**另开技能 tab |

**为何当前这些读起来像工具描述**：它们就在薄端——本质是「单个工具的进阶用法」、为省常驻 prompt 预算才挪成按需 `consult`。域级技能（用户技能 / 商店）也进同一本提示词，不另开技能目录。

### 判定标准

- 需要 LLM 推理（有 ReAct 循环）→ **Agent**
- 描述一类任务的**可复现** SOP（过程 / 形状 / 产品合同；Prompt 指引）→ **Skill**。出厂可留强吸引子原则，不写质量菜谱 → [上下文工程 · 内容闸](/docs/03-AI核心/上下文工程.md#内容闸可复现不服务更好)
- 不需要推理、给参数固定执行返回结果 → **Tool**

### Skill 与 Rule 的区分

| 维度 | Skill | Rule |
|------|-------|------|
| 职责 | 「怎么做」— 多步操作模板、领域指引 | 「不能做什么」— 行为约束、质控合规 |
| 粒度 | 域级（如"合同审查"、"数据分析"） | 原子级（如"中文优先"、"禁止虚构") |
| 加载方式 | 按名 `consult`；人侧常驻进 `<设定>`，按需进 `<按需目录>` | 常驻进 `<设定>`；按需进同一 `<按需目录>` + `consult`；路径进 `<路径约定>`，全文跟真实路径走。`conditional` 否决 |

**加载方式已合一**：Skill 与 Rule 的按需侧走同一 `<按需目录>` 与同一 `consult`。**存储不合一** → [记忆 · 用户规则](/docs/03-AI核心/Agent记忆与知识系统.md#用户规则)。

### Agent→Skill 降级判定

当某个 Agent 满足以下全部条件时，应降级为 Skill：

1. 其**每次判断都依赖领域上下文**（不具备独立完成推理的能力）
2. 领域 Agent 挂载对应 Skill 后**可独立完成同等质量输出**
3. 该 Agent 的存在**增加调度歧义**（委派路由难以区分）
