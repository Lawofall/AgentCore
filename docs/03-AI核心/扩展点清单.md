## 一、新增一个内置工具

注册面主体已声明式收敛：三 registry（builtin / worker / CEO）、能力图鉴、白板接线均从声明名册收集，**普通内置工具新增 = 三触点**。例外：`surface=ceo_orchestration` 运行时仍经 `_assemble_ceo_toolset` 手工装配（双轨；收口见架构债 G3，未完成前勿只改名册）。

| 落点 | 职责 |
|---|---|
| `tools/builtin/<your_tool>.py`（或子包如 `web/`） | 工具实现：`ToolSchema` + `execute`（协议 `tools/protocol.py`），并加类属性 `registration = ToolRegistration(surface / audience / 可选 execution_class·browser_class·local_only·ceo_wire·needs_location·accepts_exec_languages)` |
| `tools/registration/rosters/<surface>.py` · `load_roster()` | 按 surface 子名册追加该类；权威序 = builtin → worker_only → ceo_orchestration 拼接（`rosters/__init__.py`） |
| `tests/test_tool_registry_catalog_snapshot.py`（+ 工具自身单测） | 快照钉住三 registry 成员序、受众、审批档与授权名集 |

**声明字段即分流**：`surface=builtin` 进内置全集（`audience` 含 `ceo` 且 `NEVER` 自动进 CEO 直持集）；`surface=worker_only` 只挂 worker 集（`local_only` 仅本地 backend）；`execution_class` 整类随 `code_execution_enabled_for` 闸、自动进委派授权白名单；**`browser_class`** 叠在 execution 闸之上，另需 `browser_execution_enabled_for` / `browser_host_kind_for`（✅ **Bridge 健康 → local**；**无 Bridge 但 gVisor/沙箱/netns 健康 → sandbox**（含过桥 `location=local`）；**server → sandbox**；真·本地无桥无 gVisor → 不装配；见 `tools/builtin/__init__.py`）；`accepts_exec_languages` 才把本机探测到的 language 列表传进构造（模型面已并入 `run`，现无独立 `code_execute`）——`needs_location` 只表示要 `location=`，不等于收 `languages=`；`surface=ceo_orchestration` 进能力图鉴静态 schema、**不**进 worker registry——其运行时构造仍是手工装配（重依赖）：`ceo_wire=always/memory/checkpoint` 在 `runtime/resolve/prepare.py` `_assemble_ceo_toolset`，`coordination` 在 `runtime/resolve/ceo_surface.py`，`board` 走 `register_board_ceo_tools`（assemble / resume 共用）。

**仍要手动碰的例外**：新 CEO 编排原语除声明外还需在 `_assemble_ceo_toolset` 写构造；子命令升格审批（如 `git` 写入、`terminal start`、`host` 的 GRANTABLE action）在 `runtime/approvals.py` · `tool_call_requires_approval`。工具本身无专用 codegen；改 REST schema 走 `pnpm gen:types`（`scripts/dump_openapi.py`）。

### 抄对范例（工具 / CEO）

| 场景 | 抄这个 | 勿只改这个 |
|---|---|---|
| 普通内置 / worker 工具 | `tools/builtin/<tool>.py` 的 `registration` + 对应 `tools/registration/rosters/<surface>.py` + 快照测 | 勿手改三 registry 构造；勿只改 catalog 文案；勿改错 surface 子册 |
| 新 `ceo_orchestration` 原语 | 名册声明 **且** `runtime/resolve/prepare.py` · `_assemble_ceo_toolset`（`ceo_wire`）；coordination → `ceo_surface.py`；board → `register_board_ceo_tools` | **勿只改名册**（运行时仍手工装配，双轨未收口前） |
| 改 REST / OpenAPI | 改 schema 后根 `pnpm gen:types` | 勿手改 `contract-rest-types` 生成物当源 |
| 改 SSE / InteractionKind / fold | 扩展点对应节落点 → `pnpm gen:types` → **必跑** `pnpm conformance` | 勿只改一端 fold；门禁 → `.cursor/rules/protocol-conformance.mdc` |

行为权威 → [工具与能力系统](/docs/03-AI核心/工具与能力系统.md)、[执行引擎 §五](/docs/03-AI核心/执行引擎架构设计.md)。

## 二、新增一种辩论形态

成员集拆两集，禁止把广告子集与回放全员捆成一次相等：

- **回放 / wire 全员**：权威源 = `DebateForm`；`DEBATE_FORM_VALUES` / `FORM_LABELS` / SSE `form` 同集。
- **schema 广告子集**：`DEBATE_SCHEMA_FORM_VALUES`（产品入口只认正反）。扩 `DebateForm` **不**自动扩发给模型的 enum。

**新增形态的行为面**仍要手写。

| 落点 | 职责 |
|---|---|
| `runtime/debate/types.py` · `DebateForm` + `RoundPolicy.for_form` / `DebateConfig` | **回放全员权威源** + 轮次策略；扩 enum 即扩 wire 成员，不自动扩 schema 广告 |
| `runtime/debate/constants.py` · `FORM_LABELS` / `DEBATE_FORM_VALUES` / `DEBATE_SCHEMA_FORM_VALUES` | 展示名（import-time 穷尽断言）；wire 全员序；**广告子集**（须 ⊆ 全员） |
| `runtime/debate/form_profile.py` · `form_profile` | 形态 → 交互单元 + 轮内 phase 拓扑 + 质询/结辩门槛 |
| `runtime/debate/prompt.py`（+ moderator 族） | 辩手/主持人 prompt 与循环差异（`moderator.py` / `moderator_phases.py` / `moderator_agenda.py` / `moderator_judge.py` / `moderator_brief.py`） |
| `tools/builtin/debate/schema.py` · `parse_form`（+ `tool.py`） | 解析接受全员；**`form` enum 由 `DEBATE_SCHEMA_FORM_VALUES` 派生**，勿手抄、勿改回全员 |
| 根 `pnpm gen:types`（payloads 已用 `DebateForm`；`dump_sse_payload_types.py`） | 再生 `packages/contract-types`（含 `DebateForm` 别名）。只扩广告子集时不必跑 |
| 桌面 `apps/desktop/.../chat/debate/model/{types,labels,projection}.ts` + `arena/`（入口 `DebateArena.tsx`） | 投影 / 文案 / 形态英雄区（如 `FindingThreads` / `ConsensusMap`）；类型已跟 payload `form` |
| 窄屏辩论 | 走桌面 `DebateArena` 同一套（手机 `DebateView` / fold **已退役**）；键仍须覆盖 `DebateForm` |
| `tests/test_debate_form_member_snapshot.py` | 棘轮分钉广告集 vs 回放全员（漏扩必红） |
| `conformance/vectors/debate/`（builder + `__init__.py` 登记）→ `packages/protocol-conformance/fixtures/` | 金样；跑 `pnpm conformance` |

**边界**：若新形态需要全新 phase 原语（现有 `attack` / `nominate_serial` … 组合表达不了），改动面扩到 `moderator_phases` / `rounds` 等——以 `form_profile` 能否表达为判据。行为权威 → [辩论编排设计](/docs/03-AI核心/辩论编排设计.md)。

## 四、新增一个 LLM 厂商

| 落点 | 职责 |
|---|---|
| `config/platform.py` · `PlatformSettings` | 厂商 `*_api_key` / `*_base_url` 字段 |
| `llm/factory.py` · `_VENDOR_PROVIDERS` + `build_provider` / `build_router*` | 有 key 时注册进 router 的厂商表 |

| `llm/catalog.py` | **模型目录唯一事实源**（`GET /v1/users/me/models`）：BYOK 发现混排 + 平台上架（`platform_listable_model_ids` / `visible_platform_listable_model_ids`）；产品身份 `ref`（`@platform/{id}` / `@byok/{provider_id}/{id}`）；改「用户能看见哪些模型」先读这里 |
| `llm/model_profiles.py` | **派生查询层**：用户组合 CRUD + expand；系统预置 = 对 catalog 上架集的 uuid5 投影（不自管模型元数据） |
| `llm/pricing.py` · `_VENDOR_PREFIXES`（+ `community_prices.py` / `pricing_data/` 可选） | 前缀计价分支 / 价卡 |
| `llm/image_accept.py` | **主模型是否收图单一所有者**（`model_accepts_images`）；目录 vision 位与原生 multimodal 路由共用；厂商契约 + 进程内负例 |
| `llm/model_metadata.py` | 目录行展示增强（显示名/非 vision 能力/上下文）；族前缀变体不抄 vision；`vision` 由 `model_metadata_for` overlay 自 `image_accept`；未知 id best-effort 派生；**发现源是 catalog，metadata 只 enrichment** |
| `runtime/spans.py`；`api/routes/inference/proxy.py` | 可观测厂商名归一；sidecar 推理代理 |
| 文档 [平台 LLM 接入](/docs/05-平台与运维/平台LLM接入.md)（计费口径 → [成本配额与计费](/docs/05-平台与运维/成本配额与计费.md)） | 运维配方，改完同步 |

**边界**：BYOK 主路 = 用户自配多服务商列表、任意 OpenAI 兼容端点（`llm/provider_service.py` + `api/routes/llm_providers.py`），**不必**动 `_VENDOR_PROVIDERS`——厂商表服务于部署级前缀路由（多模型辩论等）。非 OpenAI 兼容协议需新 `LLMProvider` 实现并改 factory，不能只加前缀（当前仓库无第二套协议实现）。
