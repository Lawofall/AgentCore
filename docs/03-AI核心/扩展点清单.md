## 一、新增一个内置工具

注册面主体已声明式收敛：三 registry（builtin / worker / CEO）、能力图鉴均从声明名册收集，**普通内置工具新增 = 三触点**。例外：`surface=ceo_orchestration` 运行时仍经 `_assemble_ceo_toolset` 手工装配（双轨；收口见架构债 G3，未完成前勿只改名册）。

| 落点 | 职责 |
|---|---|
| `tools/builtin/<your_tool>.py`（或子包如 `web/`） | 工具实现：`ToolSchema` + `execute`（协议 `tools/protocol.py`），并加类属性 `registration = ToolRegistration(surface / audience / 必填 catalog_summary「这是什么」 / 必填 blurb 货架简介（不进模型目录） / 可选 execution_class·browser_class·local_only·ceo_wire·needs_location·accepts_exec_languages)` |
| `tools/registration/rosters/<surface>.py` · `load_roster()` | 按 surface 子名册追加该类；权威序 = builtin → worker_only → ceo_orchestration 拼接（`rosters/__init__.py`） |
| `tests/test_tool_registry_catalog_snapshot.py`（+ 工具自身单测） | 快照钉住三 registry 成员序、受众、审批档与授权名集 |

**声明字段即分流**：`surface=builtin` 进内置全集（`audience` 含 `ceo` 且 `NEVER` 自动进 CEO 直持集）；`surface=worker_only` 只挂 worker 集（`local_only` 仅本地 backend）；`execution_class` 整类随 `code_execution_enabled_for` 闸、自动进委派授权白名单；**`browser_class`** 叠在 execution 闸之上，另需 `browser_execution_enabled_for` / `browser_host_kind_for`（✅ **Bridge 健康 → local**；**无 Bridge 但 gVisor/沙箱/netns 健康 → sandbox**（含过桥 `location=local`）；**server → sandbox**；真·本地无桥无 gVisor → 不装配；见 `tools/builtin/__init__.py`）；`accepts_exec_languages` 才把本机探测到的 language 列表传进构造（模型面已并入 `run`，现无独立 `code_execute`）——`needs_location` 只表示要 `location=`，不等于收 `languages=`；`surface=ceo_orchestration` 进能力图鉴静态 schema、**不**进 worker registry——其运行时构造仍是手工装配（重依赖）：`ceo_wire=always/memory/checkpoint` 在 `runtime/resolve/prepare.py` `_assemble_ceo_toolset`，`coordination` 在 `runtime/resolve/ceo_surface.py`。

**定名**：新增 / 改 schema `name` 先过 [工具与能力 · 模型面工具名](/docs/03-AI核心/工具与能力系统.md#模型面工具名)。禁止用「预训练标准」当唯一理由；废名不双注册。

**仍要手动碰的例外**：新 CEO 编排原语除声明外还需在 `_assemble_ceo_toolset` 写构造；子命令升格审批（如 `git` 写入、`terminal start`、`host` 的 GRANTABLE action）在 `runtime/approvals.py` · `tool_call_requires_approval`。工具本身无专用 codegen；改 REST schema 走 `pnpm gen:types`（`scripts/dump_openapi.py`）。

### 抄对范例（工具 / CEO）

| 场景 | 抄这个 | 勿只改这个 |
|---|---|---|
| 普通内置 / worker 工具 | `tools/builtin/<tool>.py` 的 `registration` + 对应 `tools/registration/rosters/<surface>.py` + 快照测 | 勿手改三 registry 构造；勿只改 catalog 文案；勿改错 surface 子册 |
| 新 `ceo_orchestration` 原语 | 名册声明 **且** `runtime/resolve/prepare.py` · `_assemble_ceo_toolset`（`ceo_wire`）；coordination → `ceo_surface.py` | **勿只改名册**（运行时仍手工装配，双轨未收口前） |
| 改 REST / OpenAPI | 改 schema 后根 `pnpm gen:types` | 勿手改 `contract-rest-types` 生成物当源 |
| 改 SSE / InteractionKind / fold | 扩展点对应节落点 → `pnpm gen:types` → **必跑** `pnpm conformance` | 勿只改一端 fold；门禁 → `.cursor/rules/protocol-conformance.mdc` |

行为权威 → [工具与能力系统](/docs/03-AI核心/工具与能力系统.md)、[执行引擎 §五](/docs/03-AI核心/执行引擎架构设计.md)。

## 二、新增一种辩论形态

**默认否决**再加形态。产品入口只认正反；挑刺 / 压测走 `delegate` 审校岗，多视角走 `delegate`。行为权威 → [辩论编排设计](/docs/03-AI核心/辩论编排设计.md)。

产品与 wire 同集，仅正反：

- **权威源** = `DebateForm`；`DEBATE_FORM_VALUES` / `FORM_LABELS` / SSE `form` / `DEBATE_SCHEMA_FORM_VALUES` 同集（仅 `debate`）。未知或历史 form 字符串 coerce 成正反，旧磁带不炸。
- **工具 schema** **不暴露** `form`。勿把 `form` 加回模型面当第二种入口。

动成员集（标签 / 快照 / 前端键）时这些文件须对齐——不是加形态的施工单：

| 落点 | 职责 |
|---|---|
| `runtime/debate/types.py` · `DebateForm` + `RoundPolicy.for_form` / `DebateConfig` | **产品与 wire 权威源** + 轮次策略；未知值回落正反 |
| `runtime/debate/constants.py` · `FORM_LABELS` / `DEBATE_FORM_VALUES` / `DEBATE_SCHEMA_FORM_VALUES` | 展示名（import-time 穷尽断言）；wire 与广告同集仅 `debate` |
| `runtime/debate/form_profile.py` · `form_profile` | 正反：`parallel_wave` + 质询 |
| `runtime/debate/prompt.py`（+ moderator 族） | 正反提示（`moderator.py` / `moderator_agenda.py` / `moderator_judge.py` / `moderator_brief.py`）；未知 form 不另开分支 |
| `tools/builtin/debate/schema.py` + `tool.py` | 开辩写死正反；**模型面无 `form`，执行不读该键** |
| 根 `pnpm gen:types`（payloads 已用 `DebateForm`；`dump_sse_payload_types.py`） | 再生 `packages/contract-types`（含 `DebateForm` 别名） |
| 桌面 `apps/desktop/.../chat/debate/model/{types,labels,projection}.ts` + `arena/`（入口 `DebateArena.tsx`） | 投影 / 文案；回放块惰性挂载 → [辩论室 UX](/docs/04-前端/辩论室UX.md) |

| `tests/test_debate_form_member_snapshot.py` | 棘轮钉产品与 wire 同集（仅正反）；误扩成员或把 `form` 加回模型面必红 |
| `conformance/vectors/debate/`（builder + `__init__.py` 登记）→ `packages/protocol-conformance/fixtures/` | 金样（历史 form 字符串回落正反，旧磁带不炸）；跑 `pnpm conformance` |

**边界**：现有 phase 组合已够正反热路。新 phase 原语 / 第二种 `DebateForm` 默认否决。

| `llm/model_metadata.py` | 目录行展示增强（显示名/非 vision 能力/上下文）；族前缀变体不抄 vision；`vision` 由 `model_metadata_for` overlay 自 `image_accept`；未知 id best-effort 派生；**发现源是 catalog，metadata 只 enrichment** |

## 五、新增一个系统 Skill {#新增一个系统-skill}

设计权威 → [工具与能力 · 系统 Skill 按需目录](/docs/03-AI核心/工具与能力系统.md#系统-skill-按需目录)（§二 是引用质量闸，非 Skill 边界）。动哪些文件：

| 落点 | 职责 |
|---|---|
| `runtime/skills/`（`catalog` 装配 + 分文件正文） | 系统 Skill 单一真相源：`name` / `summary`（何时才查阅，加一句假朋友不查阅；禁把手册塞进目录行） / `blurb`（人侧简介，不进目录） / `body` / 可选 `requires_tools`。`group` 是 registry 元数据；工具箱「官方」铺在「提示词」货架（准则在前），不投影成用户夹。写什么 → [上下文工程 · 提示词设计原则](/docs/03-AI核心/上下文工程.md#提示词设计原则)（先过[内容闸](/docs/03-AI核心/上下文工程.md#内容闸可复现不服务更好)） |
| `tests/test_skills.py`（+ 相关 prompt 测） | 注册命中、目录显隐、`consult` 拉正文 |

用户技能 / 可编目录：**账号级「我的」加成 `<按需目录>`** ✅；官方 HOW 只读、查阅在「官方」（不占槽、不搬家）。本机插头在工具箱「MCP」栏 ✅（桌面 `listServers` 本地合并，不写进 `GET /v1/capabilities`）→ [工具与能力 · 用户技能](/docs/03-AI核心/工具与能力系统.md#用户技能与可编目录)。能力商店 ✅（`/v1/skill-store` + 桌面 `/toolbox/market` + admin `/store`）→ [工具与能力 · 能力商店](/docs/03-AI核心/工具与能力系统.md#能力商店)。

**减名不是默认优化**：目录已有能指到该 HOW 的名字 → 不加新名。正交 WHEN 不合本（合本 = 一次 `consult` 打进没点的手册；例：`product_help` vs `page_ui`）→ [上下文工程 · 目录行是触发器](/docs/03-AI核心/上下文工程.md#目录行是触发器)。
