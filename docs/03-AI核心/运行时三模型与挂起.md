# 运行时三模型与挂起

> **权威范围**：Interaction / Turn Journal / Run 三模型、端口契约、一轮一网关。入口 → [执行引擎](/docs/03-AI核心/执行引擎架构设计.md)。
>
> **主循环归属**：「**拍**」的机制底座（挂起 / 恢复怎么做到不丢状态）；产品口径在 [检查点与开工卡](/docs/03-AI核心/检查点与开工卡.md) → [主循环](/docs/01-产品/产品定位与品牌.md)。

依赖：Interaction 最小独立；Journal 是 Run 的地基；Run 落在两者之上。

## Interaction（唯一交互式挂起原语）

收编审批 / `ask_user` / 本地工具 / `plan_review` / 阻塞升级 / 逐轮辩论 / `stage_card`。热路 `POST …/interactions/{id}`；冷路 `POST …/resume`。五种用户面暂停语义（审批 / 发问 / 波间提纲 / 升级 / 开辩幕间）**全留**——加 `InteractionKind` 须已有种盖不住。

| 决策 | 取值 |
|---|---|
| pending 真相源 | journal fold；**否决**新建 `interactions` 表 |
| 不答语义 | 默认无限等待；废除静默 auto-DENY / 超时回落。用户侧热审批/授权未点时，团队状态是「等你允许」——调度外层 cancel / settle **不得**把未结队员收成整队取消或「调度已停」（显式 Stop / regenerate 仍 orphan + 取消） |
| orphaned | turn 终了 / sweeper / resolve 410 / abort·retry·stop；**断连 ≠ 失效** |
| 同对话并发 | 见下节 [同对话再发](#同对话再发steer--queue)；热挂起→409；冷 paused 可发消息 |
| 冷卡 × live | 见下节 [冷 resume 与 live 交叉](#冷-resume-与-live-交叉deferred)；**否决** busy 时 409 丢放行意图 |
| 跨端 | 补齐客户端；**否决**后端按客户端能力降级 |
| 非交互暂停 | 瞬时上游限流导致的回合暂停**不是** Interaction——没有可拍板的决策、没有未闭合的 tool_call。走独立 **CEO 续跑闩**：`paused_turns` 里一条 `kind:"ceo_continue"` 只当 claim-once 锁，`list_paused_turns` / `recovery.paused` / `/resume` claim 全部跳过它；续跑热路 `POST …/messages/{id}/continue`（空 body、SSE），折叠 journal 重建 CEO 窗口后**跳过** settle 决策路径。客户端据 `usage.outcome` 区分两者：闸卡暂停 `finish=paused` 且 `outcome=null`，限流暂停 `outcome=paused`。**否决**为它新增第四种 `SuspensionKind`——`checkpoint_id` / `tool_call_id` 只能硬造，且会污染 `paused_turn_outcomes` / attention / 冷卡 deferred 那一整套「用户要拍板」语义 |

⏳ 跨进程等待（Redis BLPOP）——放开前置见 [部署拓扑 · API 进程约束：多 worker 一律拒启](/docs/05-平台与运维/部署拓扑与环境.md#api-进程约束多-worker-一律拒启)。

## 冷 resume 与 live 交叉（deferred）

冷 `plan_review` / `ask_user` 与「paused 可另开 live」交叉时的完整语义：

| 决策 | 取值 |
|---|---|
| 点继续 / 提交时仍有 live | **收下决策**：`prewrite` settlement 后同连接 SSE 先发 EPHEMERAL `resume_deferred`（`busy_reason=wrap_up\|live_turn`），槽空后再 claim + 同连接续跑；对齐「发送即有流」排队姿势 |
| `busy_reason` | `wrap_up`＝registry 上仍是本 `message_id` 宿主收口；`live_turn`＝其它回合占槽 |
| 与 FIFO | 槽空时 **冷 deferred 优先于** `turn_queue` FIFO；deferred 跑完再 drain 排队消息 |
| Stop | 只停 live，**不清**冷帧 / 不撤销已 prewrite 的放行；卸锁后 deferred 被唤醒 |
| 卡「取消」 | 与 Stop 正交；deferred **之后** settlement 已锁，不可再改口取消放行——UI 改展示「已记下」 |
| 断连 | 同排队：等待中断连不丢已写 settlement；槽空后可 detached 续跑 |
| composer 旁路 | 发送 = **另开一轮**，**不**取消冷等待（禁「发送将取消等待」假文案） |
| 本地引擎（sidecar） | ✅ 与云端同语义：busy 时 prewrite 后经 `turn/event` 发 `resume_deferred`，槽空再 claim 续跑，RPC 应答延到跑完。**否决**本机互斥硬拒 `turn already running`——冷挂起帧可 claim 时宿主 task 常仍在 hold 等 detached 工人，硬拒会让「补派与在跑队友并行」这一产品目的失效 |
| 重复提交 | 同 `message_id` **一律幂等成功**（200 + SSE，不再 404）：忙槽窗口内 join 已 park 的 waiter，共用同一次续跑、不重复 prewrite；会话空闲、帧已被那次续跑吃掉（peek 扑空 / claim 竞争落败）则回 EPHEMERAL `resume_settled`（`kind` / `checkpoint_id` / `decision` / `decided_at` / `turn_status`），续跑仍在跑就同连接接着看完。顶替（last click wins）只适用于同会话**另一张**冷卡。⏳ sidecar 侧仍报错 |
| 判据 | 吃掉帧的那一方在**同一事务**里写下结论（`paused_turn_outcomes`：决策 / 时刻 / `checkpoint_id` / 结算方），扑空者读它。**否决**回捞 `turn_journal` 末条 settlement——落败方几毫秒前刚预写过自己那条，捞到的通常正是它自己，界面会谎称「你的决策生效了」。落败者仍须**先确认帧真没了**：帧还在（claim 吞了 DB 故障）→ 500，不许冒充成功。`checkpoint_id` 由 CHECK 约束保证非空（空串桌面整帧丢弃），写不进去就回滚、帧留着可重试。预写仍在 claim 之前（另一端立刻看到卡已花掉），去重键不含 `decision`；**claim 成功后**赢家把同 checkpoint 的 journal `*_resolved` 对齐到自己的 decision（同键多行只留一行），已一致则不动——重开折 journal 与 outcomes 同为赢家 |
| 真失效 | 没有结论行才是失效，且 404 文案二选一：结论行写着 `expired` = 超 7 天保留期被清扫（TTL 删帧时盖章，同时清消息行 `usage.paused` 闩，否则前端还画一张点了必死的卡）；两者皆无 = 回合已重新生成 / 删除（结论随消息级联走）。**否决**含糊的「不存在或已处理」，**否决**用「assistant 行还在不在」猜超期——与 TTL「顺手删 journal、遗弃挂起不产可投影消息」的前提互相矛盾 |
| `turn_status` | 取回合自己的状态（assistant 行 `usage.status`），客户端据它决定收不收口气泡。**否决**由单 worker 进程内注册表决定——它不知道别处的续跑；挂本机在跑的流只是传输捷径 |
| **否决** | busy→409 丢意图；resume 自动 cancel live；有冷卡就禁发；发送清掉 paused 帧；claim 竞争输家 404 |

→ 见代码: `api/routes/conversations/turns.py` · `runtime/suspension/consumed.py` · `runtime/turn/runs.py` · `runtime/turn/queue.py` · `sidecar/server_pkg/handlers.py` · 桌面 `ResumePrompt` / `composerPendingHint`

## 同对话再发（Steer / Queue）

用户在同对话再发消息的三种意图（**已定案**；P0 ✅ · P1 ✅）：

| 原语 | 意图 | 入口（产品） |
|---|---|---|
| **Steer** | 软插入当前回合，不硬停 | 空闲：Enter / 主发送；生成中：草稿旁「插队」次级钮 / Ctrl/Cmd+Enter（桌面）；已排队项「立刻插队」（取消该项 + 同内容 steer 重发，仅 cancel 确认才重发）；`delivery=steer` |
| **Queue** | 当前回合完整结束后再开新回合 | 生成中：Enter / 主发送「排队」（默认；图标文案与空闲发送区分，禁复用 Send 冒充发送）；`delivery=queue` |
| **Stop** | 硬打断 | 主槽停止**常显**（有草稿时与插队/排队并存，对齐手机；与发送解耦，**否决**发送默认=Stop&send） |

| 决策 | 取值 |
|---|---|
| 请求体 | `delivery: "steer" \| "queue"` **必填**；缺 → 422；**否决**缺省回落旧自动分流（开发期无兼容层） |
| 空闲 | 开新回合；客户端仍带 `delivery=steer` |
| 热挂起 | `approval` / 用户侧 `escalation`（`awaiting==ceo` 除外）→ **409**；Steer/Queue 均不可绕 |
| 本机 live（sidecar） | ✅ 与云 **同一套** in-flight 内核（`runtime/turn/delivery.py`）。占槽在 sidecar 进程的 `turn_runs`，云 API 进程看不见——桌面生成中以 `getActiveSidecarTarget` 为准走 `deliverMessage` RPC，**禁止** POST 云 `/messages`（否则云当空闲开新回合：框不清、插话不上屏、刷新后后发消息排到先发的「待同步」之上）。FIFO drain 走本机 pipeline+outbox+pump，**禁止**默认 `stream_chat`。取消/列表同进程 `cancelQueuedTurn` / `listQueuedTurns`（recovery 合并；问不到队 ≠ 空队）。**否决**只改前端 ack 清框冒充已插队 |
| 协调活跃 + steer | 现 `user_interjection` → CEO；CEO 可智能升格为排队（仅 Steer 路径） |
| 协调活跃 + queue | **强制** FIFO（绕过 CEO 插话） |
| 经典 in-flight + queue | 现 `turn_queued` FIFO，同连接续流；drain 时新回合 sink 首帧 `turn_queue_started` |
| 经典 in-flight + steer | ✅ ReAct/工具步边界真注入（DURABLE `user_interjection`：`received`→`injected`；收口 leftover → `queued` + `turn_queued.degraded_from=steer`）；无 accepting 窗口 → 回落 queue（`degraded_from=steer`，不进插话生命周期） |
| 排队取消 | ✅ 按 `queue_id`（云 `POST …/queued-turns/{id}/cancel`；本机 live 走 sidecar `cancelQueuedTurn`）+ EPHEMERAL `turn_queue_cancelled`；Stop/abort **≠** 取消排队 |
| 出队开跑 | ✅ EPHEMERAL `turn_queue_started`（`queue_id` / `remaining_depth` / **`content`**；可选附件与 `@`）；时间线用户泡入场（正文在帧上）；**否决**靠前端 `message_start` 猜出队；**否决** persist-first |
| 协调升 FIFO | ✅ `enqueue_and_ensure_drain(on_live_sink=True)` → live sink `turn_queued`（条可见可取消） |
| 多端可见 | ✅ 队列类短暂态到**每个订阅该对话的端**，不只发起端：`turn_queue_started` 本就是新回合 sink 首帧（对话级订阅 `GET …/stream?follow=true` 自动重放）；`turn_queued` / `turn_queue_cancelled` / `resume_deferred` 走对话级信号道扇出，宿主回合已收口、drain 未起时（队列比回合活得久）也送到。每条连接只收一份——正跟播该 sink 的端不再收信号道副本，`follow` 端契约上是该对话的唯一连接。`turn_queued` / `cancelled` 仍只是「变了」信号，条权威仍是下一行的 `GET …/queued-turns`；`turn_queue_started` **除外**（入场帧，正文在帧上）。**否决**为此新增事件类型或 durable queue |
| 条内容权威 | ✅ `GET …/queued-turns` 进程内 FIFO 快照仍是**排队条**权威（`queue_id` / `content` / `position` / `interjection_id?` / 可选 `attachments` / 可选 `agent_mentions`，后两项与出队转发 `stream_chat` 同形，免客户端自缓存；`interjection_id` 标明该项由插话升格而来）。`turn_queued` / `turn_queue_cancelled` 仍是「队列变了」信号；**`turn_queue_started` 除外**——入场帧（正文在帧上）。对账时机：开 / 切会话 · SSE 重连（含 204 无 live）· `turn_queued` 报了本地没有的 `queue_id` · `turn_queue_started` / `turn_queue_cancelled` 到达（出队与撤单都可能来自另一端，且少掉一项后剩下几条的「第 N/M」本端算不出）；**否决**轮询。**否决**只靠 EPHEMERAL 攒条（曾如此）——那只反映「本端某次连接收到过什么」，刷新即空条但队仍在跑、多端不同步、协调升队项永远进不了条因而无法取消。发送路径仍保留 ack 后即时 upsert（省一次往返），对账只做兜底与权威修正 |
| 队列耐久 | 进程内；重启丢队 → 对账发现本地项服务端已无时**一次**轻提示再清（**否决**静默消失）；**否决**本切片做 durable queue |
| 展示 | Queue → 仅 QueuedTurnsBar（条即反馈，不再 toast）；出队开跑再进主时间线用户泡；Steer（经典+协调）→ 共用 `user_interjection` 状态机（协调四/五态含 addressed；经典无 addressed，`injected` 即终态） |
| 插话状态机 | ✅ 协调 `received`→`injected`→`addressed`\|`queued`\|`failed`；经典 `received`→`injected`（终态）\|`queued`\|`failed`。`injected` = 内容真正写入模型上下文（协调：CEO 注入点；经典：ReAct 步顶 drain），是**结构化可证事实**，非启发式推断。同 `interjection_id` 保最新 |
| 时间线落点 | ✅ 插话在助手回合过程时间线上按**真实发生位置**落零宽 marker（`ProcessStep.kind="user_interjection"` + `interjection_id`，与 `team` / `ask` 同构；同 id 只在首次 `received` 落一次，正文与五态仍由旁路 `userInterjections` 按 id 查）。桌面 / 手机各自 fold 同构，过 conformance。**否决**统一挂在助手气泡末尾——插话发生在回合中途，堆到 footer「N 轮 · 用时」之下会造成**因果倒置**（CEO 正文已写「这就让他停下」，用户那句「让他停止」却显示在更下方）。marker 顺带打断 content 尾步合并，经典 steer 正文自然拆成「插话前 / 插话后」两段；纯文本回合的 process 也因结构 kind 而得以持久化。协作图**不**表达插话（图只讲拓扑，无回合内时刻维）→ [协作图与双视图UX](/docs/04-前端/协作图与双视图UX.md) |
| 图内处置标记 | ✅ `addressed` 由编排工具汇合点（`execute_tools`）**统一**标：CEO 本步成功用过 `update_synthesis` / `cancel_worker` / `delegate` 任一 → 清 `pending_interjections` 并标 `addressed`（note 按工具区分）。**展示层不画**该徽章与 note（见下行）。**否决**各工具实现里逐个补标——曾因只有 `update_synthesis` 补，CEO 用 `cancel_worker` 响应插话后 pending 未清、收口被 `promote_pending_on_close` 误升格排队，用户白等一回合且同一件事被答两遍；逐个补属同一根因改多层，遗漏面随新工具持续扩大。**否决**把「只发正文、不调工具」算已处置（启发式）。已知误伤：CEO 无视插话却同步做了图内动作时会误标 `addressed`——取「结构可证的工具事实」优于「猜是否针对插话」。→ 见代码：`runtime/coordination/interjections.py:address_interjections_after_ceo_tools` |
| 事件退役 | ✅ `turn_steer_accepted`（EPHEMERAL 纯 toast ack）**已删除**——它承载的是一条用户发言却不落 journal，刷新即丢、历史重建看不到；统一到 DURABLE `user_interjection`。**否决**保留双事件（语义重叠 = 长期漂移源） |
| 向量顺序 | 经典 steer 向量必须把 `user_interjection` 穿插在 `message_start` **之后**（与协调向量同序）——插队定义上只发生在回合流式输出期间。**否决**客户端为迁就乱序向量加缓冲兜底 |
| 辩论掌舵 | 仍走独立 `/debate-steer`；与主框共用语言、**不**强制并控件 |
| UX 默认 | ✅ 空闲默认 `steer`；生成中默认 `queue`；强制 `steer`（插队）靠显式钮 / Ctrl/Cmd+Enter（桌面）；**否决**伪装「已插入」（插队 ack 只标 `received`，生效由 `injected` 说话；降级才 toast） |
| 状态文案 | 两端逐字对齐（**展示**四态）：`received`「已送达，等待主 Agent 读取」· `injected`「主 Agent 已看到」· `queued`「将在下一条回复处理」· `failed`「未被处理」。`addressed` 协议仍发（清 pending、避免升格排队），**两端不画徽章与 note**——结果已在协作图与助手回复；再贴「纳入合成 / 停掉对应成员」无增量，且「纳入合成」对 `cancel_worker` 是错隐喻。徽章与服务端 `note` 是**两层**（仅对仍展示的四态）：note 讲具体原因（「未能排队，请重试或再说一次」「本回合已中止，这条插话未被主 Agent 读取，已丢弃」等），徽章只讲结果——`failed` 两种成因（Stop 丢弃未读 / 转排队失败）下插话都**已送达**，故**否决**「未送达主 Agent」这类措辞（曾用，与 note 自相矛盾）。`addressed` 仅证明 CEO 本步成功用过图内处置工具（见上行），**不**证明正文回应了用户 → 若再展示**禁**用成功色（勿假绿）；**否决**加「是否先回用户句」的结构化门禁（属启发式判服从度） |

### 已知行为（steer / queue）

以下为**已验证、按现状接受**的语义（非缺陷清单；若要改须另定案，禁顺手补丁）：

| 情境 | 实际行为 |
|---|---|
| 单轮散文（无后续 ReAct/工具步） | 仍可立刻 `user_interjection(received)`；若本回合再无步顶可 drain → 收口 **leftover 升队**，live sink 再发 `user_interjection(queued)` + `turn_queued.degraded_from=steer`（诚实纠正）；用户补充常落在**下一回合** |
| 多轮 / 有工具步 | pending 在下一轮步顶 `drain` → `engine.turn_steer_inject` + `user_interjection(injected)`，**同回合**消化（真跑已见注入标记进同一条助手回复） |
| Stop 与排队 | Stop **不清** FIFO；当前回合结束后 **立即 drain** 下一项——此时按项 cancel 常已 404（项已开跑），属「不清队但会开跑」，**不是**「Stop 后冻结队列」 |

探针（维护者）：`apps/server/scripts/archive/probe_delivery_steer_live.py`（`--suite all`）。

现状：本机 live 与云同语义；账户默认 Steer/Queue、辩论文案对齐、队列重排 **未做、可选**。→ 见代码：`runtime/turn/delivery.py` · `messages.py` · `sidecar/server_pkg/delivery.py` · 桌面 `midFlight.ts` / `composerDelivery.ts` · 手机 `messageDelivery.ts`

## Turn Journal（唯一事实源）

执行事实与展示事件共用**单一有序日志**；**否决**执行流/展示流分家再归并。

| 决策 | 取值 |
|---|---|
| 落盘 | Append-on-Emit：SSE 送达前先落盘；writer 单消费者 write-behind；owner 终了前必 `flush` |
| 展示信封 blob | `tool_use_end.result` 落盘对齐过程车道 `cap_process_result`（8k+`…`）；**live SSE 仍全文**。完整模型回灌在 `tool_call.result`（冷 resume / 诊断窗）。可选 `tool_call.cross_turn_retry`（`futile` / `not_futile`，未知省略）答「跨回合同一动作是否徒劳」，与回合内 `error_class` 正交、不据此拦截；下轮 CEO 易变尾 one-shot `<prior_futile_retries>` 见编排器。其它 DURABLE 字符串 1MiB 安全封顶（拦病态单行，非展示预算；`run_context` 仍走决策④）。存量不 backfill |
| process 车道 | 语义边界步落盘（非 per-token）；纯散文回合不扩 `process_*` |
| 流式投影 | token 不进 journal → `turn_stream_state` UPSERT；终态删；对话硬删 / 消息删除级联；7 天未触达 TTL（对齐 `paused_turns`，`TURN_STREAM_STATE_RETENTION_DAYS=0` 关） |
| seq | live 由 DB 原子分配；merge 保留显式 seq；**否决**无锁 MAX+1 / 主键改 ULID。本机 outbox JSON 另盖 `ord`（发射序号，对标 PG `created_at`）；缺字段回落旧序 |
| settlement | 同 write-behind 插队必达；dedupe 键须携完整事件 kind |
| 暂停态 | 新增回合内累积态须声明挂起归宿与再水化点（`turn_paused`） |
| 审计 | `agent_audit_events` = 下游只读投影，**非第二事实源** |

投影入口：`TurnState.from_journal`；恢复原语：`recover_turn`（恢复前先 orphan 热路 pending）。执行级 kinds / 窗口·计划投影 as-built → [执行引擎 · 8.3 执行级 Turn Journal facts](/docs/03-AI核心/执行引擎架构设计.md)。

**崩溃重驱归属原回合**：租约清扫重驱那条被中断的助手回合时，恢复期事实续写**原回合 journal**（`recover_lease.py` 用租约身份构造 sink 并绑 `TurnJournalWriter`），协作图归属随之回原回合。原消息盖 `usage.recovered`，桌面与手机均渲染「曾中断恢复」——**诚实优先**，不许静默假装没崩过。工人跑完后按团队终态结算：主管仍在则本轮写结尾；已离开则只通知，**不再**另开收口轮或合成用户行。**否决**「恢复成果另起一条无关联助手消息」。

## Run（唯一执行单元）

执行形状是数据（`depends_on`），不是离散模式。辩论/审查 = 主持人确定性循环驱动普通 DAG（**非独立 kind / 无 Arena**）。

| 决策 | 取值 |
|---|---|
| CEO | 根 Run 节点（CAPTAIN）；**否决** `synthesis` 零成本伪 run |
| 嵌套 | `depth ≤ 3` 硬上限；depth=3 永不获 `delegate`；单 lead 扇出 ≤4 |
| RunSession | transcript 可恢复延伸；续派接缝见 [多轮编排与同人续派](/docs/03-AI核心/多轮编排与同人续派.md) |

### 终态读取

「这个回合 / 这个 run 处于什么终态」只读 `runtime/terminal.py`。三层不要压成一种、也不要四处交叉比对：

| 层 | 口径 | 答的问题 |
|---|---|---|
| 节点 | `RunPhase` / `TERMINAL_PHASES` | 这个 DAG 节点关没关（调度能否推进） |
| 流 | `FinishReason`（含 `PAUSED`） | `message_end` 怎么收口。`PAUSED` 是收口但不是 `END_TURN`、也不是 `CANCELLED` |
| 产出 | `TurnOutcome` / `resolve_turn_outcome` | 这回合产出好不好。闸卡挂起为 `None`；限流可续跑才显式 `paused` |

Run 关帧事件是两套有意不同的集合（外加一套 flush 边；格：product ⊂ stream-flush ⊂ close），禁止并成一个：occupancy（sink / team_batch）含 `cancelled`/`skipped`；fold 重建产出只认 `completed`/`failed`。→ 见代码: `runtime/terminal.py`
