# 上下文传递可视化

> 让用户看见每个 Run **实际被喂进**什么。装配机制（保真度/工作区）→ [编排器 §2.3](/docs/03-AI核心/编排器与CEO主Agent.md)；是否统一 Assembler → [上下文工程](/docs/03-AI核心/上下文工程.md)。
>
> **主循环归属**：「**看**」——把「队员到底知道什么」摊开给用户 → [主循环](/docs/01-产品/产品定位与品牌.md)。
>
> → 见代码: `runtime/runs/executor/context.py`

## 核心：单一源 / 双投影

先装配系统消息原文与有序材料 `ContextBlock`。材料块渲染 user prompt；`run_context` 的 sink = 镜像 `system` 块 + 材料块（CEO 则镜像整个 messages 数组）。

CEO：blocks **镜像** messages（`system` 块 = 系统消息原文，不进 user）。队员：`system` 块同样镜像本回合 `system_content`（身份 + 基座 + 合同）；**user 消息仍只由材料块拼出**——把 system 块再 join 进 user 会双份注入。

**否决**另起「为展示而拼」的路径（与真实 prompt 漂移比「不展示」更坏）。

## 通道

端到端五路：① CEO 输入 · ② 上游产物 · ③ 工作区 · ④ 任务装配 · ⑤ worker→CEO 回流。worker 开工面展开为多值 `channel` 枚举（含 `request`/`dependency`/`workspace`/`task`/…）；辩论续写 / 带现场续派另扩（`continuation` 等）——详见代码与 [辩论编排](/docs/03-AI核心/辩论编排设计.md)、[续派](/docs/03-AI核心/多轮编排与同人续派.md)。

## 四条决策

| # | 决策 |
|---|---|
| ① | `run_context` **进 journal**（重载可回放） |
| ② | `system` / 常驻指令：宽屏按需可见；窄屏（`isNarrow`，非 `platform===mobile`）整组恒隐藏 |
| ③ | **不分级**（无 usageDetail/powerMode）+ **简报阅读器**（目录按通道；常驻指令合为一条；CEO 默认 `request`，队员坞默认第一条材料） |
| ④ | 事件投影 body 有标记截断护 journal；**prompt 仍全文**；CEO 与队员的 `system` 块均豁免截断 |

前端：CEO 弹窗与队员右坞共用同一阅读器壳；弹窗固定框（`max-w-2xl` × `min(32rem,70vh)`），不随选中段伸缩。队员坞只留一条入口（标题 + 段数），点开同一弹窗；目录只在弹窗里。**否决**等权折叠卡；**否决**通道/段顶栏 tab；**否决**把装配标签抬成第一层目录；**否决**坞内铺目录/全文；**否决**后端去重/指针化（破双投影）。CEO 开场 = 回合级 `captainContext`（非图节点）；回流 `team_result` 追加不覆盖。resume 不重发开场 `run_context`。
