## 一、`ask_user`（通用澄清）✅

`ask_user` 是 CEO 在 ReAct 循环中的**通用澄清步**（可与检索/读文件等任意穿插，可连续多次）。参照通用 Agent（Cursor / Claude Code 式），非垂直生成器式选项闸。

**产品原则（挡路拍板）**：用户需求是「该聊就聊、必须拍板时再冻回合」——不是多一种问卷。判据与呈现：

| 原则 | 口径 |
|---|---|
| **挡路才问** | 没有答复，是否就不能负责任地钉**桌上结果**（要什么、给谁、做到哪一档）？不能、且猜错会做错活 → 可 `ask_user`。仅可逆低杠杆（语气、次要样式）才标假设继续。闲聊、窗口已有证据、规格已齐 → 不当检查点 |
| **冻结要贵** | 阻塞挂起打断心流、占住回合；只在拍板价值高于打断成本时用。软偏好、继续共创 → `end_turn`，球留在输入框 |
| **桌上结果未定 ≠ 一律发卡** | 「讨论类开场」三选仅当请求**可能**变成成文 / 落盘、且形态真会影响编制时。桌上结果已是对话本身（共创、审美对齐、闲聊式探讨）→ 不发卡、不写盘（闲聊自己回；干活仍派、收口仍 CEO 写） → [编排器 · 团队形态](/docs/03-AI核心/编排器与CEO主Agent.md) |
| **选项服务动作** | choice `label` 对齐下一步会做什么（交付档、调研主体、手段/授权等）；**通用澄清 / 升级提问只一行**（权衡写进选项名，不另写副标题）。第二行仅整理清单 / 每日复盘（路径或落盘合同）。**禁止**把正文已摆出的候选菜单再投进卡里催偏好收敛 |
| **聊天续聊 ⊥ 检查点** | 续聊＝普通气泡 + 输入框；检查点＝冷卡提交/取消。礼貌追问、脑暴后「你更倾向哪个」属续聊 |

| 项 | 决定 |
|---|---|
| 开场仪式 / kickoff 味 UX / 提案体硬闸 | **取消** |
| 澄清方式 | 多轮短问；**Agent 自主**决定何时问、问什么（须符合上表挡路原则）；交付类建议选项写**桌上结果**（先一条主路径 / 一次做完再拆等），不写编制名单、不映射具名做软件流水线；建站糊说只问形态（展示页 / 工具壳 / 业务应用）（→ [编排器 · 团队形态](/docs/03-AI核心/编排器与CEO主Agent.md)） |
| 「就这样开做」开场主 CTA | **不作为**产品主路径 |
| 场面账（`style_options` / `format_options` + 风格/演讲/自动化硬门禁） | **取消**；缺信息靠短问，错了再改。点名载体/手段次优时的顾问短问 ≠ 复活场面账 → [编排器 · 载体/手段顾问](/docs/03-AI核心/编排器与CEO主Agent.md) |

**统一机制**：单一 `ask_user` 工具；调用即冻回合。阻塞检查点 = 挂起即收口，冷路 `POST …/resume`。「该结束还是挂起」归运行时。可逆低杠杆就在回复里写明假设、不出卡。不挂住全场的提问走 `escalation`（不挂起回合、兄弟继续跑）。浏览器需用户登录时 CEO 设 `browser_login=true`（与 worker `escalate(browser_login)` 同形「需要你登录 / 已登录，继续」卡，**禁止**把完整 escalate 开给 CEO）。

**Live 出卡（桌面 / 窄屏 ✅）**：挂起可操作面只靠 ResumePrompt ← InteractionStore cold pending（时间线挂起态不画标记，对齐 ask_user）。本会话 live `*_required`（带 `origin`）入 IX 后须能出卡；`serverMessageId` stamp 晚到则 rebind 立即补画——**否决**靠硬刷新 journal hydrate 才看见。第二轮 / 同会话再次冷挂起：新 host 上真实 `*_required` 可替换已结算墓碑；同 host 重放仍挡。窄屏 / 手机 Capacitor 挂同一 renderer，不另写出卡面。→ 见代码: `ResumePrompt.tsx`

**冷开出卡（桌面 / 窄屏 ✅）**：硬刷新后可点面只认「这题现在还挂着」——`recovery.paused` 帧还在，或本会话 live `origin`。journal 里的 `checkpoint_required` 只证明曾经问过，**不能单独出卡**；配对 `*_resolved` 仍作墓碑（deferred「已记下」、禁止翻回 pending）。问 recovery 失败 ≠ 空闲，才回落到 journal pending。输入框「另开一轮，确认卡仍保留」与 ResumePrompt 共用 `selectVisibleColdResumes`。**否决** `toMessage` 从 `usage.paused` 合成可点壳（本机 claim 后闩仍真、云 GET 还是挂起快照时会把已答卡闪回来）。棘轮：`coldOpen.stillWaiting.test.ts`。→ `selectVisibleColdResumes` · `pausedTurns.openRecovery`

**冷卡终态权威（桌面）**：checkpoint 一旦在服务端结算，**客户端任何路径都不得把它翻回 pending**。可点性收敛到单一判据 `isColdCheckpointSettled`（本会话已观察过结算 / IX 条目已 resolved·orphaned / 消息 journal 有配对 `*_resolved`），由 `reopen` 与画卡闸 `selectVisibleColdResumes` 共用：传输失败只表达「连接断了 / 重连中」，不表达「卡又待答」，已结算的冷卡维持 `submitting`；未结算的冷卡（如 sidecar probe 失败）仍回 pending。`upsertRequired` 重放与 `message_end(paused)` 合成壳照旧写 store，但已结算的画不出可点卡。冷开另加「还挂着」门槛（见上），**不是**在这三条复活路径上再叠一道 if。→ 见代码: `stores/interactions/coldSettlement.ts` · `stores/interactions/store.ts` · `services/resume.ts`

**本机引擎须自证终态**：硬刷新后桌面能判的持久证据只有「消息 journal 有配对 `*_resolved`」——引擎必须把它写进 PG。云端 resume 在 `claim_paused_turn` **之前**把 `*_resolved` prewrite 进同一 `message_id` 的 `turn_journal`，写失败即 500 且不消耗帧。本机 resume：解封 Outbox；`persist_turn_journal` 的 **replace** 语义——只有持完整权威前缀者（本机 resume 重写 / outbox 写回）用前缀区间替换（只覆盖本快照占用的 live-band seq，迟到的更高 seq 天然保留）；salvage 与云端渐进写入仍 insert-if-absent，但只在已占用 live seq 内补洞；超出部分不得用 fact_log 下标扩带；缺的 / 更终态的 `turn_end` 走 `seq=None`（MAX+1）；resume 边界补一次 best-effort 写回（失败不挡开工）。本机结算另补 `paused_turn_outcomes`（`stamp_settled`，不要求已有 `paused_turns` 行），误点旧卡得 `settled` 而非 `regenerated` 404。**否决**给本机 prewrite 加直写 PG；**否决**按条数/长度猜哪份快照更完整；**否决**在图闸另加防守（与上条同源）。棘轮：桌面 `coldRefresh.kickoffCardResurrect.test.ts` + 后端 `test_sidecar_cold_resume_journal_gap.py`。→ 见代码: `sidecar/settlement_prewrite.py` · `conversation/store/outbox.py` · `runtime/journal/persist.py` · `db/repositories/runs.py`

**卡上 CTA（桌面/手机）**：冷卡（`ask_user` / `plan_review` / `browser_login`）次要键文案一律「取消」。`ask_user`：主「提交」=`decision: continue`；次「取消」= 拒答（wire 仍 `decision: stop`）→ tool result 回灌 CEO 短续一轮（软引导收口 / 换假设；**不是**空 continue「按默认继续」；对齐 OpenAI reject→resume）。中途协调已启动时：提交仍从 journal 重派未完成节点；**取消 / 超时不重建 worker、不 `execution_detached` 转后台**（卡=冻场，取消≠把同一批人拉起来再跑）。**同回合连续第二次**挂起 `stop`（跨卡种累计；中间若有 continue/adjust 或新用户消息则清零）→ 系统直接 `INTERACT` 终端收口，不再起 CEO 轮（人话说明已停下 + 保留已产出正文）；连 cancel 同样不拉起团队。冷路预写的**当前卡** `*_resolved` 不计入连 cancel 次数。取消结算桌面画「已取消本回合」存根（与确认 / 超时同形可展开）；CEO 续聊正文仍露出。问句只在存根展开里，不回落成气泡正文。缺 `decision` 不猜成超时（「已经处理过了」）。`plan_review` 三键：继续 / 调整 / 取消。整回合协作停止（`user_stop`；界面「停止 / 已停止」）与此正交，不归本卡——**禁止**把后者 gloss 成取消。

**冷卡 × live（deferred）**：有并行 live / 宿主尚未卸锁时点继续 → 决策立刻 durability（settlement prewrite），SSE 先 `resume_deferred`，槽空后同连接续跑；卡面改「放行已记下…」。旁路发消息不取消等待。权威状态机 → [运行时三模型 · 冷 resume 与 live 交叉](/docs/03-AI核心/运行时三模型与挂起.md#冷-resume-与-live-交叉deferred)。

**何时不用**：简单问答直答；桌上结果已钉 / 规格已齐 → 直接干 / `delegate`；可逆低杠杆或软偏好 → 标假设或 `end_turn`（球留输入框）；意图都复述不出 → 短 ask（或先正文澄清）——不搞开场提案墙。

**否决**：开场问题墙；独立 `kickoff` 工具；场面硬账门禁；ask 与编制确认并成超级卡；开场仪式 / 问卷式 Wizard（进度条、不能回看、把拍板做成问卷）；为单次失败 case 写场景黑名单 / 话术剧本（靠上表原则，不扩意图分类器）；手机另写出卡树（Capacitor 挂桌面 renderer）。

**卡文案**：普通澄清（`intent=decision`）**一题一个题干、不要总标题**——用户看见的问句 = `questions[].prompt`；壳 caption「需要你拍板」是 chrome。工具 `message` → wire `question` 仍必填（absorb / 无题退化），**普通卡不画成标题**；无 `questions` 时 `message` 仍当唯一题干。禁止再拆「问句 / 背景」或加 header chip；权衡进选项 `label`。Skill `asking_the_user` 是 HOW 落点，不是产品分型。整理 / 复盘清单确认仍可用 `message` 当批次标题；方案挑选与风险勾选走普通澄清，不另立卡名。**一张卡一件事**：范围 / 手段 choice 不挂 `grant_*` / `bind_*` / `open_*`；这些 action 只出现在整题都是授权的卡（跳过项可无 action）。混合卡按普通拍板画，选中授权项再换授权壳。授权选项第二行只写「允许改：{文件夹名}」/「将整理：{名}」，禁止空心「加入本对话」。

**卡上选择（✅）**：打开**不预选**。倾向写在选项名末尾「（推荐）」。无勾选且无人话，主 CTA 禁用；取消始终可点。无题卡（只有总题干）提交保持可点。协议层空 continue 仍确认 `default`（引擎回灌「按确认默认」）——桌面卡不再走打开即交。`choice` 收完仍无选项 → 当填空题出卡（题干在）；题上误写的 `label` 收成一项。不亮零按钮选择卡。→ `AskDecisionBody` · `useAskAnswer`

**多题卡面（✅）**：普通澄清 `questions.length ≥ 2` 时体内一次只画当前一题。非末题主 CTA「下一题」（只推进、不 resume），末题才「提交」。头上编号**可点切换各题**（没写补充也能切）；切题 ≠ 交卡，不可靠默认偷偷交。点提交时若仍有未访，带到第一道未访，不交卡。choice 选项下常驻本题人话（按 `question.id`）；本题勾选或本题人话才推进/交本题，整卡有字不得放行未答的其他题。text 题不叠第二格。无题卡仍用整卡人话。`n=1` / 无题 / 清单确认不出现编号。升级提问（`escalation`）仍平铺；有结构题时不在卡底再留一格。无进度条、不禁止回看已访。→ `AskDecisionBody` · `AskQuestionPager`

**卡上人话**：choice 卡 = 选项 + **本题**常驻自由文（不折叠，状态按 `question.id`）。前端**禁止**注入「其他…」——列表不对、或已选还要补一句，都写本题框。placeholder「没有合适的，写在这里」。回灌：有勾选则 `· 题干：选项`，本题有字再同行加 ` · 补充：…`；无勾选有字则人话即该题答案。禁止再挂全局 `· 补充：`。桌面不发出空提交；若仍空 continue（兼容）引擎写「按确认默认」。整理口头同意短允许表认本题人话（精确匹配，且该题未勾 listed）。整理 / 复盘清单 CTA 须勾选。**否决**问卷式 Other+Comments、互斥显隐两套字段。

**现状**：桌面/预览前端统一为通用澄清壳（`AskDecisionBody`）。`assumptions`（起步计划）只读陈列：`label` 教 2–6 字项名，超 8 字并入 `value`、项名改「假设」（不拒卡）；卡上上下叠排，不走固定窄列。后端普通 ask intent 默认 `decision`。建站 / 做软件均不走具名 playbook。→ 见代码: `CheckpointCard.tsx` · `tools/builtin/ask_user/`

## 二、波间停顿与其它卡

| 原语 | 触发 | 语义 |
|---|---|---|
| `ask_user` | CEO 挡路拍板（桌上结果未钉且猜错会做错） | CEO 工具效应（通用澄清，见 §一） |
| `plan_review` | 套餐提纲步 / 画布 `human_gate` 写入的波间标记（CEO schema 不暴露；手写先派再 `ask_user`） | 波间结构挂起；前置强制 CEO 把关摘要 |

**否决** 编制确认卡：组队 / 开辩直接开跑；`command` 只留 `ask` / `auto`（再发 `kickoff` → 422）。存量帧不恢复、leftover resume → 410、事件对进退役跳过表。→ 见代码: `runtime/events/types.py` · `runtime/kickoff/retired.py` · 桌面 `selectVisibleColdResumes`

**不答 / 超时（对齐 ask，用于仍会挂起的冷卡）**：默认无限等（D2 `checkpoint_timeout_seconds=None`）。卡钉在底栏 `ResumePrompt`，不因流收口 / recovery 热路空快照消失。运维若配了上限而触发 `TIMEOUT`：**不**自动放行、**不** grant，回灌 CEO 自行收尾。**否决**超时静默「已自动开做」。取消仍回灌短续（与 ask 拒答同形）。

**`plan_review` 的 `adjust`**：steer 下游后继续。`ask_user` 上 `adjust` 直接拒收。只看 `decision` 不看 kind 会误判。→ 见代码: `runtime/kickoff/adjust_guidance.py`

**阶段推进卡 `stage_card`**：kind 仍在 journal / 时间线投影，**已不是开辩入口**（点卡 410）。新调研不登记。要辩请直接说开辩。实现仍在 `runtime/kickoff/stage_card.py`。**否决**二步制与「发消息即 orphan」。

**清单确认**（`card` 参数，不新增 kind）：仅 `organize_plan` / `daily_review`。确认后服务端落盘（整理绑 plan、复盘写记忆/规则/reviews）；用户面 caption 仍「需要你拍板」，不另立产品名。方案挑选 / 风险勾选走普通 `ask_user` choice，**不**再设 card。权限三轴 → [安全 §三](/docs/05-平台与运维/安全权限与治理.md)。`plan_review`/checkpoint **不受**三轴影响。
