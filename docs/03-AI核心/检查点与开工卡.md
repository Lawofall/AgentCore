## 一、`ask_user`（通用澄清）✅

**定案（已落地）**：取消「开场 / 开工提案」产品位与场面账；`ask_user` 仅为 CEO 在 ReAct 循环中的**通用澄清步**（可与检索/读文件等任意穿插，可连续多次）。参照通用 Agent（Cursor / Claude Code 式），非垂直生成器式选项闸。

**产品原则（挡路拍板）**：用户需求是「该聊就聊、必须拍板时再冻回合」——不是多一种问卷。判据与呈现：

| 原则 | 口径 |
|---|---|
| **挡路才问** | 没有答复，Agent 是否**不能**负责任地做下一步？不能 → 可 `ask_user`；能（含「先按合理默认聊/做，错了再改」）→ 不当检查点 |
| **冻结要贵** | 阻塞挂起打断心流、占住回合；只在拍板价值高于打断成本时用。软偏好、继续共创 → `end_turn`，球留在输入框 |
| **桌上结果未定 ≠ 一律发卡** | 「讨论类开场」三选仅当请求**可能**变成组队摸清 / 成文、且形态真会影响编制时。桌上结果已是对话本身（共创、审美对齐、闲聊式探讨）→ 正文推进，不发卡 → [编排器 · 团队形态](/docs/03-AI核心/编排器与CEO主Agent.md) |
| **选项服务动作** | choice `label` 对齐下一步会做什么（交付档、调研主体、手段/授权等）；**通用澄清 / 升级提问只一行**（权衡写进选项名，不另写副标题）。第二行仅方案挑选 / 风险确认 / 整理清单 / 每日复盘。**禁止**把正文已摆出的候选菜单再投进卡里催偏好收敛 |
| **聊天续聊 ⊥ 检查点** | 续聊＝普通气泡 + 输入框；检查点＝冷卡提交/取消。礼貌追问、脑暴后「你更倾向哪个」属续聊 |

| 项 | 决定 |
|---|---|
| 开场仪式 / kickoff 味 UX / 提案体硬闸 | **取消** |
| 澄清方式 | 多轮短问；**Agent 自主**决定何时问、问什么（须符合上表挡路原则）；交付类建议选项写**桌上结果**（MVP 主流程 / 模块流水线等），不写编制名单；绿场选档后由 CEO 填 `playbook_args.intensity`；建站糊说只问形态（展示页 / 工具壳 / 业务应用）（→ [编排器 · 团队形态](/docs/03-AI核心/编排器与CEO主Agent.md)） |
| 「就这样开做」开场主 CTA | **不作为**产品主路径 |
| 场面账（`style_options` / `format_options` + 风格/演讲/自动化硬门禁） | **取消**；缺信息靠短问，错了再改。点名载体/手段次优时的顾问短问 ≠ 复活场面账 → [编排器 · 载体/手段顾问](/docs/03-AI核心/编排器与CEO主Agent.md) |
| `team_preview` | **产品位已拆**（组队 / 开辩直接开跑；与 ask 仍正交，不并成超级卡） |

**统一机制**：单一 `ask_user` 工具；调用即冻回合。阻塞检查点 = 挂起即收口，冷路 `POST …/resume`。「该结束还是挂起」归运行时。答案不要紧就在回复里写明假设、不出卡。不挂住全场的提问走 `escalation`（不挂起回合、兄弟继续跑）。浏览器需用户登录时 CEO 设 `browser_login=true`（与 worker `escalate(browser_login)` 同形「需要你登录 / 已登录，继续」卡，**禁止**把完整 escalate 开给 CEO）。

**Live 出卡（桌面 ✅）**：挂起可操作面只靠 ResumePrompt ← InteractionStore cold pending（时间线挂起态不画标记，对齐 ask_user）。`*_required` 入 IX 后须能出卡；`serverMessageId` stamp 晚到则 rebind 立即补画——**否决**靠硬刷新 journal hydrate 才看见。第二轮 / 同会话再次冷挂起：新 host 上真实 `*_required` 可替换已结算墓碑；同 host 重放仍挡。手机 ResumeCard 各自实现（`coldInteractions` / `coldResume`），语义对齐。→ 见代码: 桌面 `stores/interactions/store.ts` · `services/resume.ts` · `ResumePrompt.tsx`；手机 `lib/coldInteractions.ts` · `lib/coldResume.ts`

**冷卡终态权威（桌面 ✅）**：checkpoint 一旦在服务端结算，**客户端任何路径都不得把它翻回 pending**。可点性收敛到单一判据 `isColdCheckpointSettled`（本会话已观察过结算 / IX 条目已 resolved·orphaned / 消息 journal 有配对 `*_resolved`），由 `reopen` 与画卡闸 `selectVisibleColdResumes` 共用：传输失败只表达「连接断了 / 重连中」，不表达「卡又待答」，已结算的冷卡维持 `submitting`；未结算的冷卡（如 sidecar probe 失败）仍回 pending。`upsertRequired` 重放与 `message_end(paused)` 合成壳照旧写 store，但已结算的画不出可点卡——**否决**在这三条复活路径上各加一道防守（同一根因改 ≥3 层即触补丁绊线）。个案 2026-08-18 cid `513d8c06-…`（trace `ad1db7c4…`）：后端 16:35:27 即 `team_preview_resolved`、全程 `paused_count=0`，桌面 16:43 起 40 秒内对同一 turn 全量 attach 重放 4 次，终稿落库后仍反复画出「预计 2 人开工」可点卡。→ 见代码: `stores/interactions/coldSettlement.ts` · `stores/interactions/store.ts` · `services/resume.ts`

**本机引擎须自证终态（✅ 2026-08-19）**：上条三条判据里，硬刷新（Ctrl+R）后**只有**「消息 journal 有配对 `*_resolved`」是持久的——引擎必须真把它写出来，桌面才有得可判。云端 resume 在 `claim_paused_turn` **之前**把 `*_resolved` prewrite 进同一 `message_id` 的 `turn_journal`，写失败即 500 且不消耗帧。本机（sidecar）此前只写本地 Outbox，而 pause 已把该记录封成 `READY`（`mutate` 遇 READY 直接返回），于是 resume 之后的全部事实（`*_resolved`、`run_started`、finalize 整段替换）都进不了 PG：硬刷新**必然**把已开工的卡画回 pending，协作图被同一份 pending 按住（图闸口径 → [协作图 UX](/docs/04-前端/协作图与双视图UX.md)），按钮回落成发送。故「卡复活」与「图不出」是**同一根因的两个表现**，不是两个缺陷。定案三件：resume 解封 Outbox；`persist_turn_journal` 增**显式** `replace` 语义——只有持完整权威前缀者（本机 resume 重写 / outbox 写回）用前缀区间替换（只覆盖本快照占用的 live-band seq，迟到的更高 seq 天然保留），salvage 与云端渐进写入仍 insert-if-absent，但**只在已占用 live seq 内补洞**（否则稀疏 display 快照会清掉 append-on-emit 已占的更密行）；超出部分不得用 fact_log 下标扩带（`journal_entries = [*live, *overflow]` 比 `max_seq+1` 长时会再插一条 trailing `process_content`），缺的 / 更终态的 `turn_end` 走 `seq=None`（MAX+1）；resume 边界补一次 best-effort 写回（失败不挡开工）。**否决**给本机 prewrite 加直写 PG——会给本机引擎引入云可达依赖，且只修卡、修不掉图与按钮；**否决**按条数/长度猜哪份快照「更完整」；**否决**在图闸另加防守（与上条同源）。本机结算另补 `paused_turn_outcomes`（`stamp_settled`，不要求已有 `paused_turns` 行），使误点旧卡得 `settled`「已被处理」而非 `regenerated` 404。个案 2026-08-19 cid `a296d88a-…`（trace `9e30066c…`）：本机 5 人审计队，回合跑完后 Ctrl+R 必现「预计 5 人开工」可点卡且无协作图。棘轮：桌面 `coldRefresh.kickoffCardResurrect.test.ts` + 后端 `test_sidecar_cold_resume_journal_gap.py`。→ 见代码: `sidecar/settlement_prewrite.py` · `conversation/store/outbox.py` · `runtime/journal/persist.py` · `db/repositories/runs.py`

**卡上 CTA（桌面/手机）**：冷卡（`ask_user` / `plan_review` / `browser_login`）次要键文案一律「取消」。`ask_user`：主「提交」=`decision: continue`；次「取消」= 拒答（wire 仍 `decision: stop`）→ tool result 回灌 CEO 短续一轮（软引导收口 / 换假设；**不是**空 continue「按默认继续」；对齐 OpenAI reject→resume）。中途协调已启动时：提交仍从 journal 重派未完成节点；**取消 / 超时不重建 worker、不 `execution_detached` 转后台**（卡=冻场，取消≠把同一批人拉起来再跑）。**同回合连续第二次**挂起 `stop`（跨卡种累计；中间若有 continue/adjust 或新用户消息则清零）→ 系统直接 `INTERACT` 终端收口，不再起 CEO 轮（人话说明已停下 + 保留已产出正文）；连 cancel 同样不拉起团队。冷路预写的**当前卡** `*_resolved` 不计入连 cancel 次数。取消结算桌面画「已取消本回合」存根（与确认 / 超时同形可展开）；CEO 续聊正文仍露出。问句只在存根展开里，不回落成气泡正文。缺 `decision` 不猜成超时（「已经处理过了」）。`plan_review` 三键：继续 / 调整 / 取消。整回合协作停止（`user_stop`；界面「停止 / 已停止」）与此正交，不归本卡——**禁止**把后者 gloss 成取消。

**冷卡 × live（deferred）**：有并行 live / 宿主尚未卸锁时点继续 → 决策立刻 durability（settlement prewrite），SSE 先 `resume_deferred`，槽空后同连接续跑；卡面改「放行已记下…」。旁路发消息不取消等待。权威状态机 → [运行时三模型 · 冷 resume 与 live 交叉](/docs/03-AI核心/运行时三模型与挂起.md#冷-resume-与-live-交叉deferred)。

**何时不用**：简单问答直答；信息已够 → 直接干 / `delegate`；能按合理默认续聊或推进 → `end_turn`（偏好留给用户下一条）；意图都复述不出 → 可先正文澄清，或短 ask——不搞开场提案墙。

**否决**：开场问题墙；独立 `kickoff` 工具；场面硬账门禁；ask 与 `team_preview` 并成超级卡；多步 Wizard；为单次失败 case 写场景黑名单 / 话术剧本（靠上表原则，不扩意图分类器）。

**卡文案**：普通澄清（`decision` / `kickoff`）**一题一个题干、不要总标题**——用户看见的问句 = `questions[].prompt`；壳 caption「需要你拍板」是 chrome。工具 `message` → wire `question` 仍必填（absorb / 无题退化），**普通卡不画成标题**；无 `questions` 时 `message` 仍当唯一题干。独立 `context`（开场 brief 遗留）已删，禁止再拆「问句 / 背景」或加 header chip；权衡进选项 `label`。专用卡（方案挑选 / 风险 / 整理 / 复盘）仍用 `message` 当卡标题。

**多题卡面（✅）**：普通澄清 `questions.length ≥ 2` 时体内一次只画当前一题，头右侧编号可乱序跳；底栏仍一次「提交」整张卡（未看过的题走已有 `default`）。人话框常驻、不属于某一题。`n=1` / 无题 / 专用卡不出现编号。**不是**已否决的 Wizard：无「下一步」主 CTA、不拦未访题、不开场仪式。升级提问（`escalation`）仍平铺。→ `AskDecisionBody` · `AskQuestionPager`

**卡上人话**：choice 卡 = 选项 + **一句**常驻自由文（不折叠）。前端**禁止**注入「其他…」——列表不对、或已选还要补一句，都写这里。回灌：有勾选则列勾选，人话另起 `· 补充：`；全空无字才「按你的默认」；全空有字则人话即答案、不叠默认。整理口头同意短允许表认同一格（精确匹配，且该题未勾 listed）。专用卡同一模型。**否决**问卷式 Other+Comments、互斥显隐两套字段。

**现状**：桌面/预览前端统一为通用澄清壳（`AskDecisionBody`）。`assumptions`（起步计划）只读陈列：`label` 教 2–6 字项名，超 8 字并入 `value`、项名改「假设」（不拒卡）；卡上上下叠排，不走固定窄列。后端普通 ask intent 默认 `decision`；场面账（`style_options` / `format_options`）**已退役**，不再出现在工具 schema / SSE / resume wire。建站不再走具名 playbook。落盘含 HTML/CSS/JS/SVG 即跑静态质检（语法 / 假联系方式 / anti-slop）；DESIGN.md 合同仅当内部仍盖 `web_quality_scan`。该开关**不在** CEO schema。`visual_critic` 仍默认关。→ [编排器 · 派活单三档 · 网页质检](/docs/03-AI核心/编排器与CEO主Agent.md)。→ 见代码: `CheckpointCard.tsx` · `tools/builtin/ask_user/`、`runtime/runs/website_style.py`、`runtime/runs/web_quality_scan.py`

**建站品味（2026-08 复审）**：维持无场面风格卡。具名建站套餐已删；默认手写一人整页。网页质检不进派活单、不恢复 `style_options`/风格硬门（与上表否决一致；静态扫描跟落盘 → [编排器](/docs/03-AI核心/编排器与CEO主Agent.md)）。若日后真实使用仍「同质化严重」，再议仅用通用 `ask_user` 的软短问（仍禁止场面硬账）。

## 二、检查点与团队预审

| 原语 | 触发 | 语义 |
|---|---|---|
| `ask_user` | CEO 挡路拍板（无答复则不能负责任推进） | CEO 工具效应（通用澄清，见 §一） |
| `plan_review` | 套餐提纲步 / 画布 `human_gate` 写入的波间标记（CEO schema 不暴露；手写先派再 `ask_user`） | 波间结构挂起；前置强制 CEO 把关摘要 |
| `team_preview` | **不再触发** | 产品位已拆：组队 / 开辩直接开跑。事件对已进退役跳过表；kind 仍服务存量 resume → 410，不再 recover |

**`team_preview` 已拆（现状）**：用户需求是控制结果（看得见、不对能停），不是批准编制。开辩也不先问。权限不再绑编制确认——`command` 只留 `ask` / `auto`；`team_kickoff` / `command=kickoff` 已删（API 再发 kickoff → 422；库内旧 JSON 靠迁移写改写，读侧不再并档）。新回合桌面/手机不出「授权并开工 / 开赛」；协作图在工人开跑后出现。存量 pending **不解挂、不画继续/取消**；冷 `resume` 诚实失败（410）。`adjust` 再出新卡的闸已无产品面。`team_preview_required` / `team_preview_resolved` 已进 `RETIRED_EVENT_TYPE_VALUES`（与 `question_posted` / `delegation_authorization_*` 同形）：journal fold / 桌面 fold / 投影 / leftover SSE 跳过，旧磁带不再投影开工卡。热路径不再 persist、不再写 resolved。kind 仍服务存量 resume → 410。→ 见代码: `runtime/events/types.py` · `runtime/kickoff/retired.py` · 桌面 `selectVisibleColdResumes`

**不答 / 超时（对齐 ask，用于仍会挂起的冷卡）**：默认无限等（D2 `checkpoint_timeout_seconds=None`）。卡钉在底栏 `ResumePrompt`，不因流收口 / recovery 热路空快照消失。运维若配了上限而触发 `TIMEOUT`：**不**自动放行、**不** grant，回灌 CEO 自行收尾。**否决**超时静默「已自动开做」。取消仍回灌短续（与 ask 拒答同形）。

**`plan_review` 的 `adjust`**：steer 下游后继续（与已拆开工卡的「回灌重出卡」不是同一语义）。`ask_user` 上 `adjust` 直接拒收。只看 `decision` 不看 kind 会误判。→ 见代码: `runtime/kickoff/adjust_guidance.py`

**阶段推进卡 `stage_card`**：幕间一步授权。「按此开辩」= 机制直起；「先补充调研」= 回灌 CEO 再开一轮调研（决策值仍是 `research_first`，≠ 已拆的开赛前开工卡按键）。实现仍在 `runtime/kickoff/stage_card.py`（包名历史遗留，kind 独立）。**否决**二步制与「发消息即 orphan」。

**专用卡**（`card` 参数，不新增 kind）：`proposal_pick` / `risk_ack` / `organize_plan` / `daily_review`（站立任务·每日复盘勾选墙）；主拍板四选一通则在提示词层。权限三轴 → [安全 §三](/docs/05-平台与运维/安全权限与治理.md)。`plan_review`/checkpoint **不受**三轴影响。
