## 核心定位

执行引擎是 CEO 与 worker 之间的调度中枢：接收 `delegate` 子任务（`build_run_plan` 据 `depends_on` 建 DAG），连续依赖调度、在决策边界让出、处理失败/取消，经 SSE 推状态。

## 一、DAG 调度与受监督波循环

### 连续依赖调度

计划是 DAG：每 step 声明 `depends_on`。`WaveScheduler` **连续依赖调度**——节点自身依赖就绪且并发有空位（`max_parallel`）即发射，**不等同一拓扑波的其余节点**。步骤 `queued → running → completed`，异常 `failed` / `skipped` / `cancelled`。多 Agent = 多 asyncio Task。

**扇入默认宽松（取消≠失败）**：CEO **不填**汇聚开关。默认 ≥1 上游成功即跑，缺席上游以「前置缺席」块注入（禁编造）；零成功且存在硬缺席才跳过；`FAILED`+`degrade` 属软缺席仍放行。内部 `RunSpec.require_upstream` 仍可严格级联（测试 / 套餐多余键，不进 CEO schema）。内部 `RunSpec.force_continue` 仍可零成功放行（不进 CEO schema）。CEO 经 `replaces_run_id` 补派可改写下游 `depends_on` 并复活被级联跳过的节点。

**否决**：把「上游须 SUCCESS」写进 ready 谓词——失败节点永不变 COMPLETED，下游会死等，且与 merge 重派冲突。正确路径：级联跳过 + `replaces_run_id` 改边复活。

级联跳过 / 中途取消均 DURABLE（`run_skipped` / `run_cancelled`），重载图上呈「未执行 / 已停止」而非假排队。

### 检查点（与审批正交）

- **CEO `ask_user`**：唯一发问原语；挂起即收口 → `POST …/resume` 冷路。语义见 [检查点与开工卡](/docs/03-AI核心/检查点与开工卡.md)。
- **DAG `checkpoint_after`**：波间 `plan_review`；仅顶层 `depth==0`；挂起即收口。**协调态例外**：只发 `BOUNDARY_YIELD`，用户拍板改走 `ask_user`。
- **勿与工具审批混淆**：`approval_required` 是 GRANTABLE 闸门，非检查点。

**不引入 `RunPhase.PAUSED`**：暂停的是整回合，用 `paused_turns` 落盘；细节 → [运行时三模型与挂起](/docs/03-AI核心/运行时三模型与挂起.md)。

### 受监督波循环（晚绑定 + 边界让出）

把「CEO 下完计划即缺席」改为「CEO 是波边界的监督者」：一次建全 DAG，节点可晚绑定，调度器只在**决策边界**让出，续跑同一张图。

| 概念 | 取值 / 语义 |
|---|---|
| 晚绑定 | `bind_after_deps`：依赖就绪后 CEO 定稿；未定稿绝不调度 |
| 边界判据 | `CHECKPOINT` / `BIND` / `SCOPE`（checkpoint_after · 待定稿 · 未消费 escalate scope） |
| 边界结果 | `PROCEED` / `YIELD`（软暂停、排空 in-flight、尾部不 skip）/ `ABORT` |
| 双臂 | BIND/SCOPE → CEO（无感 `plan_revised`）；CHECKPOINT → 用户 `plan_review` |

**成本纪律**：无晚绑定 / 无 escalation / 无 checkpoint 时一路跑到 terminal——**CEO 回合数 = 真实决策点数，不是波数**。

**偏离信号**：复用非阻塞 `escalate` + `kind=scope|dep`，同走 SCOPE 边界；**否决**为 scope/dep 单立 `InteractionKind`。

**被否决**：worker 实体化（暂压）；默认阻塞路径的波内抢占 / CEO 波内重入（协调模式除外）；运行期软护栏（边界结构性决策后基本不需）。

协调模式 as-built → [编排器 · 协调模式](/docs/03-AI核心/编排器与CEO主Agent.md)。→ 见代码: `runtime/runs/`

### 失败策略与性能约束

| `on_failure` | 行为 |
|---|---|
| `retry`（默认） | 调度器内退避；用尽 FAILED 后按扇入规则处置下游。**瞬时上游错误（429 等）除外**——见下「重试只在一层」 |
| `skip` / `degrade` / `abort` | 同款扇入 / 下游照跑 / 排空后停整波 |

**重试只在一层**：瞬时上游限流的重试收在 LLM 调用叶——仅当 `Retry-After` 是 attested 且不超场景上限才坐一次。**否决**调度器级整节点重跑：要重拼 prompt、重装工具，代价远高于单次调用，同一冷却窗口内必然再撞，且同一 `run_id` 会双发终态帧（直播两帧、重载 fold 只剩一帧，两端对同一回合说法不一致）。provider+credential 级冷却闸在窗口内直接返回限流信号、**不** `sleep` 占着回合——否则兄弟调用各自去撞同一堵墙（生产实测：worker 两连败后 CEO 收尾 2 秒后第三次撞同一个 429）。未 attested 的冷却秒数**不进**用户可见文案。CEO 因此中止的回合走 `outcome=paused` 可续跑，语义 → [运行时三模型 · Interaction](/docs/03-AI核心/运行时三模型与挂起.md#interaction唯一交互式挂起原语)。

| 约束 | 值 |
|---|---|
| 最大并行 | 12（`engine_max_parallel_delegations`） |
| 单次 delegate 最大步骤 | 20（`MAX_DELEGATION_TASKS`，产品口径） |
| 事件传播延迟 | < 50ms（目标） |

树级预算：根 CEO 扇出仍「分而不乘」（父波按可派发宽度切开 ContextVar 份额）。**嵌套** `delegate`（depth≥1）在子团 drive 入口**重装满额** `engine_max_parallel_delegations`，避免兄弟 lead 把单团挤成 `12//N`；安全带为 depth≤3 + 单 lead `MAX_WORKER_SUBDELEGATIONS=4`。超额仍排队（管延迟，不限团规模）。

产物经 `WaveScheduler.completed` 按 `depends_on` 注入下游（无 worker↔worker 直连）。

## 三、执行管线

`conversation/service` → `runtime/pipeline` ReAct → SSE。

**关键决策 / 否决**：

- **历史重建**：最近 N 条 user/assistant 文本进上下文；工具 I/O 不回放；空正文失败轮折叠为系统注记。历史系统收口行（`usage.origin=execution_harvest`）折成 user 角色系统注记（可带草稿/团队成品摘录），不以用户口吻回灌「已全部完成」模板；新回合不再写这类行。云端与 sidecar **同一** `load_chat_context`（摘要 + 近窗）；sidecar 经 account `POST …/conversations/chat-context` 取窗，桌面不再从本地 store 拼全量原文。拉窗失败不得静默空窗开跑（5xx 重试或 cookie / 已盖章同窗回退；仍无则回合明确失败）。
- **Finalize**：开局必插 running 占位；Finalize 只结算已有行。**否决**失败再补写/对账自愈。`messages.content` = 最终交付 only。本地 sidecar 回写观测：云端 `decision_spine` 认 `chat.local_turn_*`（不双写 `turn_start/complete`）→ [对话日志分析指南](/docs/05-平台与运维/对话日志分析指南.md)。
- **压缩 / 工具清理**：跨回合折叠旧轮（治 context rot + 缓存失效）；回合内 `tool_clear` / `write_args_clear` 只投影发给模型的视图（`write_args_clear` 保留原写工具名、参数压成 landed 短状态，禁 `_write_landed` 作 `function.name` 诱饵 / 非可写 stub / 非 `_landed_summary` 回灌模板），不动 journal。二者正交。

### 长对话压缩

对齐「摘要续跑、禁止长期只砍不压」。与回合内 `tool_clear` **正交**（一管跨轮对话态，一管当轮工具投影）。实现见 `conversation/compaction.py`。

| 决策 | 定案 | 理由 / 边界 |
|---|---|---|
| 策略 | 超出近端 → 滚动结构化摘要（事实 / 决策 / 未决 / 文件标识）+ watermark；近端原文高保真 | 否决纯 FIFO 调 N；Assembler / Rules **不进**可压缩对话态 |
| 近端窗 | `compaction_recency_messages = 12` | Agent 干活档；闲聊略损可接受 |
| 双扳机（任一 due） | ① **消息**：DB 对 watermark 后 batch 做 `_select_fold`，且可 fold ≥ `compaction_message_trigger_min_fold`（默认 **16**）；② **token**：`input_tokens ≥ 32_000` | 禁用 turn `history_len`（含摘要块会误触发）；`min_fold=4` 若兼作扳机会过频重压、打穿 summary 前缀缓存；内部 fold 门仍 `min_fold=4`（空跑不耗 LLM），与消息扳机解耦 |
| 调度时机 | 云 / **本地** finalize 均 `schedule_compaction_if_due`（后台 fire-and-forget） | 与云对称；本地亦有 `input_tokens` |
| 近顶预压 ✅ | 发轮前（send / regenerate / resume / sidecar `chat-context`）若上一轮 **单次请求** `prompt_tokens` ≥ **本轮模型**窗口 **80%**（无 `context_length` 时绝对阈值 `200_000`）→ **await** 折叠（最多 3 遍增量），再 `load_chat_context`。窗口取自 `llm/model_metadata`（**按本轮 SKU id**：现网 `deepseek-v4-flash` = **1M** → 近顶 800K；Zen `-free` 档仍是 200K，不在现网上架）→ [平台 LLM](/docs/05-平台与运维/平台LLM接入.md)。折叠写成功则继续发（水位可能仍显近）。近顶且折叠未写入 → **拒发**（产品溢出文案：开新对话或换更能装长对话的模型），不打上游 413。`input_tokens` 仍是回合内各轮合计（计费），空失败回合的 0 不覆盖水位 | 定案⑦A：勿等用户手敲 `/compact`；普通路径仍否决「无差别同步阻塞等压缩」——仅近顶例外；失败冷却对近顶不挡；否决「请压缩较早对话」文案（无手动压缩入口） |
| 失败 / 可用性 | 回合后压缩 **best-effort**：后台不可用则跳过、不挡刚结束的回合；失败不推水位。近顶预压：折不进去且已贴顶 → 拒发（见上） | 产品诚实：无钥/配额耗尽时回合后仍可能只砍不压（越过装载窗口即出声，见「失败可见」）；摘要会丢过程细节（硬标识尽量保留），近顶也无法压扁已贴顶的近端原文窗 |
| 失败冷却 ✅ | 失败后进程内冷却（默认 **90s**），期内 **双扳机都不 schedule**；成功写库清除 | 省配额；与 `_inflight_tasks` 同姿态；多 worker 可不完全一致；**近顶预压绕过冷却** |
| 装载 | 有摘要 → 摘要块 + watermark 后尾；无摘要 → 最近 40（安全帽） | 靠提早首压 + 近顶 await 避免长期无摘要硬帽服役；后台异步仍无法让「未 await 的当轮」立刻见摘要 |
| 用户可见 ✅ | REST `context_compacted`；桌面输入区上方轻提示「较早对话已压缩」 | **不**暴露摘要正文；**无**自动压缩 SSE；旗标随 list/get，**无**压缩专用 SSE |
| 失败可见 ✅ | 压缩没跟上**且**未折进摘要的尾巴已越过装载窗口 → 同一条 REST 缝加 `context_gap`（`dropped_messages` + 上游申报 `recovery_at`），桌面同一条灰字带改说降级文案（`context_gap.py` / `ComposerContextCompactedHint`） | 只在**真丢了**才出声：短会话压缩失败无后果，不打扰（判据纯来自库内状态，跟上折叠的对话永远碰不到这条线）；沿用旗标缝，**仍无**压缩专用 SSE；文案须同说「什么没做成 + 原文仍在 + 能怎么办」，禁读成能力永久丧失（对齐记忆常驻配额卡诚实性）；恢复时刻报**未封顶**申报值——1h 封顶是调度问题，说给用户就是骗他白等一轮；时刻走 ISO 绝对瞬间、客户端按读者本机时区成文（见 429 定案） |

**否决**：压缩失败弹红卡 / 为失败另开 SSE 事件族 / 无损失也提示；只改小 40 无早触发；**无差别**同步阻塞自动路径等压缩（近顶预压除外）；用 `history_len` 当可 fold 代理；消息扳机绑 `min_fold=4`；用户可关自动压缩；做成记忆同款大卡或可编辑摘要；**手动压缩入口**（桌面「压缩较早对话」+ `POST …/compact`）——面向大众 GUI 对齐自动-only，专家向 `/compact` 若将来需要另开需求，不占主输入区；「只改溢出失败文案、不做近顶自动压」（定案⑦ 否决 B）。

### 回合内 `tool_clear`

与上表跨轮压缩正交：只投影发给模型的当轮工具结果，不动 journal / UI。调查类（`NEVER` + FILESYSTEM / SEARCH / RESEARCH）里 ≥ `min_chars`（2000）的旧结果收成稳定指针；`file_read` 另附 ≤1200 字结构摘要，清理动作记下全文已清的 path（结构化占位：路径 / 内容已清 / 可重读），其后重读不计同 path 上限。写成功仍授核对读。→ 见代码: `runtime/engine/tool_clear.py`

| 决策 | 定案 | 理由 / 边界 |
|---|---|---|
| `keep_recent` | 调查窗 **2** | 工人当轮税主要来自多份读窗叠进下一轮 LLM，不是跨轮对话态。journal 仍全文；清掉的 `file_read` 有摘要 + 结构化占位，重读不计上限。否决靠拧跨轮 32K 压缩扳机给工人瘦身（工人不用那条路径） |
| 单次 `file_read` 窗 | 默认整读；安全顶 **2000 行或 8 万字符**（磁盘原文，先到先停）；绕开通用 4k 头尾裁 | 对齐 Cursor 手感。否决为堆叠税去拧单次读手感 / 把 `file_read` 塞回 4k 头尾裁。从第 1 行要满安全顶的整读计同 path 天花板；开窗仅当请求范围已被交付且正文仍在投影窗时计次（新范围分页不计）。触顶回短指针、不硬拒。`tool_clear` 全文已清后的重读不计次。计数 per-run 隔离。`read_folder_file` 仍 500 行抽样，不继承本顶 |
| exec 窗 | `host(action=shell)` / `terminal` 独立 `keep_recent=1` | **不**并进调查窗（空转治理用同一 `investigation_tools` 集合）。指针写「已发生、勿仅为回看而重跑」；长驻新日志用 `terminal read`。否决 `code_execute` / `test_run` 进此窗 |

**否决**：把 exec 工具塞进 `investigation_tools`；为「少留全文」加意图分类器。

## 四、ReAct、收敛与执行解耦

### 不变量

轮次上限 `ModelProfile.max_rounds`；治理统一进 `LoopController`（滑窗循环 → NUDGE/FINALIZE、工具失败熔断、无产出早停）；交付前 `finish_guard`；结构化 `RoundOutcome` → `LoopDirective`，主循环穷尽 `match`。

### 收敛治理（决策摘要）

| 机制 | 决策要点 |
|------|----------|
| 重复失败 / 交替 | 同参**失败**连撞或 A-B-A-B 滑窗满阈 → NUDGE；再触发 → FINALIZE。同参**成功**连调（再读 / 分页）不是卡住 |
| LLM 重试 | 未提交前透明重试；已提交后不重试（否决「按已吐行数」判可重试） |
| LLM 空响应 · length | 协议字段 `finish_reason=length` 且空正文无工具 → **首轮即 DEGRADED**（不做 Continue；船长协调 listen 豁免也不覆盖）；普通 silent empty 仍按 streak 阶梯。只认协议字段，不扫推理长度启发式。用户面：SSE `LLM_EMPTY_RESPONSE` + `empty_diagnosis`（HTML/登录页 → `upstream_non_api`，**否决** Sub2API 专名文案）；空响应走红卡，**否决**再叠软收尾灰标（权威 → [协作图 UX · 一回合一处判决](/docs/04-前端/协作图与双视图UX.md#三内嵌协作图与状态条)）；**否决**把空响应当连通失败追加 Base URL/API Key。→ `llm/errors.py` · `LoopController.empty_response_action` · `directive_apply` |
| 硬失败 / 已提交掉线 | ERROR 或 DEGRADED 收口，保留半成品；**否决** profile 级 Flash→Pro fallback |
| 工具熔断 | 按工具累计；`policy_failure` / `contract_failure` 不进累计 |
| Worker token 硬顶 | 统一单值 backstop（否决四档启发式）；到顶 `force_finalize`；瘦身主力是 `tool_clear` |
| 交文件空转·修码 / 报告 | **已退役**。否决「久读无写 = 空转」→ 催写盘 / 收搜索：摸底读文件是本职，卸检索会逼整篇读、把预算读穿。factory 对 `files_expected`（含报告岗）不再打开；settings 残留 >0 也忽略。额度将尽 wind_down 仍独立。→ `create_loop_controller` |

| Turn token 硬顶 | 触顶禁新派、在飞跑完不 cancel（策略 A）；交付预留软闸；否决杀在飞 / USD 顶 / 按 playbook 分档 |
| 检索预算 | `web_search`+`read_url` 共用 per-run 池（统一 14，开发期假设阀非实测值）；缓存命中 / A3 契约拒绝不计费；剩余 ≤2 提前告知、耗尽转 wind_down（与 worker token 硬顶同构）。花过额度的 worker **每轮回灌分项余额**——缺余额感知的 agent 只会盲搜，单纯放大额度不涨效果（[BATS](https://arxiv.org/html/2511.17006v1) 实测预算 100 处饱和，回灌后 1/10 预算反超）。**否决** CEO / task schema 配置口（原有覆盖口因一次 `form=prose` 误用致调研员预算归零而撤，改为运维常量）、按 role / form 猜档、批级共享池（接受 N×线性税） |
| 协作取消 ✅ | **断连 ≠ 取消**。停止分三档：`POST …/run-stop`（用户直控，停单个 worker 或整支团队，**保留回合与 CEO** 让它交代；走 `redirect_queue` 同一 per-run cancel 通道，不触发热/冷续派，落 `run_cancelled(reason=user_stop)`）、显式 Stop = **取消**（`user_stop` 全清：停协调、关回合）、排队项经 `queued-turns/{id}/cancel` 单独取消。**否决** Stop→pause 可续（价值薄、同 turn 暂停状态机过重、行业无此惯例）。Interaction 挂起（ask_user 等）仍用 `FinishReason.PAUSED` + 冷 Resume，与 Stop 正交。**Stop 即停**：不为取消再开一轮思考。**Stop 即静默**：未被读取的插话丢弃并标 `user_interjection(failed)` + note，不再降级成自动开跑的新回合（自然收口仍降级排队）；中止后若动过工作区，入口走终稿路径 / 右坞「改动」tab（**否决**状态条再挂改动 chip；**否决**队员详情再嵌清单）→ [协作图 · 状态条](/docs/04-前端/协作图与双视图UX.md#三内嵌协作图与状态条)。**worker 硬超时强杀**（软着陆 → 宽限一轮交卷 → 强杀）复用同一 per-run cancel 通道，但落 `run_cancelled(reason=worker_timeout)`、前端念「超时结束」——没人给它派新活，**不得**冒充 `redirect` 的「已改派」；半成品照样 salvage 进 CANCELLED 态供收尾对账。**Drive 取消指纹**：`drive_task.cancel` 前盖 `CANCEL_REASON_ATTR` + `session.drive_cancel_reason`；`delegate.coordinate_cancelled.reason` 区分人点停止 / 队员裸 cancel 上溢 / 无指纹。禁止无理由 `task.cancel()`。→ `runtime/coordination/drive_cancel.py` |

**上游 LLM 限流（429）失败可见**：**不做** pause 代等。交互回合（`chat` / `agent`）无 attested `Retry-After`（`local_backoff`）或头 >2s → 立刻 `LLM_RATE_LIMIT`（日志 `reason=interactive_fail_fast`），禁止再走无头 2→4→8→16 空等；头 ≤2s 最多等一次。后台档（title / compaction）仍走短退避（最多 6 次，`Retry-After`>30s 不睡满）。**title 日级 Retry-After 只武装 title 槽**；compaction 仍探路上游（进程冷却分车道；后台不读平台号冷却戳）。产品态中文终态；限流族 attested `retry_after` 大于共享 `MAX_RETRY_AFTER`（30s，前后端同一常量）时客户端**不展重试**（与「重试会失败」文案对齐；**不加** ErrorPayload `retryable`）。本发空失败（无正文 / 工具 / token）时云端 `stream_chat` **硬删**本发 user+空助手，发送当没发生（`cost_events` 留下；sidecar 本机 finalize 未接同一刀）。首发因此变成空会话时，客户端再软删会话行、回到草稿，错误挂输入框卡片（跟发不拆）。CEO 回合 `failed` 时若仍 `execution_detached`，失败与「团队后台运行中」**并陈**。与平台 API `RATE_LIMITED` 正交。→ 见代码: `core/errors.LLMRateLimitError` · `packages/contract-types/src/rateLimit.ts` · 桌面 `errors.ts` / `turnOutcome.ts`

**失败面（本机与云端同一套）**：气泡 = 错误说明，过程时间线保留已做步骤；**否决**把读文件过程糊进船长口吻。对面 5xx / 530 ≠ AgentCore 挂了（530 用户面：「你选的模型暂时不可用」）。工具已跑再遭对方 4xx：说明做到一半被拒绝，不留空气泡。Class B「发送当没发生」硬删范围**不扩大**（仍只限流 / 坏 Key / 余额）。→ `llm/errors.py` · 桌面 `errors.ts`

**用户可读时刻不进文案**：日级 `Retry-After`、平台配额重置这类「用户据以决定等还是睡」的绝对时刻，一律以 ISO-8601 UTC 瞬间随 `recovery_at` / `reset_at` 下发（`core.errors.wire_moments`），服务端文案只说事、不报钟点，读不到时刻的客户端退到更薄但仍真的一句；客户端按读者本机时区成文，**不标时区名**（屏幕上的钟就是他自己的）。**否决**服务端预措辞 UTC 挂钟（UTC+8 用户得先换算成次日 0 点才知道该不该睡，换错就再撞一次同一堵墙）、改用服务端本地时区（只是换个人的时区错）、请求头带时区交服务端渲染（三端加 sidecar 每个 HTTP 客户端都要改，成本高于收益）。→ 见代码: `core/errors.utc_moment_iso` · 两端 `lib/recoveryMoment.ts`

**检索预算的已知错配**：`web_search`+`read_url` 共用 per-run 池（统一 14）是**搜/读混池**——两者成本结构不同（SERP 约为抓页的量级差，抓页成本主要在 token），打满也不是质量事故信号。⏳ 已确认待落地：拆成搜 / 读两池、搜收紧读放宽，读池按「页」而非「次」计量（未来若加批量抓取原语，一次取 N 页能自然扣 N 而不是扣 1）；具体数值待预算感知窗口的分工具用量实测（埋点 `engine.retrieval_budget_awareness`，`final=true` 行一 run 一条）后再定。小样本内测不作发布门禁、不外推。→ 见代码: `runtime/runs/retrieval_budget.py`

| 轨 | 管什么 | 挂载 | 代表模块 |

两轨**不共享判定顺序**：新规则按语义挂对侧——回合收敛 → engine；批次能不能开/续 → delegate。**否决**统一成单一 gate 注册表（语义层不同，强合易抽象泄漏）。软提示边界 → [编排器](/docs/03-AI核心/编排器与CEO主Agent.md)。

**delegate 轨的两条铁律**：① 闸拒之前先看有没有合法入口——收口后「动同一支团队」按结构路由到续派 / 补缺口，只有真冷开的那堆才判大扇出；② 闸无模型跳过键。权威口径与三堆判据 → [编排器 · 同队续派一等入口](/docs/03-AI核心/编排器与CEO主Agent.md#同队续派一等入口)。

**到顶收口**：`is_thrashing()` → DEGRADED + 上浮信号（不自动重分解）；正轨 → `force_finalize`。**顺序分裂已退役**——真并行只在规划层 `delegate`。触顶禁换马甲（须 `continue_from_run_id`）。零写 / prose_idle 中途 warn→FINALIZE+DEGRADED 已退役（仅硬顶 `ceiling_backstop`）。交文件空转催写、调查空转催结论、调查轮绝对顶（满 N 轮强制收工）亦退役（同上节）。

### finish_guard

模型自报 done 是唯一终止信号；放行前过纯代码轻层守卫，未过才回炉。`LoopController` 强制收口**不过此守卫**。**对话气泡不因引用回炉**：`#rN` / 悬空 `[n]` / 书目形态不是气泡 `finish_guard` 的命中项——引用是检索产物，来源卡与闸的分工见 [工具与能力 · 引用质量闸](/docs/03-AI核心/工具与能力系统.md)。**已删**交卷后自动 `read_url` 升级、剥号时伪装 `content_reset(finish_guard)`、过程步 `rework` 与「正在按规则修订… / 引用/格式核验后已重写」chip。守卫仍管**结构完整性**（围栏未闭合 / 空语言围栏）与**产物结构窄闸**（交付诚实多为影子观测，见下）。这类回炉仍发 `content_reset` / `run_output_reset`（transport-only，与 retry 一样只清正文、不留核验痕迹）。回炉清空后、重写尚未流出时若用户 Stop：按行业习惯回灌重置前已流正文再 `message_end(cancelled)`（空壳否决）。→ 见代码: `runtime/verify.py` · `engine/round.py` · `EventSink.interrupt_salvage_content` · `close_user_stop_turn`

**可用性诚实性（定案：甲 + 丙；乙并入姿势 A；档位真源 ✅；全面禁吹二期不做）**：

- **真相（丙）**：验证形工具失败（`browser_navigate` / 有界验证 `test_run` / verify 形 `code_execute`·`terminal` 等）必须压低 `delivery_status` verdict，不得仍为 `delivered`；缺口 `reason=verify_failed`。`test_run` 超时（定案：**idle 挂起停用**；灾难顶安全网**不算工具家族熔断**；非旧墙钟预算）：idle 挂起 → `exec_timeout`（计入执行环境家族停用）；灾难顶强制中止 → `exec_forced_stop` / `contract_failure`（验证未完成）。同 run 内 `code_execute`/`test_run` 连续 idle 超时满 2 次 → 家族停用；真实执行首次失败仅在硬证据（退出码 127 / 启动被拒）时立刻停用并安静告知用户（`EXEC_ENV_DEAD_USER_VISIBLE`）；执行超时不停用。本地回写失败码归一含 `schema` / `git_*`（如 `git_timeout`/`no_repo`）/ `exec_*`（`exec_timeout` / `exec_forced_stop`）。默认 idle **60** / install **120** / disaster **1200**；gVisor cap **1230**。→ 权威口径 [工具与能力 · 写码验证双环](/docs/03-AI核心/工具与能力系统.md)
- **路径验收**：`delivery_status.artifacts` = 本 `execution_id` 各波**声明且落盘**路径的并集（同 path 后写覆盖；主清单数据源）；未声明的额外落盘不进卡、不打「未通过」。`delivered_files` / CEO「已交付」**仅** accepted **且工作区 `exists`**（工具自报 / `file_products` 尾注不够；收尾 `stamp_results_disk_truth`）。draft 不进 artifacts。非空声明只验缺（`path_mismatch` gap），`artifact_dir` 不给未声明路径兜底，`form=files` 的裸文件名须在进验收**前**归一成全路径；`form=workspace` leftover 目录不 join。口径归 [双模式工作区 · 约定文档目录](/docs/02-架构/双模式工作区.md)。→ 见代码: `runtime/runs/file_acceptance.py` · `runtime/runs/disk_truth.py` · `delegate/delivery_status.py`
- **成品归位已撤销**：收口不搬文件。`delivery_status.promoted` 仅兼容历史事件。→ [术语表 · 成品归位](/docs/01-产品/术语表.md)。
- **呈现（甲）**：用户面**否决**「交付验收」大卡与卡上动作。主呈现 = 船长散文（工作区相对路径可点开）；**用户面否决**聊天流产物清单卡。**通过行不打「已验收」徽章/绿勾**（默认全过、零信息，且「验收」像用户拍板）；仅未通过走正文缺口承认，不再单独出清单行。对账档位**全部静默**——`delivered` / `notes` 不弹验收，`partial` / `blocked` **亦无提示句**（轻提示已撤：「未能交付：N 项未完成」给出的数字无从追问——缺口明细本就否决呈现——且与姿势 A 已保证的正文缺口承认重复；`delivery_status` 事件与前端 `deliveryStatus` 字段保留，仅供 finish_guard 与「只合回产物」读路径，无用户可见出口。要恢复须先解决「可追问」这一缺陷，不得原样加回）。`delivery_status.gaps` / `actions` **有意不接**（否决验收大卡）：勿当死码删、勿当缺口接。可用性短问仍可复用最近一次对账事件（供 finish_guard），不另造第二套。软自注（`unverified_note`）不单独把 state 打成 `notes`；「待核实」诚实标注不再进 soft 扫（`placeholder_scan`）。
- **收口诚实性 · 真源 = 对账档位**：`delivery_verdict.state`——`delivered`=正式完成；`partial`/`notes`≈草稿·部分；`blocked`=阻塞。档位 ≠ 正式完成时，正文不得姿势 A（宣称完整交付）。**队员 `COMPLETED` 不是用户交付。** 文献证据降档、已声明复核落盘未对齐（`thin_review`）、`verify_failed`、契约硬失败/节点 FAILED/拒收产物（`node_failed` / `artifact_rejected`）、声明路径未落盘（`path_mismatch`）、或写盘形态下 blocking 的 `files_not_landed` 时 `requires_draft_ack`：正文须出现草稿/缺口承认（正向要求，不靠加「综述已完成」「核实落盘」词）。单一闭集探测「是否在说 A」；**禁止**靠案面加完成话术词修案。条数/模块名单与 synthesis「路径已核」/ `accepted` artifacts 同源。无对账卡 / 本轮 `no_batch`：**不拦正文**（团队状态走结构面）。档位挂 `TurnPromotionLedger.delivery_verdict` 共享槽（与回合台账同一对象；该对象不再写新的归位行）。**否决**再造第三种通道；**否决**改去查 `turn_journal`。→ 见代码: `runtime/closing_posture/` · `delegate/delivery_status.py` `bind_delivery_verdict` / `read_delivery_verdict`
  - **影子观测（默认）**：**姿势 A / `requires_draft_ack` / 概览篇幅超限只打 `engine.finish_guard_honesty_shadow`（`hit=posture_a|draft_ack|overview_length`），不回炉、不 `content_reset`、不改终稿**。影子 → 真拦由单一开关切换，**默认影子**；转真拦前须先读影子日志的真实分布（`intercept-discipline` 阶梯 2「先看见再谈拦」）。`engine_ceo_overview_max_chars` 默认 1000 未改，仅不再据此回炉。B1 结构轴（浏览器声称 / 超顶空心）不经 verdict 门控，一直生效。空交 ≠ 整轮失败。
  - **姿势 A 收窄**：保留「对账档位为真源」骨架（回炉现为影子观测，见上）；扩面词族（复核/审查/验收通过、已修复、可玩等）不进姿势 A；乙（修好/验绿）仍在。书目形态闸**只打落盘成文**（与 closing 正交；对话气泡不跑，见 [工具与能力 · 书目形态闸](/docs/03-AI核心/工具与能力系统.md)）。漏拦优先回**档位呈现 / 产物结构**，**禁止再扩大**完成话术正则冒充近零误报（与 `intercept-discipline` 默认否决对齐）。
  - **零写落盘声称扫词硬回炉已撤**：不再因正文「已改好 / 已落盘」等闭集 + 无写盘证据而 `finish_guard` 清气泡；检测器可留测试/观测；不恢复【落盘说明】横幅、不加软提醒。解释诚实规则时的禁语举例不得再误伤。
- **本回合团队状态（三态）✅**：真源 = turn journal 派生 `team_batch`（`no_batch` / `in_flight(n)` / `settled(n)`）。没派工是确定态，不是信息缺失。计数 = 本波 kickoff 编制、不含 captain、不含历史队员；**不**复用 `execution.progress` / `coordination_wait` / `workerProgress`。通路仍是 `message_end`（wire 字段；**用户面不渲染**）与 `persist_turn_journal` → `obs.turn_spans`。本地 sidecar 暂停回写与云端 `save_paused_turn` 同样落 journal 快照，故冷加载 `team_batch` 不因空 journal 误成 `no_batch`；未派工仍为 `no_batch`。`no_batch` 下 finish_guard **不扫正文**。呈现：有派工看协作图与条上 `n/m`；否决气泡顶栏「本轮未派工 / N 人进行中 / 已收工」→ [协作图 UX](/docs/04-前端/协作图与双视图UX.md)。→ 见代码: `runtime/journal/team_batch.py`
- **产物结构窄闸（非词表主防线；verdict 门控三闸中唯一仍真回炉）**：`blocked`+空盘不得「已生成/请下载」；有落盘但无 `.pptx` 不得宣称 PPT 可打开；正文点名声明/自报但磁盘没有的路径且夹「已生成/已落盘」同类宣称时回炉。判定结构化可证、误伤面可枚举，故不随姿势 A 走影子。
- **✅ `code_audit` 缺 JSON 归因（写盘不可用）**：`landing_failure_kind=channel_dead|write_failed` 时，缺/读不到配套 `*.audit.json` **不**走结构硬闸；归因进零写 / 队员 soft tip。已读到的 JSON 仍做字段语义校验。→ 见代码: `runtime/runs/contract.py` · `code_audit_gate.py`
- **✅ 团队终态：本轮写结尾，后台只通知**：CEO 派人后在**当前这一轮**等结果，在**当前这一条回复**里写结尾，写完即停。主管已 `end_turn`、队员还在跑 → 散了只通知（状态条 / 协作图「团队好了」；推送：好了 / 有失败 / 已停止，打开对话看协作图），点开再看或用户再问。图终态仍发 `execution_completed`（success / failed / cancelled）。**否决**假用户消息、**否决**自动新开思考轮、**否决**为取消再开一轮。历史库 `origin=execution_harvest` 行前端继续隐藏（读侧防泄漏，不是功能兼容层）。→ 见代码: `runtime/coordination/harvest.py` · `session.py` `finish_detached_coordination`
  - **ALL_COMPLETED 注入**：当场写终稿；`user_facts.files` 已接受相对路径供概览点名，禁止整段粘贴当产物卡。写盘形态且未见已接受文件时，注入事实「队员回合结束不是用户交付」。无条件「先派审计」已收窄为审计套餐 / 审校节点 / `code_audit_gate`。取消/中断收口说法按结构事实分行（用户停止 / 协调被打断 / `cancel_worker` 已开工 / 仅撤排队），禁止把已开工队员说成没启动；取消态注入前缀不得为 `all_completed`（短接袋满仍可结束 wait）。→ 见代码: `runtime/coordination/inject.py` · `cancel_close.py`
  - **收口轮的正文是交付物，不得按旁白回滚**：`deliverable_only` narration 闸（同轮有成功的非终端工具就把 persist 正文滚回 `content_before_round`）在 attached_inject 收口轮**不生效**。worker / debater / 中途旁白仍照原逻辑回滚。→ 见代码: `engine/tool_round.py`
  - **✅ 热审批未决不整队收口**：用户侧允许卡还在（`has_hot_user_pending`）且非显式 Stop 时，不取消未结队员、不把 `DRIVE_CANCELLED` 说成调度中断；wave 外层 cancel 对在飞队员 `uncancel` 继续等（否则 `suspend` finally 会丢掉卡片）。点允许/拒绝后再继续或收口，文案点名工具。→ 见代码: `interaction_orphan.holds_for_hot_user` · `runs/wave.py` · `coordination/harvest.py`
- **✅ 本机访问失败要对上原因**：① 区外挂载 `not_directory` = 路径是文件不是文件夹（请选所在目录或放进工作区），禁止只说找不到；② `exec_env_dead` 后新队员进环即退役 `code_execute`/`test_run`（`can_execute` 随后才算），CEO 注入禁止再派跑命令的人，只读/只写文档可派；③ 工作区通道 sticky-dead 人话与写盘拒派对齐「连不上 / 重开桌面 / 基于已有材料收口」。→ 见代码: `external_mount_readonly.py` · `apply_exec_env_dead_retire` · `channel_dead_gate.py`
- **不做（全面禁吹二期）**：终稿堆正则全面禁「可用」类话术；**不做**「综述已完成 / 站点做好了」等加词修案。裸「已完成 / 已交付 / 弱可用」故意不进姿势 A（修码/建站正常收口不得误伤）。完成态条**不**再标「交付未过关」（失败细节交正文）。

→ 见代码: `delegate/delivery_status.py` · `runtime/verify.py` · `runtime/closing_posture/` · 桌面终稿路径可点（`remarkWorkspacePaths`；对账档位无独立用户面出口）

### 执行与请求解耦

回合执行从 SSE 生命周期解耦：`send` / `regenerate` / `resume` 把 pipeline 作 **detached task** 交 `TurnRunRegistry`；SSE 仅 **attach**；`turn_leases` 持久 RUNNING，崩溃后 sweeper 续跑。

**契约**：

- 客户端断连 ≠ 取消；显式 Stop = **取消**（细则与否决 → 上表「协作取消」）。graceful 关停 = 抢救收口；仅真硬杀标 orphaned。Stop 取消作用域含出站 I/O：在飞 LLM HTTP 流与工具 HTTP 同被中止（拆连接），取消与重试互斥（不得把 `CancelledError` 翻译成可重试网络错误再开下一 attempt）；UI 仍等 `message_end`，数秒内未到则 hydrate 已写结果并结束 stopping（不靠刷新）。sandbox 子进程已在 cancel 路径杀树。
- **停机预算（40s 宽限期内分配）**：排空不得无限等 SSE（否则进不到 lifespan，宽限期耗尽即 SIGKILL）。现行分配 = **排空 5s**（`uvicorn_graceful_shutdown_seconds`；reload 仍 2s）+ **抢救 20s**（`turn_shutdown_grace_seconds`）+ **收尾硬顶 8s**（`shutdown_teardown_seconds`，包住抢救之后整段）+ 余量 7s。收尾内再封两处长尾：gVisor `close_all` 并行 + 整段墙钟 6s（`browser_shutdown_close_all_seconds`；非停机路径仍走 `runsc` 180s 单次上限），compaction `gather` 2s（`compaction_shutdown_seconds`）。三处超时各打 `server.shutdown_teardown_timeout` / `browser.close_all_timeout` / `compaction.shutdown_timeout`，沙箱残留交重启/reaper 收尸。**否决**：加长 `stop_grace_period` 糊过去（排空仍无限，只是更晚 137）；只改排空不封收尾（长尾照样吃光余量再 137）。SSE 生成器看 shutdown 旗标自退 = 可选优化，未做；5s 帽是硬后门。
- 持久化独立于连接；重连 = journal 回放 + live tail。
- 进程内 registry 非真相；真相在 `turn_leases`。

**Resume 身份不变量**：不新开 turn；`message_id` / `execution_id` / journal 游标不变。**否决** resume 伪装新回合、client UUID 当执行槽键。挂起即收口；窄兜底（帧失败退限时挂起）已删。

`regenerate` = 推翻重来。**否决** `retry-failed`（只补失败节点）：产品入口与 API 已退场；部分失败走对 CEO 续聊 / 同人续派，不另开机械补跑旁路。

## 五、工具装配原则

- **声明式单源**：工具类自带 `registration`；三 registry / 能力图鉴从名册收集，禁平行清单。
- **全部 opt-in**：无「对所有 Agent 默认发放」的 core 档（MVP 装配现状以代码为准）。
- **审批与来源无关**：只认 `ToolSchema.approval`；`GRANTABLE` 仅 worker、本地经 `ApprovalGate`。
- **时间即上下文**：当前时间进 system prompt `<runtime_context>`，不走工具。
- **schema 体积按棘轮管，无预算闸**：工具 schema 是每轮重发、且坐在 prefix 前段的输入（CEO 回合近 4 万字符，与系统提示同量级），`prompt_budget_char_soft_cap` 管不到它。膨胀形态几乎恒定：同一条约束在工具描述 / 参数描述 / 兄弟工具里各抄一份，或字段删了负面清单还留着。`tests/test_tool_schema_size_ratchet.py` 按**字符**（不用 token 估算——chars/token 口径会调）钉住已去重的面，并断言结构不回潮；红了先问是不是又抄了一份别处已有的话，确属新增有效语义才抬数字。写什么归哪层 → [上下文工程 · 提示词设计原则](/docs/03-AI核心/上下文工程.md#提示词设计原则)。

## 六、任务分级与模型选择

无 `classify_task`、无旧式 worker 模型档位（`ModelTier` / `model_preference`）。CEO 回合仍解析会话 `turn_model`（主槽）；worker **默认**跟组合 Worker 槽；**节点可显式覆盖**（CEO/`tasks[]`；非法硬失败；确认面不提供人改模）→ [编排器](/docs/03-AI核心/编排器与CEO主Agent.md#per-worker-模型覆盖abc-同一功能)；解析/凭据 → [平台 LLM](/docs/05-平台与运维/平台LLM接入.md)。力度差异仍优先走协作结构。**否决**请求级 `"auto"` 分级树、账号角色→模型矩阵、质量档自动降级。

## 七、提示词架构

World A（Agent 主提示词，`PromptAssembler`）与 World B（内部窄任务）互不相交——关注点不同，禁强行共用。装配顺序权威 → 见代码: `runtime/context/`（`SectionOrder`）；新段只能尾插或按 key 稳定插入（稳定前缀为成本优化，非产品不变量；`cost.prompt_assembled.assembly_hash` 观测漂移）。记忆注入决策 → [记忆系统 §二](/docs/03-AI核心/Agent记忆与知识系统.md)。World B 统一 registry **暂不收敛**（同形样板拖累或第 4 处窄任务再抽薄助手）。

**「变尾置后 ⇒ 命中前缀缓存」是计费主张，不是装配文本的性质**：真实请求是 system + 历史 + user，服务商按整段 token 前缀匹配，系统提示尾部一变、其后全部历史一并失效，而长对话里历史才是 token 大头。故先补实测：每次调用一条 `cost.prefix_cache` = 实际命中率 + 击穿归因到具体叶段（`workspace_context` 文件索引 / `folder_catalog` 项目清单 / 变尾段 / 纯历史增长）+ 按对话长度分桶；默认 info 不落 jsonl，查前缀缓存击穿须 `LOG_LEVEL=DEBUG` → 见代码 `observability/prefix_cache.py`（聚合读数 `scripts/log_stats.py`）。

**两个口径不要混读**：provider 侧 `cache_hit_tokens` / `hit_ratio` 是计费真相；我方 `breach` / `reusable_tokens` 是拿同链前一次请求做的结构推断，两者相减才是 `forfeited`。`reusable_basis=none` 编码的是「算不出」而非「零可复用」，同理 `forfeited_tokens=0` 是「无法判定」不是「零浪费」——一条 98% 命中却报 `cold_chain` 的记录并不自相矛盾。链按 `cost_role` 分档：**CEO 会话级、worker / 辩手 run 级**。因为每个用户回合都新铸一个 captain run（`agent_id == run_id`），run 级链会让 CEO 每回合首调恒为 `cold_chain`，跨回合——正是这套观测最该回答的那一面，也是段级 `breach_section` 唯一可能点亮的场景——一次都测不到。代价是同会话两个重叠 CEO 回合（supersede）会在一条链上交错、互读为改写；理由与边界见 `_chain_scope` docstring。

**调整装配顺序或把易变环境事实移出 system 仍须等实测数据，不得据推理先动结构**——管道已能产出跨回合读数，但样本尚未积累到足以据此动结构。不受这条闸约束的是**同层内去重**（同一条纪律只留一处，不改段的位置与归属）→ [上下文工程 · 提示词设计原则](/docs/03-AI核心/上下文工程.md#提示词设计原则)。

### 8.3 执行级 Turn Journal facts

展示事件（SSE kind）与执行级 facts（`runtime/facts.py` · `FactKind`）交错写入同一 `turn_journal`。display fold / attach 重放跳过 `EXECUTION_ONLY_KINDS`。

| 投影 | 入口 |
|---|---|
| CEO / worker LLM 窗口 | `window_from_journal`（调用 **input 不落盘**，由先前 facts fold） |
| DAG / 已完成 worker | `plan_from_journal` / `completed_from_journal` |
| 暂停态（引用池、controller、正文） | `pre_pause_from_journal`（末条 `turn_paused`） |
| 唯一投影入口 | `TurnState.from_journal` → `recover_turn` |

本回合不存历史消息全文（只 `history_len`）。`paused_turns.frame` 只留身份键、卡面重绘、冷 resume 的 worker 净提示词、sidecar 本地 bind。云端不序列化 transcript / plan / completed / journal_entries / citations。缺 `turn_started` 无法折窗 → 用户面 `ResumeJournalDegradedError`，禁止空窗续跑。

CEO `turn_started.system_prompt` ≠ worker 净提示词。冷 resume 用 frame 上的 worker base；crash / 限流 continue 用 `rebuild_fresh_worker_base_prompt` 重算。

**否决**：执行流与展示流分家再归并；用 frame 与 journal 对账；`turn_started` 充当 worker base。
