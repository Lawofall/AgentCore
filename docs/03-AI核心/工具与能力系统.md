### 模型面工具名 ✅ {#模型面工具名}

schema / journal / function calling 的 `name` 与给人看的过程线不是同一套词。用户面用人话（如「Read page」），**不**把 schema 名暴露给用户；历史 journal 保留当时原始 `tool_name`。

**没有全行业预训练标准词表。** 各家官方表连同一件事的标识符都不统一。改名须点名对照哪一家的哪张**官方** `name` 列、且职责同形；对不上就保持产品名。禁止用「贴合预训练 / 行业标准」当唯一入场理由。

| 对照源 | 用不用 |
|---|---|
| Anthropic Messages API / Managed Agents 的官方 `name` 列（蛇形） | **用**：职责同形时取这套方言（本产品已是蛇形，与 `web_search` 同形） |
| Claude Code 权限规则 PascalCase（`WebFetch` / `Read`） | **不用**：词根可参考，大小写不跟 |
| OpenAI Responses 托管工具 | **只认已公布的**：有 `web_search`，**没有**托管 `web_fetch`；知识库 MCP 深读约定是 `search` + `fetch`（≠ Anthropic `web_fetch`） |
| Cursor 公开 Agent 文档 | **不公布** wire 名；第三方逆向 PascalCase 表（含 `StrReplace`）不作金标 |

**已对齐**（职责同形 + 官方蛇形）：`web_search`（Anthropic + OpenAI Responses）；`web_fetch`（Anthropic Messages `name: "web_fetch"` + Managed Agents 同名 = URL → 正文进上下文，**不是**浏览器、**不是**落盘）；`glob` / `grep`（Claude 各面词根同，本产品已蛇形）。

**刻意不改**（假朋友 / 产品分裂 / 短名撞车）：

| 现状 | 不改成 | 理由 |
|---|---|---|
| `file_read` / `file_write` / `str_replace` / `file_delete` | `read` / `write` / `edit` / `delete` | 只对齐 Managed Agents；Claude Code 是 PascalCase；Cursor 侧常见 `StrReplace`；Codex 改文件是 `apply_patch`。短 `read` 还会撞 `read_conversation` / `read_image` / `read_folder_file` |
| `run` | `bash` / `shell` | Anthropic `bash`、Claude Code `Bash`、Cursor `Shell`、Codex `shell_command` 各说各的；改成 `shell` 与 `host(action=shell)` 撞车 |
| `delegate` | Cursor `Task` | 假朋友（编排原语 ≠ 子代理工具） |
| `download_url` | 并进 `web_fetch` 或改名 `fetch` | 产品把落盘与深读拆开。Unix `wget`/`curl`/裸 `fetch` ≠ Anthropic `web_fetch`，也 ≠ OpenAI MCP `fetch` |
| `file_list` 等产品分裂、编排原语 | 外家短名 | 职责本产品才有，没有同形官方名可对 |

**别名**：未知名只 did-you-mean，**永不**自动改写执行；**不**给废名注册第二把可执行工具。Unix `fetch`/`wget`/`curl` → 指向 `download_url`（不是 `web_fetch`）。废名 `file_append` → 指向 `str_replace`。废名连删（如已删的 `read_url`），禁止靠点名废字段「禁复活」。表 → 见代码：`tools/registry.py` `_KNOWN_TOOL_ALIASES`

**否决**：全套改成 Claude Code PascalCase；把 `file_*` 改成 `read`/`write`/`edit` 并称为行业标准；`run` → `bash`/`shell`；裸 `fetch` 指到 `web_fetch`；把 Cursor 逆向表当预训练金标。

→ 见代码：`tools/registration/`、`runtime/skills/`、`tools/catalog.py`、`tools/registry.py`

### 工具目录（ToolFace + resident）

图鉴与模型按需栏共用一份目录：**分组轴 = `ToolFace`，开场轴 = `resident`**。人在提示词概览看一份「工具」货架（跟在常驻 / 按需后面，按能力面分组；`resident` 只写在卡上「开场即用 / 查阅后启用」，不拆成两摊投放区），点开弹窗第一面是说明书（干什么 / 谁能用 / 审批 / 要填的参数），源码才是 schema；模型 `<按需目录>` 的低频工具栏只列尚未启用的工具（常驻开场即用不进该栏）。提示词四源（skill / 低频工具 / rule / memory）经 `consult` 骑同一按需目录，工具按开场轴并进提示词目录，**不**另开工具种类 tab。夹名是种类标记，开场即用 / 查阅后启用写在卡上与读卡标题旁。

八面：文件 / 文件夹 / 检索 / 网络 / 执行 / 本机·浏览器 / 白板 / 编排。文件夹 = 产品 Folder 实体 + 记忆写入；白板 = 白板作画/读像素 + 工作区读图；编排 = 组队协作原语。注册面 `ceo_orchestration` 不是展示面，禁止把 CEO 专属工具默认丢进编排。超时豁免只跟真编排原语走（分组 ≠ 超时）。

## 二、引用质量闸

`web_search` / `web_fetch` 双通道：**来源卡**（`citations_event` = 成稿实际引用）与**回合证据台账**（除 `blocked` 外全量登记）。档位单源 `citation_tier_for_url`——禁第二套分级器。

| 档位 | 来源卡 | 台账登记 |
|---|---|---|
| `blocked` | 出口剔除、永不挂卡 | **永不进** |
| `weak` | 仅成稿 `#rN` 引用时挂卡（来源卡不打档位徽标） | 登记宽、`citable=true` |
| `official` / `media` / `unknown` | 同上 | 登记宽 |

- **对话成稿 = 检索产物（✅ 重设计）**：气泡来源卡 = 正文实际引用的已登记 id（`citable`，含 search-only / `weak`）。来源卡不渲染档位徽标；`deep_read` 标「已读」，搜索摘要引用保持沉默。`finish_guard` / settle **不因** `#rN`、悬空 `[n]`、书目形态清空气泡或整篇 Rework；未登记号不当可点角标（可留白字），**不** `content_reset`。深读是终稿前模型自己 `web_fetch` 的加分，不是入场券。**已删**交卷后自动深读升级。
- **落盘成文仍闸窄**：文件合同 / `two_phase` 升 B / 内容类落盘走 `citation_quality_reworks`，可引用集 = `deep_read ∪ selected`（对齐辩论 `commit_research`）。`AgentCore/文档/research/*.md` 成功落盘时，正文已引用且可登记的 `#rN` 升为 `selected`（供 CEO 汇总继承）。伪造/越界 id 仍不进台账。
- **`selected`**：settle 时正文实际引用且已 `deep_read` 的 id 持久标 selected；调研方向笔记落盘亦可 promote（见上）；跨回合 hydrate 保留。可选 `doc_kind`（登记时可写；否则 title/snippet 启发式）。
- **书目形态闸**：只打在**落盘成文**上——学位论文/期刊式著录绑定 `#rN` 时该 id 须 deep_read；元数据呈开题/答辩/公告类 → 文件合同回炉（禁域名黑名单）。无 `#rN` 绑定的 GB/T `[D]`/`[J]` 著录亦然。对话气泡不跑此闸。调研 `research/*.md` 遇未绑定书目时不再文末补脚注装锚。
- **调研两阶段引用**：**只认** `citation_mode=two_phase`（playbook 内部盖戳）→ 阶段 A 草案**不**跑成稿引用闸；同 worker 升 B 后再验；未声明退出。draft 不进 `delivery_status.artifacts` 主清单。**路径入口已撤**（原「落盘/声明路径在 `AgentCore/文档/research/` · `reviews/` 即算调研类」）：那个落点由扫 role·task 的正则填出，是隔一层的自由文推断；即兴成稿走 `cite_write_review`。✅ 该字段已离开 CEO schema，仅 playbook 内部盖戳。权威 → [编排器 · 交付物：钉路径才催写](/docs/03-AI核心/编排器与CEO主Agent.md#交付物钉路径才催写)。→ 见代码：`runtime/runs/research_quality.py:is_two_phase_citation_deliverable`
- **跨回合 hydrate**：新回合 `#r` 台账从历史 assistant `evidence_ledger` 合并进引擎核；LLM history 可不带 ledger 全文。
- `search_policy`：per-run 结构化信号（禁 prompt 触发）；`debate_evidence` 额外硬剔 weak / 商城词典等。
- 前置：query 词数/CJK 加权上限（超限可机械规范化并明示；无法规范化才拒）；CJK 查询剔无 CJK 命中；缓存键 casefold + 拉丁词序归一。
- 名单无真实分布依据——以合成样本校准（目前无真实数据，以下为假设）。

→ 见代码：`runtime/citations.py`、`runtime/evidence_ledger.py`、`tools/builtin/web/`

## 三、沙箱

代码执行：subprocess + `SandboxProvider`；云端 **云桌执行环境**（长寿命 gVisor guest，**默认开**；紧急 `GVISOR_ENABLED=false`）——工作区 rw-bind、uid≡文件侧 `app`、出站 SSRF chokepoint（与 `download_url` 同政策）；guest 用户态是声明的 packed rootfs，不是 API `/usr`；sidecar **本机桌**保留 subprocess。本机 `language=python` 的启动器按主机解析（POSIX `python3` 优先 → PEP 394；Windows `py -3` → PEP 397），语言 id 仍是 `python`；云桌 guest 仍只 exec 镜像里的 `python3`，不做 PATH 搜索。**本机引擎坐无绑定的云文件夹不装配** `run`：隔离执行只属于云执行面，sidecar 禁止在用户电脑上假装起隔离沙箱（Windows 会 `not_linux` 10ms 炸、还把本机解释器说成坏了；也禁止用 sidecar subprocess 冒充云隔离 → [安全 · 五、代码执行沙箱](/docs/05-平台与运维/安全权限与治理.md)）。缺口、换桌注册表与 `code_execution_enabled_for` 同一谓词。云协作 Linux 回合正常。云端 `run` / `package_install` / `browser` 同一装配谓词。云桌 guest 启动失败走 `exec_env_sandbox_unavailable`（对用户说云端隔离，不说本机）。云端 Chromium 在该 guest 内（能看桌上 `127.0.0.1` 开发服务器）；本机健康 Bridge 仍走 Local。

✅ **第一刀**：gVisor / Chromium 不进 API 进程；开通在 prepare / resume（可短等，空气泡诚实）；`run` / `execute` 不准开机。切流替换、不留 in-API 回落。装配谓词 = host 健康 ∧ 这张桌已注册（gVisor）；subprocess 逃生口仍只跟配置 / 健康。⏳ **第二刀**蓝图已确认：产品按钮换票、sandboxd 反代、就绪输出解析端口；不另立浏览器壳；Sandbox 相对 HTML 仍诚实失败（见下）。权威 → [安全 · 五、代码执行沙箱](/docs/05-平台与运维/安全权限与治理.md)。部署现状 → [部署拓扑 · 云端执行](/docs/05-平台与运维/部署拓扑与环境.md#云端执行gvisor)。

### 执行三分（短 / 有界验证 / 长驻）

模型面 **一个工具 `run`**。三类 **CEO+worker** 同形，审批不因角色另造闸。`command` 按这台电脑的真 shell 执行（云端 / Linux / 已装 Git 的 Windows = bash；否则 PowerShell）。写了 `| tail` / `&&` / `cd` 就按写的发生。每次调用从工作区根起（或这次的 `cwd`）；`cd` 只在这一行有效，走出工作区或已授权根 → 失败并明说。长驻用 `background=true`（省略 `wait_for` 则起来就返回），已有进程用 `action=read|stop|list`。运行时按命令分类（短执行 / 验证 / 长驻）；分类是实现细节，不是三道模型题。缺口有无 `run`（`package_install` 仍独立）。审批 → [安全 §三](/docs/05-平台与运维/安全权限与治理.md)。

| 类 | 用途 |
|---|---|
| 短执行 | 会很快自行退出的内联代码 / 短命令；墙钟与验收同一灾难顶（20min），**不**因沉默掐、**不**按长得像不像打包换钟。永不退出的等结果 / 开发服务器 → 长驻类（`background`）或本机 `host(action=shell)`。同会话多 worker 的短执行串行排队（验证 / 长驻不在此锁内）。读已有源码正文走 `file_read`，搜符号走 `grep` / `code_search`，勿 dump 或 open+re 到 stdout。派工把本回合已给的凭据写进 task（任务书落库；对外展示打码） |
| 有界项目验证 | **外环**项目 check（**install** / test / typecheck / build / 显式 verify）；流式输出仅在沙箱内跑的通道成立（subprocess / gVisor 读 `on_output`），桌面通道不转发回调、输出结束时一次性返回；超时 = **灾难顶 20min 安全网强制中止** → `exec_forced_stop` / `contract_failure`（验证未完成，**不算工具家族熔断**）；**不**因一段时间没刷出新字就掐。真实执行失败（退出码 127 / 启动被拒）只失败该次。同 `execution_id` 内 sibling 相同验证（解析后 argv 指纹）**inflight 合流 + 结果复用**，避免双 worker 各烧满超时；任一队员成功写盘后 cache **失效**（generation 丢弃陈旧入缓存）。执行中 busy=`verify`（不挡 idle patrol / `cancel_worker`）。云端装包 = 桌上 SSRF chokepoint（netns + 代理，与 `download_url` 同政策）+ 包装源白名单 env + 拒改源旗（`--registry` / `--index-url` 等）；PM 白名单 = npm/pnpm/yarn **与** uv/pip/poetry（同纪律；纯 Python 仓 install 不落 npm）；工作区即 guest 盘，`node_modules` / `.venv` 直接落盘。本地装包 = 权限轴 + 钉源 env（不吃主机 `registry_egress_available`），装在用户绑定目录。无授权 / 云无 chokepoint → 诚实甲降级（结构自检 / export_to_local），勿空转。修码自检走内环 `code_diagnostics`，勿用验证类冒充内环 |
| 长驻 | 开发服务器等永不退出进程；`background` / `long_running` 分流。本机传统：桌面主进程托管（`WorkspaceOp.process_*`）。云协作：同一张云桌 guest 内起进程，按 `conversation_id` 记账（同 Folder 多对话不共用一条 vite）。schema `GRANTABLE`（`action=read|stop|list` 免审；启动吃 `command` 轴）。健康失败则整类不装配（与 `run` 同一谓词） |

外环验绿（task / `playbook_args.verify`）**默认走** `run` 验证类。项目级慢命令（`npm/pnpm/yarn install|ci|test|build`、`uv sync` / `pip|poetry install`、`tsc`、`pytest`/`vitest`/`jest` 等）由运行时分进验证核：**任一段**像检查即整串进核（`rebuild; typecheck`、`test && echo hi` 同形），按灾难顶跑，**不**拒跑再改道到已合并掉的 `test_run`。装包闭环：链里只要有正规 install 段（`pnpm add` / `uv sync` 等）就钉源；拒改源旗（`--registry` / `--index-url`）；`cd` 只许落在工作区内。否决整串 `cmd /c`；否决剥掉 `| tail` 冒充真终端。引擎解析出的 check（无用户 command）仍走 argv，不套壳。→ 再 build/typecheck。打开源码再 print/dump 或正则扫描进短执行核 → **硬拒**并改道 `file_read` / `grep`（同构 `contract_failure`；解析表格 / 改文件 / 跑计算仍走短执行）。这些**选错通道**的硬拒在过程时间线上是 `tool_use_end.status=redirect`（「改用搜索」一类中性步），不是失败红行；模型回执仍是失败以便换工具。真短脚本仍走短执行核（解析 / 装包分流；墙钟与验收同一灾难顶）。云端沙箱 / GRANTABLE 与 `run` 同级治理（`code_execution_enabled_for`）。

写工具 miss 回执：执行类未装配 → 对照 `<工作区>` 缺口，勿空转；`escalate` / `handoff` 仍仅工人通道。worker 面工具已默认全开（含写盘），不催写盘的交付只约束进度（不要求 `str_replace`），不靠硬卸写工具。CEO 同样持写盘与 `run`（与工人同形；开场表有写盘族；导出 / 归档仍按需）。Local 破坏性删（`run`/`host(action=shell)` 启发命中）→ 回滚主（回合 zip 基线）+ 窄闸辅；与 `file_delete` 软删分轨对齐 → [双模式工作区 · 脚本破坏](/docs/02-架构/双模式工作区.md) · [安全权限 · 熔断](/docs/05-平台与运维/安全权限与治理.md)。事实层只报根有无 Git，不软提示 `init_baseline`。→ 见代码：`tools/builtin/run.py` · `run_verify.py` · `run_short.py` · `run_process.py` · `source_inspect.py` · `runtime/engine/tool_exec.py` · `workspace/destructive_fs.py`

**长文落盘（✅）**：不成系统 Skill（不进按需目录；写工具 schema 只留「这是什么」）。【主路径】完整正文（含超长）一次 `file_write`（不硬拒字数、不扫括号配平 / 省略套话 / 覆盖缩水）；成篇后修订只用 `str_replace`。写盘只留这两把笔。HOW 在写回执与参数契约 landing 族；正式长文当场 brief 可由 `cite_write_review` 撰稿 task 带。截断逃生：更短但完整的 `file_write`，或用 `str_replace` 在唯一锚（含写回执 `end_preview`）后续写。成篇草稿 `file_delete` 不硬拒（默认可逆软删）。`str_replace` 找不到：单行短锚可附邻近原文（非精确、不标百分比）；多行只报整段不在（不按行模糊打分）；不唯一仍给精确命中 + 可复制邻行。写工具参数解析失败 → 过程线人话提示改完整写入或按锚续写，模型回执保留技术细节；连续失败**不**停用写文件（`force_segmented` 只留笔、不摘工具表）。空必填参数（如 `str_replace` 空 `old_string`）仍为 `contract_failure`，但指纹收敛为稳定 sentinel，使 REPEATED_FAILURE / validation streak 能收口（禁止靠换 path/new_string 刷空参）。CEO 识别用户粘贴的旧「参数不是合法 JSON」报错时禁教转义。否决：第三把写笔 / 骨架填空专收 append / 成篇后禁 append 硬闸；失败回执用单行模糊满分冒充整段已匹配；再立独立成文落盘 Skill / 并进表格落盘或交付环境。→ 见代码：`tools/builtin/file_ops/` · `runtime/engine/tool_exec.py` · `runtime/loop_controller.py`

**工具参数契约（✅）**：LLM tool-call `arguments` 恒为 JSON **字符串**；协议渣预清洗后走唯一解析点 `parse_tool_call_arguments`：`json.JSONDecoder().raw_decode()` 接受完整值后的尾部多余字符；EOF 截断闭合对所有工具通用。失败按统一分型 `parse_class`∈`truncated|escape|other`（sanitize **后**计算；不确定归 `other`），回灌与熔断文案**只读 class + 工具族**——禁止截断场景教「原样重发全部」、禁止靠「是否写工具」猜根因。族策略：landing＝长文落盘姿势（截断改短或按锚续写/不停笔）；orchestration（`delegate`/`ask_user`）＝禁双包 + parse-only 不停用；handoff 无参数、不走字段 salvage（**禁**再按工具打第三条 salvage、**禁**通用 JSON repair 黑盒）；解析失败一律不改写参数，走 `args_parse_failed`。memory（`remember`）＝独立 `MEMORY_TOOLS` parse-only 不停用（勿塞进 dispatcher 用的 `ORCHESTRATION_TOOLS`）；截断→完整一句/分次，转义→修引号。`remember` 内容完整性：中段命中 omission 字面、或 `add`/`replace` 的 content 以 `…`/`...`/`……` 收尾 → **拒写入**（半截规则不得进库）。日志 `tool.args_parse_failed` 带 `parse_class`。→ 见代码：`runtime/engine/tool_exec_args.py` · `tool_exec_call.py` · `tool_protocol_sanitize.py` · `runtime/loop_controller/` · `tools/builtin/remember.py`

**工作区 Office/PDF 读（✅）**：`file_read` 对「看一下文件」交**观察信封**（成功结果），不是失败作文。docx（python-docx 段落+表，抽到字符顶即停）/ pdf（`start_page` 开窗、每窗约 40 页走 pdfminer；仅第 1 页窗抽失败才 markitdown）/ pptx·odt·rtf 与附件预解析同一核、可杀子进程。抽取闸是**抽出字符 + 墙钟约 12s**，不是整文件 5 MiB 入场券。摄入三闸分开：磁盘后端（sidecar / 云盘）**100 MiB**；过桥 `LocalWorkspace` IPC **25 MiB**；用户上传 / `download_url` **50 MiB**。sidecar / 云盘父进程只 stat，抽取子进程按路径打开；过桥仍走通道 `read_bytes`（桌面 Node 无 Python 抽取栈）。嗅探误后缀 / OLE 取 size 走 `read_head`（头字节 + 总大小），不走整文件闸。超时 / 扫描件 / 旧版 `.doc` OLE / 抽失败 / 超摄入顶 → 成功信封（`kind`: extract / scan / binary / truncated），`next` 指向 `read_image` 或按文件名归类，**禁止**「请用户转文本 / 提供更小文件」。抽出成功仍走现有编号窗口；PDF 页脚写明本窗页码，后面的页用 `start_page` 再读（`offset`/`limit` 仍是本窗文本行号）。`start_page>1` 不读旁路 `*.md`（旁路只覆盖首页窗）。xlsx/csv 不抽全文，同样成功信封。读时默认不写 `*.md`。文案不提抽取库、不教 `run` 硬解 Office。文本整读仍 5 MiB，超限才是 `too_large` 失败。→ [双模式 §七](/docs/02-架构/双模式工作区.md) · 见代码：`tools/builtin/file_ops/observe.py` · `workspace/file_kind.py` · `workspace/attachment_parse.py`

**工作区 zip 解压（✅）**：大包持久展开主路径 = `archive_extract`（工作区 zip → 指定目录；zip-slip 拒；Local/云同形直写）。**禁止**假定「仅沙箱内解压成功 = 工作区已可见」。写路径 sanitize **保留**有意义前导 `_` / `.`（如 `_inventory`）。→ 见代码：`tools/builtin/archive_extract.py` · `workspace/_paths.py`

**工作区 zip 打包（✅）**：子树持久打成 zip 主路径 = `archive_create`（工作区文件/目录 → 指定 `.zip`；Local/云同形直写；与 `archive_extract` 同族 consult）。**禁止**假定「仅沙箱内打包成功 = 工作区已可见」。→ 见代码：`tools/builtin/archive_create.py`

**约定文档写路径扁平（✅）**：`AgentCore/文档/{research,reviews,debate}/` 与 `工作稿/` 下嵌套段压成单文件名（`/`→`_`）；`file_write` / `file_move` / `file_copy` / `file_batch` 同形。规范化后源≡目标 → 幂等成功（非错误）。任务书 `artifacts`、对账、下游前置指针按落地名认。契约说明 → [双模式 · 约定文档](/docs/02-架构/双模式工作区.md#四约定文档目录约定)。→ `workspace/_paths.py` · `tools/builtin/file_ops/`

**工作区结构化下载（✅）**：`download_url` = HTTP(S) URL → 工作区相对路径落盘（`WorkspaceBackend.write_bytes`）。大小闸对齐用户上传顶（`workspace_upload_max_bytes`，约 50 MiB），**勿**与 AI `file_read` 5 MiB 读闸混淆。SSRF 复用 `core.net.classify_url` + 逐跳重校验 + `PinnedIPTransport`（与 `web_fetch` 同政策）。审批 `GRANTABLE`（FILESYSTEM 写副作用；少打断下走既有 `file_write=session` / turn grant 轴）。安装包扩展名/MIME **允许落盘并标明**，不执行、不静默安装（≠ 桶4 装软件）。边界并列：用户面板 upload = 人推文件进工作区；`git` 浅克隆 = 仓进工作区；本工具 = 单文件 URL 拉取。落盘到工作区仍用本工具（大小闸 / 安装包标明）；guest 内 HTTP 与本工具同 SSRF 政策。正文深读仍用 `web_fetch`。→ 见代码：`tools/builtin/web/download_url.py`

**`web_fetch` / `file_read` 入参互斥（✅）**：工具保持拆开。`web_fetch` 仅 `http`/`https` 公网页；工作区相对路径、`file://`、盘符误喂不抓取、改道 `file_read`（`policy_failure`，不计网页深读熔断）。**禁止**给路径补 `https://` 再抓公网（文件夹名可长得像域名）。反向：`file_read` 收到 `http://`/`https://` 开头的 path 改道 `web_fetch`（`contract_failure`）；`http_client.py` 这类文件名不是 URL。不扫用户原文猜「这是文件」、不拦 GitHub URL。→ 见代码：`tools/builtin/web/web_fetch.py` · `tools/builtin/file_ops/read.py`

**`file_read` 区间视图（✅）**：默认整读（省略 `offset`/`limit` 读到 EOF 或安全顶）。安全顶 = **2000 行或 8 万字符**（磁盘原文，先到先停、完整行；单行超字符顶则整行留下）。未截断页脚「全文 N 行」；安全顶「第 a–b 行，共 N 行；已达行顶/字符顶」；自愿开窗且未达安全顶「第 a–b 行，共 N 行；未达安全顶，省略 limit 可整读」。**禁止**静默丢尾、**禁止**在正文插入通道头尾省略、**禁止**把安全顶做成 4k 头尾裁。`ToolResult.output_limit` 覆盖整段视图。通道/预算截断标记（`[系统视图截断·非磁盘内容]`）与交付残缺标记（「中间省略…」）**语义拆开**；`tool_clear` 摘录标明磁盘未截，**不等于**文件被切。教员（`file_read` / `grep` / `code_search` / 审查纪律）同向：定位用检索，单文件默认整读，仅页脚已达安全顶或已有行号时开窗。超 5 MiB 磁盘闸禁止再教 `offset`/`limit`（分段仍先整文件入内存）。`read_folder_file` 保持 500 行轻量抽样，不继承本顶。当轮堆叠税由 `tool_clear`（`keep_recent=2` 轮；一轮并行多读都留；**「全文 N 行」不进清理**）投影 → [执行引擎 · 回合内 tool_clear](/docs/03-AI核心/执行引擎架构设计.md)。

**`glob` / `file_list` / `grep` / `code_search` 定位（✅）**：职责拆开，不是换名。不知目录时从工作区根搜。**`glob` = globstar**（与 Cursor Glob / Claude Code Glob 同类）：无斜杠按 basename 任意深度（`*.py`）；有斜杠按相对路径（`src/*.py` 一层，`pkg/*/name` 一层子目录，`src/**/*.py` 递归，`**/name/**` 任意深度该目录下）；`*` / `**/*` 在深度顶 8 + 命中预算内递归列举。`path` 可省=整仓；`directory` 与 `path` 同义；`path` 不是目录时从根按该段目录名（或同一 pattern）续找，回执诚实说明，不红。回执扁平相对路径、不是树。**已知目录一层**走 `file_list`（无 pattern；残留 `pattern`/`recursive`/`max_depth` 失败并改用 `glob`）。当前出生桌列目录 / 读文件走通用 `file_list` / `file_read`，不必先 `list_folders`。`file_list` / `glob` 按文件名列出图片（png/webp 等）；`grep` / `index_files` 仍跳过像素与其它 AI 噪音（列名 ≠ 进检索）。编译产物与工作区根压缩包仍不进列表（区外压缩包 / `*.zip` glob 豁免不变）。`grep` / `code_search` 省略 path 默认整仓（内容 / 概念）。`list_folder_dir` 只给 CEO 派前轻量认**另一张桌**（一层；跨桌按名找走 `delegate`），不是工作区按名查找、不是跨文件夹摸底主通道。→ `file_ops/` · `grep.py` · `code_search.py` · `folder_fs.py`

**同轮并行 `file_read` 去重（✅）**：同一模型轮内 key = path + 有效窗，重复调用只执行一次。否决同 path 次数天花板（误伤迭代改稿；税由 `tool_clear` + 单次安全顶 + 本去重管）。→ 见代码：`runtime/engine/tool_exec_coalesce.py`

**确定性导出 Word/PDF（✅）**：`md_to_docx` / `md_to_pdf` 把工作区 `.md` 导出为同目录同名 `.docx` / `.pdf`（共享 `docs_export`；PDF 引擎 fpdf2）。用户要「PDF / 可分享」时成文主路径 = 落盘 `.md` → `md_to_pdf` → handoff；**禁止**多份 HTML 顶替 PDF，**禁止** `run`+reportlab 做主路径。云 = 本地同能力。→ 见代码：`docs_export/` · `tools/builtin/md_to_docx.py` · `tools/builtin/md_to_pdf.py`

**FILESYSTEM 容量合同 ≠ 活性超时（✅）**：文本整读字节顶（5 MiB）/ 行 / 条目触顶 → 早失败 `contract_failure`（`too_large` 等）+ 可执行下一步（不计工具熔断累计）。Office/PDF **抽取**墙钟约 12s 或无文本层 = 成功观察信封，不是合同失败、不是通道活性挂起。墙钟只表示通道/协程**活性挂起**（文案禁原样重试；仍计熔断，steer 强调缩小范围/换策略）。云 `ServerWorkspace` 文本整读上限与桌面 Local `WORKSPACE_READ_MAX=5MiB` 对齐；过桥抽取摄入 `WORKSPACE_EXTRACT_SOURCE_MAX=25MiB`（IPC）；磁盘抽取 `OFFICE_EXTRACT_DISK_MAX_BYTES=100MiB`；上传 50 MiB。三闸不许绑死。Local 通道 deadline **由外层工具活性预算派生**（非第二套独立 60s）；`timeout_ms` 下发桌面 AbortSignal，迟到 settle 仍 stale no-op。单次 settle 超时只失败该 op。履约流断开时桌面已在跑的文件通道 op 立刻失败（「桌面在重连，请再试这一下」），不算连不上；尚未投到桌面的仍走 reconnect grace。文件连不上只认履约在场（桌面未连接 / 未持根 / 发起设备离线），不认超时次数；桌面重新连上后恢复文件工具与写盘派工。用户可见句：「工作区/本地文件连不上，请稍后重试或重开桌面」；写盘派工硬拒。本机执行环境失败不粘性收走 `run`（新队员仍能看见工具）。通道有界并发（默认 16）：仅约束 Local `WorkspaceChannel` 同时 await 桌面的 op；超额排队（计入外层墙钟）——云盘/`workspace_lock` 不动。**过桥 settle（✅）**：云 `interactions` POST 带墙钟；桌面对 `NetworkError` / 5xx / 429 **进程内短重试**（仍在服务端 op 预算内）；重试耗尽才记 fail，并强制 SSE 走 transport-drop → rejoin，避免「本地已算完、settle 毛刺当连不上」与后续 `workspace_op` 无人履行。→ 见代码：`workspace/limits.py` · `workspace/channel.py` · `runtime/tool_deadline.py` · `runtime/engine/tool_exec.py` · 桌面 `clientToolFulfill.ts` · `interaction.ts` · `streamConversation.ts`

## 四B、本机 Host（第三能力面）✅ 单工具 `host`

|---|---|---|---|

## 四D、Git 闭环 {#git-闭环}

> **产品心智**：结构化 `git` = Agent 工程工具；用户 SCM = 会话旁版本面板。两边同一工作区仓；**回合 zip 基线**仍是「本回合可回滚」主路径，与 git **正交**（不合并语义、不做三方 merge UI）。主路径禁止教模型用 `host(action=shell)`/`run` 自由敲 git 当闭环。凭据：**人配置、进程继承、失败诚实**——工具永不收密码参数。→ [安全 · git force 统一 DENY](/docs/05-平台与运维/安全权限与治理.md) · [前端 UX · 改动双轨](/docs/04-前端/前端UX设计.md)

现行面：`status`/`diff`/`log`/`show`/`blame`/`add`/`commit`/`branch`/`checkout`/`fetch`/`pull`（ff-only）/`push`/`stash`/`merge`/`rebase`/`cherry-pick`/`tag`/`remote`/`clone`/`create_pr`（GitHub-only）/`init_baseline`。push / 开 PR 恒确认。force、保护分支、`reset`/`clean`、stash drop/clear、remote remove、tag 删除硬拒。pull 冲突诚实停。**工具** `git clone` 仅 GitHub http(s)；**UI** `clone_repo` 为任意 http(s)+SSRF。`create_pr` 仍 GitHub-only。私仓账户级 PAT（设置 · Git 凭据，AES-GCM）；Local 继承 OS credential helper / `gh auth`；认证失败指向「去设置凭据 / 打开已配置凭据的本地仓」。Local 通道：ServerWorkspace / Sidecar 同进程 subprocess；LocalWorkspace 经桌面 `git_run`（闭集 op，与 UI 的 `git_repo_status`/`git_scm` 分立）。有 `local_subpath` 时 cwd/探测/`init_baseline` 均落该文件夹子目录（与 file_* 同基准，禁止打到共享容器根）；无 subpath 则根即该文件夹。

| 面 | 要点 |
|---|---|
| 用户 SCM | 分支+dirty 条 →「改动」双轨（zip ∥ git 列表）→ 人可 stage/commit/push/pull，与结构化 git 同口径 |
| 同仓串行 | 按仓串行会写 index 的子命令；只读与 `push`/`create_pr`/`branch`/`tag`/`remote` 不排队；等不到报 `repo_busy` |

**否决**：AI 代持密码；改动 tab 冒充三方冲突工具；默认放开 hard reset / force 保护分支；全局 git 锁（不同仓库/工作区互相排队）。→ 见代码：`tools/builtin/git_ops/`（`repo_lock.py` · `policy.py` 超时表）· `workspace/channel.py`（`GIT_RUN`）· `workspace/git_credentials.py` · `workspace/github_pr.py` · `runtime/safety_breaker.py` · `runtime/approvals.py` · 桌面 `main/fs/workspace/gitRun.ts`

## 用户技能与可编目录 ✅ {#用户技能与可编目录}

> **主循环归属**：**组**（CEO `consult` 看见的那份目录）+ **记**（文件夹设定仍沿近的覆盖远的）。跨用户货架 → [能力商店](#能力商店)。

已确认并落地。账号级「我的技能」加成 `<按需目录>`；官方 HOW 只读（代码真源，不占槽、不搬家）。出厂工具与本机插头并进提示词目录（一块「工具」货架 / 按需「官方」区）。开口仍是一句话：配置发生在工具箱，不摊进「说」。

**三面怎么打开**

| 面 | 用户可配 | 仍只读 |
|---|---|---|
| 技能 | 基座 `on_demand` 条目：加成新目录行（名字 + `description` + 正文） | 系统薄技能代码真源；全员准则 / 角色身份；官方 HOW 不开放改 / 换 / 搬家 |
| 工具 | 连接器增删启停；提示词目录工具块「连接器」接线（不把插头报出的动作再铺一层） | `DECLARED_TOOLS`；不开放注册内置级工具；不按名卸掉某个内置工具（权限轴已管写盘 / 命令 / Host） |
| 目录 | 人侧：加或编「我的」行并切常驻·按需 | 模型仍只吃一份 `<按需目录>`（`name` + `description`）；`GET /v1/capabilities` 仍是部署级图鉴，不是用户配置真源 |

**官方 HOW 不是用户资产。** 系统薄技能的 `name` 仍是运行时槽位（工具 schema 写死 `HOW→consult(ask_kickoff)` 等），正文只出厂。不喜欢某一条 → 写偏好或「我的」，不能卸能力、不能把用户稿接到官方槽。

**存储。** 用户技能是普通基座条目，不新建 Skill 表、不把系统 Skill 搬进 DB。协作桌成员吃这张桌文件夹层的设定；账号层「我的」仍私有。

**人侧。** 工具箱「提示词」是一本目录（不是「我的页」），账号层，不钉回 `/files`。画布货架概览，无左栏文件树。常驻 / 按需是提示词怎么进模型的主轴：叶子铺成 `CatalogTile`（全员准则 / 角色身份只读；偏好 / 画像锁在常驻里；用户常驻可写、可拖走）。按需区竖向：**新建空卡 → 我的夹 → 官方**。用户夹是区标题，包住我的 / 市场卡（名字 + 触发语进 `<按需目录>`，`consult` 才拉正文）。未入夹的按需进「其他」。官方 HOW 收进按需 **官方** 区（仍按需、只读、不能拖、不从树上删除；registry 的 `group` 不投影成夹）。出厂工具与连接器不骑两轨，跟在按需后面单独一块「工具」（按能力面分组；连接器区含添加空卡；点开弹窗接线；不把插头报出的动作再铺一层）。开场即用 / 查阅后启用写在卡上与读卡标题旁，不是两个投放区；出厂工具拖不动。读 = 居中 Dialog。点卡直达正文，弹窗不再出夹名单（`?tool=` / `?connectors=1` 同样直达）。官方 HOW / 准则只预览；我的默认源码（名称 / 一句话 / 正文，停敲自动存），可切预览。出厂工具第一面是说明书，源码才是 schema。点开后的标题徽标只标来源：**官方** / **我的** / **市场**（工具卡标开场即用 / 查阅后启用；行上不标常驻/按需）。市场装来的不改姓成我的。「新建条目」默认进刚建的夹，否则进「其他」；新建条目 / 新建夹是按需区格子里的空卡；空夹是「拖到这里」。换档 = 拖到常驻区或拖进某一夹的区（弹窗里不提供常驻\|按需开关；右键不列搬家）。我的 / 市场不要了就删。上架只接受自己写的、夹里的文件。工具箱不提供停用。纠错（这条不对）只在文件页、且只给 AI 维护的记忆。不要把 `<按需目录>` 做成整块 XML 文本框。不要把记忆做成与常驻 / 按需平级的第三区——核是常驻、主题是按需。最近学到入口在常驻区头，不是货架卡。

落地触点 → `api/routes/skill_catalog.py` · 工具箱 `PromptCatalog`（人侧只改账号层；出厂工具与连接器同树）· `ConnectorsPage`（提示词目录 helper，不是独立页；桌面 `listServers` 本地合并，**不**写入 `GET /v1/capabilities`）。条目形态 → [记忆 · 目标形态](/docs/03-AI核心/Agent记忆与知识系统.md)。工具箱壳 → [前端 UX · 工具箱](/docs/04-前端/前端UX设计.md)。

## 能力商店 ✅ {#能力商店}

> **主循环归属**：**组**——工具箱货架给 CEO 的 `<按需目录>` 增加可安装的域级 Skill。形态仍是工作台，不改称生态平台 → [定位 §四](/docs/01-产品/产品定位与品牌.md)。

与 ✅ [用户技能](#用户技能与可编目录)（账号层「我的」；文件夹层是设定）正交：那边是自己写；这边是陌生人上架与一键安装。平台官方法律货是代码合成进货架的，不占 listing 表。

**第一刀只卖 Skill。** 上架对象 = 用户技能那类基座条目（名字 + `description` + 正文）。全员准则 / 角色身份仍只读、不许上架。Agent 不是 SKU。Tool 仍只走 MCP，不进货架。Rule / Memory / Team **不上架**（否决按其做远期，不是「第一刀之后再做」）。

**后端货架 API ✅**（`/v1/skill-store`，须登录；admin 下架 / 举报队列 `/v1/admin/skill-store`）。工具箱壳 ✅（桌面 `/toolbox/market` + 自己写的提示词上架；admin `/store`）。工作流第二刀 ✅ → [第二刀](#能力商店-工作流)。

### 上架（开放）

自己写的提示词可 **上架**：把当时的名字、`description`、正文、场景分组打成 **版本快照** 送进公开货架，无预审。分组是闭集（法律合规 / 写作成稿 / 研究调研 / 产品商业 / 开发工程 / 决策对抗），上架必拣一组；只给人逛货架，不投影进提示词树、不进 `<按需目录>`。之后改草稿不影响已上架版本；再上架 = 新版本（可改组）。下架只下 listing（`unpublished`；平台 `taken_down`），已安装副本仍在各账号。公开列表只 `published`。

### 安装（一键 · 快照复制）

入口在工具箱 **市场**（桌面；窄屏不上工具箱故不上）。点卡片出居中 Dialog：先见 `description`（装进去之后咨询目录会看到的那句，与标题重复则不铺），正文直接展示。主 CTA **安装** = 把该版本快照复制进提示词目录（徽标「市场」），立刻进 `<按需目录>`。壳 → [前端 UX · 工具箱](/docs/04-前端/前端UX设计.md)。

不绑：作者后续改稿不活跟随（有更新则再点一次）；删掉已装副本即卸装，货架回到可安装（不显示已装 / 有更新）。不改官方 HOW；不摊进「说」。

新实体只三件（现有基座条目盖不住跨用户发现）：**listing**、**version 快照**、**本账号安装记录**（指向那条本地文档）；另加 **reports**。不新建 Skill 表、不把系统 Skill 搬进 DB、不复活 Agent 版本当货架单元。注销级联 listing / installs / reports，已装副本不删。

信任（开放上架 = 无预审；Skill 正文经 `consult` 进模型）→ [安全 · 能力商店](/docs/05-平台与运维/安全权限与治理.md#能力商店开放上架)。壳 → [前端 UX · 工具箱](/docs/04-前端/前端UX设计.md)。→ 见代码：`api/routes/skill_store.py`

### 第二刀：工作流 ✅ {#能力商店-工作流}
