## 一、Tool / Skill / Rule 边界

| | Tool | Skill | Rule |
|---|---|---|---|
| 是什么 | 副作用 / 读写 / 需审计 | HOW 教法（按名拉取） | 行为约束（进 `<rules>`） |
| 装配 | 声明式 `ToolRegistration` → registry | 系统 Skill 常备目录；市场 Skill ⏳ 绑定后进集 | Document `role=rule`（见 [记忆系统](/docs/03-AI核心/Agent记忆与知识系统.md)） |
| 注入 | 常驻工具 = 每轮 LLM function calling；低频工具仍注册，schema 改列同一 `<按需目录>`，`consult(name)` 后**本回合下一模型轮**进工具表（≠等用户再发一条；未进开场表 ≠ 能力行未装配） | ≤阈值全文；超阈值 = 按需目录 + `consult` | 用户规则 always → `<rules>`；on_demand → 同一按需目录 + `consult`（`conditional` reserved） |

**Skill / Rule 两列合并**：读侧已合（✅ 步 1）——`<能力目录>` / `<规则目录>` / `<记忆主题目录>` 撤销为单一 `<按需目录>`，三个 consult 工具收敛为 `consult`。⏳ 剩存储侧：条目化后二者都是带 `description` 的 md 条目（步 2），Skill 从代码搬进 DB 是第 4 步。Tool 一列不变——有副作用、有 schema、有权限轴，刻意不与条目共享基类。低频工具只是**骑同一目录**：固定名册 `tools/on_demand.py`（非意图分类器）+ 动态发现的 `mcp_*`（同一 `is_on_demand_tool` 闸，不进开场 FC 表），catalog / execute / skill 门控仍看注册表。→ [记忆 · 目标形态](/docs/03-AI核心/Agent记忆与知识系统.md) · [上下文工程 · 扳机 A](/docs/03-AI核心/上下文工程.md)

**单源**：现状 = 固定注册内置工具（`DECLARED_TOOLS` 名册，见 [扩展点 §一](/docs/03-AI核心/扩展点清单.md)）。规划中的统一绑定层 `AgentEntityBinding` **⏳ 暂不启动**——它属生态市场面，全仓无该符号，勿当既有实现引用 → [定位 §四](/docs/01-产品/产品定位与品牌.md)。运行时只读「本地侧」，不碰市场侧。Skill 永不自动注入工具（仅 `suggested_tools`）；系统 vs 市场 = 两类来源、同一 `SkillRegistry` + `consult`。

**表达形态 ≠ 工具**：mermaid / markmap / vega-lite = 直写代码块 + 前端渲染；需持久可编 → 创作产物。

**协议**：MVP = 内部 `Tool` Protocol + OpenAI FC；**MCP Client** ✅（→ [§四C](#四c本机-mcp-client)）。审批 `never`/`grantable` → [安全 §三](/docs/05-平台与运维/安全权限与治理.md)。CEO/worker 分集 → [执行引擎 §五](/docs/03-AI核心/执行引擎架构设计.md)。

→ 见代码：`tools/registration/`、`runtime/skills/`、`tools/catalog.py`

## 二、引用质量闸

`web_search` / `read_url` 双通道：**来源卡**（`citations_event` = 成稿实际引用）与**回合证据台账**（除 `blocked` 外全量登记）。档位单源 `citation_tier_for_url`——禁第二套分级器。

| 档位 | 来源卡 | 台账登记 |
|---|---|---|
| `blocked` | 出口剔除、永不挂卡 | **永不进** |
| `weak` | 仅成稿 `#rN` 引用时挂卡 + 弱源徽标 | 登记宽、`citable=true` |
| `official` / `media` / `unknown` | 同上 | 登记宽 |

- **登记仍宽 / 成稿闸窄**：台账除 `blocked` 外均可登记；成稿 `#rN` 闸 = `deep_read ∪ selected`（对齐辩论 `commit_research` 精神）。search-only 默认不得进成稿闸；`finish_guard` / settle reconcile 用 draft 子集，不用全量 `citable_ids()`。例外：`AgentCore/文档/research/*.md` 成功落盘时，正文已引用且可登记的 `#rN` 升为 `selected`（供 CEO 汇总继承队员笔记引用；伪造/越界仍不过闸）。仅 search-only 引用落到收口时，引擎会自动 `read_url` 升级台账再验——**机制与上限权威 → [执行引擎 · `finish_guard`](/docs/03-AI核心/执行引擎架构设计.md#finish_guard)**（勿在本文复述）。本文只钉一条工具侧不变量：无论升级成败，**成稿可引用集的定义不放宽**。
- **`selected`**：settle 时正文实际引用且已 `deep_read` 的 id 持久标 selected；调研方向笔记落盘亦可 promote（见上）；跨回合 hydrate 保留。可选 `doc_kind`（登记时可写；否则 title/snippet 启发式）。
- **书目形态闸**：正文以学位论文/期刊式著录绑定 `#rN` 时该 id 须 deep_read；元数据呈开题/答辩/公告类 → 回炉（禁域名黑名单）。无 `#rN` 绑定的 GB/T `[D]`/`[J]` 著录亦回炉。台账接通时，**worker 合同闸**对内容类落盘文件复用同一套 `citation_quality_reworks`（与 `finish_guard` 同源）；调研 `research/*.md` 遇未绑定书目时不再文末补脚注装锚。
- **调研两阶段引用**：**只认** `citation_mode=two_phase`（playbook/CEO 盖戳）→ 阶段 A 草案**不**跑成稿引用闸；同 worker 升 B 后再验；未声明退出。draft 不进 `delivery_status.artifacts` 主清单。**路径入口已撤**（原「落盘/声明路径在 `AgentCore/文档/research/` · `reviews/` 即算调研类」）：那个落点由扫 role·task 的正则填出，是隔一层的自由文推断；即兴委派要成稿级引用验收须自报 `citation_mode`。→ 见代码：`runtime/runs/research_quality.py:is_two_phase_citation_deliverable`
- **跨回合 hydrate**：新回合 `#r` 台账从历史 assistant `evidence_ledger` 合并进引擎核；LLM history 可不带 ledger 全文。
- `search_policy`：per-run 结构化信号（禁 prompt 触发）；`debate_evidence` 额外硬剔 weak / 商城词典等。
- 前置：query 词数/CJK 加权上限（超限可机械规范化并明示；无法规范化才拒）；CJK 查询剔无 CJK 命中；缓存键 casefold + 拉丁词序归一。
- 名单无真实分布依据——以合成样本校准（目前无真实数据，以下为假设）。

→ 见代码：`runtime/citations.py`、`runtime/evidence_ledger.py`、`tools/builtin/web/`

## 三、沙箱

代码执行：subprocess + `SandboxProvider`；云端 gVisor（**默认开**；紧急 `GVISOR_ENABLED=false`）——禁网默认、产物 copy-in/out；sidecar 保留 subprocess。能力行拆 `code_execute=`（形状 A `--rootless`）/ `package_install=`（形状 B，与 `browser=` 同 `sandboxd` 探针）。→ [安全 §五](/docs/05-平台与运维/安全权限与治理.md)、[部署拓扑 · 云端执行](/docs/05-平台与运维/部署拓扑与环境.md#云端执行gvisor)

`browser`：工具装配与共控行为（本文）；**产品壳 / partition / 页签** → [前端技术 §9.12](/docs/04-前端/前端技术与架构.md)。统一 BrowserSession——单一工具 `browser(action=navigate|click|type|scroll|snapshot|console|screenshot)`；**`navigate` / `click` / `type` / `scroll` / `snapshot` / `console` 为 CEO+worker**（与 `host(action=shell)` / 本地 `terminal` 并列；captain 直调尽量不弹审批）；**`screenshot` 仍 worker-only**（视觉验收）。宿主分流（`browser_host_kind_for`，整会话单一 host，禁 local+sandbox 混绑）：**健康 DesktopBrowserBridge → Local**（Electron `WebContentsView`；仅 `action=type` 借 CDP `Input.insertText` 打真实输入、用后即 detach，其余动作仍走 `executeJavaScript`）；**无 Bridge 但 gVisor 形状 B（`sandboxd` net 探针）健康 → Sandbox**（覆盖大众默认云端过桥：`location=local` + `via=cloud`，云 API 够不到本机 loopback）；**`location=server` / Web / 无 Electron → 仅 Sandbox**（地址栏 create+navigate，拒本机 localhost）；真·本地引擎无 Bridge 且无 gVisor → 未装配（禁假成功）。**禁止**以 Bridge loopback 冒充云可达。**定案 A**：云端看浏览器 = Linux API 上 Sandbox 跑通；Windows 本机 API 狗粮云工作区预期不装配——验收口径 → [部署拓扑 · 云端执行](/docs/05-平台与运维/部署拓扑与环境.md#云端执行gvisor)。`action=console` 返回会话内环形缓冲：页面 console 消息 + pageerror/未捕获异常（Sandbox）或 console-message + 主框 did-fail-load（Local）；硬上限截断，禁止回传密码/超大 blob——修码白屏定锚用，**不**硬闸「没 console 不许 patch」。AI 永不经手密码（password 硬拒 → worker：`escalate(browser_login=true)`；CEO：`ask_user(browser_login=true)`）。用户明确「右坞打开 / 浏览器打开 / 帮我看页面 / 短搜短点」时 CEO 自己调 `browser`（勿为此 delegate；「随便搜」省略过重验收）；截图验收仍可 delegate。mutation（navigate/click/type/scroll）成功结果含当前 `snapshot_version` **与新 ref 表**（`untrusted_web_content.elements`，Playwright MCP 同形）。**动作回执是后置条件、不是装饰**：`type` 回 `typed{requested_chars, actual_chars, matched}`、`click` 回 `clicked{was_disabled}`，不满足即 `success=False`（`postcondition_failed`；证据仍留在 output 供改策略）——「执行器没抛错」与「动作真生效」是两回事：`el.value=` 直写会被 React `_valueTracker` 吞掉 onChange，受控组件形同没填，旧实现却照样回 ok。快照对表单控件把 `placeholder` 与 `value` **分列**（旧取值链 `aria-label||textContent||placeholder||value` 让带 placeholder 的输入框永远看不到 value），并附主区域可见正文摘要 `visible_text`（纯文本气泡不进 ref 表，否则「消息是否已发出」不可观测）。三处缺一模型就只能猜，并倾向顺着用户口风给结论。回合内发模型前投影只保留最近一次完整 elements/aria（更早字段级 `omitted`，canonical/journal 仍全文），折叠时补 `ref_delta{added, removed}` 顶替被裁掉的前后对比。`complexity_hint=light` 不再盖短 `max_rounds`，浏览器路径不再依赖「勿 auto-light」规避。

**打开本会话 HTML 站点（定案 · 甲 + 乙降级）**：仅 **host_kind=local**（真·Bridge）时 `browser(action=navigate)` 支持 workspace 相对 HTML 路径，走与用户产物「完整预览」同源的 `workspace://`（该对话的 workspace partition；URL host 须等于 partition 绑定 cid）；打开后可继续 click/type/snapshot。公网 URL 仍走该对话的 web partition（按 `conversation_id` 切开，不与其它对话共享 cookie）。**Sandbox（含过桥无 Bridge 回落）** → 相对路径诚实失败（引导点产物完整预览），禁止假成功。→ 见代码：`tools/builtin/browser.py` · 桌面 `browser/host.ts`；产品蓝图 → [前端技术 §9.12](/docs/04-前端/前端技术与架构.md)

### 写码验证双环（内环诊断 / 外环门禁）✅

行业对齐：改码循环用**语言服务增量诊断**，交付验收才跑**全量项目 CLI**。禁止把全仓 `tsc` 当修码自检、禁止靠盲加超时掩盖误用。

| 环 | 工具 / 机制 | 用途 |
|---|---|---|
| **内环** | `code_diagnostics` + 写盘成功自动附加 | 本地 TypeScript LanguageService（桌面 `WorkspaceOp.diagnostics`）；按改动路径秒级反馈。云端 / 无 LS → 诚实 `unavailable`，**不**用全仓 `tsc` 冒充。不计入外环验绿 |
| **外环** | `test_run` | 验收员 / task·`playbook_args.verify`：install · test · typecheck · build · 显式 command。超时分两类：**idle 挂起**（长时间无输出）→ `exec_timeout`、执行环境家族停用；跑满**灾难顶安全网**强制中止 → `exec_forced_stop` / `contract_failure`（**不算工具家族熔断**）。真实执行首次失败才分类：退出码 127 / 找不到解释器、或启动被拒（EACCES/EPERM）才停用，范围随语言——python 连带停 `test_run`（它把每条 check 都包成 python 脚本），其它语言只停自己；执行超时**不停用**（用户代码慢或机器抖动，不是环境不可用）。不起解释器的整后端判定（云 gVisor `runsc` 冒烟）仍停整族；同 run 连续 idle 超时满 2 次 → 停用 `code_execute`/`test_run`。均安静告知 |

外环超时（定案：**idle 挂起停用**为主，灾难顶为辅；**废弃**「300/600 验证预算」合同与「墙钟熔断」口径）：默认 **60s** 无 stdout/stderr 即按挂起中止（`install` **120s**）→ `exec_timeout`、计入执行环境家族停用；绝对安全网 **20min（1200s）** 强制中止 → `exec_forced_stop` / `contract_failure`（**不算工具家族熔断**）。云端 gVisor 时长 cap **1230s**（≥ 灾难顶 1200 + slack；`GVISOR_TIMEOUT_MAX_SECONDS`）。验绿诚实口径仍 = **落盘 ∩ 外环真绿**（✅ S3：引擎不再按 `completion_criteria` kind 硬判批次完成）。修码 playbook：靠角色提示 + `verify_policy` 分流（不再靠 `tasks[].tools` 白名单裁工具）；全量 typecheck 仅验收/外环。调查/审查角色默认 `verify_policy=inner`（结构化，非文案猜）：`test_run` 拒全仓 typecheck/build，改道 `code_diagnostics` / browser；验收员可显式 `outer`。→ 见代码：`tools/builtin/code_diagnostics.py` · `write_diagnostics.py` · `test_run.py` · `tools/sandbox/exec_env.py` · `runtime/runs/worker_budget.py` · 桌面 `fs/workspace/diagnostics.ts`

### 执行三分（短 / 有界验证 / 长驻）

| 面 | 工具 | 用途 |
|---|---|---|
| 短执行 | `code_execute` | 会很快自行退出的内联代码 / 短命令；硬顶仍短（≤60s）；同会话多 worker 的 `code_execute` 串行排队（`test_run` / `terminal` 不在此锁内）。读已有源码正文走 `file_read`，勿 dump 到 stdout |
| 有界项目验证 | `test_run` | **外环**项目 check（**install** / test / typecheck / build / 显式 verify）；流式输出仅在沙箱内跑的通道成立（subprocess / gVisor 读 `on_output`），桌面通道不转发回调、输出结束时一次性返回；超时 = **idle 挂起（60s/装包120s 无输出）** → `exec_timeout`、执行环境家族停用；或 **灾难顶 20min 安全网强制中止** → `exec_forced_stop` / `contract_failure`（验证未完成，**不算工具家族熔断**）。同 run 连续 idle 超时满 2 次仍会家族停用 `code_execute`/`test_run`；真实执行首次失败仅在硬证据（退出码 127 / 启动被拒）时立刻停用并安静告知用户，执行超时不停用。同 `execution_id` 内 sibling 相同验证（解析后 argv 指纹）**inflight 合流 + 结果复用**，避免双 worker 各烧满超时；任一队员成功写盘后 cache **失效**（generation 丢弃陈旧入缓存）。执行中 busy=`verify`（不挡 idle patrol / `cancel_worker`）。云端装包 = allowlist egress（netns + 代理）+ 包装源白名单 env + 拒改源旗（`--registry` / `--index-url` 等）；PM 白名单 = npm/pnpm/yarn **与** uv/pip/poetry（同纪律；纯 Python 仓 `check=install` 不落 npm）；持久工作区 rw-bind（install 例外），`node_modules` / `.venv` 落盘，短命沙箱不整树 base64 回传。本地装包 = 权限轴 + 钉源 env（不吃主机 `registry_egress_available`），装在用户绑定目录。无授权 / 云无 chokepoint → 诚实甲降级（结构自检 / export_to_local），勿空转。修码自检走内环 `code_diagnostics`，勿用本工具冒充内环 |
| 长驻 | `terminal` | 开发服务器等永不退出进程；`long_running` 分流保持；**CEO+worker**（仅 `location=local`）；schema `NEVER`，`start` 运行时升审批；CEO 限纯启/停/读，改码仍 delegate |

外环验绿（task / `playbook_args.verify`）**默认走** `test_run`。项目级慢命令（`npm/pnpm/yarn install|ci|test|build`、`uv sync` / `pip|poetry install`、`tsc`、`pytest`/`vitest`/`jest` 等）进 `code_execute` → **硬拒**并改道 `test_run`（与长驻改 `terminal` 同构；`contract_failure`，不进工具熔断；与已删 kind 正交）。装包闭环：`check=install` 或 `check=command` + 正规 install 形态（`--prefix`/`--directory`/`working_directory` 相对路径；禁 `cd&&`；禁裸 shell 冒充装包）→ 再 build/typecheck。真短脚本仍走 `code_execute`（≤60s）。云端沙箱 / GRANTABLE 与 `code_execute` 同级治理（`code_execution_enabled_for`）。

写工具 miss 回执分角色：CEO 面 → 须 `delegate`；worker 面工具已默认全开（含写盘），`form=prose` 只约束交付形态与进度催促（不要求 `str_replace`），不靠硬卸写工具。Local 破坏性删（`code_execute`/`terminal`/`host(action=shell)` 启发命中）→ 回滚主（回合 zip 基线）+ 窄闸辅；与 `file_delete` 软删分轨对齐 → [双模式工作区 · 脚本破坏](/docs/02-架构/双模式工作区.md) · [安全权限 · 熔断](/docs/05-平台与运维/安全权限与治理.md)。无 git 时上下文软提示 `git.init_baseline`（不硬拦开工）。→ 见代码：`tools/builtin/test_run.py` · `code_execute.py` · `project_verify.py` · `runtime/engine/tool_exec.py` · `workspace/destructive_fs.py`

**长文落盘（✅）**：【主路径】完整正文（含超长、无省略）一次 `file_write`（不硬拒字数）；成篇后修订只用 `str_replace`。`file_append` **仅**骨架填空路径（本 execution 已 prose 则继续禁 append）。骨架+分段可选（防截断/超大）。**成篇体量若含交付残缺标记**（「中间省略」「已保留首尾」等）→ **硬拒**（须一次写完完整正文，或骨架+SECTION 按节填）。写工具参数解析失败 → 过程线人话提示改完整写入或分段，模型回执保留技术细节；连续失败**不**停用写文件。同 path 连续 ≥2 次同类写硬拒（成篇后禁 append / 代码结构完整性拒）→ 合流 `force_segmented`：收窄 `file_append`，保留 `file_write`/`str_replace`（成篇后 str_replace 修订；整文件覆盖须完整正文）。空必填参数（如 `str_replace` 空 `old_string`）仍为 `contract_failure`，但指纹收敛为稳定 sentinel，使 REPEATED_FAILURE / validation streak 能收口（禁止靠换 path/new_string 刷空参）。CEO 识别用户粘贴的旧「参数不是合法 JSON」报错时禁教转义。→ 见代码：`tools/builtin/file_ops.py` · `runtime/engine/tool_exec.py` · `runtime/loop_controller.py`

**工具参数契约（✅）**：LLM tool-call `arguments` 恒为 JSON **字符串**；协议渣预清洗后走唯一解析点 `parse_tool_call_arguments`：`json.JSONDecoder().raw_decode()` 接受完整值后的尾部多余字符；EOF 截断闭合对所有工具通用。失败按统一分型 `parse_class`∈`truncated|escape|other`（sanitize **后**计算；不确定归 `other`），回灌与熔断文案**只读 class + 工具族**——禁止截断场景教「原样重发全部」、禁止靠「是否写工具」猜根因。族策略：landing＝长文落盘姿势（分段/不停笔）；orchestration（`delegate`/`ask_user`）＝禁双包 + parse-only 不停用；handoff 另保留裸字段加引号（**禁**再按工具打第三条 salvage、**禁**通用 JSON repair 黑盒）；解析失败一律不改写参数，走 `args_parse_failed`。memory（`remember`）＝独立 `MEMORY_TOOLS` parse-only 不停用（勿塞进 dispatcher 用的 `ORCHESTRATION_TOOLS`）；截断→完整一句/分次，转义→修引号。`remember` 内容完整性与写盘残缺标记对称：中段命中 omission 字面、或 `add`/`replace` 的 content 以 `…`/`...`/`……` 收尾 → **拒写入**（半截规则不得进库）。日志 `tool.args_parse_failed` 带 `parse_class`。→ 见代码：`runtime/engine/tool_exec_args.py` · `tool_exec_call.py` · `tool_protocol_sanitize.py` · `runtime/loop_controller/` · `tools/builtin/remember.py`

**工作区 Office/PDF 读（✅）**：`file_read` 对 docx/pdf/pptx/odt/rtf **透明抽文本**（复用附件预解析核；读时默认不写 `*.md`）；xlsx/csv 等不抽、改 `code_execute`。扫描件给明确 notice，不做复杂 OCR。→ [双模式 §七](/docs/02-架构/双模式工作区.md)

**工作区 zip 解压（✅）**：大包持久展开主路径 = `archive_extract`（工作区 zip → 指定目录；zip-slip 拒；Local/云同形直写）。**禁止**假定「仅 `code_execute` 沙箱解压成功 = 工作区已可见」。写路径 sanitize **保留**有意义前导 `_` / `.`（如 `_inventory`）。→ 见代码：`tools/builtin/archive_extract.py` · `workspace/_paths.py`

**约定文档写路径扁平（✅）**：`AgentCore/文档/{research,reviews,debate}/` 下嵌套段压成单文件名（`/`→`_`）；`file_write` / `file_move` / `file_copy` / `file_batch` 同形。规范化后源≡目标 → 幂等成功（非错误）。契约说明 → [双模式 · 约定文档](/docs/02-架构/双模式工作区.md#四约定文档目录约定)。→ `workspace/_paths.py` · `tools/builtin/file_ops/`

**工作区结构化下载（✅）**：`download_url` = HTTP(S) URL → 工作区相对路径落盘（`WorkspaceBackend.write_bytes`）。大小闸对齐用户上传顶（`workspace_upload_max_bytes`，约 25 MiB），**勿**与 AI `file_read` 5 MiB 读闸混淆。SSRF 复用 `core.net.classify_url` + 逐跳重校验 + `PinnedIPTransport`（与 `read_url` 同政策）。审批 `GRANTABLE`（FILESYSTEM 写副作用；少打断下走既有 `file_write=session` / turn grant 轴）。安装包扩展名/MIME **允许落盘并标明**，不执行、不静默安装（≠ 桶4 装软件）。边界并列：用户面板 upload = 人推文件进工作区；`git` 浅克隆 = 仓进工作区；本工具 = 单文件 URL 拉取。**禁止**教 `code_execute` / `terminal` / `host(action=shell)` 当 wget/curl 主路径；正文深读仍用 `read_url`。→ 见代码：`tools/builtin/web/download_url.py`

**`file_read` 区间视图（✅）**：默认整读（省略 `offset`/`limit` 读到 EOF 或安全顶）。安全顶 = **2000 行或 8 万字符**（磁盘原文，先到先停、完整行；单行超字符顶则整行留下）。未截断页脚「全文 N 行」；截断「第 a–b 行，共 N 行」并标明行顶或字符顶。**禁止**静默丢尾、**禁止**在正文插入通道头尾省略、**禁止**把安全顶做成 4k 头尾裁。`ToolResult.output_limit` 覆盖整段视图。通道/预算截断标记（`[系统视图截断·非磁盘内容]`）与交付残缺标记（「中间省略…」）**语义拆开**。教员（`file_read` / `grep` / `code_search` / 审查纪律）同向：定位用检索，单文件默认整读，仅页脚已截断或已有行号时开窗。超 5 MiB 磁盘闸禁止再教 `offset`/`limit`（分段仍先整文件入内存）。`read_folder_file` 保持 500 行轻量抽样，不继承本顶。当轮堆叠税由 `tool_clear`（`keep_recent=2`）投影 → [执行引擎 · 回合内 tool_clear](/docs/03-AI核心/执行引擎架构设计.md)。

**同 path `file_read` 天花板（✅）**：约束空转再读（`FILE_READ_SAME_PATH_MAX`；含双省、只传 `offset=1`、只传 `limit=行顶` 的整读）。开窗仅当本次请求行范围已被此前交付覆盖、且投影窗内仍有该 path 正文时计次；新范围分页不计次、不触顶。触顶且投影窗口仍有该 path 正文、又无再读授额 → **成功回短指针**（不灌全文、不 `contract_failure`）。正文已被 `tool_clear` 清理后的重读**不计次**；写成功重置计数与已交付范围并授核对读。计数器 **per-run**：worker / CEO / 续派 fork 时换新 ledger，禁止浅拷贝共用（并行审计同一文件会提前顶满）。同轮并行去重 key = path + 有效窗。**视图截断 ≠ 交付残缺**（见上节区间视图 / `core.text`）。→ 见代码：`tools/builtin/file_ops.py` · `tools/protocol.py` `isolate_file_read_ceiling` · `runtime/engine/tool_clear.py` · `runtime/engine/tool_exec_coalesce.py` · `core/text.py`

**确定性导出 Word/PDF（✅）**：`md_to_docx` / `md_to_pdf` 把工作区 `.md` 导出为同目录同名 `.docx` / `.pdf`（共享 `docs_export`；PDF 引擎 fpdf2）。用户要「PDF / 可分享」时成文主路径 = 落盘 `.md` → `md_to_pdf` → handoff；**禁止**多份 HTML 顶替 PDF，**禁止** `code_execute`+reportlab 做主路径。云 = 本地同能力。→ 见代码：`docs_export/` · `tools/builtin/md_to_docx.py` · `tools/builtin/md_to_pdf.py`

**FILESYSTEM 容量合同 ≠ 活性超时（✅）**：字节/行/条目/Office 抽取成本触顶 → 早失败 `contract_failure` + 可执行下一步（不计工具熔断累计）。墙钟只表示通道/协程**活性挂起**（文案禁原样重试；仍计熔断，steer 强调缩小范围/换策略）。云 `ServerWorkspace` 整读上限与桌面 Local `WORKSPACE_READ_MAX=5MiB` 对齐。Local 通道 deadline **由外层工具活性预算派生**（非第二套独立 60s）；`timeout_ms` 下发桌面 AbortSignal，迟到 settle 仍 stale no-op。单次 settle 超时只失败该 op；**连续两次**真实 op 活性超时 → 通道 sticky **dead**（同通道 inflight 失败信封收口 + 后续 op fail-fast，防连环 60s；成功 settle 清零计数）。通道有界并发（默认 16）：仅约束 Local `WorkspaceChannel` 同时 await 桌面的 op；超额排队（计入外层墙钟），dead 后排队者拿槽即 fail-fast——云盘/`workspace_lock` 不动。**过桥 settle（✅）**：云 `interactions` POST 带墙钟；桌面对 `NetworkError` / 5xx / 429 **进程内短重试**（仍在服务端 op 预算内）；重试耗尽才记 fail，并强制 SSE 走 transport-drop → rejoin，避免「本地已算完、settle 毛刺 → sticky」与后续 `workspace_op` 无人履行。→ 见代码：`workspace/limits.py` · `workspace/channel.py` · `runtime/tool_deadline.py` · `runtime/engine/tool_exec.py` · 桌面 `clientToolFulfill.ts` · `interaction.ts` · `streamConversation.ts`

## 四B、本机 Host（第三能力面）✅ 单工具 `host`

> 与 Workspace / Browser 正交。模型面 **一个工具 `host`**，按 `action` 分流、运行时升审批（同构 `git` / `terminal`）。运输层仍是桌面回填 `HostOp`（`status` 对本刀既有 L1 op **并行 fan-out** 拼装，不改桌面契约）。GUI 面见 [§四B′](#computer-use)。

| 项 | 契约 |
|---|---|
| 可用性 | 仅桌面 + 回填通道可达；与 folder/bind 正交（裸聊云 scratch 亦可） |
| 通道 | `ChannelProfile`（`X-Client-Platform` → surface / `desktop_online` / `can_bind_folder`）为单源；缺头 / 未知 → fail-closed（两旗均为假）；**禁止**用 `location=local` 抬升 `desktop_online`（与鉴权 `parse_client_platform` 缺头/未知 fail-closed 同精神，aud 侧则直接拒）。**本机引擎（sidecar）回合**与云端桌面回合同构：传 `desktop` → `desktop_online=True` → 建 `DesktopClientChannel`（真机已验收） |
| 运输 | ClientTool / channel 回填（对标区外挂载 / `desktop_notify`）；**禁止**以 DesktopBrowserBridge loopback 冒充云可达；**禁止**在 sidecar 内再拉一套 MCP/Host stdio。`DesktopClientChannel` 在 `desktop_online` 时装配（含云 backend） |
| 工具 | 单一 `host`（`host_class` · schema `NEVER` · CEO+worker 注册）；**不**挂 `execution_class`；GRANTABLE **action** 不吃 kickoff/`command=auto` 静默授。工具名不再当权限表 |
| 分工 | CEO 持 `host`；worker-only action 运行时结构化失败并令 `delegate`（同 `git` 写入）。另持本地 `terminal`（非 Host 面、schema `NEVER`，`start` 运行时升） |
| 权限 | PermissionAxes `host`：`off`/`ask`/`session` → [安全 §三](/docs/05-平台与运维/安全权限与治理.md) |
| **三分日志** | ① **OS Host 事件日志** → `host(action=os_log)`（仅本机 Host）；② **任务/沙箱/构建 stdout** → `terminal` read / `code_execute` / `test_run`（**云侧任务日志亦此主路径**）；③ **产品 AI 对话日志** → `search_conversations` / `read_conversation`。禁止混称 |

| `action` | 谁可调 | 审批 | 做什么 |
|---|---|---|---|
| `status` | CEO + worker | 免批 | 一次返回有界快照：OS / 磁盘 / 电源 / 网卡 / 音频设备 / 应用抽样。可选 `facets` 投影，默认全要。有界探测在 handler：不做全盘枚举、不扫端口 |
| `os_log` | CEO + worker | 免批 | 有界 OS 事件摘要（来源/时间窗/级别；条数·字节硬上限；密钥形脱敏、路径可保留；Win=Get-WinEvent / Linux=journalctl；禁整机倾倒） |
| `shell` | CEO + worker | `host` 轴 | 短时本机命令；无 `cwd`（home / 默认 shell cwd）；Win PowerShell / Unix `$SHELL -lc`；毁灭性 + 长驻 + 静默安装启发式硬拒（dev server → `terminal`；装软件 → `install_package`）；禁倾倒 Event Log / journalctl / 扫 `*\logs` |
| `open_settings` | 仅 worker | `host` 轴 | 白名单系统面板 `sound\|display\|network\|apps\|about` |
| `set_audio` | 仅 worker | `host` 轴 | 切默认音频设备（须先 `status` 观测设备） |
| `restart_service` | 仅 worker | `host` 轴 | 白名单服务（起步仅 `Audiosrv`） |
| `install_package` | 仅 worker | **恒确认**（按参数，对齐 `git push`） | manager∈{winget,brew,apt} + package id；brew 可选 `cask`；`host=session` / kickoff / turn grant **不覆盖**；超时默认 600s、上限 900s |

`<workspace_context>`：能力行含 `code_execute=` / `package_install=` / `host=` 等；云 reach =「工作区在云；本机 Host 以 `host=` 为准」。通道是否可达由装配 / `host=` 表达，**不**每轮打 INFO、**不**把电量/磁盘/应用列表塞进每轮上下文。`host_ping` 不进模型面（通道不可达则整面不装配）。**`package_install=` ≠ `code_execute=`**：云端装包另需 netns/`registry_egress`；本机装依赖跟执行类，装本机软件仍须 `host=` + `host(action=install_package)`。

**否决**：13 个 `host_*` 旧名注册或转发兼容层；每加一种观测就加一个工具；只放开 `host(action=shell)` 当装包 / 倒日志闭环；用工具名隔离 CEO / 恒确认；把 L3 给 CEO；Web/手机假装已查本机；任意 URL / exe 静默装；云 Alone 假装装到用户本机；放宽工作区 cwd；单点音频特例工具；用「工具很多」当隐私闸（隐私写在 handler 返回什么）。

→ 见代码：`desktop/channel.py` · `tools/builtin/host.py` · `runtime/pipeline/prepare.py`

## 四B′、Computer Use（本机 GUI）⏳ 已确认未落地 {#computer-use}

| 分工 | 网页 → `browser`；装软件 → `host(action=install_package)`；本刀不替代二者、不并进 `browser` |
| 下一刀（另案） | 远程机窄切（SSH 为通道之一）——不在本刀范围 |
| 否决 | 第一刀做坐标点击 / 截图当模型感知通道 / 空树盲猜坐标兜底；第一刀默认整屏；第一刀带 mac；引入 robotjs·nut.js 类原生键鼠模块；第一刀做 SSH；只写剧本不接通控；GUI 与 browser 合并成一套工具名；新开第五权限轴 |

→ 安全权限要点见 [安全 §三](/docs/05-平台与运维/安全权限与治理.md)（`host` 轴 + 整屏额外 grant）；落地后补代码指针。

## 四C、本机 MCP Client ✅

> 桌面配置本地 stdio MCP Server，工具经现有 Tool 管线进 worker（审批 / Journal / SSE 同径）。不做 AgentCore 对外 MCP Server；不替换 builtin；远程 SSE·HTTP MCP / 按文件夹绑定 / Computer Use = 另项（Computer Use → [§四B′](#computer-use)）。

| 项 | 契约 |
|---|---|
| 运输 | **仅 stdio**；桌面主进程用官方 `@modelcontextprotocol/sdk`（`Client` + `StdioClientTransport`）拉起；回填对标 Host/`DesktopClientChannel`（`mcp_op_required` ClientTool）；**本机引擎回合与云端桌面同通道**（sidecar 传 desktop，禁引擎内第二套 stdio）；**禁止**云端假连本机 stdio；Web/手机无「已接本地 MCP」假象 |
| 谁持有 | **默认仅 worker**；CEO 工具集不含 MCP |
| 审批 | MCP 工具一律 **`grantable`**（未知 Server 不得 `never`）；走**通用 Approval** 卡（挂起 / fulfill / 拒绝同径），不另开「信任 Server」轴；云工作区 + 桌面在线时 worker 仍须对 MCP/Host 弹卡（本机副作用） |
| 装配 | **账户/会话级**：用户启用的 Server → 本回合 worker **注册表**（仍只挂 worker、CEO 不含）；**开场 FC 表不灌 MCP schema**——发现的 `mcp_*` 走同一 `on_demand` / `consult` 闸，清单出现在 worker `<按需目录>`，模型 `consult` 该 Server 任一工具后按 Server 成族晋升（同 Server 的 `mcp_*` 一并上表；不抬其他 Server）。**prepare/resume 只读进程缓存**（`cache_only`，miss → 未装配、不 await ClientTool）；打开文件夹 / 非回合暖写入缓存（seed 或显式 network `list_tools`）；桌面按 warm 回传的 `ttlSeconds` 在 `startTurn`/`resume` 过期后续暖，并在 **detached execution 存活期**周期续暖（与账户 rules/memory 同纪律，避免 sidecar 内部收口空装配）。不做按文件夹 / Agent 绑定。账户 rules/memory 同纪律 → [记忆 · 注入](/docs/03-AI核心/Agent记忆与知识系统.md#二注入) |

| UX | 工具箱「集成 · 连接器」增删启停；手册「MCP（本机连接器）」 |

→ 见代码：`desktop/channel.py` · `tools/mcp/` · 桌面 `mcp-service.ts`（SDK）/ `mcpOps.ts` · `ConnectorsPage`

## 四D、Git 闭环（✅ Phase 1 · ✅ G1–G4 · ✅ U1–U3 · ✅ Local 通道） {#git-闭环}

> **产品心智**：结构化 `git` = Agent 工程工具；用户 SCM = 会话旁版本面板。两边同一工作区仓；**回合 zip 基线**仍是「本回合可回滚」主路径，与 git **正交**（不合并语义、不做三方 merge UI）。主路径禁止教模型用 `host(action=shell)`/`terminal` 自由敲 git 当闭环。凭据：**人配置、进程继承、失败诚实**——工具永不收密码参数。→ [安全 · git force 统一 DENY](/docs/05-平台与运维/安全权限与治理.md) · [前端 UX · 改动双轨](/docs/04-前端/前端UX设计.md)

| 阶段 | 状态 | 范围 |
|---|---|---|
| **Phase 1** | ✅ | `status`/`diff`/`log`/`add`/`commit`/`branch`/`checkout`/`push`/`init_baseline`；push 恒确认；force/保护分支/`reset|clean` 硬拒；无仓软提示 `init_baseline` |
| **G1 读写闭环** | ✅ | `fetch`（免批）· `pull`（ff-only，审批；冲突诚实停）· `show`/`blame`（有界只读）；审批卡 `paths` 可读 |
| **G2 协作** | ✅ | `stash`（list 免批；push/pop 审批；drop/clear 硬拒）· `merge`/`rebase`/`cherry-pick`（冲突停，禁 force 旋钮）· 轻量 `tag`（list 免批；create 审批；禁删）· `remote`（list 免批；add 审批；禁 remove）；仍禁 `reset`/`clean`/force→保护分支 |
| **U1–U3 用户 SCM** | ✅ | 分支+dirty 条 →「改动」双轨（zip ∥ git 列表）→ 人可 stage/commit/push/pull（与结构化 git **同口径**：桌面 `window.confirm` + 主进程镜像护栏；push 恒确认、ff-only pull、禁 force/保护分支） |
| **G3 远程产品化** | ✅ | 云工作区浅克隆接已有 HTTP API（仅 http(s)、SSRF、浅克隆）；云私仓账户级 PAT（设置 · Git 凭据，AES-GCM）；Local 继承 OS credential helper / `gh auth`；push/clone 认证失败指向「去设置凭据 / 打开已配置凭据的本地仓」 |
| **G4 PR** | ✅ | `git create_pr`：GitHub-only 结构化开 PR（`api.github.com`，非自由 shell）；参数 title/body/base/head；凭据复用 G3 PAT / Local `gh`·env；无凭据/非 GitHub remote 诚实失败；与 push 同口径恒确认 |
| **Local 通道** | ✅ | ServerWorkspace / Sidecar：同进程 subprocess。LocalWorkspace（无 Path.root）：Agent 经桌面 `git_run`（闭集 op，与 UI 的 `git_repo_status`/`git_scm` 分立）；有 `local_subpath` 时 cwd/探测/`init_baseline` 均落该文件夹子目录（与 file_* 同基准，禁止打到共享容器根）；无 subpath（打开文件夹）则根即该文件夹；只读无仓仍 `no_repo`；无通道人话硬错 |

**同仓串行（✅）**：一轮工具并行派发常让同一仓同时收到多条 git，抢 `.git/index.lock` 会伪装成 git 故障。**按仓（非全局、非按对话）** 串行会写 index 的子命令；只读不排队（`GIT_OPTIONAL_LOCKS=0` 使其不碰 index），`push`/`create_pr`/`branch`/`tag`/`remote` 也不排队（不碰 index，且不该让远程往返堵住本地 commit）。等锁**有界且已计入引擎外层超时预算**——排队永远不会把调用者推过外层超时；等不到则诚实报 `repo_busy`（本次未执行、仓库未改变），不重试。同一 checkout 的两个对话共用一条队列（磁盘上本就同一把锁）。

**否决**：AI 代持密码；改动 tab 冒充三方冲突工具；默认放开 hard reset / force 保护分支；全局 git 锁（不同仓库/工作区互相排队）。→ 见代码：`tools/builtin/git_ops/`（`repo_lock.py` · `policy.py` 超时表）· `workspace/channel.py`（`GIT_RUN`）· `workspace/git_credentials.py` · `workspace/github_pr.py` · `runtime/safety_breaker.py` · `runtime/approvals.py` · 桌面 `main/fs/workspace/gitRun.ts`
