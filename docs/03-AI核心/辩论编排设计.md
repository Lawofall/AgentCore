## 一、产品目标

**目标**：用对抗性多视角思考，帮用户得到能信、考虑过反面的**结论或决策**，同时看懂**思想如何交锋**。

| 三问 | 答案 |
|---|---|
| 谁用 | 决策者 / 学习者 / 方案作者 |
| 解决什么 | 决策（选 A/B）、压力测试方案、学懂争议话题、思辨 |
| 如何呈现 | 用户点名开辩（正反）；产出**过程 + 结论**双产物。挑刺 / 压测走 `delegate` 审校岗；多视角走 `delegate` |

**主持人为何存在**：辩论需要有状态编排——发起对抗 → 逐轮判收敛 → 裁决 → 交付双产物。它不是独立执行引擎，而是 **CEO 之下、辩手之上**的编排角色；底层仍复用并行委派 + 上游产物注入。「轮次」对用户隐藏，由收敛自停。

---

## 二、主持人循环

主持人 =「主持 + 裁判 + 书记」三合一。一轮四步：

| 步 | 做什么 |
|---|---|
| 1. 定本轮议题 | 首轮 `_frame` 拆争议焦点；后续优先用上轮 `verdict.next_focus`；`focus_override`（主框插手）最高优先 |
| 2. 派各方发言 | 按形态 profile 分流（正反并行波 / 红队星型三拍 / 圆桌点名串行）；缺席方标 `absent`，跳过对其质询与对抗记分 |
| 3. 质询交锋 | 仅正反 DEBATE + `thorough`；细节 → [质询证据与证人](/docs/03-AI核心/辩论质询证据与证人.md) |
| 4. 裁判 + 决策下一步 | 一次调用兼产：是否真交锋 / 可否收场 / 记分 / 本轮小结 / `next_focus`；收敛 → 简报收场，未收敛 → 下一轮 |

**收场前结辩**：新场不跑（`form_profile.closing` / `closing_enabled` 恒假）。结辩 runner 留旧场回放与单测。细节 → [质询证据与证人](/docs/03-AI核心/辩论质询证据与证人.md)。

**收敛**：由裁判逐轮自判（无实质新论点 / 焦点已成价值之争 / 红队风险挖尽）；`max_rounds` 仅安全保险丝。认真档约 5 轮上限、快速档 `thorough=False` 单轮。主持「裁判」= 辩论域交锋与收敛判定，≠ 通用 worker 质量门。

## 三、产品入口与 runtime 形态

产品入口只认**正反**：CEO / 工具 description / `debate_and_review` 开辩即 `form=debate`。挑刺 / 压测走 `delegate` 审校岗；多视角走 `delegate`。发给模型的 `form` enum 只广告 `debate`（`DEBATE_SCHEMA_FORM_VALUES`）；`DebateForm` / wire / `DEBATE_FORM_VALUES` 仍三员，供旧场回放。`parse_form` 与 `parse_motion_card` 接受历史三值，缺省或非法回落 debate，不硬拒旧 form。

一套循环仍经 `FormProfile` 参数化。红队 / 圆桌 runtime 留旧场回放与现有单测。

| 形态 | 参与方 | 轮内拓扑 | 质询/结辩（新场） | 产物侧重 |
|---|---|---|---|---|
| **正反辩论** | 正 / 反 | `parallel_wave`（+ thorough 质询） | ✅ / ❌ | 简报先行 |
| **红队挑刺**（回放） | 方案方 + 1~N 红队 | finding 星型：攻→合并→应（thorough 复攻） | ❌ / ❌ | finding 台账 + 门决 |
| **多方圆桌**（回放） | 3~N 视角 | `nominate_serial`（+ 可选 crux） | ❌ / ❌ | 过程 / 共识地图先行 |

红队之间不互驳；圆桌不作全员并行波（否则各自独白）。

## 四、双产物

结束交付两样，不分主次：

1. **结论 · 决策简报**（正反用户面）：倾向（可带「若…则翻」）+ 胜负手 + 置信档 + **handoffs**（`value` / `fact` / `question`——按谁能闭合分）。有交接就不另写建议复述倾向；`strongest_points` 可存档、终审不展。
2. **过程 · 交锋叙事线**（三层）：L1 焦点小结流 → L2 逐轮攻防 → L3 全文 + 交锋边（`clashes`）。

呈现顺序：决策类（正反）简报先行；旧场红队同简报先行、圆桌过程先行。前端 → [辩论室 UX](/docs/04-前端/辩论室UX.md)。工作区落盘 → 见代码: `runtime/debate/persist.py`。

## 五、庭前取证（决策）

取证是辩论质量的**内在前提、系统责任**，不是开赛前再问用户要不要先调研。**取证前提 ≠ 庭前调查员舰队**——内化的是「成稿只引场级台账」的质量闸，不是开赛后另拉一支取证员并行扫网。

**系统责任**（开赛后、首轮立论前与发言期）：

1. **约定文档桥无条件汇流**（CEO 检索 / background / `research/` 等 → 场级 `#eN`）→（可选）**Evidence Pack 组卷**（主持人上下文已有可用正文附件时）。
2. Pack / 证据完整度为 **`full`** → 立论外搜预算 **0**（不再外证扫网）。
3. 否则认真档（`thorough=True`）各方在**发言期**做**对称有界检索**，命中写入场级台账 `#eN`；成稿**只引台账**。
4. **`thorough=False`** 不带庭前重流程（秒过）。

**已退役（勿再写为现行）**：开赛后主辩点单 → 主持人代派取证员 → 并行登记；`gap_fill` 派员；不留「深证」窄门。

**就地否决**（仍否决）：给辩手 `delegate` 提深度；中立取证员；取证笔记全文灌主辩起点。→ 见代码: `runtime/debate/pretrial.py`。

## 六、进行中插手

用户是老板：辩论默认自动跑、**永不硬停**。进行中对这场说话走**主输入框**（传输仍 `/debate-steer`），主持人在**下一轮边界非阻塞**捞起：`continue` / `conclude`（「出结论」）。

干预只作用议程 + 价值层，不篡改事实层。收场后再辩 = 对 CEO 说话重开全新辩论（无 durable resume / 结构化补轮）。前端 → [辩论室 UX](/docs/04-前端/辩论室UX.md)。→ 见代码: `runtime/debate/steer_queue.py`。

**「永不硬停」的边界**：指辩论**自身不设阻塞式逐轮闸**——不会停下来等用户点头才进下一轮。它**不豁免全局 Stop**：用户显式 Stop 照常取消整个回合（含在跑的辩论），权威 → [执行引擎 · 协作取消](/docs/03-AI核心/执行引擎架构设计.md)。两者不冲突：一个说辩论内部不主动挂起，另一个说用户始终能掐断。

## 七、技术落点摘要

- **入口**：用户点名后 CEO 调编排工具 `debate`（schema 在 `tools/builtin/debate/`；域逻辑在 `runtime/debate/`）。主持人 = 确定性 Python 循环 + 逐步结构化 LLM 判定，非自由发挥编排 agent。
- **复用**：并行委派 / `continue_run`（辩手跨轮带记忆）/ WaveScheduler / 工人发射闸 / steer 队列；不重建引擎。
- **图结构**：CEO → 主持人（完成态节点）→ 辩手。开辩独立成图，不链调研宿主、不把调研员拉进场当证人。跨回合开幕另起一张锚在本回合的图（旧磁带 `prev_execution_id` / divert 仍可回放） → [编排器 · 跨回合延续](/docs/03-AI核心/编排器与CEO主Agent.md)。
- **契约**：`DebateResult` = brief + rounds + `narrative_first`；收场 `debate_result` 为 journal 权威；发言全文靠 `run_id` 取回，不进事件。
- **约束**：`stance` 薄单句（禁论点清单）；`background` 可选底料双方共享；辩手 `collaboration=False`。
- **真·多模型辩手**：**接线 ✅**——各方可填不同厂商模型（目录身份 `@platform/{id}` / `@byok/{provider_id}/{id}` 或口语消歧含用户「平台的」偏好 / `cross_model` 默认对阵；勿写未加 `@` 的路由键）；第一刀仅正反 2 方；空身份 = 同模型场。**端到端真跑验收 ⏳**（平台 vs DeepSeek 真跑待验）→ [路线图摘要](/docs/01-产品/产品路线图摘要.md)。细节 → 见代码: `runtime/debate/`（model plan / router extras）。

## 八、否决项

| 方案 | 结论 |
|---|---|
| **独立 Arena 子系统**（独立 SSE / 状态机 / `arena` RunKind） | **仍否决**——主持人不是独立引擎，只补产品层 |
| CEO 一次 `delegate` 静态展开 2N 节点 | 被主持人逐轮推进替代 |
| 机械 `min_rounds` 楼层 | 被裁判自适应收敛替代；`max_rounds` 仅保险丝 |
| 二元 pro/con 专属 | 被立场标签替代；产品入口正反，红队/圆桌 runtime 留回放 |
| 只留正反、红队/圆桌改组队（旧否决） | **已撤销**：产品入口只认正反；挑刺/压测走 `delegate` 审校岗、多视角走 `delegate`。红队/圆桌 runtime 留回放，不硬拒 `form` |
| 辩论室收成过程列 + 结论卡 | 否决；赛事页仍是看的面 |
| 默认 `thorough=false` 单轮 | 否决；点名后仍认真档；用户只要轻量才快速档 |
| 主持人 = depth-1 LLM 编排 agent | 改为工具内确定性循环 |
| 辩论独立 SSE 通道 / 散乱事件族 | 仍否决；收场靠 `debate_result` |
| 逐轮阻塞挂起（`DEBATE_ROUND`） | 被主框 ambient steer 替代 |
| 人设模拟当「多模型」 | 否决；走真·多模型 |
| 非法模型身份 silent 回退 | 否决；空身份回退合法，非法硬失败 |
| 庭前调查员舰队（主辩点单→代派取证员→并行登记 / `gap_fill` 派员） | 否决；取证前提 = 约定文档桥 + 可选 Evidence Pack + 发言期对称有界检索入台账 |
| 把一场辩论固化成工作流 | 否决——命题一次性，可复用的是形态不是这一场；正确载体是带命题槽位的官方模板。技术上辩论不写 `plan_snapshot`、辩手 `depth=2`、身份在 `DebateConfig` 不在 plan 层 → [工作流固化与复跑 §四](/docs/02-架构/工作流固化与复跑.md) |
