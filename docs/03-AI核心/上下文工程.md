## 认知同构 · 执行异构

对模型而言 Tool / Skill / 用户规则皆为 token；执行侧异构（Skill 只读、Tool 有副作用、Agent 有循环与状态）。原则：**默认不放，按需才拉**。

注入侧载体同构：Skill / 按需用户规则都是一条带 `description` 的 md 条目，异构只剩执行侧。AI 笔记停写停注入。

五杠杆（选择 / 时机 / 压缩 / 外置 / 分治）实现归属见用户规则·工具·执行引擎·协作模式各篇——本文不复制。「谁来拉」：**模型自选**（否决 embedding / LLM 预筛）。

## 注入侧 Assembler

prompt 注入收口于 `assemble_system_prompt` / `runtime/context/` 的 `ContextAssembler`（含 `PromptContributor` 插件化）。这就是注入侧收口，不必再立门派。

否决叠一层「目录 + 按需取」超级 Provider：consult 源已合并成同一种条目（skill / rule；低频工具另挂 `ToolConsultSource`，不共享 Tool 基类）；Tool 仍有副作用 / schema / 权限轴，registry 与条目刻意不共享基类；复杂度在写侧 / 执行侧 / 预算侧。用户技能入基座 ✅ → [工具与能力 · 用户技能](/docs/03-AI核心/工具与能力系统.md#用户技能与可编目录)。

守恒律：统一只罩注入侧；输出侧（副作用 / 循环 / 状态）复杂度搬家不消灭。

## 按需与写侧配额

`Consultable`（目录露出 + 按名取文）由 skill / rule 实现，低频工具另挂 `ToolConsultSource`（只 promote 进 FC 表，不把 Tool 改成条目）。`MergedConsultSource` 为唯一源——**提示词目录与工具 `fetch_by_name` 读同一个实例**；有票时规则目录与正文都读 prepare 快照（与 always 注入同源，fetch 不另打云列表），故「目录里列了什么」与「按名能拉到什么」在结构上无法漂移。对外单一 `consult`；重名按 skill → tool → rule 解析。生效方式对外仅 `常驻` | `按需`。权威行为 → [记忆 · 用户规则](/docs/03-AI核心/Agent记忆与知识系统.md#用户规则)。

常驻配额闸在**写侧**：满了不许再往常驻加（AI 写超限抛错并推卡，用户改既有条目放行）；**读侧全量注入、不截断**。落地面：`memory/always_quota.py` + `GET /v1/documents/always-quota`。装配器上的 `budget` 字段不裁剪、不淘汰。**文件页不展示常驻池剩余，条目行尾也不标单条字数**——用量条会把安全阀做成「还能再塞」，混着常驻与按需的列表上稀疏字数会被读成缺数据。闸对人不可见，只在 AI 写满时推卡（文案不报字符配额）。工具箱「必带」仍标满千字的精确字数（该区每条都是常驻）。COST-004 仍只观测不闸。

否决：读侧截断常驻做内容取舍；自动淘汰常驻条目；用调大读取帽「修」写超；文件页用「满千字才标」把单条字数补回来。

## 提示词设计原则

> **覆盖**：CEO 常驻核、全员基座、队员身份、辩论辩手/主持人、系统 Skill、工具 schema、场面门、一次性尾、引擎 `[系统提示]`。不覆盖用户规则 / 用户上架正文（用户资产：用户可以冻自己的编制）。CEO 路由语义仍归 [编排器](/docs/03-AI核心/编排器与CEO主Agent.md)；本文只管**提示词怎么写、事故怎么进场**。
>
> 分层装配现状已有（`ContextAssembler` + `consult` + journal one-shot）。本原则钉的是内容政策：先过内容闸（可复现；挡强吸引子；不服务「更好」）；常驻写宪法，不写判例。按需 HOW 默认所有者是 `consult`；写参当轮必见的合同所有者是该工具按钮（现：`delegate` 编制、`ask_user` 填卡）。How（入场闸怎么走、测什么、出门检验）→ `.cursor/rules/prompt-design.mdc`。

**行业对照**（钉原则，不是跟风清单）：Anthropic *Building Effective Agents*——先简单提示，只在 eval 证明需要处加复杂度，用工具回执与结构状态纠偏，而不是把边角预写成剧本。Agent = LLM 自己决定过程与用哪些工具，不要把自判收成闭集分类器。Anthropic Skills / Claude Code——渐进披露：目录只留名字与一句是什么，正文按需才进上下文；最佳实践默认模型已经很聪明，只补它没有的上下文；自由度跟脆弱性匹配（开放场地只给方向，窄桥才锁死序列）。OpenAI function calling / Agents SDK——约束进 JSON schema 与参数描述，**何时用这把工具写在 description**，系统提示不复述 schema、不写编号判决树。OpenAI *Rethinking skills and prompts for GPT-6 Astra*——过度具体的菜谱会妨碍更强的模型。验收旋钮对齐 [编排器 · 交付物：钉路径才催写](/docs/03-AI核心/编排器与CEO主Agent.md#交付物钉路径才催写)，不进经理常驻或填参面。共同点：**常驻写决策时刻宪法（身份 / 诚实 / 输出）和按需钩子；听谁的归消息角色与注入点；何时用工具写在工具 description；HOW 与边角靠 schema / 环境 / 按需 / 当场；出厂提示词服务可复现和挡强吸引子，不服务「更好」。**

长提示的真实成本不只是 token：指令互相打架、中间段被丢掉（lost-in-the-middle）、模型在例外里任意挑一条。再加一段禁令往往看起来像修了事故，实际在稀释宪法。把「写得更好 / 更好看 / 更专业」的步骤写进任何一层，是同一类稀释。点名预训练默认脸、留下一条方向原则，不是。

### 内容闸：可复现，不服务更好

往任何产品 AI 提示词加一行之前（常驻、按需、当场、schema、官方出厂模板皆是），两问**任一成立才留**：

1. **产品合同**：删掉这句，前沿模型会不会用错**本产品**（工具语义、身份、诚实对照结构面、必须同形的机构流程）？
2. **强吸引子**：删掉这句，会不会走进预训练 / 助手习惯的默认输出，且正向原则盖不住？成立则只许写原则或 `A ≠ A′`，不许写替代步骤、不许规定「更好」长什么样。

两问都不成立（只是更漂亮、更专业、更完整、更像某本范文）→ **不写**，任何层都不进。

| | 产品合同 | 强吸引子原则 | 质量菜谱 |
|---|---|---|---|
| 没有这句 | 用错这套产品 | 走进紫蓝渐变、空洞「专业」、套话收口 | 只是不像范文精致 |
| 写什么 | 语义必须同形 | 点名吸引子，不点替代脸；例子说明形态，不是风格菜单 | 不写 |
| 例子 | `run` 三分；主张对得上结构面；官网三条；无执行交表三份材料；适合可视化则优先呈现 | `page_ui`：预训练默认脸 ≠ 方向；「好看 / 现代 / 专业」不是方向 | 字号配色课、表格行色/配图、文风课、「写得更像律师」 |

强吸引子原则三条边界：只点吸引子、不点替代脸；例子必须可替换；场面不是每回合都发生 → 按需 `consult`，不进常驻核。挡的是坏默认，不是把某种「好看」冻成出厂审美。不把「不够好」做成拦截。

用户规则与用户上架正文不走本闸——那是用户选择冻自己的编制。出厂稿没有这个特权。本闸约束**我们写给模型的字**。

审议已有一句是否留下：方向相反、同一两问。两问都不成立 → 删，即使它已经放在「正确」的层。

### 宪法，非法例

常驻提示只写**决策时刻宪法**和按需钩子。工具何时用写在该工具 description。不写编号判决树、不写某次失败的话术剧本、不枚举禁说的近义词、不点名个案查询词。

产品 AI 提示词给模型看，也给维护者审：仓内自造压缩词不进提示词，改用产品面中文（工具名、schema 字段、事实层注入的字面标记除外）。

段标题对应回合里的决策时刻，不是作者目录：

| 时刻 | 标签 | 所有者 |
|---|---|---|
| 我是谁、对谁负责 | `<身份>` | 角色层唯一一块（CEO 核残差；辩手立场）。**无残差则不注入该标签。** 叶子 / 队长不写工厂身份。基座不另写、不套同名标签 |
| 这段字是指令还是材料；听谁的 | （无常驻段） | 真用户 `role=user`；引擎信封/纠偏 = `[系统提示]` 围栏的合成 user；回执 `role=tool`；网页 `untrusted_web_content`。用户 vs `<设定>` 在设定块前言与路由硬约束；能改多大在 `ask_user` / `escalate` description |
| 能不能这么声称 | （无段标题；基座一段末句 + 目录前言） | 已做以回执为准：全员基座。目录行 ≠ 已查阅：`<按需目录>` 前言 |
| 写出去的字长什么样（产品形状，不是文风） | （无段标题；基座一段前句） | 全员基座 |

「如何工作」不是另开一块：它是权威+诚实的并集，不当段标题。基座默认一段无标签（输出形状、末句诚实）；某时刻长到需要目录再套该时刻标签。按需钩子仍是 `<按需目录>` + `consult` description。

基座只写 **CEO 与 worker 同真**的句子。工种不对称（卡住问谁）进工具 description 或节点合同，不因为「都叫诚实 / 输出」就推进基座。对照：已做以这回合回执为准在基座一段末句，核不列变体表；目录行 ≠ 已查阅在 `<按需目录>` 前言；来源编号在回执尾，不进常驻散文。已声明路径 / 章节才进当场「交付物规格」，不进 `<身份>`、不展览交法。输出句只钉产品形状（适合可视化则优先呈现），不写文风、版式、论证强度。不把「已落盘则结论给路径」写进基座——条件句每回合都在，会被读成催写盘；写盘场面才成立，不预写进常驻。CEO 工厂身份现空，不进共享基座。

常驻身份 = 工具图编码不了的策略残差。工具表已经分开的工种差不写；观察里已经为真的不复述。对照：官网 / 「你是谁」→ `product_help`；CEO 工厂 `<身份>` **现空、不注入**（共享基座收不了 CEO 专属出口；何时派在 `delegate` description）。凭据明文落盘走写侧熔断。叶子 / 队长不写工厂 `<身份>`；队长嵌套层数是开场能力事实，不进身份标签。头衔咒语（「你是资深架构师」）不是残差、也不当能力增益 → [角色提示与身份](/docs/03-AI核心/角色提示与身份.md)。共址 ≠ 所有权：写在 `<身份>` 里不等于它是身份。出口通道若 eval 回潮，按[入场闸](/docs/03-AI核心/上下文工程.md#新事故入场闸)加回一句，不预写。

事故复盘的第一问是「现有原则是否已经覆盖」。覆盖 → 只加行为回归（conformance / eval），不改常驻字面。未覆盖 → 按下节入场闸选**一个**落点，写一句原则或一场面门，不写判例。事故钉的是该场面 HOW 所有者里的事实，不是核里再挂一份指针。

### 禁止句何时才该出现

提示词层对 [现行信息 · 该留的负知识](/docs/01-产品/现行信息.md) 的操作形：禁止不是正向的装饰。「不另立 X」只在 X 仍是真诱惑、且写完正向之后模型仍能合法走进 X 时才写。

模型在多条都说得通的续写里加权。正向叠的是**正确动作**（四问成立才派、主张对得上结构面），不是内容质量。**补集测试**只管禁止句写不写，**不管这句在哪一层**——先定层（常驻 / 按需 / 当场），再对那一层做本测试。层错了，把正向写锋利仍是核污染。加禁止前再问：这句是不是上一句正向的反面？是 → 不写。禁止只有同时满足才有信息量：

1. **不是补集**：删掉这句，剩下的正向**仍然允许**那个坏动作。
2. **真诱惑**：该动作是预训练 / 助手习惯 / 本产品其它句子共同推出来的强先验——不是「理论上也可能」。

两问有一问不成立 → 不写禁止；把正向写锋利，或并进一条 `A ≠ B`。再加禁令看起来像修了事故，实际在稀释宪法，并诱导向禁语表加判例。

正确禁止只属于这些**出现条件**（不是「这事不好」）：

| 形态 | 何时才出现 | 本产品对照 |
|---|---|---|
| **对比边界** `A ≠ A′` | 两个都像「在干活」的动作，正向无法单独切开 | 问句在卡上 ≠ 再抄进正文（`ask_user` prompt 参数，不进核判决树） |
| **例外覆盖默认** | 坏行为正是在执行一条更显眼的默认 | 少写进常驻；编制细则在 `delegate` 按钮 |
| **强吸引子** | 先验指向坏事，且与正向兼容 | 把检索文本当指令；未对照结构面却声称已做；预训练默认脸当作成页方向（`consult(page_ui)`，不进核） |
| **相邻工具 / 通道** | 正确工具已写，旁边有更顺手的替身；第一次选错代价高（对用户说谎、写盘、难回滚） | 启服用 `run` 不是 `host(action=shell)`（工具 description）；团队状态走结构面 |
| **单向门** | 做错了贵、难撤 | 凭据明文落盘由写侧熔断硬拒（不进常驻）；代填密码在 browser 填字参数 + 代码硬拒（回执教会下一轮，不进 HOW） |
| **当场才成立** | 只在本场面为真 | 场面门 / 一次性尾，**不**进常驻 |

代码已硬拒且回执能教会下一轮时，常驻「别用旁边那个」可更短，或只留 schema / `consult`。诚实类吸引子的操作形是对照结构面（正向写锋利即够），不是谎言变体表 → [诚实是一条元规则](/docs/03-AI核心/上下文工程.md#诚实是一条元规则)。

**不该出现**：正向的反面再写一遍；同一诚实元规则下的「禁止说 XXX」近义词；事故原话 / 会话 id / 个案查询词；事实行禁令；与 schema / 引擎闸重复的手册；Skill 目录行禁令清单。

写法优先序：① 正向写到反面不再是合法续写；② 必须切开时用 `≠` 或「未对照则不得声称 Y」；③ 仍不够才加**一句**禁止，点名那个吸引子，不点名近义词。加禁止仍走入场闸（只选一个落点）；删禁止后若回潮，回到入场闸 / eval，不换硬闸 → [瘦身不换闸](/docs/03-AI核心/上下文工程.md#瘦身不换闸)。

### 分层边界：一层一所有者

同一条纪律在装配后的提示串里**只应出现一次**。谁写什么：

模型看见的段标题（XML 开闭标签）用中文；`consult(name)` / 工具名 / schema 字段保持英文键，目录行左边仍是查阅键。工具 schema 的 `name` 怎么定（无全行业预训练词表、假朋友不改）→ [工具与能力 · 模型面工具名](/docs/03-AI核心/工具与能力系统.md#模型面工具名)。

| 层 | 只写 | 不写 |
|---|---|---|
| **常驻层**：全员基座、CEO 常驻核、队员身份、辩论辩手/主持人 | 决策时刻：角色 `<身份>`（唯一一块）；基座一段（诚实 / 输出，不套标签）；按需钩子。听谁的不进常驻散文（角色与注入点）。环境事实只在 `<工作区>`（CEO 文件索引为该块末节，工人不加；文件夹对话可点名本对话写/改/导出）。**CEO 与工人该块都走 `[系统提示]` 信封，不进 `role: system`**（工人不加文件索引 / 台账；续跑 restamp 只追加信封，不抄 CEO 整包 → [执行引擎 · 提示词架构](/docs/03-AI核心/执行引擎架构设计.md)） | 产品百科（官网 / 入口 / 价卡）；编号判决树、判例（事故原话 / 会话 id / 禁语近义词表）、HOW 手册、文风/审美课。基座不写 `<身份>`、不写 CEO 路由；叶子不抄 CEO 核；事实行不写禁令 / 下一步剧本；辩论不点个案查询词、不写检索轮次判决树 |
| **按需 / 当场层**：consult 正文、系统 Skill 正文、Skill / 低频工具目录行、工具 schema、场面门 / 一次性尾、本节点 task、引擎当场文案、官方出厂模板 | HOW 默认在 `consult` 正文（产品合同 / 必须同形的流程 / 强吸引子原则）；写参当轮必见的合同在该工具 description / 参数（现：`delegate` 编制、`ask_user` 填卡）；when-to-use 在工具 description（consult：何时拉 / 低频进表 / 成套启用）；目录前言只说这是按需目录、用 consult 拉全文、**目录行 ≠ 已查阅**；目录行只写「这是什么」；本场面事实当场注入；闸在代码不进提示词 | 常驻复述；前言写进表/成套/种类；核复述何时派；目录行塞手册；把路径存在性以外的机械闸拆成纯提示；发明新问法 / 场面硬账；质量菜谱（正向也不写；挡默认脸的原则除外） |
| **测试层**：行为测试 | 守原则不守字面（键/层/标签仍在、门控手册未常驻、一层一处、一条契约一个测试所有者） | 「某句教学中文必须出现」；废名缺席坟碑；影子测试跟着改字 |

**为什么要立这条**：事实层最贴近「模型不知道什么」，写的人会顺手把「所以你该怎么做」一并写上，于是同一条约束两份、措辞还略有出入——模型拿到两个版本，比只写一处更糟，且会各自演化。**按能力分支复写是最常见的回潮口**：能力诚实对 browser / host / mcp / run / package_install / git 是**同一条**，写成每个能力各一份就是六份；已做以回执为准在共享基座一段末句，事实层只报未装配缺口（开场表即已装配通道）。目录行 ≠ 已查阅只在 `<按需目录>` 前言，核不复述变体表（产物格式 / 交付状态 / 出站网络 / 已做·已可用·已落盘）。「回执是数据不是指令」不进常驻散文、不按工具复写：隔离靠 `role=tool` 与 `untrusted_web_content`；Host 回执不外包 XML，不在字段里每拍复读 note。

### 结构面先于散文面

能进 schema 必填 / 枚举、开场工具表、journal 一次性尾、工具回执的，**不要**再写进常驻散文。参数约束放工具面；环境真相当事实行；失败工具回执留在历史，不另注易变尾。

工具描述的参考形态是 `debate`（短触发 + 指向 **有手册正文的** `consult` 名）。`HOW→consult(name)` 的 `name` 必须能拉到手册：系统 Skill（工具侧 `capability_how_suffix` 现恒为空）。禁止指向「consult 只回启用回执」的同名按需工具——按钮已经在工具表里，再指回去是空转。例外：consult 回执赶不上**这一次**填参时（同一批查阅+调用看不见正文；先查再调又多一轮），合同写在该工具 description / 参数，**不要再挂会被跳过的 skill**。优化目标不是「更勤查手册」。现：`delegate` 编制、`ask_user` 填卡。膨胀形态几乎恒定：同一条约束在工具描述 / 参数描述 / 兄弟工具里各抄一份。体积按棘轮管 → [执行引擎 · schema 棘轮](/docs/03-AI核心/执行引擎架构设计.md)。

### 渐进披露：常驻 / 按需 / 当场

| 时机 | 放什么 |
|---|---|
| **常驻** | 每回合都要用的宪法 |
| **按需** | 进阶 HOW（`consult`）；低频栏只列有 HOW 正文的面（工具侧现无，栏空则不渲染）。已装配工具 schema 在开场表，不靠目录当通行证。目录在多于一栏时按「能力指引 / 有 HOW 的工具 / 设定」分栏（只一栏不打栏名）。能力指引栏内按决策时刻排列（编排 / 工作区 / 交付 / 产品 / 工具），不打子标题。成套 HOW（同一 MCP 不进目录当晋升）。名与目录行 → [工具与能力 · 系统 Skill 按需目录](/docs/03-AI核心/工具与能力系统.md#系统-skill-按需目录) |
| **当场** | 本场面才成立的事实与一句姿势（附件缺件）；CEO / 工人当轮信封（日期 / 工作区 / 附件；CEO 另有台账 / 场面门），不进 `role: system`。信封与窗里上一封字节相同则不重拍。CEO 目录/设定相对会话 node 0 的更新走 DeepSeek in-history 额外 `role: system`（钉死 `messages[0]`；只追加变化段，基座/核变了才整份重发），不塞进信封 |

「模型可能不 consult」不是把手册打进常驻的理由，也不是把产品事实留在 `<身份>` 的理由（身份的操作定义见上文「宪法，非法例」），也不是留一本主路不查的 skill。consult 赶不上这一次填参 → [结构面先于散文面](#结构面先于散文面)。正解：目录行只写这是什么；何时用工具写在工具 description；该场面出现时走当场门。手册正文跟用户回合走：下一句要用 HOW 须再 consult。**已装配工具的 schema 在开场表**，不必 consult 才调。用户 `@` 点名的按需设定本回合当作常驻注入（`<钉住条目>`），不是附件、不必再 consult。

### 诚实是一条元规则

用户可见主张必须对照本回合**结构真相**（开场工具表、按需目录、`<工作区>`、工具回执）。基座一段末句只写已做以回执为准（工人没有对账档位）；目录行 ≠ 已查阅在 `<按需目录>` 前言，不进基座。来源编号在回执尾，不进常驻散文。不是禁语表：禁止为每个谎言变体加一条「禁止说 XXX」，也不把变体表抄进 CEO `<身份>`。禁语表当硬闸已经撤过（误伤）→ [编排器 · 失败与否决](/docs/03-AI核心/编排器与CEO主Agent.md)；把同一张表改写进提示词，只是把闸换成常驻判例。

收口诚实：**档位真源**是 `delivery_verdict`；姿势 A / `requires_draft_ack` / 概览超限**默认影子、不回炉**；产物结构窄闸、浏览器声称扫词硬回炉已撤；B1 空心措辞扫描已删。口径 → [执行引擎 · 可用性诚实性](/docs/03-AI核心/执行引擎架构设计.md)。禁止扫用户 / task 长文猜意图。闭集声称探测不得扩面。

### 新事故入场闸

往任何产品 AI 提示词加一行之前，按序只选一个落点（本表 = **入场闸**，与拦截阶梯不是同一套编号）。先过[内容闸](/docs/03-AI核心/上下文工程.md#内容闸可复现不服务更好)：产品合同或强吸引子原则两问都不成立 → **不写**，任何层都不进。任一成立 → 再选层。加的是**禁止句**时，先定层，再做[补集测试](/docs/03-AI核心/上下文工程.md#禁止句何时才该出现)：是上一句正向的反面 → 不进任何层。

1. 现有原则已覆盖 → **只加行为回归**，不改字面。
2. 当场 / 按需落点 → **不进常驻**：罕见场面 → **场面门或一次性尾**（先事实，姿势一句；挡路权威在 [检查点 · 挡路拍板](/docs/03-AI核心/检查点.md)）；按需能力 HOW → **`consult` 正文**；参数约束 → **schema**（短触发；写参当轮必见、且 consult 回执赶不上这次调用的合同，可上收进该工具 description / 参数，不另开 skill；现：`delegate` 编制、`ask_user` 填卡）；本回合环境 → **事实行**（只陈述，不写禁令）。
3. 常驻落点 → 新的常驻**身份**语义（工具图编码不了的策略残差，不是产品百科、不是头衔），在**唯一所有者**加一句原则；棘轮抬顶须在 PR 说明多出来的是什么（余量不足时抬顶是正道，不视为回潮）。

审议核里**已有**一句是否留下时，方向相反、仍走本闸：先过内容闸（两问都不成立 → 删）；再问删掉之后，**给定其余通道**（工具表、任务块、基座），非该场面的回合还要不要它来选动作？不要 → 出核。已有按需所有者 → 删核留所有者，禁止再抄「以免不 consult」。覆盖了的事故 → 只加行为回归，不把指针留在核里当护身。

禁止（不可进常驻）：会话 id、具体查询词、某次失败原话；编号判决树（要不要派 / 探路几轮 / 成文产线闭集）；用「字面必须出现在 `_CEO_CORE_HINT`」当回归（禁语或产品事实皆是）；何时用工具（写在该工具 description）；不要把工具图欠定的策略残差赶进 `consult`；署名 / 产品「你是谁」走 `product_help`，不进核。也不要用「别把身份赶进 consult」把产品事实留在核里。

### 测试守卫原则，不守卫字面

棘轮盯的是悄悄变长。改措辞（含一次改很多处）按内容落笔，不单开压字讨论，不删这次没点名的句子。红了先分清：新常驻身份语义走入场闸第 3 条，同一次改动里抬顶并在 PR 说明，不视为回潮；同一句话又抄进第二层则删这份抄写。远低于上限才把数字调下来。工具面 `tests/test_tool_schema_size_ratchet.py`；CEO 常驻总长 `tests/test_ceo_core_ratchet.py`（量的是基座+核，不含按需目录 / 挂门手册 / 易变尾）。`prompt_budget_char_soft_cap` 只观测不裁（见 [按需与写侧配额](/docs/03-AI核心/上下文工程.md#按需与写侧配额)）。

`test_prompt.py` / `test_skills.py` / `test_workspace_context.py` 守卫结构，不守卫现行教学句。钉 XML 开闭标签（注入槽；有残差才钉 `<身份>`；基座一段无标签）、英文工具/字段/skill 名、`consult(name)` / `HOW→consult`、`host(action=…)`、围栏 `【…】`、装配顺序、日期粒度、一层一处（标识符在所有者、不在别层）。不钉「挡路才问 / 生产者→消费者」这类帮助文案，也不钉目录摘要精确等于。一条契约一个测试所有者：schema 字段语义只在 schema 测；skill HOW 只在 `test_skills`；核测分层，无残差则断言不注入身份标签。影子测试因同一旧词失败 → 删影子，不要跟着改字。改功能时先改所有者测试；禁止为这次改动再加一条「新句必须出现」。

不守卫某次事故的禁语字面，也不守卫正向产品事实字面（禁止用核内必须出现某 URL / 入口名把层钉死）——那种回归属于 conformance / eval，或已有的收口结构测试（`test_closing_posture` 等）。出核后删对应字面断言，不改成缺席坟碑。激励必须可逆：**加判例不再零成本**；删判例或收成原则不应看起来像退步。废名连删；schema 用现行键白名单，禁止靠点名废字段「禁复活」——测试里也不写废名负表。回潮靠棘轮 / 分层 / 行为回归，不预埋词表。

### 瘦身不换闸

提示词变短之后，禁止用新硬闸 / 累计软提醒 / 扫用户长文的意图分类器「补服从度」。**拦截阶梯**不变 → `.cursor/rules/intercept-discipline.mdc`。删掉的判例若回归：回到入场闸（原则 / schema / 当场 / eval），不升级拦截。拦截阶梯 1（提示词）失败应观测 / 当场纠偏，不是跳到硬闸。已有结构契约硬拒（schema 必填等）不在「不换闸」的拆除范围。回潮用棘轮盯体积，不靠新闸补服从度。

### 目录行是触发器

`<按需目录>` 的 summary 只回答「这是什么」，名字只出现在 `consult("name")` 里，不裸列在行首。对照：`run` 那种一句名字。把跨文件夹步骤、FAQ 题面、落盘六步、场面 if-then 写进**系统**目录行，等于每回合为没拉的手册付注意力税。系统 Skill / 出厂工具的 WHEN 写在对应工具 description 或 skill 正文，目录行不当场面分类器。**用户 / 商店按需条目**的 `description` 是发现的全部，须兼写何时该查阅；空则不可检索（人侧编辑器按需才教这句）。**正交 WHEN 的 skill 不要为减名并成本**（例：`product_help` vs `page_ui`）——同一 WHEN 的细节（入口 / FAQ）收进该 skill（索引卡合同 + `consult("name:<节id>")` 语料），不拆成目录上的闭集分类器；目录行当触发器。能力指引的排列轴是决策时刻，不是 WHEN，也不写成目录子标题。

### 环境纠偏优于预写剧本

工具失败回执、委派结果尾的一次性软提示、journal 当场尾，比预先写十八种「若用户说了 X」更稳，也更符合「观测先于拦截」。点名「先了解」当普通干活（读文件）。→ [记忆 · 否决](/docs/03-AI核心/Agent记忆与知识系统.md#否决)。

### 否决

- **补集禁止**：把正向的反面再写一遍禁止——无信息量；真诱惑用 `≠` / 例外 / 吸引子，不叠补集。
- **判例入常驻**：常驻提示当事故日志（会话 id / 查询词 / 禁语近义词表）；用常驻判例顶结构验收；把编号判决树写进常驻核。
- **层放错**：按需 HOW 再挂进常驻核；事实行写禁令；把「何时用工具」写进核而不是工具 description；把工具图欠定的策略残差赶进 `consult`；为挡路 / `ask_user` 写场景黑名单；`HOW→consult(name)` 指向没有手册正文的查阅键（按需工具自指只回启用回执）；把写参当轮必见的合同挂成会被跳过的 skill（consult 赶不上这一次填参）。
- **产品事实冒充身份**：把官网 / 入口 / 价卡 / 「你是谁」百科写进 `<身份>`，再用「别把身份赶进 consult」挡瘦身。身份 = 工具图编码不了的策略残差；产品事实走该场面的 skill（如 `product_help`）。同条纪律：产品能力目录也不进用户规则 → [记忆 · 否决](/docs/03-AI核心/Agent记忆与知识系统.md#否决)。
- **重复抄写**：同一 HOW 在核 / skill / schema / 事实层再抄一份；用抬棘轮数字「修」回潮（别处已有的话又抄一份）——新身份语义抬顶不在此列。
- **瘦身换闸**：瘦身同时加拦截补服从度——**拦截阶梯** 1 失败应观测 / 当场纠偏，不是跳到硬闸。
- **测试钉散文**：用现行帮助句 / 说明书当回归；一条契约多个测试所有者；改措辞就改影子测试。
- **质量菜谱**：文风课、设计系统、论证强度、「写得更专业」的步骤——正向也不进出厂。挡预训练默认脸的原则（如 `consult(page_ui)`）不在此项 → [内容闸](/docs/03-AI核心/上下文工程.md#内容闸可复现不服务更好)。用户要冻编制 → 用户规则 / 上架，不出厂。不把「不够好」做成拦截。
- **头衔当能力**：出厂提示写「你是资深 X」指望更准或当法律安全垫。头衔改口吻与自信，不注入领域知识 → [角色提示与身份](/docs/03-AI核心/角色提示与身份.md)。

## 长度上限与截断（跨层判据）

硬上限的职责是**拦病态**，不是做内容取舍。

- **阈值定在正常绝不会碰到的量级。** 一个上限若在正常流量里常态触发，它就不再是安全阀，而是在用一个魔法数字替产品做内容取舍——这是设计缺陷，调大数字不能修。
- **正常路径要控规模，那不叫上限，叫预算分配**：结构感知（决策性内容优先于可再生叙述）、留可见标记、**生产者侧可感知**、可观测。
- **可感知状态禁止静默截断。** 已有分域定案：用户规则读侧不截、超窗须失败说清（[记忆 · 用户规则](/docs/03-AI核心/Agent记忆与知识系统.md#用户规则)）；文件树 `truncated` 一路送到 UI（[工作区](/docs/02-架构/工作区.md)）；`read` 禁止静默丢尾、通道截断标记与交付残缺标记语义拆开（[工具与能力](/docs/03-AI核心/工具与能力系统.md)）；长对话压缩真丢才出 `context_gap`（[执行引擎 §三](/docs/03-AI核心/执行引擎架构设计.md)）。本判据把同一条延伸到委派链。
- **同一份内容不得跨层重复截断。** 两层各按自己的数字切一遍，两侧看到的就不是同一份，且没有任何一层知道这件事发生了。
- **涨数字前先分类**：新语义可以抬；触发过频须重设计，不是抬阈值。未经实测的阈值是假设阀，须就地标注。

**为什么要立这条**：上列判据在用户规则 / 工作区 / `read` / 压缩各域已被独立定过，委派链上的硬帽多为无差别头尾截，生产者侧无感。CEO 综述已按这条落地：工人正文共享 `CEO_SYNTHESIS_BUDGET`（落盘走指针，不占池）；名册 / 缺口 / 终稿纪律不进这笔预算。拼好的包只经 `compose_all_completed_output` 一次，回合内 ToolResult 与收工 `ALL_COMPLETED.output` 是同一份；病态安全阀才是 `DELEGATE_OUTPUT_LIMIT`。曾用整包约四千字头尾切当内容整形（打在包装而非工人正文），已撤——禁止再抬那个数字冒充瘦身。反例（校准正确，勿「顺手统一」）：`DEP_CONTEXT_BUDGET` 与 `run_context` 块帽无触发记录，工人 task 体量远低于阈值。

否决：用调大常数「修」常态触发的帽；静默尾截决策性内容（已确认约束、验收口径、失败项、缺口）；同一个数字同时服务「防病态」与「控成本」两个目的。
