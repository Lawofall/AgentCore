# 上下文工程

> **定位**：注入侧决策备忘。装配收口于 `ContextAssembler`（`assemble_system_prompt` / `runtime/context/`，含 `PromptContributor`）。按需三源合一 `consult`，权威行为 → [记忆与知识 · 目标形态](/docs/03-AI核心/Agent记忆与知识系统.md)。**产品 AI 提示词写什么**（宪法非法例、一层一所有者、事故入场）权威在本文「提示词设计原则」。非装配实现权威（顺序/预算细节 → 记忆·执行引擎）。现行文出门检验 → [现行信息](/docs/01-产品/现行信息.md)。

## 认知同构 · 执行异构

对模型而言 Tool / Skill / 记忆等皆为 token；执行侧异构（Skill 只读、Tool 有副作用、Agent 有循环与状态）。原则：**默认不放，按需才拉**。

注入侧载体同构：Skill / 记忆主题 / 按需规则都是一条带 `description` 的 md 条目，异构只剩执行侧。

五杠杆（选择 / 时机 / 压缩 / 外置 / 分治）实现归属见记忆·工具·执行引擎·协作模式各篇——本文不复制。「谁来拉」：**模型自选**（否决 embedding / LLM 预筛）。

## 注入侧 Assembler

prompt 注入收口于 `assemble_system_prompt` / `runtime/context/` 的 `ContextAssembler`（含 `PromptContributor` 插件化）。这就是注入侧收口，不必再立门派。

否决叠一层「目录 + 按需取」超级 Provider：三份 consult 源已合并成同一种条目（低频工具另挂 `ToolConsultSource`，不共享 Tool 基类）；Tool 仍有副作用 / schema / 权限轴，registry 与条目刻意不共享基类；复杂度在写侧 / 执行侧 / 预算侧。余项（`role` 三分、市场 Skill 入基座）→ [记忆与知识](/docs/03-AI核心/Agent记忆与知识系统.md)。

守恒律：统一只罩注入侧；输出侧（副作用 / 循环 / 状态）复杂度搬家不消灭。

## 按需与写侧配额

`Consultable`（目录露出 + 按名取文）由 skill / rule / memory 三源实现，低频工具另挂 `ToolConsultSource`（只 promote 进 FC 表，不把 Tool 改成条目）。`MergedConsultSource` 为唯一源——**提示词目录与工具 `fetch_by_name` 读同一个实例**；有票时规则目录与正文都读 prepare 快照（与 always 注入同源，fetch 不另打云列表），故「目录里列了什么」与「按名能拉到什么」在结构上无法漂移。对外单一 `consult`；重名按 skill → tool → rule → memory 解析。生效方式对外仅 `常驻` | `按需`。权威行为 → [记忆与知识](/docs/03-AI核心/Agent记忆与知识系统.md)。

常驻配额闸在**写侧**：满了不许再往常驻加（AI 写超限抛错并推卡，用户改既有条目放行）；**读侧全量注入、不截断**。落地面：`memory/always_quota.py` + `GET /v1/documents/always-quota`。装配器上的 `budget` 字段不裁剪、不淘汰。**文件页不展示常驻池剩余字数**——用量条会把安全阀做成「还能再塞」；闸对人不可见，只在 AI 写满时推卡（文案不报字符配额）。COST-004 仍只观测不闸。

否决：读侧截断常驻做内容取舍；自动淘汰常驻条目；用调大读取帽「修」写超。

## 提示词设计原则

> **覆盖**：CEO 常驻核、全员基座、队员身份、辩论辩手/主持人、系统 Skill、工具 schema、场面门、一次性尾、引擎 `[系统提示]`。不覆盖用户规则 / 记忆正文（用户资产）。CEO 路由语义仍归 [编排器](/docs/03-AI核心/编排器与CEO主Agent.md)；本文只管**提示词怎么写、事故怎么进场**。
>
> 分层装配现状已有（`ContextAssembler` + `consult` + journal one-shot）。本原则钉的是内容政策：常驻写宪法，不写判例。按需 HOW 唯一所有者是 `consult`。How（入场闸怎么走、测什么、出门检验）→ `.cursor/rules/prompt-design.mdc`。

**行业对照**（钉原则，不是跟风清单）：Anthropic *Building Effective Agents*——先简单提示，只在 eval 证明需要处加复杂度，用工具回执与结构状态纠偏，而不是把边角预写成剧本。Anthropic Skills / Claude Code——渐进披露：目录只留何时拉，正文按需才进上下文。OpenAI function calling / Agents SDK——约束进 JSON schema 与参数描述，系统提示不复述 schema。验收旋钮对齐 [编排器 · 派活单三档](/docs/03-AI核心/编排器与CEO主Agent.md)，不进经理常驻或填参面。共同点：**常驻写身份、路由脊柱、诚实元规则、按需钩子；HOW 与边角靠 schema / 环境 / 按需 / 当场。**

长提示的真实成本不只是 token：指令互相打架、中间段被丢掉（lost-in-the-middle）、模型在例外里任意挑一条。再加一段禁令往往看起来像修了事故，实际在稀释宪法。

### 宪法，非法例

常驻提示只写**身份、路由脊柱、诚实元规则、按需钩子**。不写某次失败的话术剧本、不枚举禁说的近义词、不点名个案查询词。

事故复盘的第一问是「现有原则是否已经覆盖」。覆盖 → 只加行为回归（conformance / eval），不改常驻字面。未覆盖 → 按下节入场闸选**一个**落点，写一句原则或一场面门，不写判例。

### 分层边界：一层一所有者

同一条纪律在装配后的提示串里**只应出现一次**。谁写什么：

| 层 | 只写 | 不写 | 代码 |
|---|---|---|---|
| 环境事实 `<workspace_context>` | 本回合**事实**：位置、能力行、产物格式、挂载、出口路径、装没装配、宿主是哪种 | 禁令、下一步剧本、意图分流 | `runtime/context/workspace_context.py` |
| 全员基座 | 跨角色通用：文风、工具并行、不信任外部/队友文本、凭据、能力诚实、成稿举证底线、`<work_authority>`（权威序 / 当前课题跟工作区 / 冲突通道） | 某平台产物细则、CEO 路由、队员落盘 HOW、设计三问等进阶 | `runtime/resolve/prompt/base.py` |
| CEO 常驻核 | 管理者身份（`<role>` 含品类+官网一句）、**两棵树**（`<how_you_work>` ①–⑤：挡路 / 自己做 / 要不要拉人（必须·应该分写；点名开辩） / 拉几人 / 不要拉人（结局分层；公共事件研判）；`<how_you_act>` 甲–戊：这回合能力怎么动、对用户怎么说；禁止共用 ①–⑤）、对照结构面诚实、`consult` 钩 | 进阶 HOW、产品百科、能力操作手册（三分日志 / 启服 / 右坞）、编排场面 WHEN（跨文件夹 / Office / 空桌）、主拍板形状 / 审查同字面 / 未定案细则、继续项目跟工作区（基座 `<work_authority>`）、规则载体对照、按需能力手册全文、个案话术。短问/探路/自判是脊柱，禁止赶进 `consult`；禁止把①–⑤再写进行动树 | `runtime/resolve/prompt/ceo_core.py` |
| 按需能力 HOW | `consult` 正文 = 唯一手册（host / terminal / browser / 区外授权） | 挂进冻结核；把 schema 全文再贴一遍 | `capability_how_suffix`（只给 consult 拼） |
| 系统 Skill 正文 | 某场面的进阶 HOW（含 `work_discipline`） | 常驻复述；目录行塞手册 | `runtime/skills/` |
| Skill / 低频工具目录行 | **何时拉**（一句） | 操作步骤、禁令清单 | `catalog.py` summary / 工具 description |
| 工具 schema | 取值语义、短触发、`HOW→consult(name)` | 与核 / skill / consult 同文的路由手册 | 各工具；参考已瘦的 `debate` |
| 队员身份 | 叶子/captain 合同：form、handoff、escalate、本节点交付 | CEO 路由、全员已有的诚实元规则 | `runs/executor/identities.py` |
| 辩论辩手/主持人 | 本形态举证格式、角色口吻、裁判 JSON | 全员已有的检索词数；点名某场辩论的查询词 | `runtime/debate/` |
| 场面门 / 一次性尾 | 本场面**事实** + 至多一句姿势 | 把常驻手册再抄一遍；发明新问法 / 场面硬账 | 如 `attachment_material`、`<prior_delivery_gaps>` |
| 本节点 task | NL【目标·约束·验收】 | 全局政策、QA 旋钮 | 节点 `spec.task` |
| Playbook 内部闸 | 不写进提示词；闸在代码 | 把 `required_sections` / `code_audit_gate` 等拆成纯提示 | `runtime/runs/playbooks/` |
| 引擎当场文案 | 本回合纠偏（预算将尽、回炉原因） | 新的常驻法律；与 `closing_posture` 代码闸混为一谈 | loop / wind_down |
| 行为测试 | 原则仍在、重复已删、门控手册未常驻 | 「某句禁令字面必须出现在核里」 | 棘轮 + conformance / eval |

**为什么要立这条**：事实层最贴近「模型不知道什么」，写的人会顺手把「所以你该怎么做」一并写上；行为层不知道事实层已经写过，于是同一条约束两份、措辞还略有出入。模型拿到两个版本——比只写一处更糟，且会各自演化。典型回潮：浏览器 / 跨文件夹 / 区外授权 / 三分日志在事实层与行为层对打；挂号纪律散进 `<tool_use>` / `<delivery_baseline>` / `<claim_evidence>` / `citation`；`ask_user` 预填 `default` 在同一段里重复多遍。`host` / `terminal` / `browser`：HOW 只在 `consult` 正文；schema 为短触发。未进开场表 ≠ 未装配。

**按能力分支复写是最常见的回潮口**：能力诚实对 browser / host / mcp / terminal / code_execute / package_install / git 是**同一条**（未装配：一句边界 + 禁称已用 + 禁多轮复读；已装配：禁否决论文 + 禁邻格否决 + 未进开场表仍先 `consult` 再短探），写成每个能力各一份就是七份。权威在共享基座 `<capability_honesty>`；`ceo_core` 只留禁把未装配动作派进队员任务、以及「有没有/能不能」不是问方法。事实层只报该能力装没装配。

### 结构面先于散文面

能进 schema 必填 / 枚举、能力行、journal 一次性尾、工具回执的，**不要**再写进常驻散文。参数约束放工具面；环境真相当事实行；「上轮缺口不要整锅重派」当场注入，不必每回合常驻。

工具描述的参考形态是 `debate`（短触发 + 指向 skill）。膨胀形态几乎恒定：同一条约束在工具描述 / 参数描述 / 兄弟工具里各抄一份。体积按棘轮管 → [执行引擎 · schema 棘轮](/docs/03-AI核心/执行引擎架构设计.md)。

### 渐进披露：常驻 / 按需 / 当场

| 时机 | 放什么 |
|---|---|
| **常驻** | 每回合都要用的宪法 |
| **按需** | 进阶 HOW（`consult`）；低频工具 schema 进开场表之前也走同一目录 |
| **当场** | 本场面才成立的事实与一句姿势（硬挡冷启动幕、附件缺件、上轮交付缺口、徒劳重试） |

「模型可能不 consult」不是把手册打进常驻的理由。正解：目录行把**何时拉**写锋利；工具回执提示去 consult；该场面出现时走当场门。已有的 `<prior_delivery_gaps>` / `<prior_futile_retries>` 是当场纠偏的正确形态。按需 HOW 跟用户回合走：下一回合须再 consult；同回合 resume 须能再 `offer`（历史气泡里有手册但表上没工具 = 空窗，不是「核该常驻 HOW」的理由）。

### 诚实是一条元规则

用户可见主张必须对照本回合**结构真相**（能力行、交付状态、文件面板、工具回执）。禁止为每个谎言变体加一条「禁止说 XXX」。禁语表当硬闸已经撤过（误伤）→ [编排器 · 失败与否决](/docs/03-AI核心/编排器与CEO主Agent.md)；把同一张表改写进提示词，只是把闸换成常驻判例。

收口诚实：**档位真源**是 `delivery_verdict`；姿势 A / `requires_draft_ack` / 概览超限**默认影子、不回炉**；产物结构窄闸才真回炉。口径 → [执行引擎 · 可用性诚实性](/docs/03-AI核心/执行引擎架构设计.md)。禁止扫用户 / task 长文猜意图；**短允许表点名刷新除外**（记忆探索触发）。闭集声称探测不得扩面。

### 新事故入场闸

往任何产品 AI 提示词加一行之前，按序只选一个落点（本表 = **入场闸**，与拦截阶梯不是同一套编号）：

1. 现有原则已覆盖 → **只加行为回归**，不改字面。
2. 罕见场面 → **场面门或一次性尾**（先事实，姿势一句）。挡路怎么问权威在 [检查点 · 挡路拍板](/docs/03-AI核心/检查点与开工卡.md)；场面门不发明新问法、不写开场墙、不为单次失败写发卡剧本。
3. 按需能力 HOW → **`consult` 正文**，不进常驻核。
4. 参数约束 → **schema**（短触发，不抄手册）。
5. 本回合环境 → **事实行**（只陈述，不写禁令）。
6. 新的常驻**路由脊柱**语义 → 在**唯一所有者**加一句原则，棘轮数字须在 PR 里说明多出来的是什么（余量不足时抬顶是正道，不视为回潮）。

禁止：把会话 id、具体查询词、某次失败原话写进常驻；禁止用「字面必须出现在 `_CEO_CORE_HINT`」当回归。路由脊柱（短问、探路≠摸底、编制按缝）留常驻，禁止借「渐进披露」赶进 `consult`。

### 测试守卫原则，不守卫字面

棘轮**默认**只降不升；新常驻路由语义走入场闸第 6 条抬顶并在 PR 说明，不视为回潮。工具面 `tests/test_tool_schema_size_ratchet.py`；CEO 常驻总长 `tests/test_ceo_core_ratchet.py`（量的是基座+核，不含按需目录 / 挂门手册 / 易变尾）。`prompt_budget_char_soft_cap` 只观测不裁（见 [按需与写侧配额](/docs/03-AI核心/上下文工程.md#按需与写侧配额)）。

`test_prompt.py` 守卫：原则块还在、重复已删除、按需 HOW 未漏进开场核、核不断言装配态。不守卫某次事故的禁语字面——那种回归属于 conformance / eval，或已有的收口结构测试（`test_closing_posture` 等）。激励必须可逆：**加判例不再零成本**；删判例或收成原则不应看起来像退步。废名用缺席断言，禁止靠点名废字段「禁复活」。

### 瘦身不换闸

提示词变短之后，禁止用新硬闸 / 累计软提醒 / 扫用户长文的意图分类器「补服从度」。**拦截阶梯**不变 → `.cursor/rules/intercept-discipline.mdc`。删掉的判例若回归：回到入场闸（原则 / schema / 当场 / eval），不升级拦截。拦截阶梯 1（提示词）失败应观测 / 当场纠偏，不是跳到硬闸。已有结构契约硬拒（schema 必填、`form=prose`+非空 `artifacts` 等）不在「不换闸」的拆除范围。回潮用棘轮盯体积，不靠新闸补服从度。

### 目录行是触发器

`<按需目录>` 的 summary 只回答「什么场面该拉这一条」。对照：`verify_and_fix` 那种一句触发。把跨文件夹步骤、FAQ 题面、落盘六步写进目录行，等于每回合为没拉的手册付注意力税。

### 环境纠偏优于预写剧本

工具失败回执、委派结果尾的一次性软提示、journal 当场尾，比预先写十八种「若用户说了 X」更稳，也更符合「观测先于拦截」。冷启动：**仅空画像是软幕、不挡请求**，不与硬挡并列；硬挡三因（换绑 / 点名 / 空画像+工程信号）共用一条原则，不为每种触发抄一份剧本。权威 → [记忆 · 探索触发](/docs/03-AI核心/Agent记忆与知识系统.md)。

### 否决

| 方案 | 理由 |
|---|---|
| 常驻提示当事故日志（一点名会话 / 查询词 / 禁语近义词表） | 稀释宪法；与已撤的完成话术硬闸同构 |
| 按需 HOW 再挂进常驻核 | 唯一所有者是 consult |
| 事实行写「勿再弹 / 立即发卡 / 禁止臆造设置路径」 | HOW 泄漏；模型对照能力行即可，姿势归核或 consult |
| 用抬棘轮数字「修」回潮（别处已有的话又抄一份） | 先问是不是重复；新路由脊柱抬顶不在此列 |
| 瘦身同时加拦截补服从度 | **拦截阶梯** 1 失败应观测 / 当场纠偏，不是跳到硬闸 |
| 把 playbook 内部验收拆成纯提示词 | 与派活单三档「砍更狠」同一否决；验收住代码，不住经理散文 |
| 用常驻判例替代已删 `completion_criteria` kind（含「验码绿」完成话术） | S3 + intercept；错收工接盘 = 原则 + deliverable/落盘 soft + 人审 |
| 为挡路 / `ask_user` 写场景黑名单或复活场面硬账 | 挡路权威在检查点；场面门只注入事实，不发明问法 |
| 把路由脊柱（CEO 自判、短问、自己做、探路≠摸底）赶进 `consult` | 组队靠常驻提示词；常见短问勿先 consult |
| 读侧截断常驻提示做内容取舍 | 长度上限是病态阀，不是编辑器（见下节） |

## 长度上限与截断（跨层判据）

硬上限的职责是**拦病态**，不是做内容取舍。

- **阈值定在正常绝不会碰到的量级。** 一个上限若在正常流量里常态触发，它就不再是安全阀，而是在用一个魔法数字替产品做内容取舍——这是设计缺陷，调大数字不能修。
- **正常路径要控规模，那不叫上限，叫预算分配**：结构感知（决策性内容优先于可再生叙述）、留可见标记、**生产者侧可感知**、可观测。
- **可感知状态禁止静默截断。** 已有分域定案：记忆读侧不截、超窗须失败说清（[记忆与知识](/docs/03-AI核心/Agent记忆与知识系统.md)）；文件树 `truncated` 一路送到 UI（[双模式工作区](/docs/02-架构/双模式工作区.md)）；`file_read` 禁止静默丢尾、通道截断标记与交付残缺标记语义拆开（[工具与能力](/docs/03-AI核心/工具与能力系统.md)）；长对话压缩真丢才出 `context_gap`（[执行引擎 §三](/docs/03-AI核心/执行引擎架构设计.md)）。本判据把同一条延伸到委派链。
- **同一份内容不得跨层重复截断。** 两层各按自己的数字切一遍，两侧看到的就不是同一份，且没有任何一层知道这件事发生了。
- **涨数字前先分类**：新语义可以抬；触发过频须重设计，不是抬阈值。未经实测的阈值是假设阀，须就地标注。

**为什么要立这条**：上列判据在记忆 / 工作区 / `file_read` / 压缩各域已被独立定过，委派链上的硬帽多为无差别头尾截，生产者侧无感。⏳ 已判定待重设计：`CEO_SYNTHESIS_MAX_CHARS` 在正常流量里近半触发，且帽实际打在包装（名册 + 缺口 + 多人 pointer stub + 终稿纪律）而非工人正文，属内容整形器误用；同一份产出还会经回合内 `DELEGATE_OUTPUT_LIMIT` 与收口 `ALL_COMPLETED` 二次切，两侧 CEO 看到的不是同一份。反例（校准正确，勿「顺手统一」）：`DEP_CONTEXT_BUDGET` 与 `run_context` 块帽无触发记录，工人 task 体量远低于阈值。

否决：用调大常数「修」常态触发的帽；静默尾截决策性内容（已确认约束、验收口径、失败项、缺口）；同一个数字同时服务「防病态」与「控成本」两个目的。
