## 认知同构 · 执行异构

对模型而言 Tool / Skill / 记忆等皆为 token；执行侧异构（Skill 只读、Tool 有副作用、Agent 有循环与状态）。原则：**默认不放，按需才拉**。

条目化后（✅ 载体）注入侧连**载体**也同构：Skill / 记忆主题 / 按需规则都是一条带 `description` 的 md 条目，异构只剩执行侧。

五杠杆（选择 / 时机 / 压缩 / 外置 / 分治）实现归属见记忆·工具·执行引擎·协作模式各篇——本文不复制。「谁来拉」已决：**模型自选**（否决 embedding / LLM 预筛）。

## 决策：注入侧 ContextAssembler ✅；不另立 ContextProvider

**现状**：prompt 注入已收敛于 `assemble_system_prompt` / `runtime/context/` 的 `ContextAssembler`（含 `PromptContributor` 插件化）。这与「不建第二套大一统 Provider」不矛盾——Assembler 即注入侧收口，不必再立门派。

仍不建「目录 + 按需取」式超级 `ContextProvider` 的理由：

1. 三份 consult 源（Skill / 记忆主题 / 按需规则）走的是**合并成同一种条目**（读侧 ✅ 步 1，服务端+文件页 UI ✅ 步 2，余 ⏳ 步 3–4），不是「在三种异构源上盖一层 Provider」——收敛掉的是重复，不是差异。低频工具另走同一目录的第四源（`ToolConsultSource`），不共享 Tool 基类。
2. 条目侧同构之后，Tool 仍不同构于条目（有副作用、有 schema、有权限轴）；registry 层 Tool / 条目刻意不共享基类。
3. 复杂度在写侧 / 执行侧 / 预算侧；注入侧已有 Assembler，勿叠 Provider。

守恒律：统一只罩注入侧；输出侧（副作用 / 循环 / 状态）复杂度搬家不消灭。

## 扳机

- **A 抽接口**：✅ **已吃满**（步 1）。`Consultable`（目录露出 + 按名取文）现由 skill / rule / memory 三个源分别实现，低频工具另挂 `ToolConsultSource`（只 promote 进 FC 表，不把 Tool 改成条目）。`MergedConsultSource` 聚合为唯一源——**提示词目录与工具 `fetch_by_name` 读同一个实例**；有票时规则目录与正文都读 prepare 快照（与 always 注入同源，fetch 不另打云列表），故「目录里列了什么」与「按名能拉到什么」在结构上无法漂移。这是合并的主要风险被架构消掉而非靠测试盯住。对外单一 `consult` 工具；重名按 skill → tool → rule → memory 固定优先级解析。生效方式对外仅 `常驻` | `按需`；`conditional` 随条目化清理。eval 机制已就位但 baseline 经决策跳过。权威行为 → [记忆与知识](/docs/03-AI核心/Agent记忆与知识系统.md)。
- **B 建预算**：**✅ 已触发并落地**。触发出的既不是原设想的「长裁剪降级」，也不是读侧配额。触发源是取消固定文件名（`偏好.md` / `画像.md` / `导航.md`）后常驻集合失去天然上限；结论是**把闸放在写侧**——常驻满了不许再往常驻加（AI 写超限抛错并推卡，用户改既有条目放行），**读侧永远全量注入、不截断**。落地面：`memory/always_quota.py` + `GET /v1/documents/always-quota`；读侧已无 `keep_rank`（`rules_injection.py`）。`budget` 从预留读取点变成写侧用量口径；引擎不自动裁剪或淘汰（自动淘汰与读侧截断均已进否决表）。**文件页不展示常驻池剩余字数**——用量条会把安全阀做成「还能再塞」的预算；闸对人不可见，只在 AI 写满时推卡（文案不报字符配额）。旧 `max_instruction_*` 超限静默整条丢弃 + `keep_rank`（全局>文件夹、用户>AI）随权威档一并撤销——权威取消后该排序失去依据，且读侧不再有「淘汰」这回事。装配主干 + `PromptContributor` 插件化已落地；COST-004 仍只观测不闸。

## 分层边界：事实归事实层，HOW 归行为层

同一条纪律在装配后的提示串里**只应出现一次**。谁写什么：

| 层 | 只写 | 代码 |
|---|---|---|
| 环境事实 `<workspace_context>` | 本回合**事实**：执行位置、能力行、产物格式、挂载、产物出口路径（各约定目录现有文件或空）、某能力装没装配、宿主是哪种 | `runtime/context/workspace_context.py` |
| CEO 行为 | 「该怎么做 / 禁止什么」：路由、姿势、禁令 | `runtime/resolve/prompt/ceo_core.py` |
| 全员基座 | 跨角色通用纪律：挂号、凭据、交付与只读口径、未装配勿声称已用、已装配勿声称没有 | `runtime/resolve/prompt/base.py` |
| 工具面 | 取值语义留参数描述；跨工具路由 / 审批策略留工具描述 | 各工具 schema（→ [执行引擎 §五](/docs/03-AI核心/执行引擎架构设计.md)） |

**为什么要立这条**：事实层最贴近「模型不知道什么」，写的人会顺手把「所以你该怎么做」一并写上；而行为层的作者并不知道事实层已经写过，于是同一条约束在两层各活一份、措辞还略有出入。模型拿到的是同一条规则的两个版本——这比只写一处更糟，且两份会各自演化。典型回潮形态：浏览器指引 / 跨文件夹指挥 / 区外授权 / 三分日志在事实层与行为层对打；一条挂号纪律散进 `<tool_use>`、`<delivery_baseline>`、`<claim_evidence>`、`citation` 四处；`ask_user` 预填 `default` 在同一段里重复六次。

**按能力分支复写是最常见的回潮口**：能力诚实对 browser / host / mcp / terminal / code_execute / package_install / git 是**同一条**（未装配：一句边界 + 禁称已用 + 禁多轮复读；已装配：禁否决论文 + 禁邻格否决 + 未进开场表仍先 `consult` 再短探），写成每个能力各一份就是七份。权威在共享基座 `base.py` 的 `<capability_honesty>`（CEO 与队员都看见）；`ceo_core` 只留禁把未装配动作派进队员任务、以及「有没有/能不能」不是问方法。事实层只报该能力装没装配。

**回潮防线只有棘轮，没有闸**：工具面有 `tests/test_tool_schema_size_ratchet.py`；CEO 常驻核有 `tests/test_ceo_core_ratchet.py`（只许降不许升；可履约手册跟装配门走，例如区外两步交付挂 `external_mount_readonly`）。`prompt_budget_char_soft_cap` 只观测不裁（见 §扳机 B），不要误当上限。

## 长度上限与截断（跨层判据）

硬上限的职责是**拦病态**，不是做内容取舍。

- **阈值定在正常绝不会碰到的量级。** 一个上限若在正常流量里常态触发，它就不再是安全阀，而是在用一个魔法数字替产品做内容取舍——这是设计缺陷，调大数字不能修。
- **正常路径要控规模，那不叫上限，叫预算分配**：结构感知（决策性内容优先于可再生叙述）、留可见标记、**生产者侧可感知**、可观测。
- **可感知状态禁止静默截断。** 已有分域定案：记忆读侧不截、超窗须失败说清（[记忆与知识](/docs/03-AI核心/Agent记忆与知识系统.md)）；文件树 `truncated` 一路送到 UI（[双模式工作区](/docs/02-架构/双模式工作区.md)）；`file_read` 禁止静默丢尾、通道截断标记与交付残缺标记语义拆开（[工具与能力](/docs/03-AI核心/工具与能力系统.md)）；长对话压缩真丢才出 `context_gap`（[执行引擎 §三](/docs/03-AI核心/执行引擎架构设计.md)）。本判据把同一条延伸到委派链。
- **同一份内容不得跨层重复截断。** 两层各按自己的数字切一遍，两侧看到的就不是同一份，且没有任何一层知道这件事发生了。
- **涨数字前先分类**：新语义可以抬；触发过频须重设计，不是抬阈值。未经实测的阈值是假设阀，须就地标注。

**为什么要立这条**：上列判据在记忆 / 工作区 / `file_read` / 压缩各域已被独立定过，唯独委派与上下文管线从未按此审视——那条链上的硬帽多为无差别头尾截，生产者侧无感，日志里也看不见触发。⏳ 已判定待重设计：`CEO_SYNTHESIS_MAX_CHARS` 在正常流量里近半触发，且帽实际打在包装（名册 + 缺口 + 多人 pointer stub + 终稿纪律）而非工人正文，属内容整形器误用；同一份产出还会经回合内 `DELEGATE_OUTPUT_LIMIT` 与收口 `ALL_COMPLETED` 二次切，两侧 CEO 看到的不是同一份。反例（校准正确，勿「顺手统一」）：`DEP_CONTEXT_BUDGET` 与 `run_context` 块帽无触发记录，工人 task 体量远低于阈值。

否决：用调大常数「修」常态触发的帽；静默尾截决策性内容（已确认约束、验收口径、失败项、缺口）；同一个数字同时服务「防病态」与「控成本」两个目的。
