# 上下文工程

## 认知同构 · 执行异构

对模型而言 Tool / Skill / 记忆等皆为 token；执行侧异构（Skill 只读、Tool 有副作用、Agent 有循环与状态）。原则：**默认不放，按需才拉**。

注入侧载体同构：Skill / 记忆主题 / 按需规则都是一条带 `description` 的 md 条目，异构只剩执行侧。

五杠杆（选择 / 时机 / 压缩 / 外置 / 分治）实现归属见记忆·工具·执行引擎·协作模式各篇——本文不复制。「谁来拉」：**模型自选**（否决 embedding / LLM 预筛）。

## 注入侧 Assembler

prompt 注入收口于 `assemble_system_prompt` / `runtime/context/` 的 `ContextAssembler`（含 `PromptContributor` 插件化）。这就是注入侧收口，不必再立门派。

否决叠一层「目录 + 按需取」超级 Provider：三份 consult 源已合并成同一种条目（低频工具另挂 `ToolConsultSource`，不共享 Tool 基类）；Tool 仍有副作用 / schema / 权限轴，registry 与条目刻意不共享基类；复杂度在写侧 / 执行侧 / 预算侧。余项（`role` 三分、市场 Skill 入基座）→ [记忆与知识](/docs/03-AI核心/Agent记忆与知识系统.md)。

守恒律：统一只罩注入侧；输出侧（副作用 / 循环 / 状态）复杂度搬家不消灭。

## 按需与写侧配额

`Consultable`（目录露出 + 按名取文）由 skill / rule / memory 三源实现，低频工具另挂 `ToolConsultSource`（只 promote 进 FC 表，不把 Tool 改成条目）。`MergedConsultSource` 为唯一源——**提示词目录与工具 `fetch_by_name` 读同一个实例**；有票时规则目录与正文都读 prepare 快照（与 always 注入同源，fetch 不另打云列表），故「目录里列了什么」与「按名能拉到什么」在结构上无法漂移。对外单一 `consult`；重名按 skill → tool → rule → memory 解析。生效方式对外仅 `常驻` | `按需`。权威行为 → [记忆与知识](/docs/03-AI核心/Agent记忆与知识系统.md)。

常驻配额闸在**写侧**：满了不许再往常驻加（AI 写超限抛错并推卡，用户改既有条目放行）；**读侧全量注入、不截断**。落地面：`memory/always_quota.py` + `GET /v1/documents/always-quota`。装配器上的 `budget` 字段不裁剪、不淘汰。**文件页不展示常驻池剩余字数**——用量条会把安全阀做成「还能再塞」；闸对人不可见，只在 AI 写满时推卡（文案不报字符配额）。COST-004 仍只观测不闸。

否决：读侧截断常驻做内容取舍；自动淘汰常驻条目；用调大读取帽「修」写超。

## 提示词设计原则

> **覆盖**：CEO 常驻核、全员基座、队员身份、辩论辩手/主持人、系统 Skill、工具 schema、场面门、一次性尾、引擎 `[系统提示]`。不覆盖用户规则 / 记忆正文（用户资产）。CEO 路由语义仍归 [编排器](/docs/03-AI核心/编排器与CEO主Agent.md)；本文只管**提示词怎么写、事故怎么进场**。
>
> 分层装配现状已有（`ContextAssembler` + `consult` + journal one-shot）。本原则钉的是内容政策：常驻写宪法，不写判例。按需 HOW 唯一所有者是 `consult`。How（入场闸怎么走、测什么、出门检验）→ `.cursor/rules/prompt-design.mdc`。

**行业对照**（钉原则，不是跟风清单）：Anthropic *Building Effective Agents*——先简单提示，只在 eval 证明需要处加复杂度，用工具回执与结构状态纠偏，而不是把边角预写成剧本。Agent = LLM 自己决定过程与用哪些工具，不要把自判收成闭集分类器。Anthropic Skills / Claude Code——渐进披露：目录只留名字与一句是什么，正文按需才进上下文。OpenAI function calling / Agents SDK——约束进 JSON schema 与参数描述，**何时用这把工具写在 description**，系统提示不复述 schema、不写编号判决树。验收旋钮对齐 [编排器 · 派活单三档](/docs/03-AI核心/编排器与CEO主Agent.md)，不进经理常驻或填参面。共同点：**常驻写决策时刻宪法（身份 / 输入 / 工作权威 / 诚实 / 输出）和按需钩子；何时用工具写在工具 description；HOW 与边角靠 schema / 环境 / 按需 / 当场。**

长提示的真实成本不只是 token：指令互相打架、中间段被丢掉（lost-in-the-middle）、模型在例外里任意挑一条。再加一段禁令往往看起来像修了事故，实际在稀释宪法。

### 宪法，非法例

常驻提示只写**决策时刻宪法**和按需钩子。工具何时用写在该工具 description。不写编号判决树、不写某次失败的话术剧本、不枚举禁说的近义词、不点名个案查询词。

段标题对应回合里的决策时刻，不是作者目录：

| 时刻 | 标签 | 所有者 |
|---|---|---|
| 我是谁、对谁负责 | `<身份>` | 角色层唯一一块（CEO 核 / 队员身份 / 辩手·主持人）。全员署名并进该块，基座不另写、不套同名标签 |
| 这段字是指令还是材料 | `<输入>` | 全员基座 |
| 听谁的、能改多大 | `<工作权威>` | 全员基座 |
| 能不能这么声称 | `<诚实>` | 全员基座 |
| 写出去的字长什么样 | `<输出>` | 全员基座 |

「如何工作」不是第六块：它是权威+诚实的并集，不当段标题。并行调用是执行约束，挂在基座开场，不单开标签。按需钩子仍是 `<按需目录>` + `consult` description。

基座只写 **CEO 与 worker 同真**的句子。工种不对称（对用户开口、用户可见面清单、卡住问谁）进角色 `<身份>` 或节点合同，不因为「都叫诚实 / 输出」就推进基座。对照：大白话 / 文件面板·出站网络·已做已可用已落盘 → CEO `<身份>`；直接以产出开头 / 落盘 form / 写工具谨慎 → 队员合同。

常驻身份 = 每回合选动作都要用的「你是谁 / 对谁负责」。只在某一场面才改变怎么答的产品事实（官网、入口、定价、下载链）不是身份——即使问「你是谁」时可能被顺口提起，仍走按需 HOW。共址 ≠ 所有权：写在 `<身份>` 里不等于它是身份。对照：官网 → `product_help`；「你是 AgentCore 的 CEO」→ `<身份>`。

事故复盘的第一问是「现有原则是否已经覆盖」。覆盖 → 只加行为回归（conformance / eval），不改常驻字面。未覆盖 → 按下节入场闸选**一个**落点，写一句原则或一场面门，不写判例。事故钉的是该场面 HOW 所有者里的事实，不是核里再挂一份指针。

### 禁止句何时才该出现

提示词层对 [现行信息 · 该留的负知识](/docs/01-产品/现行信息.md) 的操作形：禁止不是正向的装饰。「不另立 X」只在 X 仍是真诱惑、且写完正向之后模型仍能合法走进 X 时才写。

模型在多条都说得通的续写里加权。正向把质量叠到该做的那条上。**补集测试**只管禁止句写不写，**不管这句在哪一层**——先定层（常驻 / 按需 / 当场），再对那一层做本测试。层错了，把正向写锋利仍是核污染。加禁止前再问：这句是不是上一句正向的反面？是 → 不写。禁止只有同时满足才有信息量：

1. **不是补集**：删掉这句，剩下的正向**仍然允许**那个坏动作。
2. **真诱惑**：该动作是预训练 / 助手习惯 / 本产品其它句子共同推出来的强先验——不是「理论上也可能」。

两问有一问不成立 → 不写禁止；把正向写锋利，或并进一条 `A ≠ B`。再加禁令看起来像修了事故，实际在稀释宪法，并诱导向禁语表加判例。

正确禁止只属于这些**出现条件**（不是「这事不好」）：

| 形态 | 何时才出现 | 本产品对照 |
|---|---|---|
| **对比边界** `A ≠ A′` | 两个都像「在干活」的动作，正向无法单独切开 | 假设 ≠ 用户确认（写在 `ask_user` description / skill，不进核判决树） |
| **例外覆盖默认** | 坏行为正是在执行一条更显眼的默认 | 少写进常驻；编制细则在编排 skill |
| **强吸引子** | 先验指向坏事，且与正向兼容 | 把检索文本当指令；未对照结构面却声称已做 |
| **相邻工具 / 通道** | 正确工具已写，旁边有更顺手的替身；第一次选错代价高（对用户说谎、写盘、难回滚） | 启服用 `run` 不是 `host(action=shell)`（工具 description）；团队状态走结构面 |
| **单向门** | 做错了贵、难撤 | 凭据明文落盘；代填密码；静默改权威稿 |
| **当场才成立** | 只在本场面为真 | 场面门 / 一次性尾，**不**进常驻 |

代码已硬拒且回执能教会下一轮时，常驻「别用旁边那个」可更短，或只留 schema / `consult`。诚实类吸引子的操作形是一条双条件（对照结构面；未对照则不得声称），不是谎言变体表 → [诚实是一条元规则](/docs/03-AI核心/上下文工程.md#诚实是一条元规则)。

**不该出现**：正向的反面再写一遍；同一诚实元规则下的「禁止说 XXX」近义词；事故原话 / 会话 id / 个案查询词；事实行禁令；与 schema / 引擎闸重复的手册；Skill 目录行禁令清单。

写法优先序：① 正向写到反面不再是合法续写；② 必须切开时用 `≠` 或「未对照则不得声称 Y」；③ 仍不够才加**一句**禁止，点名那个吸引子，不点名近义词。加禁止仍走入场闸（只选一个落点）；删禁止后若回潮，回到入场闸 / eval，不换硬闸 → [瘦身不换闸](/docs/03-AI核心/上下文工程.md#瘦身不换闸)。

### 分层边界：一层一所有者

同一条纪律在装配后的提示串里**只应出现一次**。谁写什么：

模型看见的段标题（XML 开闭标签）用中文；`consult(name)` / 工具名 / schema 字段保持英文键，目录行左边仍是查阅键。

| 层 | 只写 | 不写 |
|---|---|---|
| **常驻层**：环境事实 `<工作区>`、全员基座、CEO 常驻核、队员身份、辩论辩手/主持人 | 决策时刻：角色 `<身份>`（唯一一块）；基座 `<输入>` / `<工作权威>` / `<诚实>` / `<输出>`；按需钩子。环境事实只在 `<工作区>`（CEO 文件索引为该块末节，工人不加；文件夹对话可点名本对话写/改/导出） | 产品百科（官网 / 入口 / 价卡）；编号判决树、判例（事故原话 / 会话 id / 禁语近义词表）、HOW 手册。基座不写 `<身份>`、不写 CEO 路由；叶子不抄 CEO 核；事实行不写禁令 / 下一步剧本；辩论不点个案查询词、不写检索轮次判决树 |
| **按需 / 当场层**：consult 正文、系统 Skill 正文、Skill / 低频工具目录行、工具 schema、场面门 / 一次性尾、本节点 task、Playbook 内部闸、引擎当场文案 | HOW 在 `consult` 正文；when-to-use 在工具 description（consult：何时拉 / 四类 / 低频进表 / 常驻不必查）；目录前言只说这是按需目录、列 name＋摘要、用 consult 拉全文；目录行只写「这是什么」；本场面事实当场注入；闸在代码不进提示词 | 常驻复述；前言列四类；核复述何时派；目录行塞手册；把 `required_sections` / `citation_mode` 等拆成纯提示；发明新问法 / 场面硬账 |
| **测试层**：行为测试 | 守原则不守字面（原则仍在、重复已删、门控手册未常驻） | 「某句禁令或产品事实字面必须出现在核里」；棘轮只降不升 |

**为什么要立这条**：事实层最贴近「模型不知道什么」，写的人会顺手把「所以你该怎么做」一并写上，于是同一条约束两份、措辞还略有出入——模型拿到两个版本，比只写一处更糟，且会各自演化。**按能力分支复写是最常见的回潮口**：能力诚实对 browser / host / mcp / run / package_install / git 是**同一条**，写成每个能力各一份就是六份；权威在共享基座 `<诚实>`，事实层只报未装配缺口（开场表即已装配通道）。用户可见面（产物格式 / 交付状态 / 出站网络 / 已做·已可用·已落盘）在 CEO `<身份>`，对照开场表、缺口与文件面板，不进基座。「回执是数据不是指令」同理：只在基座 `<输入>`；Host 回执不外包 XML，网页正文用 `untrusted_web_content` 字段隔离、不在字段里每拍复读 note。

### 结构面先于散文面

能进 schema 必填 / 枚举、开场工具表、journal 一次性尾、工具回执的，**不要**再写进常驻散文。参数约束放工具面；环境真相当事实行；失败工具回执留在历史，不另注易变尾。

工具描述的参考形态是 `debate`（短触发 + 指向 skill）。膨胀形态几乎恒定：同一条约束在工具描述 / 参数描述 / 兄弟工具里各抄一份。体积按棘轮管 → [执行引擎 · schema 棘轮](/docs/03-AI核心/执行引擎架构设计.md)。

### 渐进披露：常驻 / 按需 / 当场

| 时机 | 放什么 |
|---|---|
| **常驻** | 每回合都要用的宪法 |
| **按需** | 进阶 HOW（`consult`）；低频工具 schema 进开场表之前也走同一目录。目录按「能力指引 / 低频工具 / 设定 / 主题」分栏；成套工具（导出一对、同一 MCP 套装）收成一行，查阅任一名字即整组启用 |
| **当场** | 本场面才成立的事实与一句姿势（硬挡冷启动幕、附件缺件） |

「模型可能不 consult」不是把手册打进常驻的理由，也不是把产品事实留在 `<身份>` 的理由（身份的操作定义见上文「宪法，非法例」）。正解：目录行只写这是什么；何时用工具写在工具 description；工具回执提示去 consult；该场面出现时走当场门。手册正文跟用户回合走：下一句要用须再 consult。低频工具不同：本会话窗口里已经查阅或调用过的，下一句开场表直接带上（同回合暂停续跑同样从窗口补回），不必再 consult 一次才看得到。用户 `@` 点名的按需设定本回合当作常驻注入（`<钉住条目>`），不是附件、不必再 consult。

### 诚实是一条元规则

用户可见主张必须对照本回合**结构真相**（开场工具表、交付状态、文件面板、工具回执）。这是诚实类吸引子的双条件（对照则声称；未对照则不得声称），不是禁语表：禁止为每个谎言变体加一条「禁止说 XXX」。禁语表当硬闸已经撤过（误伤）→ [编排器 · 失败与否决](/docs/03-AI核心/编排器与CEO主Agent.md)；把同一张表改写进提示词，只是把闸换成常驻判例。

收口诚实：**档位真源**是 `delivery_verdict`；姿势 A / `requires_draft_ack` / 概览超限**默认影子、不回炉**；产物结构窄闸、浏览器声称扫词硬回炉已撤；B1 空心措辞扫描已删。口径 → [执行引擎 · 可用性诚实性](/docs/03-AI核心/执行引擎架构设计.md)。禁止扫用户 / task 长文猜意图；**短允许表点名刷新除外**（记忆探索触发）。闭集声称探测不得扩面。

### 新事故入场闸

往任何产品 AI 提示词加一行之前，按序只选一个落点（本表 = **入场闸**，与拦截阶梯不是同一套编号）。加的是**禁止句**时，先定层，再做[补集测试](/docs/03-AI核心/上下文工程.md#禁止句何时才该出现)：是上一句正向的反面 → 不进任何层。

1. 现有原则已覆盖 → **只加行为回归**，不改字面。
2. 当场 / 按需落点 → **不进常驻**：罕见场面 → **场面门或一次性尾**（先事实，姿势一句；挡路权威在 [检查点 · 挡路拍板](/docs/03-AI核心/检查点与开工卡.md)）；按需能力 HOW → **`consult` 正文**；参数约束 → **schema**（短触发，不抄手册）；本回合环境 → **事实行**（只陈述，不写禁令）。
3. 常驻落点 → 新的常驻**身份**语义（你是谁 / 对谁负责，不是产品百科），在**唯一所有者**加一句原则；棘轮抬顶须在 PR 说明多出来的是什么（余量不足时抬顶是正道，不视为回潮）。

审议核里**已有**一句是否留下时，方向相反、仍走本闸：删掉之后，**非该场面**的回合还要不要它来选动作？不要 → 出核。已有按需所有者 → 删核留所有者，禁止再抄「以免不 consult」。覆盖了的事故 → 只加行为回归，不把指针留在核里当护身。

禁止（不可进常驻）：会话 id、具体查询词、某次失败原话；编号判决树（要不要派 / 探路几轮 / 成文产线闭集）；用「字面必须出现在 `_CEO_CORE_HINT`」当回归（禁语或产品事实皆是）；何时用工具（写在该工具 description）；不要把「你是谁 / 对谁负责」赶进 `consult`；也不要用这条把产品事实留在核里。

### 测试守卫原则，不守卫字面

棘轮**默认**只降不升；新常驻身份语义走入场闸第 3 条抬顶并在 PR 说明，不视为回潮。工具面 `tests/test_tool_schema_size_ratchet.py`；CEO 常驻总长 `tests/test_ceo_core_ratchet.py`（量的是基座+核，不含按需目录 / 挂门手册 / 易变尾）。`prompt_budget_char_soft_cap` 只观测不裁（见 [按需与写侧配额](/docs/03-AI核心/上下文工程.md#按需与写侧配额)）。

`test_prompt.py` 守卫：原则块还在、重复已删除、按需 HOW 未漏进开场核、核不断言装配态。不守卫某次事故的禁语字面，也不守卫正向产品事实字面（禁止用核内必须出现某 URL / 入口名把层钉死）——那种回归属于 conformance / eval，或已有的收口结构测试（`test_closing_posture` 等）。出核后改缺席。激励必须可逆：**加判例不再零成本**；删判例或收成原则不应看起来像退步。废名用缺席断言，禁止靠点名废字段「禁复活」。

### 瘦身不换闸

提示词变短之后，禁止用新硬闸 / 累计软提醒 / 扫用户长文的意图分类器「补服从度」。**拦截阶梯**不变 → `.cursor/rules/intercept-discipline.mdc`。删掉的判例若回归：回到入场闸（原则 / schema / 当场 / eval），不升级拦截。拦截阶梯 1（提示词）失败应观测 / 当场纠偏，不是跳到硬闸。已有结构契约硬拒（schema 必填、`form=prose`+非空 `artifacts` 等）不在「不换闸」的拆除范围。回潮用棘轮盯体积，不靠新闸补服从度。

### 目录行是触发器

`<按需目录>` 的 summary 只回答「这是什么」。对照：`run` 那种一句名字。把跨文件夹步骤、FAQ 题面、落盘六步、场面 if-then 写进目录行，等于每回合为没拉的手册付注意力税。**正交 WHEN 的 skill 不要为减名并成本**（例：`product_help` vs `team_cross_folder`）——同一 WHEN 的细节（入口表 / FAQ）收进该 skill 正文，不拆成目录上的闭集分类器；目录行当触发器。

### 环境纠偏优于预写剧本

工具失败回执、委派结果尾的一次性软提示、journal 当场尾，比预先写十八种「若用户说了 X」更稳，也更符合「观测先于拦截」。冷启动：**仅空画像是软幕、不挡请求**，不与硬挡并列；硬挡三因（换绑 / 点名 / 空画像+工程信号）共用一条原则，不为每种触发抄一份剧本。权威 → [记忆 · 探索触发](/docs/03-AI核心/Agent记忆与知识系统.md)。

### 否决

- **补集禁止**：把正向的反面再写一遍禁止——无信息量；真诱惑用 `≠` / 例外 / 吸引子，不叠补集。
- **判例入常驻**：常驻提示当事故日志（会话 id / 查询词 / 禁语近义词表）；用常驻判例顶结构验收；把编号判决树写进常驻核。
- **层放错**：按需 HOW 再挂进常驻核；事实行写禁令；把「何时用工具」写进核而不是工具 description；把「你是谁 / 对谁负责」赶进 `consult`；为挡路 / `ask_user` 写场景黑名单。
- **产品事实冒充身份**：把官网 / 入口 / 价卡等只在某一场面才用的事实写进 `<身份>`，再用「别把身份赶进 consult」挡瘦身。身份 = 你是谁；产品事实走该场面的 skill（如 `product_help`）。同条纪律：产品能力目录也不进用户记忆 → [记忆 · 三、维护协议（情景沉淀 → 语义巩固）](/docs/03-AI核心/Agent记忆与知识系统.md)。
- **重复抄写**：同一 HOW 在核 / skill / schema / 事实层再抄一份；用抬棘轮数字「修」回潮（别处已有的话又抄一份）——新身份语义抬顶不在此列。
- **瘦身换闸**：瘦身同时加拦截补服从度——**拦截阶梯** 1 失败应观测 / 当场纠偏，不是跳到硬闸。

## 长度上限与截断（跨层判据）

硬上限的职责是**拦病态**，不是做内容取舍。

- **阈值定在正常绝不会碰到的量级。** 一个上限若在正常流量里常态触发，它就不再是安全阀，而是在用一个魔法数字替产品做内容取舍——这是设计缺陷，调大数字不能修。
- **正常路径要控规模，那不叫上限，叫预算分配**：结构感知（决策性内容优先于可再生叙述）、留可见标记、**生产者侧可感知**、可观测。
- **可感知状态禁止静默截断。** 已有分域定案：记忆读侧不截、超窗须失败说清（[记忆与知识](/docs/03-AI核心/Agent记忆与知识系统.md)）；文件树 `truncated` 一路送到 UI（[双模式工作区](/docs/02-架构/双模式工作区.md)）；`file_read` 禁止静默丢尾、通道截断标记与交付残缺标记语义拆开（[工具与能力](/docs/03-AI核心/工具与能力系统.md)）；长对话压缩真丢才出 `context_gap`（[执行引擎 §三](/docs/03-AI核心/执行引擎架构设计.md)）。本判据把同一条延伸到委派链。
- **同一份内容不得跨层重复截断。** 两层各按自己的数字切一遍，两侧看到的就不是同一份，且没有任何一层知道这件事发生了。
- **涨数字前先分类**：新语义可以抬；触发过频须重设计，不是抬阈值。未经实测的阈值是假设阀，须就地标注。

**为什么要立这条**：上列判据在记忆 / 工作区 / `file_read` / 压缩各域已被独立定过，委派链上的硬帽多为无差别头尾截，生产者侧无感。CEO 综述已按这条落地：工人正文共享 `CEO_SYNTHESIS_BUDGET`（落盘走指针，不占池）；名册 / 缺口 / 终稿纪律不进这笔预算。拼好的包只经 `compose_all_completed_output` 一次，回合内 ToolResult 与收工 `ALL_COMPLETED.output` 是同一份；病态安全阀才是 `DELEGATE_OUTPUT_LIMIT`。曾用整包约四千字头尾切当内容整形（打在包装而非工人正文），已撤——禁止再抬那个数字冒充瘦身。反例（校准正确，勿「顺手统一」）：`DEP_CONTEXT_BUDGET` 与 `run_context` 块帽无触发记录，工人 task 体量远低于阈值。

否决：用调大常数「修」常态触发的帽；静默尾截决策性内容（已确认约束、验收口径、失败项、缺口）；同一个数字同时服务「防病态」与「控成本」两个目的。
