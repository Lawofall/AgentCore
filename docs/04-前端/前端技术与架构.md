## 五、客户端架构（桌面 + 手机）

**产品页单树**：对话 / 文件 / IM / 设置 / 登录走**桌面 renderer 同一棵树**（Electron · 生产 webapp · Capacitor 挂同一 `dist-web`）。壳自适应：宽屏 = 侧栏 + 右坞；**窄屏（<768px）** = 底栏 4-tab（对话 / 消息 / 文件 / 我的）+ 对话页 ☰ 会话抽屉 + 右坞全屏 sheet。能力黑名单减法仍走 `capabilities.ts`（本机盘 / sidecar / MCP / 热键 / 原生窗）。**否决** RN、纯 PWA。传输 = web SPA → Capacitor；Android WebView origin `https://localhost` 须进 CORS；无 Firebase 不得 `PushNotifications.register()`。

**范围**：窄屏不上工具箱 / 工作流 / 站立任务 / 手册 / 白板 / MCP 连接器 / 快捷键设置 / OS 浮窗。这些不是「手机另写」，是黑名单不上。空态「怎么用」是当场说明，不因此放开手册路由 → [前端 UX · 首启](/docs/04-前端/前端UX设计.md)。

**主题**：窄屏 / Capacitor **仅浅色**；宽屏桌面可暗色。

**会话抽屉 IA**（窄屏 ☰）：与宽屏同一三区（全局置顶 / 文件夹组 / 裸聊），**全量不设帽**（抽屉是唯一列表，没有「查看全部」；组序与宽屏同一份——未拖过按最近活动，拖过后手排钉死，抽屉不设帽故可排出第 7 组；云组头进文件、「＋」在此新开；本机组只列对话）。开着跟铸题（不顶位次）与位次（本对话 `message_start` / 他对话 fulfill running）；折组有等你则展开（盖 persist 不写回）；折叠记住（默认全展开，勿学宽屏侧栏「只展开当前组」）。行灯：等你光环压过云端执行中（`GET /v1/fulfill` observer，**不**扩 realtime）。删除是软删、不二次确认：主路径抽屉内撤销条，兜底「最近删除」视图（对话行可恢复；无文件夹那半、无彻底删除）。活列表可分享只读快照链接（所见即所享，可撤销）。

**减去的是本机盘，不是写权限（✅）**：云工作区在窄屏上**可写**——改名 / 移动 / 删除 / 新建文件夹 / 文本文件 CAS 编辑（同一套 `edit` 契约与冲突二选一）/ 软删区还原。只有**本机**工作区仍只读：那些字节在用户电脑上、服务端一律 409，故 UI **整个不传写契约**（而不是摆一排必然失败的禁用按钮），并如实说明「请在桌面端打开」。工作区**生命周期**（新建 / 删除工作区、绑定本机文件夹）仍归宽屏桌面；窄屏可**点选已有云文件夹**开新对话；裸聊写盘自动建的文件夹落「我的文件」，对话内不另出告知条。

**否决**：为窄屏另写主回复页 / 文件 / IM / 设置；窄屏再养一套 `apps/mobile` TabLayout 作长期产品壳；把宽屏 `AppShell`（侧栏 + ≥280px 坞）原样缩到 390px。

**否决各端全新建一套业务页**（漂移与 UI 分叉盖过「共享核爆炸半径」）。fold **只留桌面一套**；`pnpm conformance` 只跑桌面。协议常量仍走 `@agentcore/protocol-fold-kit`。浏览器窄屏走 `app.` 同源 cookie SPA；独立 `m.` 站**已下线**。Capacitor 仍 Bearer，挂 `dist-web`。

**桌面价值**（vs Web）：后台常驻 + 通知、热键、本地文件、本地 MCP。**否决** PWA / 全原生 / Tauri（备选）。

**主进程**：renderer 本地加载；SSE 直连后端或经 sidecar `/v1/inference`（不经 IPC）。✅ local-store 只读离线；✅ outbox 回写器（主进程耐久，renderer 退出 HTTP 回写）；✅ sidecar recovery/attach。⏳ `connection-manager` / `mcp-pool`。边界 → [双模式 · Sidecar / 契约 α](/docs/02-架构/双模式工作区.md)。

## 十、SSE 与协议一致性

入口：`services/sse/dispatch.ts`（单一分发）；传输/重连在 `streamConversation.ts`。事件语义 → [SSE 事件与录制回放](/docs/03-AI核心/SSE事件与录制回放.md)。

**约束**：发送即有流（POST 恒 SSE；`turn_queued` / `turn_queue_started` / `turn_queue_cancelled` EPHEMERAL；运行中插话 `user_interjection` DURABLE）；✅ `delivery` 必填。产品默认与原语 → [运行时三模型 · 同对话再发](/docs/03-AI核心/运行时三模型与挂起.md#同对话再发steer--queue)。Store 最小更新；乐观发消息（含草稿首发：先画在 draft slice，建完 `adoptDraftRuntime`；生成中再发 ack 即入主时间线用户泡）；⏳ `reconcileAllRuns` 未实现。

**打开对话水合**：消息窗与 `loadRecovery` 并行；**UI ready** = 消息窗 adopt 之后（有 opened 本地快照则先揭，空数组不得 adopt/抢先揭）。有正文或列表确认 `messageCount===0` 时 **不等** recovery；冷 GET 空窗且非确定空会话则 overlay 等 recovery 把 unsynced **严格更厚** 的同 id 投影完再揭，仍空且列表 `messageCount!==0` →「对话加载失败」（禁止 ready 白板；空数组不得写入 opened 缓存；不等活 sidecar 回合结束）。本机传统开跑即有云 `user+running`（契约 α），冷 GET 可带 overlay 正文；**overlay 的 `isGenerating` 不是本端泵**——attach 所有权只认 `hasLocalConversationStream`（同会话 `startTurn` 仍活时外层跳过 attach）。attach/settle 经 `scheduleHydrateAttachSettle` 在 recovery 落地后后台跑（本地 sidecar live 不挡已有正文的揭开；error 后 attach 仍可后台继续）。在线 SWR：有 opened 本地快照则先揭开再 reconcile。切会话保留最近 5 个 idle slice（busy 不踢）以暖开；**切会话 ≠ 卸 sidecar 观察泵**（hydrate 不传页级 AbortSignal；显式 detach 另传）。本地事实（sidecarLive / unsynced）→ 投影 + attach，**不调** `resolveSidecarRoot`、不走云 attach；无本地事实 → 云 `attachOnOpen`。live attach：journal 回放段经 `: attach-caught-up` 边界一次折叠（避免已完成 worker 再走 running→completed），再 live tail；`full_replay` **原位**清空正文/过程/执行槽、保留气泡 id（换泡会把已画 Markdown 卸掉）；sidecar 快照同步 fold。✅ **多端同权**：云侧另有**对话级订阅**（`GET …/stream?follow=true`，`conversationFollow.ts`）——揭窗即订、切走立刻停（follow-only 落下 `isGenerating`，不杀本端 POST/sidecar）；所有权只认 `hasLocalConversationStream`；页 AbortSignal 只取消该 effect 的窗 GET（cleanup 先 `cancelled` 再 abort，overlay 只认 `cancelled`）；游标仅 fold/dispatch 后推进。空闲会话也挂得住、新回合自动接上（不再 204），同一回合可多端同时跟播互不挤占；与回合级 attach 靠「本端连接闸」让位，同端只保一条。跨会话「等你」灯以 fulfill `ai_attention_snapshot` 整表 replace 为权威（空表灭假灯），增量 `ai_attention` 可走 fulfill / realtime；打开对话不清灯（`stores/aiAttention.ts`）。列表 `GET …/messages` 只带正文 + 薄过程摘要（`runs.events` 可截断并标 `events_complete=false`）；协作图 / 回合详情再 `GET …/messages/{id}` 拉全量 journal 后 fold（禁止用骨架 journal 折图）。`jumpToMessage` around 空窗不写；重叠 id 保留更厚气泡（禁止整窗更薄替换，但不挡历史切片跳转）。契约 α：刷新双面恢复、resume 中勿只信云薄壳；hydrate **不**放宽、**不**透传 unsynced journal 充云投影。→ 代码 `ConversationPage` / `sliceLru` / `streamConversation.attachConversation`；权威 [双模式 · 契约 α](/docs/02-架构/双模式工作区.md)、[运行时三模型](/docs/03-AI核心/运行时三模型与挂起.md)。

**conformance**：`fold(events)→ProjectedTurn` 纯函数；后端 oracle 裁判；`pnpm conformance`。向量 = 手写 builder + 录制裁切并存。纪律 → `protocol-conformance.mdc`。payload **叶字段消费棘轮**（给已有事件加可选字段但 desktop / admin / fold-kit 没人读 → CI 红；存量分组豁免）→ `apps/server/scripts/check_event_field_consumers.py`。

`ProjectedTurn` 的 TS schema（`packages/protocol-conformance/src/projectedTurn.ts`）**维持手写**；**否决**「从后端生成」：oracle（`agentcore/conformance/projection.py`）出口是裸 `dict[str, Any]`，无 Pydantic/TypedDict，要生成就得先给 oracle 补结构化模型——那是动整个体系的唯一基准实现，一次字段语义打滑（如 Pydantic 给默认值 vs 原 dict 不放键）会同时移两端基线且 `pnpm conformance` 抓不到，因为套件的 ground truth 就是该 oracle。手写的残余风险只剩**纯类型层**：无向量覆盖的「可选 vs 可空」，以及 TS 声明了但没有任何 fold 去填的死字段。值层形状由 `diffProjected` 走 golden ∪ actual **键并集**守住（`harness.ts`）——Python 加字段 → golden 有、actual 缺 → 红；fold 多吐字段 → actual 有、golden 缺 → 同样红，故漏改 TS 不产生静默错判。（golden-only 切片只用于可选 `turnVerdict` 旁路 `diffTurnVerdict`，那里多余字段确实被忽略。）**另否决**为此加「TS 键集 ↔ golden 键集」对账脚本（对账兜底，触补丁绊线）。

**离线预览**：`#/preview` 经真实 dispatch 回放；**否决** Storybook / 手写 mock。e2e：Playwright + webapp 壳 + 向量 SSE；**否决** `route.fulfill`。→ `frontend-preview.mdc`。
