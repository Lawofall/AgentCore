> **读投影**：协作图 / 双视图消费 SSE 折叠态（如 `projectExecution`），**不是**执行写权威。派发与协调态记账在后端 `drive*` / `CoordinationSession`；边界权威 → [编排器 · 执行写路径 vs 进度读视图](/docs/03-AI核心/编排器与CEO主Agent.md#执行写路径-vs-进度读视图)。

## 三、内嵌协作图与状态条

多 Agent 团队界面 = 消息内嵌 `InlineTeamGraph`：状态条四态 + 可折叠图；「在画布打开」→ `TurnDetailPage`。窄屏同一套内嵌图，点节点开 sheet（竖排 `TeamView` **已随手机 fold 退役**）→ [前端技术 §五](/docs/04-前端/前端技术与架构.md)。

| 场景 | 行为 |
|------|------|
| 简单任务（无 plan） | **不出图** |
| `delegate` | `run_plan` 到达自动内嵌 |
| 跨回合延续 | 新回合另起一张图、锚在**本**回合，自带完整内嵌图；「新开一队、接着上一张继续」锚点挂在**当前**图上（`prev_execution_id`，桌面可点跳回上一张，手机仅文案行）；文案不写「续自 / 追加 N 名」——跨回合是新图接上文，不是往旧图加人。桌面宿主气泡不在已加载消息窗时退化为不可点说明（尚有更早记录 → 「往上翻可查看」，否则「不在当前对话」），**否决**静默吞点击。**否决**旧模型「生长 divert 回旧气泡、新回合只剩锚点条」——图锚错回合、进度分母吃上一轮已完成节点、journal 因宿主回合已死被丢。**否决**把上一张的 run 画成灰态上游节点 / 跨图依赖边：图只画本回合拓扑，跨图上游得让旧 run 进本图 payload（协议新增一类节点）且两端各加一种渲染态（手机是纵向精简版，无 canvas / ELK），当前只有锚点点不动这一条实测证据，撑不起这个代价；外图 `continuesRunId` 因此在 `graph/helpers.ts` 显式丢弃，不是漏画 |
| 开工挂起零 run | **不出图**（注意力归续跑卡） |
| 完成 / 停止 | 战绩收缩 / 「已停止」（只陈述，无救火按钮） |

**硬停改动入口**：状态条不挂「改动 N 个文件」。与气泡末产物卡「查看改动」同进右坞「改动」tab，再挂是第二入口。**否决**状态条再挂改动 chip；**否决**队员详情再嵌「工作区改动」（与「改动」tab 同组件，清单是回合基线不是这个人写的文件）。

**状态条只报战绩（定案）**：细工具栏——生命周期图标（无解说句）+ `n/m` + 用时 + 回放/折叠 + 「在画布打开」。**否决**任务摘要 / 「等待你确认」等解说标题、「团队完成」大字、条上「停止整轮」（主槽输入框已有停止）、合成草稿行寄居状态条（成员细节走图节点）。**否决**「接续 N 次」（对比只走全屏页顶栏「对比」；图上「续 ×N」只陈述）、「互相把关」计数行（升级卡/节点已是事实；气泡脚也不挂）、「同时开工省下」并行省时（反事实对比；图已表达并行）、已拍板开工卡摘要「预计 N 人开工」（开工卡产品位已拆；开跑后图即编制。resolved 预览不寄居状态条，图已出现时也不回时间线废卡——与「N 个 Agent」已删同因：和图重复）。**否决**气泡顶栏派工铬条「本轮未派工 / N 人进行中 / 已收工」：有派工看图与条上 `n/m`；没派工就是普通气泡。组过队之后每轮单答再标「未派工」是负向标签。`team_batch` 仍在 `message_end` / journal（诚实性与观测），用户面不渲染。

**失败收口**：协作图状态条只报战绩——meta 的 `n/m` + 图节点色 + 右坞详情，**不**另挂「N 个子任务失败」红条；救火统一「对 CEO 再说」或再发一条（同人续派 / `continue_from_run_id`）。**否决**状态条「重试」「重试失败项」、`retry-failed` API、叠「全部重生成」、显式忽略（新 turn 隐式收口）、无帧「继续」、传输/续跑错误条「重试」「重连」、**助手红错误卡上的「重新生成」**（定案 A：错误卡本身不挂整轮 regenerate——整轮推翻易乱，救火改再说/改发；卡上仍留「复制排查包」/去配置。底栏 footer 不在此列，归属见下「一回合一处判决」）。传输失败仅 `RetryBanner` 文案 + 关闭（可选「去配置」）。`cancelled`/`interrupted` 不出 finishReason chip。

**一回合一处判决（定案 ✅）**：一个终态回合只出**一处判决 + 一处恢复动作 + 一处「复制排查包」**。起因是生产实测里一次上游 429 点亮了五条互不知情的错误管线，用户同时看到两条横幅、给出互斥建议（「2 秒后重试」与「发下一条重试」）。收敛姿势：每端一个回合仲裁器（`lib/turnOutcome.ts`）算出判决 `kind` + `recovery` + 一组呈现旗，气泡 / 状态条 / 输入区退化成**笨渲染器**只读旗。**否决**组件各写叶子 `if`（八处互斥点自增长，正是双横幅的成因）；**否决**按 `execution.status` switch 出终态脸——限流与部分完成时它仍是 `cancelled`，会画出「已停止」盖掉真实原因；**否决** `finish-reason-chip` 自藏 `error` 分支（同一个失败被灰标与红卡各判一次）。**停止不是错误**：用户主动停止 `kind` 恒 `ok`，空停止整泡不渲染，有正文只留半成品（半成品本身就是结果）。**宿主唯一**：排查包宿主是单值（气泡 / 状态条 / 输入区提示 / 会话条），有团队图时**条是主判决**、气泡不重复红卡；空中断反过来——判决只在输入区提示上，排查包随之挂那里（那是「它就那么停了」最需要报障的形态，收敛不得把入口弄丢）。**部分完成 + 上游限流（定案 A ✅）**：条只报战绩（`部分完成` + `n/m` + 用时），**不**挂「上游限流，暂时无法继续本回合。」，也**不**回潮「未能交付：N 项未完成」（呈现甲已撤）。限流 why 与排查包挂输入区轻提示，发送下一条即恢复——与空中断同一宿主，不与「条是主判决」抢；无团队图时也不走气泡红卡。**否决**条上第二行解说句。底栏 footer 保留在失败气泡上，`recovery=none` 的硬失败里它就是唯一重试口；有具名恢复（去设置 / 等待重试 / 发下一条）时整条 footer 关掉，不与主恢复动作抢主次。限流暂停（`outcome=paused`）走独立续跑闩，why 贴在「继续」旁，公式冻结不随其余终态改动 → [执行引擎 · 重试只在一层](/docs/03-AI核心/执行引擎架构设计.md)。

**桌面一套仲裁器，判决已进 `pnpm conformance`（✅）**：主体比对桌面 fold 出的投影脸（不含判决旗），fixture 另开**可选 `turnVerdict` 旁路**——桌面 fold 后跑 `lib/turnOutcome`，再走同一套 diff，改判决规则会被门禁拦。已知漂移登记在 `packages/protocol-conformance/src/turnVerdictGaps.ts`：**字段级**（禁整条向量豁免，否则同向量的新漂移会被一并吞掉）+ 理由 + **双向棘轮**（未登记字段漂了要红；已登记字段不再漂**也**要红，逼着删条目）。信封统一为 `hasTeamStrip` + `supportPackHost`。条目数**以该文件为准、勿在此复述**（空表 = 与 golden 逐字对齐）。手机 fold **已退役**，不再双端对账。权威 → [`cross-platform-frontend.mdc`](/.cursor/rules/cross-platform-frontend.mdc)。→ 见代码：桌面 `lib/turnOutcome.ts`

默认展开，按对话持久化。多幕 LOD：≥2 幕恰好一幕展开 DAG；**否决**默认全展开。face 徽标 ≤2；行动条仅 ≥2 待决。**否决**「规划中」态（`run_plan` 同步到达）。

**运行中再发（P0+P1 ✅）**：composer 不禁发。Steer / Queue / Stop、默认、气泡与 QueuedTurnsBar → [运行时三模型 · 同对话再发](/docs/03-AI核心/运行时三模型与挂起.md#同对话再发steer--queue)。图上不表现插话 → 下段。

**插话不进图（定案 ✅）**：协作图只讲执行拓扑（谁做什么 · 依赖谁）与回合先后，**没有**「回合内时刻」这一维——回合先后在聊天时间线、DAG 是本回合执行依赖，都不是时间轴。用户插话是时刻性**对话事件**，主叙事定在聊天视图的过程时间线（零宽 marker 钉真实发生位置 → [运行时三模型 · 时间线落点](/docs/03-AI核心/运行时三模型与挂起.md#同对话再发steer--queue)）。**否决**团队块底部「插话追溯」折叠列表（`UserInterjectionsPanel` 已删——与主时间线双写，正是它降级再删的原因）；**否决**回合级「本回合有 N 条插话」徽章（弱化版双写）；**否决**图内插话节点连向被影响 worker 的因果表达（图的母语确是因果，但需新增「插话→哪个 run」的后端因果契约，本切片不做）。代价：协作图上用户干预无痕迹，**接受**。

检查点 / plan_review / ResumePrompt / InteractionStore：语义 → [检查点与开工卡](/docs/03-AI核心/检查点与开工卡.md)。内联卡只留 resolved；**挂起**可操作面统一 `ResumePrompt`（「需要你拍板」）。不挂住全场的提问走 `escalation`（兄弟继续跑）；答案不要紧则不出卡、模型在回复里写明假设。**否决**题目 accordion、Wizard、消息流再堆可操作入口。决策区 `ConversationDecisionPrompts` 单挂载在聊天时间线（画布指挥台那份已随总览撤除 → §六）。

## 五、图视图

内嵌 = 静态预览（禁缩放）；探索在放大态。节点 face：角色→在干什么→用时；¥/token 归 run 详情。点节点 → SidePanel（主坞或已浮出的对应面板；高亮跟**焦点面板**的 run）。邻居跳转回图上点节点；**否决** run 详情再列依赖 / 后续 / 上级 / 子任务（与图双写）。inject 入边只在图上按需高亮，「收到的上下文」仍展示正文。

**按人干预只在详情（定案 ✅）**：「只改这个人的方向 / 只停这个人」挂在右坞 run 详情（点节点即开），图节点只陈述「他正在干什么」。桌面右坞与手机队员详情共用 `RunInterveneControls` + `protocol-fold-kit/runIntervene`（同判定同文案）。**否决**卡片下沿干预条——与右坞同一套动作双写；点节点已开详情，悬停就地改/停不够补那份噪音。**终局不画入口**：跑完 / 失败 / 取消 / 跳过整条不渲染（桌面右坞、手机详情同一判定 `isLiveRunStatus`）——死按钮停不了也改不了，改方向改说给 CEO。排队未开工仍露出（可停；改方向灰掉并说明还没开工）。辩论幕不开放改方向属**能力本就不存在**，该按钮整体不渲染（见 `planCapabilities`）。**否决**终局变灰占位。

**布局 / 相机（白板模型）**：ELK **只**在结构变更时跑；`NODE_WIDTH`×`NODE_HEIGHT` 为布局权威 footprint，face 槽内裁切/滚动。相机只在结构 bbox 就绪/身份变化或容器尺寸变化时 fit（内联一次 fit-width）；**否决**测高二次 ELK、soft-center 抬 footprint、测高伺服相机。宿主常驻：`layoutReady` 不卸载 ReactFlow；内联折叠隐藏不卸树。契约 → `graphHost.tsx`。

**节点 = 一次执行（run）**：独立产出→新节点；轮内从属 beat→折进宿主；状态变化→角标。**否决**单卡堆叠 ×N、工具点节点。无 `continues_run_id` 的同 role ≠「同一人」。辩论不开放「改方向」。能力表一处声明 `planCapabilities.ts`。两个宿主（内嵌 / 全屏）共用 `graphHost`；布局失败显式错误。

子队盒：接续链归属单源 `layoutHints.ts`。辩论：一列=一轮，质询折进轮节点；结辩独立列。身份色 ⊥ 状态色。信息流边仅有损交接挂签。审计 inject 按需高亮；**否决**全量虚线、迷你 DAG、改 conformance。波次=拓扑层；跨委派用 `delegateBatch`（不进协议）。

## 六、两个入口：聊天内嵌 ⇄ 全屏放大

一份数据两种渲染（同 `projectExecution`）；切换不动协议。**聊天是唯一常驻面**——对话页恒 `ChatView`，看编制与进度都在聊天里（状态条 + 内嵌图 + 过程时间线）；要看大图 / 辩论 / 对比，走「在画布打开」进全屏 `TurnDetailPage`（纯深读、无命令栏）。**说只在聊天** `TurnComposer`。入口文案仍叫「在画布打开」，指的是全屏放大态，与下面已撤的总览无关。

**已撤：对话顶栏总览画布（2026-08）**。原设计是对话页左上「聊天 / 画布」段控件切出的第三个宿主 `ConversationCanvas`——同一份 `projectExecution` 摊成多回合脊柱 + LOD + 指挥台。撤的理由**不是**「没人用」（没有点击率证据，也不拿它当门禁），而是**它不产生独立的用户工作**：老板要的可见是「还在跑 / 等我 / 交到哪了」，聊天已经全给了，总览只多给一个空间、不多给一个动作。代价那侧则是实打实的——它是独立于 `GraphView` 的**第二套 ReactFlow**（自带脊柱布局、相机、键盘导航、回合轨道），还把指挥台叉进 SidePanel、与聊天决策卡互斥、给 composer 套第二层皮、多存一份 `conversationViews` 偏好。**指挥台随之撤**：它本就是「画布态卸掉 `ChatView` 之后、决策卡的复活面」，宿主没了，卡回归聊天时间线即可，不需要第二处装配。

| 方向 | 处置 |
|---|---|
| 对话顶栏「聊天 / 画布」总览 | **已撤**（2026-08） |
| 只藏入口、代码留着 | 否决——第二套宿主的维护税还在，等于没撤 |
| 连内嵌图或 `TurnDetailPage` 一起撤 | 否决——这两个才是「看」的主入口 |
| 把总览改成「图上指挥」再救 | 否决——插话 / 拍板 / 收文件不是图的母语 |
| 图即唯一界面 | 撤 |
| 对话页卡片化 | 撤 |
| 自适应默认切模式 | 否决 |
| 真持久团队实体化 | 暂不做 |
| 跨对话公司级画布 | 不在范围 |

对比透镜仅非辩论同人接续链；辩论对照归辩论室。图技术：**否决** D3、自研画布。性能：节点 ≤50；帧率按**实测原生刷新率**验收——**否决**写死 ≥60fps（高刷屏下 16.7ms 预算过松，曾让主线程 ELK 阻塞全程漏检）。真机取证 `shoot:graph-perf-live`；离线 `shoot:graph-perf` 最多 9 节点且不触发 ELK，**不能**当性能证据。

→ 见代码 `components/graph/`、`pages/TurnDetailPage.tsx`。
