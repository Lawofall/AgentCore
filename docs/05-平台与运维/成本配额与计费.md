# 成本、配额与计费

> **状态**：目标形态 = §〇·六 `billing_mode=platform` 全量代付 + 免费版 `quota_*`（默认 **5 积分/月 · 5 积分/日**）+ 付费席位 per-user 覆盖。**现网可临时 `BILLING_MODE=byok`**（平台代付休眠、无 Key → 402；再开 = 改回 `platform` 重启 api）→ **运维步骤见 §〇·七**。**dev 默认仍 `byok`**。台账权威 = **整数 nano 卖价-CNY**（1 积分 = ¥1 卖价 = 10⁹ nano；无 live FX）。Flash 平台卖价 = DeepSeek 官网人民币列表价 × 0.25；BYOK 仍官网且不扣积分。无独立「免费档」路径（免费版就是默认 `quota_*`）。计费记账 + 配额 + 限流 ✅。付费席位 = 链动小铺购买 → 卡密自动发货 → 应用内兑换；到期自动改回免费版。自动扣款 / 充值钱包 / 加购包不做。

>
> 鉴权与会话见 [`认证与会话.md`](/docs/05-平台与运维/认证与会话.md)；工具审批等安全治理见 [`安全权限与治理.md`](/docs/05-平台与运维/安全权限与治理.md)；**前端成本呈现**见 [`../04-前端/前端成本呈现.md`](/docs/04-前端/前端成本呈现.md)。

## 〇、为什么成本是产品而非基建

用户能看见这一回合的花费，积分按同一套卖价扣，所以计费在产品面。组团时花销按 run 的 `agent_id` 拆开，明细与聚合行带 `persona` / `role`；单回合工资单与 `cost.recorded` 的 `by_role` 按角色呈现。per-run 聚合由 per-call 明细推导，服务额度与复盘。账户仪表盘给窗口总额 / 积分 / 30 日趋势 / 按对话活动表（列头筛模型，汇总跟筛选），**不做月维度按角色看板**（角色工资单在气泡「用量」）。（✅ run 级积分可拆；✅ 人设级拆账；✅ 账户按模型 + 按对话活动。）

## 〇·五、计费模式：部署开关 + per-turn origin

**两档部署形态**（`config.billing_mode`）：

| 形态 | 谁付钱 | 无 Key / 无平台凭据 | 配额 |
|---|---|---|---|
| `byok`（dev 默认） | 用户自带上游 | **402 `LLM_KEY_REQUIRED`** | 有 key 的 BYOK 回合**不查**配额 |
| `platform`（生产目标） | 平台代付；自带 Key 为进阶选项 | 平台凭据缺失 → 503；用户可自备 key 走 BYOK | 平台路径过 `quota_*`（免费版 5 积分/月·5 积分/日；付费档 per-user 覆盖） |

用户侧不预选「模型来源」：聊天框选模型。这场覆盖（否则能力默认）的主模型是平台行 = 平台计费，是 BYOK 行 = 自担费用。多服务商列表在「设置·服务商」（`user_llm_providers`：label + 密文 key + base_url）；日常选模型在输入框，槽位计费不变。行业对齐见 [`平台LLM接入.md` §二](/docs/05-平台与运维/平台LLM接入.md)。

**一道闸门**：所有用户向 LLM 调用（云回合 / file assist / sidecar 推理代理）共用 `billing/gate.py::preflight_llm_credentials(model_origin=…)`：

- `origin=byok`：解密本回合 `provider_id` 凭据（fail-safe；pinned 服务商不可用 → 回落账号默认）→ 有凭据直接返回（**不查配额**）；无任何服务商 → **402 `LLM_KEY_REQUIRED`**。
- `origin=platform`：平台凭据缺失 / byok 部署未开放代付 → 503 / 402；否则过 §一 `enforce_quota` 后用平台 key。

**计费语义（call 级凭据来源）**：卖价 = 该模型官网价 × 该模型倍率。1 积分 = ¥1 卖价。`credential_source` 分流列（`llm/pricing.py::resolve_credential_source` / `sell_multiplier_for`）：

- **用户 BYOK key** → **积分记账恒 0**（`cost_total_nano=0`），token 照记；官网价（倍率 1.0）落 `cost_estimated_nano` / 气泡 ¥（永不进配额 SUM）。
- **平台主 key** / **厂商 extras key**（`doubao/` 等） → 卖价入账（整数 **nano 卖价-CNY**）。Flash 倍率 0.25；Claude 0.3；GPT-6 0.18；GLM-5.3 / GLM-5.3-Flash / Kimi K3 平台 ×2；其余默认 1（含 glm-5.2 回落）。运营可按模型改倍率；glm ×2 是 glm 官网 ×2，不是 2× DeepSeek。Anthropic / OpenAI 官网 USD 按冻结 7.2 CNY/USD 折成 CNY 卡，无 live FX。上游实付不进这把尺。

**价卡**：只认 curated CNY。Flash（官方 `deepseek-flash`、常见别名 `deepseek-v4.1-flash`、退役 `deepseek-v4-flash` / Zen-free）共用 **DeepSeek 中文官价**（空闲 ¥0.02 / ¥1 / ¥4 每百万，高峰 2×；峰谷随调用时间：北京时间工作日 9:00–12:00、14:00–18:00；周末全天空闲。中国法定节假日未编码，那些工作日可能按高峰记），**平台再 ×0.25**。Claude Opus 4.6 / 5.5 / Fable 5.1、GPT-6 Astra / 6.1 Sol：Anthropic / OpenAI USD 列表价 × 冻结 7.2，平台再 ×0.3 / ×0.18。GLM-5.3 / GLM-5.3-Flash / Kimi K3 人民币列表价、平台 ×2；豆包 / glm-5.2 回落 / kimi-k2.5 vision 默认 ×1。退役 Pro 无卡。查无卡：用户路径不出钱（token 仍记，费用位空）；平台/vendor 回落 glm-5.2 + `cost.pricing_fallback`。社区 USD 快照不再进用户面。`Cost.pricing_source` 有卡即 `curated`。platform/vendor 漏配仍 glm 回落 + warning。目录 `ModelPriceCard.multiplier` 是卖价相对该模型官网的倍率；`quota_multiplier` 是相对 Flash 空闲卖价、同等 1M 输入 + 1M 输出的消耗积分倍率。弹层目录行写官网倍率（≠1 写 `0.25x` / `0.3x` / `2x`；×1 不写）。搜索下说明行写「此倍率相对该模型官网价」；`?` 打开对照表（每百万输入 / 输出积分、相对默认：Flash「以此为 1」，其它 `Nx`；空闲卖价；高峰脚注）。卡片标题下一行平台不写描述；不写卖价积分数字、不把基准写成 1x；行上的官网倍率不在卡片重复。BYOK 卡片仍 ¥。

**后台 chrome**（title）：人不可选。代付开着钉 `PLATFORM_BACKGROUND_MODEL`（默认 Flash）+ `enforce_quota`。关掉代付跟随这场主模型。组合 background 槽不读。平台不可用（配置缺失，或上游 auth 拒绝 / 余额不足 / 订阅因付款方式停了）经 `run_background_llm` **一次**回落用户 BYOK（跟主模型）。耗尽 → skip（铸题降级），不 429 主回合、不对用户弹出和主聊天拧着的「请改用自己的 API Key」。**长对话压缩**跟这条对话的聊天付款方走（`run_compaction_llm`）。→ [`平台LLM接入.md` §二](/docs/05-平台与运维/平台LLM接入.md)。原 followups（「下一步」chips）已下线。

**服务商管理面**：`/users/me/llm-providers`（列表 / 增删改 / test / defaults）。AES-256-GCM 落库，见 [`安全权限与治理.md` §七](/docs/05-平台与运维/安全权限与治理.md)。

→ 见代码 `billing/gate.py`、`billing/preference.py`、`llm/resolve.py`、`llm/provider_service.py`、`llm/pricing.py`、`api/routes/llm_providers.py`

> **已废**：独立「每月免费额度」路径（`free_tier_*` / `PLATFORM_FREE_TIER_ENABLED` / `FREE_TIER_EXHAUSTED`）。平台代付只走统一 `quota_*`。

## 〇·六、平台额度默认 + 席位套餐 + 自带 Key

> 生产主姿势 = **平台代付 + 免费版积分（5/月·5/日）+ 付费席位含用量 + 自带 Key 进阶选项**。动机：BYOK 默认偏开发者向，与「面向大众」错位；行业常规是平台代付 + 额度制。付费不锁云端对话。

| # | 决策 | 内容与被否方案 |
|---|---|---|
| F1 | 部署形态 = `billing_mode=platform` | 全员代付、`quota_*` 限额组、耗尽 `QUOTA_EXCEEDED`。无第二套「免费档」限额组 |
| F2 | 额度数值 | 月 **5 积分** · 日 **5 积分** · 日 token 0；admin 每用户覆盖 / `is_unlimited`。列名 `quota_*_cost_cny`（env：`QUOTA_*_COST_CNY`；存卖价 CNY = 积分）。**已废**日请求配额（默认 500，按 assistant 回合计）：一次回合既不是成本也不是速率，短问先撞次数、组团先撞金额。花钱归日/月金额，刷量归滑窗限流；回合数只留用量统计 |
| F3 | 平台上游与模型集 | `PLATFORM_*` + **显式 allowlist `PLATFORM_MODELS`**（否决中转全量发现）。**每模型凭据** `PLATFORM_MODEL_CREDENTIALS`；**账号池** `platform_credentials`（admin CRUD；空池回落 env 单 key；fill-first + commit 前 429 换号，见 [平台 LLM](/docs/05-平台与运维/平台LLM接入.md)）。单点 `platform_llm_credentials(model)`。无 CNY curated 价卡的 id → **不上架** |
| F4 | 记账价 = 卖价 | 消耗积分 = 该模型官网价（元）× 该模型倍率。Flash 平台 0.25（峰谷仍按官网再 ×0.25）；Claude 0.3；GPT-6 0.18；GLM-5.3 / GLM-5.3-Flash / Kimi K3 平台 ×2；BYOK 1.0 且不进配额。其余默认 1，运营可调。无 live FX（Anthropic / OpenAI 用冻结 7.2）。上游实付不进这把尺。平台目录缺卡 = 漏配 |
| F5 | 模型不限档 | 一律按卖价扣积分；日成本帽兜底；不做「高档限量」 |
| F6 | 耗尽行为 | 主文案：本月积分用完、**额度重置后可继续**；**低于旗舰才说开通更高档**（用量将尽 CTA 看 `seat.plan`；闸门拒绝句按月帽 ≥100 积分 / 日帽 ≥10 积分推断）；旗舰用尽只重置 + BYOK。客户端主 CTA「去订阅」。次级「接入自己的 key」（设置·服务商）。文案**不写钟点**——重置瞬间以 `reset_at`（ISO8601 UTC）随错误信封下发，客户端按读者本机时区成文（原「下月 1 日（UTC）重置」被 UTC+8 用户照字面读，差了八小时）。REST 挂 `error.reset_at`，SSE / 推理叶挂 `error.context.reset_at`。信封不点名页面 |
| F7 | 自带 Key = 进阶选项 | 目录默认平台行；有 key 才出「自己的端点」；guide rows 在平台目录可用时退役。与「高级版」席位不是同一个词 |
| F8 | 文案纪律 | 「免费版含平台积分」，不说「送 N 元」；平台用户面写积分不写含¥；**自己的 Key 费用位写 ¥**（气泡脚、资源消耗、用量明细；混合一轮 `积分 · ¥`）。折扣只靠模型倍率，不二次扣减。月度清零不结转；避免余额 / 资产语义 |
| F9 | 防滥用 | 邀请制关闸可配；IP / 用户限流、inference token 限流不变 |

**套餐（席位 + 含用量）**。产品四档，一个账号一席。订阅页货架只摆三张付费卡（基础 / 高级 / 旗舰，一列）；免费档不占卡。消耗积分 = 官网价 × 倍率（DeepSeek 平台 0.25）。付费 = 兑换对应档兑换码，系统把该用户 `quota_*` / 搜索次数写成下表，并记下 `seat_plan` + `seat_until`。云端对话 / 本地对话 / 组团 / 辩论各档都有。已开通的旧上限到期前不改写；续费 / 新兑码走下表。

| 档 | 月费 | 平台积分上限 | 平台搜索 |
|---|---|---|---|
| 免费版 | 免费 | 月 5 · 日 5（全局 `quota_*` 默认） | 日 40 · 月 400 |
| 基础版 | ¥19.9 | 月 20 · 日 5 | 日 80 · 月 800 |
| 高级版 | ¥49.9 | 月 55 · 日 8 | 日 150 · 月 1500 |
| 旗舰版 | ¥89 | 月 100 · 日 10 | 日 300 · 月 3000 |

日帽是跑飞刹车，不是第二件商品。付费档接近 1 元 1 积分，高级约送 5 积分、旗舰约送 11 积分。开通：设置 · 订阅「去购买」外开链动小铺对应商品（基础 / 高级 / 旗舰各一个 30 天 SKU，续费买同一件）；小铺付款后**卡密自动发货**；回到订阅页贴兑换码立刻开通。**购买本身不加积分**——积分上限随席位覆盖改写。链动小铺是唯一购买入口，无应用内收款码。**席位从兑换日起 30 天**（到期日发登录邮箱，不走全站官方号——官方号是广播）。积分窗口仍是日历月 / 日，不结转。兑换码未使用可经小铺退款；兑换后本周期不退；付错档可补差。月中升档付该档全月价，周期从兑换日再滚 30 天（已花不重置）。降档到期后再生效（本周期不回收；兑低档码会排队到当前 `seat_until`）。到期前 3 天邮件提醒；到期未续费宽限 3 日，其后自动清覆盖回免费版。到期前续费从原到期日再 +30；宽限后已改回再兑 = 从本次兑换起新的 30 天。组团 / 辩论与普通对话同一把积分。用尽硬停，无慢速池、无加购钱包。`is_unlimited` 只给内部号。用户面写「本月上限 N 积分 / 每日上限 N 积分」，不写「含 ¥」。付费卡价格下写「DeepSeek 约官网 4 倍用量」（相对掏的现金；三档相同；不写第二个¥、不进打勾列表）。订阅页按 `seat_plan`（含宽限）标「当前」；免费用户无「当前」卡，推荐钉高级版。

展示数字 → 桌面 `subscriptionPlans.ts`。席位账在用户行：`seat_plan` / `seat_until` / `seat_pending_plan`。兑换码库存 → `redemption_codes`（只存哈希，明文只在 admin 生成时返回一次）。开通回执（登录邮箱，勿发全站 Notice）：

```text
已开通{基础版/高级版/旗舰版}。设置 · 用量里的上限已生效。席位从{开通日}起 30 天，至{到期日}。到期前续费请再购买同一档兑换码。
```

到期前 3 天提醒同一邮箱：「席位将于{到期日}到期，续费后从该日起再 30 天。」

**部署**：dev 默认 `byok`；本地要走和线上同一条付钱的路 → [本地开发 · 两条起步路](/docs/02-架构/本地开发.md#两条起步路)（独立 Key，禁止填生产池）。生产 `.env`：`BILLING_MODE=platform` + `PLATFORM_*`（主机与 Key **只写在不入仓的部署 local**，公开仓不写现网供应商；目录 allowlist 须有 CNY curated，见 [平台 LLM · §五·附](/docs/05-平台与运维/平台LLM接入.md)）+ 免费版 `QUOTA_*_COST_CNY`。贴这套 `.env` **前**须按该上游自己的地区 / 模型闸实测通过，否则全体用户一起撞上游拒绝。改 `.env` 后**必须重启 api**（无热更）。临时下架 / 恢复平台额度 → §〇·七。**明确不做**：充值钱包 / 加购包 / 自动扣款（积分是卖价 CNY 的用户面单位，不是第二套账本）；live FX / `cny_per_usd` 热更新；并发配额维（暂无信号）；为云执行另立配额维。不接微信支付商户、不按小铺 webhook 对邮箱开通——卡密就是履约凭证。

若上游是**整户共享**窗口，产品侧每用户额度拦不住全站一起被挡；单号打满时池换号，全池打满才全体被挡。兜底是用户侧「接入自己的 Key」。窗口细节按绑定端点，不在用户面点名供应商 → [平台 LLM · §五·附](/docs/05-平台与运维/平台LLM接入.md)。

**落地要点**：allowlist + per-model 凭据 → `llm/catalog.py`（缺 curated → 不上架，`platform_catalog.pricing_missing`）；系统预置由 listable 平台目录投影；日成本第四维 `quota_daily_cost_cny`；F6 文案单一来源 `conversation/quota.py`；`QuotaStatus.daily_cost_nano` 贯穿 usage / admin。→ 单测 `tests/test_quota.py`、`tests/test_model_catalog.py`、`tests/test_platform_model_credentials.py`。

## 〇·七、现网临时下架平台额度（运维）

> 复用既有 `BILLING_MODE` 部署开关（§〇·五 / §〇·六），**不是** Admin 热开关。改 `.env` **必须重启 api** 才生效，无热更。

| 动作 | 步骤 |
|---|---|
| **下架** | 生产 `.env` 设 `BILLING_MODE=byok` → **重启 api**。平台代付休眠；无用户 Key → 402 `LLM_KEY_REQUIRED`；有 Key 的 BYOK 回合照常、不查配额。 |
| **恢复** | `.env` 改回 `BILLING_MODE=platform`（`PLATFORM_*` / `PLATFORM_MODELS` / `QUOTA_*` 保持完整）→ **再重启 api**。现网平台目录由部署 env 决定 → [平台 LLM · §五·附](/docs/05-平台与运维/平台LLM接入.md)。 |
| **同步公告** | 下架时发 Notice：模板 **`quota_unavailable`**（[产品公告文案模板](/docs/05-平台与运维/产品公告文案模板.md) §4.1）。恢复时**归档**该条，并发 **`quota_platform_restored`**（同文 §4.2）。也可 `pnpm publish:notice`。仍在线的旧额度公告一并归档（旧模板 id 清单不在公开仓）。 |

**Notice 默认口径（与模板 `quota_unavailable` 一致）**：

- **标题**：`平台额度暂时不可用 · 请接入自己的 Key`
- **正文**：

```text
平台提供的额度暂时不可用。

请到「设置 · 服务商」接入自己的 Key 即可继续使用。
```

## 一、三层防线

三层正交：限流挡「刷得太快」，配额挡「用得太多」，计费只忠实记录、不拦截。

| 层 | 位置 | 管什么 | 失败行为 | 现状 |
|---|---|---|---|---|
| **限流** | 路由层（按用户）+ 中间件（按 IP） | **速率**——单位时间内的请求次数 | 超额拒绝（429 + `Retry-After`） | ✅ 已落地（默认内存单进程；`RATE_LIMIT_BACKEND=redis` 切多 worker 安全的 Redis ZSET 滑窗，含请求级 fail-open） |
| **配额** | 业务层（回合开始前 **+ 每次上游 LLM 调用前**） | **总量**——日 token / 月成本 / **日成本** | 开跑前超额 → 拒绝该回合（429）；回合中途超额 → 拒绝后续调用 | ✅ 强制已落地（含每用户覆盖 + admin `is_unlimited`） |
| **计费** | Finalize（append-only） | **记账**——每个 Run 的真实成本 | 失败 warning + 入共享 DB outbox 后台重试，不中断回合 | ✅ 已落地（详见 §三、§四） |

### 限流（速率防线，✅ 已落地）

两个互补的限流器（默认内存、单进程；配 `RATE_LIMIT_BACKEND=redis` 即切 Redis ZSET 滑窗，多 worker 安全）：

- **按用户限流**（✅ 路由层滑窗）：在消息发送 / 重新生成端点按已认证用户限频，挡单账号刷回合。因按用户需已认证主体，落在**路由层**（紧邻 `enforce_quota`）而非中间件；用**滑窗**（非固定窗口）避免边界 2x 突发；被拦的请求不记账。超额抛 `RateLimitedError` → 429 `RATE_LIMITED` + `Retry-After`。→ 见代码 `conversation/rate_limit.py`、`middleware/rate_limit.py`
- **按 IP 限认证端点**（✅ 中间件固定窗口）：限登录/注册/刷新端点（默认 10 次/60s），挡撞库；非 auth 路径与未登录请求放行。→ 见代码 `middleware/rate_limit.py::AuthRateLimitMiddleware`

回合开始前三道闸顺序：**限流（按用户）→ 所有权 → 配额**——限流最外，未过则不做资源级 DB 查询。

前端如何呈现「被拒回合」见 [前端成本呈现](/docs/04-前端/前端成本呈现.md)。

✅ 多 worker 限流：`RATE_LIMIT_BACKEND=redis` 经 `RateLimiter` protocol 缝切到 Redis ZSET 滑窗（`RedisSlidingWindowRateLimiter`）/ auth 固定窗（`RedisFixedWindowRateLimiter`），调用点零改动。✅ **请求级 fail-open**：Redis 请求期报错→放行（fail-open）并记 `rate_limit.redis_fail_open`（warning + 进程内累计 `count`，可告警）；只放松「速率」防线，DB 支撑的「总量」配额防线不经 Redis、不受影响；工厂构造期不可达仍回落内存。→ 见代码 `middleware/redis_rate_limit.py`

> **多 worker**：账本队列已迁共享 Postgres ``cost_ledger_outbox``（每进程可自 drain）。进程内单例（履约中枢 / 跟播）仍一律拒启——**勿宣称全面多机就绪**。权威 → [部署拓扑 · API 进程约束：多 worker 一律拒启](/docs/05-平台与运维/部署拓扑与环境.md#api-进程约束多-worker-一律拒启)

### 配额（总量防线，✅ 强制已落地）

> 此防线管**平台代付路径**：`billing_mode=platform` 全员代付。**BYOK 有 key 用户不查配额**（用户自担上游账单）——这是**既定姿态而非缺口**：配额的产品目的是保护平台出资；BYOK `cost_total_nano` 恒 0（名义价走展示列，§〇·五）使金额口径配额天然不覆盖它属**设计使然**，勿当 bug 修。

| 决策 | 内容 |
|---|---|
| 检查时机 | **两道**：① 回合开始前（路由 `preflight_llm_credentials` → `enforce_quota`），超额 → 429 `QUOTA_EXCEEDED`，SSE 未开先拒；② **每次上游 LLM 调用前**（叶子围栏 `ObservingLLMProvider`），超额 → `LLMQuotaExceededError`（同 code、走叶子错误面，`retryable=False`），可中途拒。云内联与 sidecar 推理代理**同粒度** |
| 三维度 | 日 token / 月成本（卖价 CNY = 积分）/ **日成本（卖价 CNY）**；**0 = 该维度不限**。单一默认组 `quota_*`（`config/quota.py`）= **日 token 0 · 月成本 5 积分 · 日成本 5 积分**。**为何用日成本兜底**：多模型目录单价差 ~30×，日 token 帽映射不了钱 |
| 每用户覆盖 | `users` 表 `is_unlimited` + 金额三维度覆盖（NULL=继承全局；含 `quota_daily_cost_cny`）以及平台搜索次数 `quota_search_daily` / `quota_search_monthly`；`scripts/set_quota.py` 或 admin API（`PATCH /v1/admin/users/{id}`）设置 |

**为何逐调用**：只在回合开始查一次时，配额挡不住两种超卖——**并发回合**（同时开跑的回合各自读到同一个旧数字、全部放行）与**团队扇出**（一个 Multi-Agent 回合内部扇出多少 worker、跑多少轮完全不再复查）。sidecar 那条路本就逐调用查（每次调用都是一次 `/inference/` 请求，路由闸照跑），云内联路径不查 = 同一个产品承诺两条路一严一松。且 §六 已拍板**不做成本预估**，配额因此是跑飞风险的**唯一刹车**，必须真的拦得住。

**口径**：闸只管**平台代付**——判据是 call 级 `credential_source != user`（platform / vendor 都由部署出钱，`cost_total_nano` 非零），与计价侧同一判据，不另起启发式；BYOK 不查（上方既定姿态）。代理转发的调用不重复查（`/inference/` 路由已为同一次物理调用查过）。额度读走 **telemetry 池**（台账本就写在那），故逐调用读不与正文写抢 primary 池。

**诚实边界**：闸读 `cost_events`，而台账由 drain **持续**物化（in-process metering 每 call 即 enqueue + `materialize_runs=True`，drain loop 常驻），所以它看到的是「约一个 drain 周期前已落完的调用」——**在飞的调用不计入**。逐调用把超卖窗口从「整个回合」收到「一个 drain 周期」，**不是预扣额度**；要零超卖需同步计数器/预留，本案**有意不做**（会新增一层对账）。

→ 见代码 `conversation/quota.py`（`QuotaLimits.for_user`）、`billing/gate.py`（回合开始闸）、`billing/call_quota.py` + `llm/call_fence.py`（逐调用闸）

### 平台搜索次数

平台 SearXNG 的次数与上面的 ¥ / token 正交，不并进金额帽。默认日 **40** · 月 **400**（`QUOTA_SEARCH_DAILY` / `QUOTA_SEARCH_MONTHLY`，`config/quota.py`）。**0 = 该窗口不限**。`is_unlimited` 跳过这两道。每用户覆盖列 `quota_search_daily` / `quota_search_monthly`（NULL = 继承）。

只计真正离开进程、打到平台 SearXNG 的请求（`platform_search_uses`）。缓存命中和被拒的查询不计。空的 HTTP 200 计入（请求已经发出）。连接失败和超时不计。自备 DeepSeek 搜索不计（含用官方 DeepSeek 服务商 Key 连接的那一档）。在飞的请求不预留，和金额闸同一诚实边界。

用尽时这一下搜索失败，回合继续。文案与 F6 同向：额度重置后可继续，或在设置 · 联网搜索改接自己的搜索。不写钟点；`reset_at` 走错误信封。搜索次数随席位档走（见 §〇·六 套餐），不做按次充值。检索结果进模型后的 token 仍走金额闸。单回合检索预算 14 是行为上限，不是这把计次尺。

→ 见代码 `tools/builtin/web/search_quota.py`

### 计费记账（✅ 已落地）

每个 **LLM call** 落一行 `cost_calls`（权威明细）；每个 **Run** 在 `cost_events` 有一行物化聚合（产品面工资单 / 仪表盘 / 配额 SUM 读这里）。云回合 finalize 双写聚合；sidecar 经云代理按 call 记明细并物化聚合。详见 §三/§四。

## 二、用量/成本不变量

token 与成本在系统中有多种形态（SSE wire、持久化、API 响应、计费台账），下列不变量保证不会算出两套数、也不会跨用户串账：

1. **唯一原始来源**：单次 LLM 调用的原始 `TokenUsage` **5 字段**（`input / output / reasoning / cache_hit / cache_miss`；`total` 为派生属性），所有用量从它累加。→ 见代码 `llm/provider/protocol.py::TokenUsage`
2. **唯一定价转换**：全系统唯一的 `calculate_cost(model, usage)` 把 token 折成钱（`input / cached / output` 三价分离，缓存命中按更低价计），任何地方要**记账 / 配额 / 用户面**成本一律调它，绝不另算单价。钱一律**整数 nano**（1 单位货币 = 10⁹），杜绝浮点。**价卡只有 curated CNY**（Flash = DeepSeek 中文官价；其余国内官价直写）；`credential_source` 只分流列：`platform` / `vendor` → `cost_total_nano`（配额）；`user` → `cost_estimated_nano`（同一名义价，不进配额）。用户面气泡按付款来源拆开展示（平台积分 · 自己的 Key ¥），不把两列加成一个积分。无卡：用户路径金额 0；平台回落 glm-5.2 + `cost.pricing_fallback`。`Cost.pricing_source` 有卡即 `curated`。展示元 = `nano_to_yuan`（nano/1e9）。→ 见代码 `llm/pricing.py`
   - **记账与展示列分离**：`enforce_quota` 月成本、admin 全站统计只 SUM `cost_total_nano`；`cost_estimated_nano` 是 BYOK 展示列（官网卡），两列互斥非零（`split_cost`）。回合聚合 `aggregate_cost`：wire `total` = 记账 + BYOK 名义价（同币可加）；`estimated_total` 仍是 BYOK 切片。客户端拆开展示（用量页写 ¥，不扣积分）。per-agent 分项仍在 `GET /messages/{id}/cost`。
   - **缓存拆分对账**：输入费按 `cache_hit/cache_miss` 拆价。解析层（`TokenUsage.from_openai_wire`，网关 / 推理代理 / 视觉读图共用）兼容两种线上方言：DeepSeek 显式拆分（`prompt_cache_{hit,miss}_tokens`，优先）与 OpenAI 风格 `prompt_tokens_details.cached_tokens`（hit=cached、miss=prompt−cached 推导）——否则 OpenAI 方言上游的缓存命中恒报 0，平台价卡（如 gpt-4o）把命中全额按 miss 计价、账单虚高。两种方言都缺时，计价层仍按 `cache_miss = max(input_tokens − cache_hit, cache_miss)` 对账——原生路径（`hit+miss==prompt`）恒等无副作用，缺拆分时整段 prompt 按 miss 计，保证「被计价的输入 == prompt」永不落空。用户面 `UsageBreakdown` 投影（消息 REST / 用量 API）对省略形 `input>0 且 0/0` 用同一 guard 填 miss；解析层 0/0 原形不动（计费公平绊线）。展示文案只说「按未命中计价」，不断言上游命中为 0。
   - **命中率可观测**：拆分出的 `cache_hit/miss` 配在每次 `llm.call` 上，并带紧凑归因（`prefix_breach` / `tools_changed` / `tools_count`；system 击穿时 `prefix_breach_section`）。完整探针 `cost.prefix_cache` 仍 debug（命中率 + 改了系统提示哪一段 / 工具表 / 中途改写历史 / 纯追加 + 按 prompt 规模分桶）。`cache_reported=false` 表示上游根本没报缓存字段（**不等于 0% 命中**，不进任何比率）。白付估计（forfeited）只在 debug 探针，不进 `llm.call`。聚合 `scripts/log_stats.py`：Prefix Cache 段抽样非纯追加（`history_rewrite` / `cold_chain` / `tools`…）供 `log_timeline --trace`。→ 见代码 `observability/prefix_cache.py`。
   - **回落可观测**：未知/未配置 `model` 回落 glm-5.2 价（缺价绝不腰斩回合），故回落时打 `cost.pricing_fallback`（warning）而非静默，便于从日志发现漏价。

**真正的钱以 `cost_events` 台账为准**（不变量 #1）；`Message.usage` / `runs` 里的成本只是展示快照。新增任何成本展示点 → 复用统一定价函数，勿手算单价。

3. **会话归属不在写路径校验**：`cost_events.conversation_id` **无**指向 `conversations` 的 FK；推理代理写入不查「该会话是否属当前用户」。会话口径读侧一律按 `(user_id, conversation_id)` 收敛，账户口径按 `user_id` 收敛（账户级行无会话，见 §三），两者的 `user_id` 都来自鉴权令牌 → **无跨用户泄漏**；伪造/错挂 id 至多把本人花销记到本人账本里无权的会话上。热路径不加归属 DB 查是有意取舍。→ 见代码 `api/routes/inference/proxy.py`（写头注释）、`db/models/billing.py`

## 三、台账：per-call 明细 + per-run 聚合（✅ 已落地）

| 决策 | 内容 |
|---|---|
| 粒度（②） | **per-call 明细（`cost_calls`，权威）+ per-run 物化聚合（`cost_events`）**。云回合与 sidecar（经云推理代理）同构：代理侧按 call 记明细并按 `run_id` 物化聚合；云 in-process 经 `log_llm_call` → call meter 入明细并 **同步物化**（`materialize_runs=True`），turn finalize 再按 `message_id` 从 `cost_calls` 对账 upsert（补齐 pause/resume / 协调波次下内存 `cost_runs` 漏折的 worker），vision 等仅在 `cost_runs` 的孤儿行再 `record_runs`。明细携带 `role`（结构桶）+ `persona`（人设标签，如「调研员」）+ `run_id`/`agent_id`/`parent_run_id`。平台代付另有 `platform_credential_id`（池成员 = 该行 UUID；env / 覆盖 = `PLATFORM_CREDENTIAL_ID` / JSON `id` 或 `(api_key, base_url)` 哈希，非 key 明文；BYOK 为空）。只进日志与台账，**不进**用户可见 SSE error context |
| 货币（①） | 整数 nano-CNY（`currency`）；冗余 `cost_total_nano`（记账/配额）与 `cost_estimated_nano`（BYOK 展示，同卡）双标量列供窗口 SUM，两列互斥非零 |
| 幂等 | 明细 `call_id` unique；聚合 `run_id` unique（finalize DO NOTHING；代理物化 DO UPDATE） |
| 写入时机 | 每成功 LLM call → 明细；turn finalize / handoff / **incomplete 收口**（`/stop` · sweeper · process_kill → `close_turn_interrupted`）/ **暂停收口**（闸卡、限流续跑、本地 `paused` 回写 → `project_settled_message_cost`）/ 代理物化 → 聚合；与 assistant message 共享 `message_id`（背景调用 NULL；账户级 chrome 连 `conversation_id` 也 NULL，见下）。interrupt 与暂停都 `cost_runs=[]`，只投影已有 call，不伪造 orphan。成功后 emit `cost.recorded`（含 `by_role`）并盖 `messages.usage` token 与 `messages.cost`（费用列已盖则跳过 emit，防双记日志；暂停刷新仍改写快照）。未计量的再次挂起不发 0 用量，避免盖掉这条回复末尾 |
| 写入失败语义 | 同步写失败：warning + **入共享 DB outbox 后台 drain 重试**（at-least-once）；回合正文已先提交，不因账本失败回滚 |
| 失败 run 计费 | 硬失败（worker `raise_on_error` 抛错、CEO/续跑循环崩溃）仍按**已完成轮**入账——`usage_sink` 把已计量 usage 从抛点带出，经 `calculate_cost` 折钱落 `FAILED` 行（token 已真花在用户 key 上，漏记 = 平台/用户白付）；用户主动取消（`CancelledError`）**不为取消本身造 FAILED 折算行**（`except Exception` 不捕 `BaseException`）——但**已成功 call 仍在 incomplete 收口时对账**（见上「写入时机」）。vision 等仅挂内存 `cost_runs` 的孤儿在 cancel 时可能仍漏物化（本案不抢救） |
| 真相源 | `cost_calls`（明细权威）；`cost_events` 为产品读侧聚合视图；`Message.usage` 仅展示快照。开发期无历史回填——老行可缺明细/`persona`；单回合工资单与 `cost.recorded` 读侧可用 `COALESCE(persona, role)` |

**账户级行 · 不属于任何会话（✅ 已落账）**：**AI 改写**（文件工作台划词改写）真花 token，却压根不属于任何会话。台账三张表（`cost_calls` / `cost_events` / outbox）的 `conversation_id` 原本 NOT NULL，call meter 只能整条丢弃——拍板**放宽账本**（钱花了就该看得见）：三处列改**可空**，role CHECK 加 `assist` 桶，`persona` 记是哪条 chrome（「AI 改写」）。这类行只挂 `user_id`（`conversation_id` / `message_id` 均 NULL）；**绝不编造会话 id** 把花销挂到用户某条无关对话上（该特例层已否决）。唯一硬要求是有付费账号：无 `user_id`（eval / 设置·测连探针）仍不记。

读侧两类口径都是**结构性**的，不是特例分支：**账户窗口全收**——`aggregate_for_window`（用量页今日/本月 + 仪表盘趋势 + `enforce_quota` SUM）、`aggregate_by_model_for_window`（各模型）、`aggregate_by_user_for_window`（全站工资单）都只按 `user_id` + 时间窗聚合；**会话 / 回合口径天然不收**——对话累计按 `conversation_id` 等值、单回合工资单与复盘按 `message_id`，NULL 一律匹配不上（admin 对话名册的 per-conversation SUM 另显式 `IS NOT NULL`，免得空分组空转）。故这笔钱与 token 照进额度，**「请求数」不被抬高**（`COUNT(DISTINCT message_id)` 忽略 NULL，与 标题 / 后台 chrome 背景调用同口径）。逐调用配额闸一如既往只读 `user_id`，额度耗尽照样拦得住。→ 迁移 `d5b8c2f7a1e4`

→ 见代码 `billing/ledger_call.py`（in-process / proxy 共享 `CallCost` 装配）、`runtime/costing.py`、`db/repositories/billing.py::CostEventRepository`、`billing/attribution.py`、失败计费 `runtime/runs/executor/shared.py::_priced_failure`

## 六、成本预估：有意不做

团队组建时给启发式预估 **否决**——代码里前后端均不存在。不要把固定假设（Captain 跑 3 轮、队员各 2 轮、每轮约 3000 输入 + 700 输出 token）当实现。

**否决理由**：单个多 Agent 回合的真实消耗取决于任务复杂度、模型自主轮数、工具调用次数与实际派工数，事前方差极大（同一张卡可能是三毛也可能是十五块）。给出的数字会被用户当成保障——**误导性预估比没有预估更糟**。

因此组队开跑**有意不带事前金额**。运行中状态条、对话累计 caption 仍不挂钱。第一次调用入账之后，气泡脚可以显示已经打到模型上的合计，未收口标「至今」；侧栏只给当前打开的那次 run。呈现细则 → [前端成本呈现](/docs/04-前端/前端成本呈现.md)。

**跑飞风险的兜底就是配额本身**：platform 代付路径由 §一 配额防线拦——正因为它是唯一刹车，D7 已把该检查下沉到**每次上游调用**（并发回合 / 团队扇出都拦得住，见 §一）。BYOK 用户不查配额（自担上游账单，§一既定姿态），故平台侧无刹车——这是 BYOK 姿态的自然结果。**否决**把运行中累计金额挂上状态条或对话累计 caption（「零噪音」定案仍在）。气泡脚「至今」和已打开 run 的「资源消耗」是同一张已入账账单，随每次调用返回更新，不是事前估算，也不是逐 token 跳动。
