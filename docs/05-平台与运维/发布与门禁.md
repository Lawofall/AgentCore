## 七、发布策略 ✅ 已确定

> **实现现状**：`GET /livez` / `GET /readyz` / `GET /version` 已实装。部署/发版走本地脚本（§三）；GHA 仅 `workflow_dispatch` 备用（CI 在 `ci.yml`，frontend/mobile **在跑**；红灯/早失败时后续 skipped → 发布以本地 `pnpm release:gate` 为准）。`/readyz` 巡检：`deploy/scripts/healthcheck.sh` + systemd timer。

### 7.1 版本钉定

**多轨道 semver**（开发期）：API（`pyproject.toml`）、Desktop（`package.json` + `desktop-v*` tag）、Web 客户端（mobile/admin build 注入 `__APP_VERSION__` + git SHA）**独立 bump**（`pnpm bump-version <track> patch|minor|major|x.y.z`）；About / 系统页双行展示「客户端版本」与「API 版本」。所有客户端请求带 `X-Client-Platform` + `X-Client-Version`（→ `scripts/client-build-info.mjs`、各端 `lib/clientBuildInfo.ts`）。

部署一律按 **git SHA**，不按浮动 `latest`。应用镜像构建期注入 `GIT_SHA` / `BUILT_AT`，运行时经 `GET /version` 暴露（端点已实装；启动入口在环境未注入时自 git 工作树补 SHA、按启动时刻补构建时间，发布流水线经环境变量注入则优先）。部署脚本传 `latest` 时，会先解析为当前 `master` 的具体 SHA 再 pin——容器跑的永远是确定 SHA（可追溯、可秒回）。

### 7.2 发布点（Release Point）

`master` 是 WIP 快照主干，**HEAD ≠ 可上线点**。用 `prod-*` tag 标记发布点（语义：「这个 SHA 是要上线的版本」）。部署以发布点为准，而非 `origin/master`——tag **仅作标记**、不触发自动部署（`deploy-backend.yml` 仅 `workflow_dispatch` 备用，§三 CI/CD 决策；漂移哨兵仍 ⏳）。

### 7.3 漂移检测

Admin 系统页 **发布漂移** 卡片（✅）：客户端拉 GitHub Latest（`AgentCore-releases`）与官网 `/api/desktop-release`，对比下载页是否滞后；控制台 SHA vs API SHA 标注「异轨/同部署」。

CI 每日自动比对线上 `/version` 与最新 `prod-*` tag（⏳ 目标；MVP 未接入）：

- prod 落后 tag → 「发了版没部署」（真漂移，告警）
- `master` 超前 tag → 「攒了未发布的 WIP」（正常，不告警）

桌面端同理：比对 `package.json` version 与公开发布仓的 `releases/latest` tag（⏳ 未接入）。

### 7.4 Deploy ≠ Release

构建/部署之上还有一层「部署 ≠ 发布」解耦——后端功能可先暗发到生产，由配置/特性开关翻开才对用户可见。支持灰度 + 最低客户端版本门控（让后端先于桌面发版，仅追上的客户端点亮）。

#### 跨轨道发布协同（2026-06 决策）

**不强制**后端与桌面（或各客户端）同一天、同 SHA 锁步发布——§7.1 多轨道 semver 的设计意图即**独立节奏 + 按需协同**。`prod-*` 与 `desktop-v*` **不绑定**；Admin 漂移卡片标注「异轨/同部署」是观测，不是告警。

| 变更类型 | 是否要快跟 | 说明 |
|---------|-----------|------|
| 纯后端（客户端无感） | 否 | skills / evals / prompt 等；桌面不必跟 |
| **协议 / 事件契约** | **是（天级窗口）** | 动了 `packages/contract-types`、protocol-conformance 向量、桌面 fold → 后端 + admin **同日** deploy；桌面 / Android APK **7 天内** patch 发版 |
| 纯客户端 UI | 否 | 主题 / 布局；后端不必跟 |

**判据**：本次 PR 是否改协议 fold 或事件类型？是 → 走「协议变更」行；否 → 各轨道独立发。

**协议变更轻量流程**（人工 checklist，非自动化门禁）：

1. `pnpm conformance` 全绿后再 prod deploy
2. 同日：`prod-*` + mobile/admin Pages deploy
3. **7 日内**：`desktop-v<patch>` + 官网 `FALLBACK_VERSION` + `deploy:pages`
4. 旧桌面用户：对话通常仍可用（后端向后兼容发事件），新 UI 等 auto-update；不应依赖「必须同天发桌面」来保活

**否决**：`prod-vN` 与 `desktop-vX.Y.Z` 强制同 tag / 同 SHA 发布——发布成本与回滚独立性不划算。

⏳ 远期：`min_client_version` 特性开关接线后，协议变更类功能可后端先上、仅新版本客户端点亮（§7.9），进一步降低人工记「7 天内补桌面」的负担。

### 7.5 Monorepo 选择性构建

`push master` **不自动构建/部署**（2026-06 切本地脚本，§三）。在自托管机执行 `pnpm deploy:backend <sha>` 构建 api 并推镜像仓库。⏳ 多服务 retag 优化未纳入。

### 7.6 桌面端构建与双仓发布

> **实现现状**：`.github/workflows/release-desktop.yml` 仅 `workflow_dispatch`（`platform=mac`）→ 预建 draft → **macOS arm64** 构建 → electron-builder 上传公开发布仓 `Lawofall/AgentCore-releases`。**Windows 不走 GHA**（为省额度；本地 `release:win` / 分步 `--win`）。`desktop-v*` tag **仅作发布点标记**，不触发构建。内测档位：**未签名**；Mac **arm64 only**（Apple Silicon，Intel / Universal 不在支持范围）。正式签名 + 公证 → 详细提案不在公开仓 / 维护者本地（路线图「远期放量」）。
>
> **更新通道**：稳定版 / 测试版双轨见 **§7.6c**（✅ 代码已落地；默认 channel=stable）。

| 环节 | 机制 |
|---|---|
| 构建触发 | Win = 本地；Mac = Actions **workflow_dispatch**（仅 `mac`）。`desktop-v<ver>` tag 仅标记，不触发 |
| 产物 | Win 本地 / Mac GHA → 公开发布仓草稿 release（人工转正） |
| 灰度 | `latest.yml` 的 `stagingPercentage` 分桶 |
| 熔断 | 后端 `DESKTOP_UPDATES_ENABLED=false` |
| 硬最低版本 | 后端 `DESKTOP_MIN_VERSION` → `GET /updates/policy` 的 `min_desktop_version`（空 = `null`，不拦；生产建议 **`0.6.25`**）。**服务端硬闸**：`X-Client-Platform=desktop` 且 `X-Client-Version` &lt; 地板时，`/v1/*` 业务 API（含 auth）返回 HTTP **426** `CLIENT_TOO_OLD`；缺版本头 / `dev` / 比较失败 fail-open；web / `mobile-web` / admin / 缺平台头不拦（**原生手机端另有独立地板** `MOBILE_MIN_VERSION`，见 §7.6a）。豁免 `/livez` `/readyz` `/version` `/updates/policy` 与 OPTIONS，旧客户端仍可拉 policy 更新。桌面端亦可据此做强制更新 UX。§7.9 特性开关的 `min_client_version` 是 **per-flag** 另一条线，本闸是全局桌面地板 |
| 客户端更新 UX | 打包桌面端：`autoDownload=false`。发现新版本弹说明窗（版本号相对当前 / feed `releaseNotes` 缺省「修复与体验改进」/ 可选包大小）→「下载安装包」立刻关窗 + 短 toast，主进程把**官网同款 GitHub 安装包**拉到系统「下载」文件夹（不经 electron-updater 下载、不经 Tunnel 大文件）；进度仅在设置·关于；失败 toast、不重开说明窗；「稍后提醒」同版本 24h 内不重复弹；「跳过此版本」持久化后同版本不弹直至更高版本。下完 sticky toast「打开安装包」，须显式 `openInstaller`（`shell.openPath`，`autoInstallOnAppQuit=false`）。低于硬地板时由服务端拒收 + 客户端强制更新门（全屏跟进度；下完同样打开安装包）。官网下载页仅为失败出口。检查仍走品牌域 `latest.yml`（几 KB）。**mac 未签名**：Squirrel 仍不能自动安装，但与 Windows 一样下 dmg 到「下载」再打开（见下文） |

**`GET /updates/policy`（现状）**：未鉴权；载荷 `{ enabled: bool, min_desktop_version: string | null }`。`enabled` 为自动更新急停闸（客户端 fail-open）；`min_desktop_version` 为硬地板（客户端强制更新门 + 本 API 闸 `CLIENT_TOO_OLD`）。本端点豁免硬闸，旧客户端仍可匿名 GET。**载荷刻意不含手机端地板**：Android 壳查版本走 CDN `android/latest.json`（§7.6a），从不打本端点，加字段无人读。§7.9 `min_client_version` 仍是 per-flag 另一条线（⏳ 未实装）。

**双仓发布模型**：源码仓已公开（MIT）；安装包仍发到公开发布仓（`Lawofall/AgentCore-releases`）——双仓是**发布产物仓**分工，不是为了藏源码。Win 与 Mac 产物汇入同一 `v<ver>` draft，**Win + Mac 齐全再 Publish**，mac 未就绪就等（各平台资产构成见 `electron-builder.config.mjs`）——内测已有真实用户，**不再允许仅 win 转正**。站点缺 mac 资产会自动隐藏 mac 按钮、`FALLBACK_VERSION` 暂留上一含 mac 版本，那是**事故兜底**，不是半发许可。**否决** electron-builder `--publish always` 当唯一上传路径——#6676 竞态常只传上 `.blockmap`、丢掉 `.exe` + `latest.yml`；现行 `release:win` = `--publish never` → `gh release upload --clobber` → 资产断言（与 Mac GHA 同构）。

**内置 Python 运行时**：electron-builder 前先跑 `pnpm bundle:sidecar`，产物经 `extraResources` 拷入安装包；动机与按 OS 打包约束见 [双模式工作区 §七](/docs/02-架构/双模式工作区.md)。CI 内 bundle 冒烟必须通过：`import agentcore.sidecar.server` + **Office 栈**（`docx` / python-docx 抽 docx、markitdown 抽 pdf 等 / md→docx）——与云同能力，禁止瘦身砍掉后仍跑同一管线。

**原生模块（node-pty）**：`asarUnpack` 解包（`.node` / conpty DLL 在 asar 内 dlopen 失败）；`npmRebuild: false` + `nodeGypRebuild: false`——官方 prebuilds 走 N-API 直接可加载，强制 rebuild 反而在缺 Spectre 缓解库的 Win 机器上失败。新增原生依赖按此模式对齐。

**macOS 内测安装**：未签名——首次打开须**右键 → 打开**（或 `xattr -cr`）。版本检查仍读 `latest-mac.yml`；安装包改为 GitHub 上的 **dmg**（与官网按钮同链），落到「下载」文件夹后打开，不再走 Squirrel zip 自动安装。

**未签名 mac 与 Squirrel（现状定案）**：Squirrel.Mac 用运行中 app 的 designated requirement 校验更新包，无 Developer ID 时必然报 `did not pass validation`——**无绕过开关**。故临时更新路径**不再调用** `quitAndInstall`：Win/Mac 一律下载官网同款安装包并 `shell.openPath`。主进程仍探测签名身份并上报 `autoInstallCapable`（日志 / 日后恢复 Squirrel），**不再拦截下载**。强制更新门始终保留「前往下载页」出口，避免抬高硬地板时把用户锁死。存量未签名用户升到签名版仍须跑一次 dmg 覆盖安装。→ 见代码 [`apps/desktop/src/main/updater.ts`](/apps/desktop/src/main/updater.ts) · [`mac-auto-update-capable.ts`](/apps/desktop/src/main/mac-auto-update-capable.ts)

发布步骤命令 → 见下文 §本地发布操作手册「桌面发版」。**真机 QA 要点**（Apple Silicon，Rosetta 不算）：安装可启动 → 登录 / SSE 流式 → 绑定本地文件夹（sidecar 内置 Python）→ 本地回合文件读写 → 检查更新能发现新版本并下载安装包到「下载」文件夹。

### 7.6a Android APK（官网侧载）✅

> **实现现状**：本地 `pnpm -C apps/mobile release:android`（需 **JDK 21** + Android SDK + `keystore.properties`）→ 签名 APK → `gh release upload` 到同一产物仓 → `sync-release-cdn --android` 写品牌域 `downloads.*/android/`。tag 轨 **`android-v<ver>`**（与桌面 `v<ver>` 分轨）；资产名 `AgentCore-<ver>-android.apk`。官网 `/download` 另查含 `*-android.apk` 的非 draft release，**有资产才露下载链**。App 内软提示「去下载」（打开 APK URL），不强制、不做壳内 OTA；要**强制**旧包更新走服务端硬地板 `MOBILE_MIN_VERSION`（见下表）。操作清单 → [`apps/mobile/README.md`](/apps/mobile/README.md)。

| 环节 | 机制 |
|---|---|
| 构建触发 | 仅本地；无 GHA 自动触发 |
| 签名 | `android/keystore.properties`（gitignore）；缺则脚本拒绝打 release |
| 产物体积 | Capacitor 壳（系统 WebView）压缩后约数 MB 属正常——**不含** Chromium / sidecar |
| 官网 | `releaseArtifacts.mjs` 的 android 三字段 + `DownloadView` |
| CDN | `downloads.*/android/AgentCore-<ver>-android.apk` + `latest.json`（App 内更新读此） |
| App 更新 | 原生 Android 用 **CapacitorHttp** 拉 CDN `latest.json`（绕过 WebView CORS）；网页壳仍 `fetch`；`dev` 不提示。软提示、可关，**不是**地板 |
| 硬最低版本 | 后端 `MOBILE_MIN_VERSION`——与桌面地板同语义、各自独立的一条闸：`X-Client-Platform` 落在**原生手机面**（`android` / `ios` / 裸 `mobile`，判定复用 `resolve_channel_profile`）且 `X-Client-Version` &lt; 地板时，`/v1/*` 返回 HTTP **426** `CLIENT_TOO_OLD`（`details.min_version` 带地板）。**`mobile-web` 不设地板**（浏览器面刷新即最新，挡它只会误伤）；缺版本头 / `dev` / 比较失败 fail-open；豁免路径同 §7.6。**不经 `/updates/policy` 下发**（Android 壳只读 CDN `latest.json`，加字段无人读）；旧包无壳内 OTA，被挡后只能去下新 APK，故**默认空、抬地板是发版时单独的人工动作** |
| API CORS（生产必配） | Capacitor WebView origin = **`https://localhost`**（另保留 `capacitor://localhost` / `http://localhost`）。缺则 App 报「无法连接后端」——`CORS_ALLOW_ORIGINS` 须含上述三项（见 `production.env.example`；改后 recreate api）。**出包自动检**：`release:android` 对公网 `/api` 发 OPTIONS（须回显该源；对照源不得带 `Access-Control-Allow-Origin`，防通配符误判）。明确拒绝才失败；网络抖动 fail-open。单跑：`pnpm check:capacitor-cors` |
| 下载 CDN CORS | `downloads.conf` 对 `latest.json` / `latest*.yml` 回 `Access-Control-Allow-Origin: *`（并处理 OPTIONS）。旧壳若仍用 WebView `fetch` 检查更新，缺此会报「暂时无法获取更新信息」。改后：`pnpm sync:release-cdn --install-nginx` |
| FCM | **无** `android/app/google-services.json` 时 `release:android` 注入 `VITE_PUSH_ENABLED=false`，**禁止**调用 `PushNotifications.register()`（否则原生闪退，JS catch 不住）。有该文件才开推送 |

**真机 QA**（设备相关三项；CORS 预检已在出包链路自动跑）：签名安装 → 系统 WebView 渲染 → 端到端 SSE。

**何时挡 Publish（2026-08 定案）**：这三项只在本波动到**原生面**时挡住 `android-v*` 转正——`apps/mobile/android/`、Capacitor 插件 / 壳配置、生产 CORS、壳内鉴权或 SSE。纯桌面 renderer / 协议跟发（产品页同一棵树）出包后直接 Publish。后端 / 桌面 / admin / web / 官网**从不**等 APK。否决：每个 patch APK 都等人点真机；否决：用真机闸挡住五轨其它发布。判不准本波算不算原生面 → 问人，不默认等人。

→ 见代码 `apps/mobile/scripts/release-android.mjs`、`deploy/scripts/check-capacitor-cors.mjs`、`apps/website/functions/_lib/releaseArtifacts.mjs`、`deploy/scripts/sync-release-cdn.mjs`、`deploy/scripts/add-capacitor-cors.mjs`（运维补 Capacitor CORS）、`deploy/scripts/strip-mobile-web-cors.mjs`（从生产 CORS 去掉已下线的独立 `m.` origin，须仍保留 Capacitor localhost 三项）

### 7.6b 品牌下载域与官网安装包源 ✅

> **实现现状**：

> - R2：曾评估；开通需绑卡，**当前未采用**。

| 环节 | 机制 |
|---|---|
| 官网 Win/Mac/APK | `artifactUrlsForVersion` / `androidArtifactUrls` → `github.com/.../releases/download/...` |

→ 见代码 `deploy/scripts/sync-release-cdn.mjs`、`apps/website/functions/_lib/downloadsCdn.mjs`、`deploy/.env.deploy.local.example`

### 7.6c 桌面更新通道（稳定 / 测试）✅ 定案已落地（发版操作跟进）

> **权威**：桌面「稳定版 vs 测试版」产品与发布通道。§7.6 表内「灰度」仍只描述 **稳定轨内** `stagingPercentage`。
>
> **动机**：内测要尽早收真实使用信号，同时不能把不稳定构建推给默认用户。对齐 Chrome Beta / VS Code Insiders：**通道 = 独立应用 + 独立 updater feed**，不是 Git 长期双分支，也不是再开源码仓。
>
> **实现现状**：构建期 `DESKTOP_RELEASE_CHANNEL` / `--channel`（默认 stable）→ 双 `appId` / 产品名 / 图标 / `publish.url`（`…/desktop/{stable|beta}`）；关于页明示通道并外链另一轨；CDN sync 写 `desktop/stable`（并镜像扁平 `desktop/` 兼容旧包）与 `desktop/beta`；官网主 CTA 稳定、次入口测试版（`?channel=beta`）。产物文件名两侧均为 `AgentCore-${ver}-…`（通道不靠改 slug）。

#### 定案

| 项 | 决策 |
|---|---|
| 对外通道 | **两轨**：`stable`（稳定版）/ `beta`（测试版）。不对用户暴露 Canary / Dev |
| 源码 / 产物仓 | **各保持一个**：源码仓 + `Lawofall/AgentCore-releases`。否决为测试版另开源码仓或长期 `beta` 分支当用户通道 |
| 安装形态 | **并列安装**：测试版独立显示名「AgentCore 测试版」、独立 `appId`、安装目录、图标（角标/色相可辨） |
| 用户数据 | **默认 userdata 隔离**（防 beta schema 污染稳定版）；**账号可共用**（同生产 API） |
| updater | feed **硬隔离**：稳定 → `…/desktop/stable/`（目录内 `latest.yml`）；测试 → `…/desktop/beta/`（同构）。稳定 feed **永不**指向带预发布标记的包 |
| 版本 / tag | 测试版用预发布 semver（如 `1.2.3-beta.N`）或等价约定；发布仓 tag 可辨（如 `v1.2.3-beta.1`）。稳定版 `vX.Y.Z` |
| 降轨 | **不做**同安装内一键覆盖降级。回稳定 = 打开已装的稳定版，或测试版设置提供「下载稳定版」外链 |
| 升轨 | 稳定版设置可链到「下载测试版」；**禁止**把稳定版 updater 静默切到 beta feed |
| 品牌呈现 | 窗口标题 / 关于页明示「更新通道：稳定｜测试」；官网主 CTA = 稳定，次入口 = 测试版 + 一行风险说明 |
| 后端 | **同生产 API**；新能力优先进测试版客户端，或后续 §7.9 flag（可按 channel / 版本门控）。破坏性协议仍走 §7.4 跨轨道纪律 |
| 灰度 | `stagingPercentage` **仅稳定轨内**最后放量；**否决**用它冒充测试通道 |
| 晋升 | **稳定通道重编**同功能基线后再 sync stable feed（构建期烘焙 `appId` / `publish.url`，**不可**把 beta 包原样拷到 stable） |
| 熔断 | 可按通道急停（至少稳定轨沿用 `DESKTOP_UPDATES_ENABLED`；测试轨可独立闸 ⏳ 落地时定） |

#### 操作心智（维护者）

| 动作 | 做什么 | 不做什么 |
|---|---|---|
| 日常开发 | 合进主干（`master`） | 不为「用户通道」长期保留平行 `beta` 分支 |
| 发测试版 | 主干打 beta 版 → 上传发布仓 → 同步 **beta** CDN feed | 改稳定版 `latest.yml` |
| 升稳定版 | 观察窗通过后，用 **stable channel 重编**同基线再 sync **stable** feed（必要时再开稳定轨 `stagingPercentage`） | 把 beta 包原样拷到 stable；依赖用户去切 Git 分支 |
| 回滚 | §7.7a；稳定 / 测试 feed 可分别指回好版本 | 删源码仓或拆仓「解决」发版事故 |

#### 否决

- 源码仓或发布仓按通道一分为二（无必要权限/产品分裂时）
- 同 `appId` 热切 feed 充当降轨（易污染 userdata、版本单调性难保证）
- 仅设置里「接收提前更新」且 UI 与稳定版无差异（反馈难归因；工作台需可辨通道）
- 用服务端特性开关代替整包测试通道（flag 是第二层，不替代独立壳 + feed）

→ 见代码：`apps/desktop/scripts/release-channel.mjs` · `electron-builder.config.mjs` · `AboutSettings` · `deploy/scripts/sync-release-cdn.mjs` · `apps/website/functions/_lib/downloadsCdn.mjs` · `DownloadView`。

### 7.7 备份与恢复策略

**只备不可重建的主数据**——PostgreSQL + 对象存储（工作区文件）。Redis 是缓存丢了自愈。

| 原则 | 说明 |
|---|---|
| 迁移前快照 | 每次正向部署：`pg_dump` **以及** `workspaces/` 卷归档（`pre-deploy-*-workspaces.tar.gz`）。盘上快照必须排在停 api **之前**，失败即终止部署（旧 api 继续服务）。逃生阀 `SKIP_WORKSPACE_SNAPSHOT=1` 独立于 `SKIP_SNAPSHOT`，默认关闭——盘上 tree 搬迁单向不可逆，跳过它等于放弃唯一回退素材 |
| 破坏性干净恢复 | 回灌前 `DROP SCHEMA public CASCADE`（非空库直接灌会主键冲突） |
| 停应用再恢复 | 避免并发写入；恢复后不自动起应用（需重新 deploy 对齐版本） |
| 异地副本 | 默认只有本地——防不了整机损坏，放量前必须开异地 |
| **灾备演练** | 备份未验证过恢复 = 没有备份。放量前必做一次完整恢复演练 |

**脚本已入仓** → 见 `deploy/scripts/backup.sh`（全量备份 + 轮转）/ `restore.sh`（破坏性干净恢复：完整性校验 → 确认门 → 停 api → 回灌 → 不自动起）/ `deploy/systemd/agentcore-backup.*`（每日定时 oneshot）。日常 `backup.sh` **仍只覆盖 PostgreSQL**；云工作区文件由**部署脚本**在每次正向部署停 api 之前打 `workspaces/` tar.gz（保留默认 2 份，见 `WORKSPACE_BACKUP_KEEP`）。回滚若库回到旧版、盘停在 tree 新布局，旧代码按平铺路径找不到文件会 `mkdir` 出空目录——回退镜像前须把对应 `pre-deploy-*-workspaces.tar.gz` 解回 `appdata` 卷。异地副本与灾备演练仍为运维动作（参数/排程见脚本与 runbook）。

### 7.7a 回滚 runbook（可照做）

> **无独立 `rollback` workflow**——回滚 = 用现有发布轨把已知好版本再推一次。勿编造蓝绿/一键回滚脚本。与 `cursor-deploy.mdc` 一致：**不**重新启用 deploy/release 的 push/tag/schedule 自动触发。

#### 后端镜像回退

对照现状：`pnpm deploy:backend <sha>`（主路径）→ 自托管机 buildx + `finish-server.sh`；备用 = GHA `promote-backend.yml`（`workflow_dispatch`，SSH 跑 `finish-server.sh <short-sha>`）或 `deploy-backend.yml`（同仅手动）。部署后机上记 `$AGENTCORE_HOME/.last-deployed-sha`。`finish-server.sh` 健康后默认保留最近 `KEEP_API_IMAGES=5` 个本机 `api:<sha>`（+ `latest`）；更早 tag 仍可从 ACR 拉。

| 步骤 | 动作 |
|---|---|
| 1. 定回退点 | 读机上 `.last-deployed-sha`、已知好 `prod-*` tag，或 ACR/`docker images` 上仍在的上一 short-sha |
| 2. 评估迁移 | 若坏版本已跑过**破坏性** `alembic upgrade`（DROP 等），**不能**只切旧镜像——须先按 §7.7 备份恢复到兼容 schema，或走 expand/contract；仅加列/可逆迁移通常可直接 pin 旧 SHA。若该版本还跑过 **workspaces tree 搬迁**（单向、无反向脚本），回退镜像前还须把对应 `pre-deploy-*-workspaces.tar.gz` 解回卷，否则旧代码看见的是空文件夹 |
| 3. 执行 | 主路径：`pnpm deploy:backend <prev-sha>`；或 GHA Promote Backend / Deploy Backend，`ref`/`sha` = 回退点；或 SSH：`bash deploy/scripts/finish-server.sh <prev-sha>`（镜像须已在 ACR/本机） |
| 4. 验收 | `GET /readyz` → 200；`GET /version` 的 `git_sha` = 回退点；关键路径手测 |
| 5. 记录 | 更新/核对 `.last-deployed-sha`；在变更记录写明回退原因（密钥值**不**入仓、不入 chat） |

### 7.9 特性开关架构（⏳ 目标设计 · 未实装）

特性开关是 §7.4「Deploy ≠ Release」的落地机制——后端代码先暗发到生产，由配置翻开才对用户可见。

**勿混读（三套现状开关 ≠ 本节目标）**：

| 现有机制 | 作用 | 与本表关系 |
|---|---|---|
| `DESKTOP_MIN_VERSION` / `MOBILE_MIN_VERSION` → `CLIENT_TOO_OLD`（§7.6 / §7.6a） | **全局**桌面 / 原生手机端硬地板 | ≠ per-flag `min_client_version` |
| `desktop_updates_enabled` / `GET /updates/policy` | 自动更新急停闸（fail-open） | 更新面，非功能灰度 |
| `config/features.py` 编译期布尔 | 垂直能力总闸（如 `legal_vertical_enabled`） | 部署期编译开关，非运行时灰度 |

**实现现状**：服务端三门求值 / 灰度分桶 / per-flag `min_client_version` 接线均 ⏳ 未建（`api/routes/system.py` 注释预留接缝）。读者**不要**把上表三套当成「已有灰度」。

**服务端求值**：灰度/版本逻辑只在后端运行，客户端与后端代码路径都只读「已解析的布尔」。理由：求值逻辑不泄漏到端、各调用方判定一致、单一真相源。

**三道门顺序求值**：每个 flag 按以下顺序判定，任一道关闭即最终为 `false`：

| 门 | 含义 |
|---|---|
| `enabled` | 总开关（关 = 永远关） |
| `min_client_version` | 仅 ≥ 该版本的客户端可见（跨列车安全阀） |
| `rollout` | 灰度百分比（0–100），按稳定 key 分桶 |

**跨列车安全阀**：`min_client_version` 让需要新客户端支持的后端功能先进生产，仅追上版本的客户端点亮——将「后端先上、桌面后放量」的跨列车顺序约束变成开关里的硬门，而非靠人工记顺序。

**分桶策略**：优先用户 `user_id`（同一用户跨设备判定一致），未登录回落到设备 `client_id`（UUID 持久化）。同一 key 永远落同一桶（不抖动），按 flag 加盐避免不同 flag 命中同一批人。登录成功后需重拉开关以纠正分桶 key 切换。

**fail-safe vs fail-open 对偶**——刻意相反的失败行为：

| 机制 | 失败兜底 | 为什么 |
|---|---|---|
| 特性开关 | **fail-safe（默认关）** | 未发布的功能要保守，不能因后端抖动误开半成品 |
| 桌面自动更新 | **fail-open（默认开）** | 已发布的安全网络要保活，可远程熔断 |

**演进预留**：v1 配置驱动（翻转需重启），运行时即时翻转（Redis/DB override）为 v2 注入缝。

## 九、工程门禁与结构治理 ✅ 已确定

> 用 CI 不变量替代人工纪律，防止多 Agent 并行开发下行为回归/类型债/结构腐化悄悄累积。

### 核心哲学：棘轮（Ratchet）

基线 = 当前现状，落地当天全绿，只拦新增腐化。修好真问题就收紧基线（只降不升），放宽必须在 PR diff 里显形并给理由。

### 三道门禁

| 层 | 拦什么 | 策略 |
|---|---|---|
| **行为回归** | 后端 lint + 测试；desktop / admin 各自 typecheck + **vitest**（`ci.yml` 与 `release:gate` 两处都跑；少接一处 = 该包单测白写）。`apps/mobile` 已无 SPA 单测（壳 + fold-kit 段） | 合并前 CI 硬阻塞；`release:gate` 同构 |
| **类型债** | tsc strict / mypy strict | 棘轮：逐文件计数基线，不允许新增错误。棘轮终局 = 修到零 → 升为硬门禁 |
| **结构治理** | god-file 膨胀、模块漏文档 | 行数棘轮（超标存量登记天花板）**已接**；模块文档守卫 / 清单守卫 **⏳ 未落地**——仓内无对应脚本，「模块漏文档」目前**没有任何门禁拦**，别据本行推断已被守住 |

### 跨端契约门禁

> **实现现状**：✅ 已写入 `ci.yml` 的 `contracts` job（"Contracts + conformance (gen + drift gate)"）：`node scripts/gen-types.mjs`（重生成 REST + SSE 契约产物）+ `agentcore.conformance.export`（重生成一致性夹具）+ `sync-story-packs --check` + `sync-legal-md --check`（桌面 legal → 仓根 `TERMS.md`/`PRIVACY.md`）+ `check-doc-section-pointers`（复合 `§<中文数字> 章节名` → 目标文 `## N、名`；判不准目标或形式不匹配则跳过，不扫 `§9.12` 决策号）+ `git diff --exit-code`——committed 产物与真相源漂移即红。Frontend 早失败时后续可能 skipped。改法律文案：改桌面 `legal/content.ts` → `pnpm sync:legal`。`ci.yml` 与 `release:gate` 两处都跑（少接一处 = 白接）。

**本地 `release:gate` 验的是同一件事、换了个问法（勿读成「本地核对与 HEAD 零 diff」）**：gate 在重生成**之前**给全部产物拍指纹，重生成后**改动了任何一个即失败**（产物相对本树源已过期），第二次重生成再变则失败（不幂等，任何 commit 都过不了 CI）。本地 WIP 树里「已重生成但还没 commit」的产物**不算漂移**——它与本树源一致，只打印一行提醒「必须随发布 commit 一起提交」。判据差异只在这一点上：CI 是干净 checkout（磁盘 == HEAD），此时「重生成没改动」与 `git diff --exit-code` 完全等价；本地脏树则改问「产物与**本树**源是否一致」，否则每个正常的契约改动都会误报成漂移。**因此「产物已 commit」的最终判定归 CI**（`deploy:backend` 前须等 `ci.yml` 全绿，见「决策与落差」）。

后端改 schema / SSE 事件必须重新生成前端类型并提交，`git diff --exit-code` 拦截 generated 静默漂移。覆盖四条契约：

| 契约 | 真相源 | 生成产物 |
|---|---|---|
| REST DTO | OpenAPI schema | `packages/contract-rest-types/src/api.generated.ts` |
| REST 路径 | OpenAPI `paths` | `packages/contract-rest-types/src/paths.generated.ts` + `validate_rest_paths.py`（扫 desktop/mobile/admin 生产代码手写 `/v1/…`，不在 OpenAPI 即红） |
| SSE | 后端 EventType + payload dataclass | `packages/contract-types` 下 `eventTypes` / `events` / `interactionKinds` / `errorCodes` |
| 一致性夹具 | `agentcore.conformance.vectors` + oracle | `packages/protocol-conformance/fixtures/`（桌面 fold 的向量与 golden；过期夹具 = 前端预览与 `pnpm conformance` 都在对着旧真值判卷） |

两处门禁的产物清单须同步：CI 靠 `git diff` 天然覆盖全树，本地 gate 只看 `CONTRACT_DRIFT_PATHS` 列举的路径——**新增生成物忘了登记 = 该产物本地无人看**。

`pnpm gen:types` 一次重生成并校验。根除「后端发了新事件/字段、前端 union 或 interface 漏抄、功能静默装死」；路径门禁另拦「客户端手写 URL 漂移出 OpenAPI」。新代码可选用 `restPath("/v1/…")`（`RestPathTemplate` 编译期约束）；存量手写路径不必一次迁完。

### Schema 门禁

破坏性迁移（DROP COLUMN/TABLE）与「旧代码仍查旧 schema」叠加会接口 500。本地：`pnpm release:gate` 内跑 offline schema gate（`apps/server/scripts/check_schema_gate.py`，校验单一 alembic head + 迁移链净 tombstone 不在 ORM/业务包）；部署：`finish-server.sh` / `deploy-server.sh` **先停 api 再迁移再切流量**，迁移后 `--live`（`alembic check`）不过则不起新 api。单机短暂不可用不等于蓝绿——零停机破坏性迁移仍须 expand/contract 双阶段，见 ⏳ 若需再提案。

**方向性**（✅）：offline 档只查墓碑方向（迁移删了、ORM 还留着）；反方向——**ORM 加了列却没写迁移**——只有 `--live` 的 `alembic check` 能报（`ci.yml` backend job 与部署链均在跑）。该反向漂移在本地极隐蔽：head 一致、`upgrade` 无操作、启动日志干净，直到第一个查该模型的请求 500。故 dev/prod 启动的 `check_migrations` 补上第四种形态——库已在 head 却缺 ORM 所映射的表/列时报 `db.schema_orm_ahead`（只报不阻断）。**不**把这个方向下沉进 offline 档：CI 已覆盖，静态 AST 双向 diff 得长期养解析器，且一条 `op.execute` 建表就会假红。部署时序（停旧 → 迁移 → live check → 起新）→ [部署拓扑 · CI/CD 流程](/docs/05-平台与运维/部署拓扑与环境.md#cicd-流程)。

### 依赖漏洞扫描（软门禁）

> **实现现状**：本地 `pnpm audit:deps`（`audit:deps:py` = `uv run --with pip-audit pip-audit`；`audit:deps:js` = `pnpm audit --prod`）。夜跑 / 手动：`.github/workflows/dependency-audit-nightly.yml`（schedule + `workflow_dispatch`），`continue-on-error` + artifact，**不**挡 PR、**不**要求清零 CVE。禁止借此给 deploy/release 加 push/tag 自动触发。

### AI 行为质量评测（软门禁）

> **实现现状**：`.github/workflows/evals-nightly.yml`（schedule + `workflow_dispatch`），**不进** `release:gate`、不挡 PR。硬门禁只有零 LLM 的用例结构校验；真模型步骤一律 `continue-on-error`，无 `EVAL_DEEPSEEK_API_KEY` 时整段跳过——**作业绿灯不代表 AI 行为被考过**。故夜跑强制写作业摘要（`apps/server/scripts/eval_nightly_summary.py`，`if: always()`）：逐步骤写明「考了没 / 出数没 / 过没过」，跳过或降级必须显式写「AI 行为面本次未覆盖」，不得静默报绿。相对基线观测（`--baseline`，报告 JSON 的 `ratchet` 段）挂在功能 / MAST / routing / style / compare / probe 的既有真跑上，零额外 LLM 成本：用共享用例翻转方向区分一夜抖动 vs 单方向变差，**不用固定容差假装能吸收方差**，也**不因观测改退出码或弄红作业**。快照落 `apps/server/eval-out/`（gitignore；跨夜靠 Actions cache `evals-baseline-<suite>-<run_id>`，作业页另有 `eval-snapshots` 制品）：`--baseline` 对着 `*-latest.json`（最近一次成功）才能看见一夜台阶；`*-baseline.json` 仍只升不降留历史峰值（只对着峰值比会让缓慢漂移看不见翻转）。作业摘要并排展示本次 vs 该峰值，让持续退化在翻转静音后仍能看见水位（只展示，不改红绿）。裁判校准（`--calibrate`，gold-set 判↔人 kappa）单列一步——夜跑 pass/fail 主轴是 L1 LLM 裁判，不校准就是拿没刻度的尺子量。**真跑是否升为硬红仍是未决项**，勿据本条推断已强制。

### 拆分实操经验

- **facade + 子包**：按子域拆，`__init__` 全量 re-export 保持公共 API 不变 → 调用方零改动
- **mixin vs 协作者类**：跨切面、读写宿主多字段的状态逻辑用 mixin——经 MRO 保留 `self._x()` 调用、零调用点改动
- **棘轮行数口径**：脚本内自产自校，CI 与基线自洽；勿用不同工具对账（口径不同）
- **陷阱**：移动挂着门禁的文件要同步硬编码路径，否则门禁静默失效
