# 管理员后台

> **状态**：后端 `/v1/admin/*` + 独立 web 控制台 `apps/admin`。→ 见 §三 模块范围。

面向平台运营者（创始团队）的管理界面。管控**跨用户**的账号与平台（独立于桌面消费端）。

## 一、形态决策：独立 web 控制台（apps/admin）

**决策**：管理后台是**独立 web 应用**（`apps/admin`），**不**塞进桌面端（Electron）。

**为什么（按分量）**：

1. **架构契合**——admin 本质是「`/v1/admin/*` 之上的薄 CRUD 客户端」，不需要桌面端的 sidecar / 本地文件系统 / MCP / inference-token 机制；独立 web 是它最干净的形态。
2. **安全 / 运维**——admin 代码不下发到消费端桌面包；独立访问路径 + 身份门（见 §二）；独立部署不受 Electron 自动更新滞后拖累；爆炸半径隔离。
3. **零浪费**——后端 `/v1/admin/*` 与前端形态无关，是真边界也是稳定面；独立形态不浪费后端工作，也省掉「从桌面端抽离」的迁移。
4. Admin 是运维端，不并入桌面产品页单树；共享仍只限 contract-types / design-tokens。产品页单树 → [前端技术 §五](/docs/04-前端/前端技术与架构.md)。

**被否**：A 扩「设置 → 成员」页（设置区窄列放表格挤、admin 代码混入消费端）；B 桌面内 `/admin` 路由（同样混入消费端、背桌面壳）。两者安全增益都只是「换个端口」——真安全取决于访问路径，而非源码放哪个目录。

## 二、鉴权 / 访问姿态（决策）

| 维度 | 决策 |
|---|---|
| 真边界 | 后端 cookie 会话 + `AdminUser`（`role==admin`）→ 403；前端只是客户端 |
| 登录 | **独立登录页**，cookie 限定在 admin origin（不复用桌面会话）|
| 网络 | **独立 origin**：管理后台与消费端分离；建议反代/Tunnel 到本机静态端口，并叠加外层身份门（可选）+ 应用内 `AdminUser`（两道互补，外层不替代登录）——见 [部署拓扑 · 管理后台（独立 origin）](/docs/05-平台与运维/部署拓扑与环境.md#管理后台独立-origin) |
| cookie 隔离 | **靠 admin 打自己域下的 `/api`**，不是靠页面 origin 分离。auth cookie 无 `domain=` → host-only、落在被访问的 **API 主机**上：只要两个 SPA 指向同一 API origin，页面分域也照样共用 access cookie，后登录者顶替先登录者（对方的 `/v1/auth/me`、`/v1/auth/sessions` 连 IP 设备一起读到，写也落对方账号）。**勿把 admin 的 API 指回产品域**——`AGENTCORE_OFFICE_API_URL` / `office-admin.conf` 的 `location /api/`。隔离的是 cookie jar 不是信任：两域共用同一 JWT 密钥 |
| 加固 | ✅ admin TOTP 2FA 已落地（`auth/mfa.py`，`admin_mfa_required` 默认强制）；独立 admin 账号体系 ⏳ |
| CORS | 后端按 admin origin allowlist + credentials |

## 四、后端契约（✅）

`AdminUser` 门控（401 未认证 / 403 非 admin）。

| 端点 | 行为 |
|---|---|
| `GET /v1/admin/overview` | 总览 Dashboard：今日脉搏 + 账号计数 + 近 7 日趋势 + 部署健康 + 近期错误 feed（`trace_id`/`conversation_id` 供下钻）。**纯读侧聚合** |
| `GET /v1/admin/users` | 全量名册，分页 + 子串过滤（`q`）+ 维度筛选（`role` / `status`，AND 组合）+ **同人多号可查**：`ip`（匹配 `users.registration_ip` **或**该用户任一 `refresh_tokens.ip`）+ 注册时间窗 `since` / `until`（对 `users.created_at`）+ 排序（`sort` ∈ {`created_at`, `cost`}、`order` ∈ {`asc`, `desc`}，默认注册时间倒序）。行含 `registration_ip`（旧账号可 null）。**累计成本** `cost` = 账本（`cost_events`）按用户 LEFT JOIN 求和（未花销账号 = 0）；每行带 `cost_total`（nano-CNY）。**注销账号（自助注销、已匿名为 `deleted_<id>`）默认隐藏**，`include_deleted=true` 才纳入（审计用，行带 `deleted_at` 标记）。`total` 随同口径；非法枚举值 → 422 |
| `PATCH /v1/admin/users/{id}` | 部分改 `role` / `status` / 配额。配额**三态**：字段缺省 = 不变 / `null` = 清覆盖回继承全局 / 值 = 设（0 = 该维度不限）|
| `POST /v1/admin/users/{id}/reset-password` | 生成一次性临时密码、改哈希并清锁定，同时**吊销该用户全部 refresh（强制登出所有设备）**；临时密码**仅在响应体返回一次**。复用 `AuthService`，未知用户 → 404 |
| `POST /v1/admin/users/{id}/set-password` | 管理员指定新密码（`new_password` ≥8 位、`force_change` 默认 true）；**不返回明文**（操作者已知）；吊销全部 refresh、清锁定。审计 `user.set_password`（detail 仅记 `force_change`，不落密码）。未知用户 → 404 |
| `DELETE /v1/admin/users/{id}` | 注销账号（用户管理强操作）：软删除 + 匿名化、吊销会话、停用，并**跨域级联**（对话软删 / 分享撤销 / BYOK 删除 / 头像清理）——与自助注销**同一路径**（复用 `cleanup_account_resources`），唯**不验证密码**（admin 门控 + 前端二次确认即意图证明）。**拒绝注销自己**（防自锁）→ 422；未知用户 → 404。账本保留；返回墓碑记录（带 `deleted_at`）|
| `GET /v1/admin/users/{id}/detail` | 用户详情下钻：单账号（含 `registration_ip`，旧账号可 null）+ **会话列表只读**（复用 `refresh_tokens`：`ip` / `user_agent` / `client_platform` / 时间等，不另起表）+ 已配服务商数（`provider_count`）+ 账号默认模型名（`default_model` / `background_model` = 账号默认指针取值，仅名、永不下发 key）+ 本人用量（含 **近 30 日 by-model**，扫 `cost_calls`）+ 最近会话 + 最近回合活动（`turn_metrics`）|
| `GET /v1/admin/usage/summary` | 全站用量看板：跨用户聚合（含 **by-model**）；byok 下为各用户**自带 key** 花费之和 |
| `GET /v1/admin/usage/go-windows` | **OpenCode Go 三窗口校准**（5 小时固定窗 / UTC 周一 / 订阅日锚月）：只加总平台代付 `cost_calls`（排除 BYOK 与 vendor extras）。两列：curated **名义价 nano-CNY**，以及按 OpenCode 公开单价（`deepseek-v4-flash`，读时算、价表单独存放）估算的 **nano-USD**——按每次调用时间戳判 Peak / Off-Peak，**不是**上游账单或余额。卡片须写明 `costMultiplier` 与 cache 字段未经实包验证时会低估。响应含各窗当前累计、`started_at` / `reset_at`、顶层 `subscription_day`（`PLATFORM_GO_SUBSCRIPTION_DAY`，空池 / env 回落）与 `estimate_price_as_of`。池非空时 `members[]` 按账号拆窗，各用该号自己的订阅日。分析页「成本」段展示 |
| `GET /v1/admin/observability/summary` | 运营观测：回合健康 + 趋势 + 近期错误 feed |
| `GET /v1/admin/observability/conversations/{id}` | 会话复盘**列表**：消息 + `turn_metrics` + `cost_events` + `turn_journal` 压缩 spans / **轻量 runs** **跨源合并时间线**；admin **跨用户**。无正文回合以「裸回合标记」入线；多 Agent 的 `ReplayMessage.runs` 复用 `runs_from_entries`→`project_turn` + `message_final` 全文（非完整 events）；前端按 `run_id` 分组 spans。列表**不**带 `runs_payload` / `projected`（始终 null），`has_final_state` 标记可点开再拉的助手回合。助手行带 `reasoning_content`（`messages` 列，与桌面冷刷新同源；用户行 / 裸回合标记为 null）。用户行带 `attachments` / `agent_mentions`（同 `MessageDetail` 形状，仅元数据、无抽取正文）。**取最新窗口**（newest-first 抓、按时间正序返回），超帽 `has_more_before=true`——长会话丢最旧一侧而非最新。软删会话可打开（与名册默认 `include_deleted` 对齐；产品 API 无旁路）|
| `GET /v1/admin/observability/conversations/{id}/messages/{message_id}/final-state` | 会话复盘**按回合终态**：该助手行的 `runs_payload`（`runs_from_entries` 原文 = `MessageDetail.runs`）+ `projected`（`project_turn(runs_payload.events)`，与 conformance golden 同一 oracle）。**不截断、不摘要化**。`projected` 为 null 时（普通对话 / 只有 process 的单聊）过程与终端 `finish_reason` 在 `runs_payload` 上，消费须**两份一起读**。用户行 / 无 journal → 两字段 null。软删会话可读 |
| `GET /v1/admin/conversations` | **对话名册 · 会话段**：跨用户分页会话索引。行含 owner、消息/回合/错误/**委派** rollup（`delegated_turns` / `workers`）、累计成本；默认**含软删会话**。筛选：`q`、`user_id`、`has_errors`、`has_delegated`、`since`/`until`；排序：`updated_at` / `created_at` / `cost` / **`delegated`** |
| `GET /v1/admin/conversations/turns` | **对话名册 · 回合段**：跨用户 `turn_metrics` 分页流水。行含 `TurnMetricLine` + 会话标题 + owner；筛选：`user_id`、`conversation_id`、`status`、`delegated`、`trace_id`、`since`/`until`；默认含软删会话 |
| `GET /v1/admin/system` | 系统状态只读：计费模式 + 全局配额 + 健康 + 版本 |
| `GET/POST /v1/admin/platform-credentials` · `PATCH/DELETE …/{id}` · `POST …/{id}/clear-runtime` | **平台额度账号池**：增删改 / 禁用（封号立刻摘除）。每成员 `(api_key, base_url)` 强绑定 + 自己的订阅日 + 可选 **上游工具面上限**（`tool_surface_limits.max_tools` / `max_properties_total` / `max_properties_per_tool`，空=不限，运维按该号订阅档填，不硬编码厂商数字）；key AES-256-GCM 落库，响应仅 `masked_key`。空池或全禁用 → 选钥回落 `PLATFORM_API_KEY`。启用成员全在冷却 / 封禁时**不**回落 env，走既有「接入自己的 Key」CTA。列表每行随行下发**运行态**（`status` = healthy / cooling / exhausted / blocked + `recovery_at` + 触发的 `limit_name`；读 `platform_pool_state`，不落库）；`clear-runtime` 清掉冷却 / 耗尽 / 封禁标记让该号重新可调度，写 `platform_credential.clear_runtime` 审计（`detail.cleared_status` 记清前状态）——**封禁号复活的唯一正规入口**，不必再靠 PATCH 字段间接触发。「平台额度」页（`/quota`）可管理 |
| `GET /v1/admin/feedback` | **反馈管理**：跨用户分页列表（`status` / `category` 筛选）；行含提交者展示名、标题、描述、`page_context`、状态、`admin_reply` |
| `PATCH /v1/admin/feedback/{id}/status` | 更新反馈状态（`open` / `acknowledged` / `resolved` / `closed`）并可选写入 `admin_reply` |
| `GET/POST /v1/admin/notices` · `PATCH …/{id}` · `POST …/{id}/publish|archive` | **产品公告**：草稿 CRUD → 发布/归档；字段含 severity / surface(banner\|inbox\|both\|modal) / dismiss_policy / 时间窗 / CTA。用户面见下方「产品公告」 |
| `GET /v1/admin/beta-group/moderators` · `PUT/DELETE …/moderators/{user_id}` | **内测群管理员**：任命/撤销 `chat_members.role=admin`（非升平台 admin）。权限与 IM 治理 → [消息 IM · 内测全员群](/docs/05-平台与运维/消息IM.md) |

路由与参数 → 见 OpenAPI / `api/routes/admin/`。

**护栏（service 层）**：admin 不能改**自己**的 `role` / `status`，也**不能注销自己**（防自锁——账号不硬删，唯一通往「零 admin」的路径是最后一个 admin 对自己动手，故此一条即保证恒有 ≥1 active admin）。停用即时生效：被停用账号下次请求 `get_current_user` 复检 `status` → 401（无需吊销令牌）。

**注销账号 = 两入口、同一落点**（防销户路径漂移）：注销 = 软删除 + 匿名化（`deleted_at` 盖戳、`username`→`deleted_<id>`、清邮箱/头像、`status=disabled`；账本不动，不变量①）。

- **两入口**：自助 `DELETE /v1/auth/me`（密码确认）与管理员 `DELETE /v1/admin/users/{id}`（防自锁 + 前端二次确认、无密码）。
- **同一落点**：跨域级联收口在 `api/account_cleanup.py::cleanup_account_resources`（对话软删 / 分享撤销 / BYOK 删除 / 头像清理）；auth 域变更（软删用户行 + 吊销会话）各自在 `AuthService`（`delete_account` 带密码 / `admin_delete_account` 不带）。
- **墓碑账号**：从名册与系统/概览计数（`total`/`active`/`admins`）**默认剔除**，仅 `include_deleted` 审计视图可见、按只读墓碑渲染。

**P1/P2 复用既有聚合与基建，不另起炉灶**：跨用户口径复用 `CostEventRepository` 的窗口聚合（去 user 过滤 + 新增 by-user 聚合，join `users` 取展示名）；账本→cost/usage schema 的映射抽到 `api/cost_view.py`，与 `/v1/usage/summary` **共用一份**（账本已定价，只读不重算）；DB 探活、版本各下沉**单一源**（`/readyz`、`/version` 均与 `system` 同源）。

**运营观测的数据源 = `turn_metrics` 表（DB），不是日志文件**：

- **为何不用日志**：AI 运行时日志（`logs/dev.jsonl`）是给 dev/cursor 排查的 firehose，生产默认仅 stdout（`settings.log_file` 缺省空）、只追加无索引、不含正文——不适合在线给 admin 查。
- **落点**：云端完成路径（`conversation/turn_persistence.py::persist_turn_result` → `_finalize_cloud`，`chat.turn_complete` / `chat.resume_complete`，与 `cost_events` 落账同一处）以及本机 sidecar 回写（`_finalize_local`：完成 / 暂停 / 取消）**best-effort 各落一行 `turn_metrics`**（同成本落账铁律：遥测写失败绝不炸用户回合）。云端写入已算好的结果/质量（status / finish_reason / rounds / duration / delegated / workers / tokens）；本机只写结构字段，**token 仍空**（折账未对齐）。看板 token 合计只计 `mode='cloud'`，**不要**按 `input_tokens = 0` 排除。覆盖面与 `mode` 分段 → [对话日志分析指南 · 本机回合与 turn_metrics](/docs/05-平台与运维/对话日志分析指南.md#本机回合与-turn_metrics)。看板用带索引 SQL 聚合。
- **`status` 枚举**：`ok | partial | paused | error`（一次 migration 加齐）。四值都在写：`paused` 来自云端 CEO 限流暂停（`_finalize_ceo_continue_pause`）与本机暂停结算。`partial` = 批次已声明有产物有缺口（`delivery_status=partial` / `product_landed` / delegate `partial_failure`），**不计入**健康看板错误率（仍只计 `status=error`）。
- **三源可拼**：钱在 `cost_events`、正文在 `messages`，均以 `trace_id` 与 `turn_metrics` join（遥测行不重复存钱/正文）。

**协作质量 · MAST 看板（多 Agent「学·度量」的在线半）✅ 已落地**：把「协作好不好」变成能数的几样，按 **MAST**（Multi-Agent System Failure Taxonomy，14 类 / 三组：规格不达 / 互相错位 / 验证缺位）打标——别自创词表。

- **在线四列**：`turn_metrics` 加 `boundary_yields` / `scope_signals` / `revises`（＝带现场续派次数，CEO `continue_from_run_id` + redirect 热修，**含 lead 子团队内的续派**——与 usage / 协作计数同一条上卷路；不计辩论）/ `escalations`（经 delegate 工具上卷、`chat.turn_complete` 日志），健康窗口算 **`first_plan_survival_rate`**（首版计划多少撑到底——直接量「太依赖第一次编排」这个痛点，也是 lead B 铺开值不值得的主证据）；前端落「分析·健康」的「协作质量 · MAST」卡片。
- **离线对照**：`scripts/log_stats.py` 按 `trace_id` 纯读现成日志算同样四样（返工率 / 首计划存活 / 漂移率 / 空转·早收），与在线同义（prod 是 stdout-only 日志姿态、可能不写 `logs/dev.jsonl`，故双面）。「空转·早收」读现成 `finish_reason`、不新增列。
- **评测半（共线）**：MAST 标签化离线评测集（`agentcore/evals/mast.py` 14 类 + `cases/mast/` 多 Agent 用例 + report `mast_breakdown`，已接入 `evals-nightly.yml`）需真模型回合才出 pass_rate——与路线图「提示词 / 真跑评测」主线共用前置（`EVAL_DEEPSEEK_API_KEY` + 裁判 gold-set）；详细提案不在公开仓 / 维护者本地。

→ 见代码：`apps/server/scripts/log_stats.py`、`agentcore/evals/`（`mast.py` / `report.py`）、`turn_metrics` 仓储 + `admin/service.py`（健康窗口）。

**tool/LLM span 级明细复用 `turn_journal` 投影，不另起 `span_metrics` 表**：

- **复用 journal**：span 事实（`llm_call` / `tool_call` …）**早已落 Postgres**（`turn_journal`，回放/续写唯一事实源，按 `turn_id`=assistant msg id），故会话复盘的「执行明细」是对它的**读侧投影**（`load_map` 批量 + 压缩成 triage 用的 `ReplaySpan`，丢掉系统提示/完整结果等重负载），零新表零迁移。
- **多 Agent runs**：同 journal 经既有显示投影（`runs_from_entries` → `project_turn`）折出轻量 `ReplayRun`（run_id / agent / task / 树边 / status / debrief / `message_final` 全文），**不**下发完整 `RunsPayload.events`；admin 用轻量树/泳道列表排障，禁止搬入桌面协作图画布。
- **终态同源，按回合按需，不造第三套投影**：列表只带压缩 `ReplaySpan` / 轻量 `ReplayRun`；点开某助手回合再拉 `runs_payload` + `projected`（见 §四），与用户端重载读的是同一对，**不截断 projected**。体积依据（**本机 DB 实测，非生产样本**；123 个有 journal 的回合）：`{runs_payload, projected}` 单回合 p50 ≈ 90KB / p90 ≈ 456KB / **max ≈ 8.5MB**，35 个回合单条 ≥256KB，最肥会话若内联约 9.3MB（其轻量部分仅约 395KB）。对照 conformance 夹具最重一对仅约 52KB——**夹具不含 live DURABLE 工具结果，勿用夹具体积推断真实负载**。**被否**：打开页面整会话下发 DURABLE 全量（把 `ReplaySpan` 刻意丢掉的重负载加回去）；用分页替代按需；admin 自写客户端 fold（生产由后端投影、离线预览用向量自带 golden，两条路都不需要客户端折）；从 `process` 反推事件或合成 `message_end`（即已退役的 journal 反推路，理由见 [`demos/README.md`](/demos/README.md)）。
- **投影撑不到的卡面按降级处理**：`ProjectedTurn` 只给交互锚点（`interactions[]`）。admin 不画编制确认卡；**计划复核的卡面**（steps·`ceo_review`）与**审批的 `decision`** 均不在投影里，admin 只画「有一张卡 + 状态」，已结的审批不标通过/拒绝。**被否**：为补卡面旁路读原始事件、或为此扩 admin 契约。
- **系统提示各取所需**：admin 投影丢掉的系统提示由**用户向**「收到的上下文」补上——CEO 与队员的 `system` 块（`run_context` 投影、与喂 LLM 同源）按需弹窗对**本人**展示（详见 [`../03-AI核心/上下文传递可视化.md`](/docs/03-AI核心/上下文传递可视化.md)）；作用域区别：admin 跨用户只读、用户向限 owner+会话。per-agent 花销/耗时已在 `cost_events` 可聚合。
- **为何暂不立表（YAGNI）**：唯一会让 `span_metrics` 扁平表成立的是「跨回合 span 聚合」（工具/模型健康看板：工具 X 的 p95、按模型错误率——对 `turn_journal` 的 JSONB 全扫不可扩展，同 turn_metrics vs 日志的理由），该需求尚未提出。per-span 延迟当前未可靠落账（执行事实多无 ts），需要时给 `ToolCallFact`/`LlmCallFact` 补 ts/duration 即可，非新表。

## 五、前端（apps/admin, ✅）

独立 web 应用：**独立登录页**，cookie 限定在 admin origin（**不复用桌面会话**；靠自有 `/api` 反代实现，见 §二「cookie 隔离」）。侧栏页（概览 / 用户 / **对话** / 分析 / 审计 / **公告** / **内测群** / **平台额度** / 系统）由 `AdminShell` + **URL 路由**（`react-router`）切换；用户详情（`/users/:id`）、会话复盘（`/replay/:id`）为可书签深链，默认落「概览」。邀请码能力已退役（开放注册，不再运营发码）。

**信息架构（去重为纲：每个明细事实只在一个页存在一次）**：

- **概览** = 枢纽：今日脉搏 4 个 KPI tile（点即深链：活跃用户→用户 / 回合·错误率→分析·健康 / 成本→分析·成本 / P95→分析·健康）+ 部署健康灯带（数据库→系统 / 计费模式→**平台额度**）+ 近期错误 preview（5 行，点行下钻会话复盘，「查看全部」→分析·健康）。**不重渲染明细**——`/overview` 仍含 7 日数组，但趋势图只在「分析」渲染。
- **对话** = 全站 AI 对话记录的**唯一索引归属**：顶部分段 `会话 | 回合` + **conversation_id / trace_id 直达复盘**框。**会话段** = 分页名册（用户 / 标题 / 消息·回合·错误 / **多 Agent 徽章** / **委派列可排序** / 成本 / 更新时间；标题搜索、`user_id`、仅有错误、**仅多 Agent**、`since`/`until`、按更新/创建/成本/**委派**排序；默认含软删会话与用户注销标记）。**回合段** = `turn_metrics` 流水（含 `trace_id` 列可点复制，对照 `logs/dev.jsonl`；**多 Agent 徽章** + **仅多 Agent** 筛选）；按状态与时间筛选。两段行点击均下钻 **会话复盘**（`/replay/:id`，回合行带 `?trace=` 锚点）。复盘宽屏 = **按用户视角的只读聊天主栏**（阅读柱 `max-w-3xl` 居中，与桌面对话页同宽；用户泡在柱内 `max-w-[80%]` 右对齐，无「用户/助手」常驻标签）：助手行经 `chatTurnFromReplay` 走 `ChatView`，**过程折叠同桌面**（过程收成摘要，收起只留标题、零思考正文；点开才见 muted 思考 Markdown 与工具 JSON；连续 ≥2 工具成组；arguments·result·display 仍在主栏不进坞；来源标题以紧凑胶囊露出，点开才见 snippet；过程标记槽内嵌协作树与已答提问，待答不占空标题；协作树节点紧凑；团队条只留生命周期图标与 `n/m`，不写「协作已完成」类解说）；**终稿超长夹层是复盘扫读密度**（约 640px「展开全文」），不跟桌面对话终稿全文。用户行画**附件与 `@Agent` 芯片**（仅元数据、不下载）；用户端本就隐藏的「系统收口」**不进主栏**，改挂 `TurnOpsBar`、点开在右坞看正文与状态。**可选右坞**（壳层侧栏，默认关；**不改阅读柱的 max-w-3xl**，默认宽 400 与桌面侧栏同档）：条为钉死「诊断」+ 可关队员 tab（对标桌面右坞「工作区 + run tab」，不搬 `+` / 改动 / 弹出）。点右上「打开诊断」开坞并停在诊断（未选回合则锚最后一条助手消息）；**点协作树节点**（或诊断面短名单）挂该队员 tab 并激活，诊断留在条上。诊断面：会话 KPI、复制 conversation_id、TurnOpsBar（系统收口 / span / BYOK / 模型 / trace）、队员短名单。队员面：角色任务锚点与思考/工具/正文交织时间线（默认展开）。坞 × 收起整坞（同回合再开记住已挂队员 tab）；切回合 / 换会话卸队员 tab、回到诊断、坞保持打开。**否决**坞内再拆「运维 / 执行 / 检视」三 tab。窄屏开坞后临时切到侧栏视图。主画面无三行顶栏/回合 pills/顶栏 KPI；浮层返回+标题；底栏禁用「只读复盘」占位条；≥2 条用户消息时右下「对话大纲」跳转回合；助手脚注仅成本·轮次(>1)·耗时。138 次调用 / BYOK / 模型 / ID 只进诊断坞。`conversation_id` / `trace_id` 可点复制；`has_more_before` 为 true 时主栏标明更早消息已截断。无输入发消息、无真实流式、无全屏放大态。→ `ConversationReplay` + `conversation-replay/` + `components/chat/`（`ChatView` / `chatTurn` / `TeamLane` / `ProcessLane`）。用户详情「最近会话」「最近活动」各保留 15/20 条 preview +「查看全部」深链到此页（带 `user_id`）。观测总览「近期错误」的 `trace_id` 亦可点复制。

  **主栏还原用户终态（✅ 已落地；当前窗口自动拉终态）**：打开复盘先拉列表（正文 + **`reasoning_content`** + 压缩 spans / 轻量 runs / 运维字段）。当前窗口内 `has_final_state` 的助手行自动拉 `runs_payload` + `projected`（并发 2，`?turn=` / `?trace=` 锚点优先；列表接口仍不内联这对）。纯聊天无 journal 时靠列表 `reasoning_content` 显示思考（与桌面冷刷新同源，DERIVED 思考流不进 journal）。主栏仍经 `chatTurnFromReplay` 走 `ChatView`（折叠策略同上）。`ChatView` 入口 = 正文 + 思考列 + `runs_payload` + **可空** `projected`（`projected` 为 null 是常态——普通对话与只有 process 的单聊都没有，此时回落 `runs_payload`；反之 `projected` 在场即以它为准，别用「空数组回落」的写法，那会吞掉多 Agent 时间线）。运维信号（成本 / `trace_id` / span 明细 / KPI / 队员全文）退到诊断坞、**未删除**；主栏助手脚注只留成本·轮次·耗时——不依赖终态接口，列表上的 spans/runs 即可。生产 `projected` 是松散 dict，每个嵌套字段都当可缺处理（向量数据永远齐全、门禁抓不到，只有生产会打崩整页）。离线自检走隐藏路由 `/preview`（选 conformance 向量渲染终态，不回放中间帧）。**保真档 = 终态**，不做流式过程重放：journal 只存 DURABLE，EPHEMERAL 帧（打字 delta / `run_phase` / 工具心跳）从不落盘。**被否**：① 抽跨端共享渲染包——桌面 `ChatView` 无数据 props、绑 conversation / execution / interactions / pausedTurns 等十余个 store，复用等于把 desktop renderer 嵌进 admin，且撞 `cross-platform-frontend` 的零共享业务逻辑；② admin 复用 `dev:webapp` 只读模式——保真最高（就是原件），但须在 owner-scoped `/v1/conversations/*` 上开 admin 跨用户旁路，爆炸半径不可接受。

  **门禁边界（易误解，勿再踩）**：`pnpm conformance` 断言的是 `fold(events) == projected`，**不看组件画面**（规则原文：组件 / chrome 不进巡检）。admin 的渲染漂移靠**自建**渲染断言（对 golden `projected` 断言结构与文本）守，不是靠 `pnpm conformance` 白捡；桌面那套 `pnpm shoot` 截图冒烟 admin 未上。生产的 `runs_payload.process` 路径无向量可依，是**已知缺口**——不为凑覆盖去造投影或造向量。
- **分析** = 用量 + 观测合并（两者同构：窗口卡 + 7 日趋势 + 表 + 会话复盘下钻，仅指标不同），顶部 `成本 | 健康` 分段切换，右侧常驻「会话 ID 复盘」框；**仅当前段拉取**对应接口（`/usage/summary` / `/observability/summary`），不一次拉两份。成本段含 **by-model**（`cost_calls`）。
- **用户 / 审计 / 系统 / 平台额度**：
  - **用户**：名册（顶部按 角色 / 状态 下拉 + **IP**（注册 IP 或会话 IP）+ **注册时间窗** + 用户名/昵称搜索，「注册时间」「累计成本」列头可点排序；行展示账号 + 配额 + 累计成本（¥）；`registration_ip` 在 API 行字段与**详情**展示，名册以 IP 筛选为主）——查同人多号：先填可疑 IP 或时间簇，再叠加用户名启发式。详情下钻（`registration_ip`、会话元数据只读、配置对话/后台模型名、近 30 日 by-model），详情页「设置密码」→ 输入新密码 + 可选「要求用户首次登录后修改密码」→ 确认（登出所有设备）；「重置密码」→ 确认 → 一次性临时密码弹窗（仅展示一次 + 复制）；行内「注销」→ 二次确认（说明匿名化 / 登出 / 级联清理、不可恢复）→ 默认视图移除该行、审计视图回填墓碑；「显示已注销」开关切审计视图（注销行以「已注销」徽标 + 只读墓碑呈现）。详情「最近会话 / 最近活动」→ **对话**页深链。**不做** IP 封禁/停用入口；滥用处置仍是单账号停用/改配额（字段语义见 [认证与会话 · 可查](/docs/05-平台与运维/认证与会话.md)）。
  - **审计**：管理员特权操作记录（改用户 / 重置密码 / **设置密码** / 注销 / **平台账号增删改与解封**），分页 + 按操作类型筛选。
  - **系统**：部署只读快照（数据库 / 版本 / 发布漂移）；账号计数的唯一家在此。计费模式与全局配额只读块已移到「平台额度」。紧急关闸注册见环境变量 `REGISTRATION_OPEN`（[`认证与会话.md`](/docs/05-平台与运维/认证与会话.md)），不在此页做产品开关。
  - **平台额度**（`/quota`）：平台侧「供给 + 上限」的唯一归属——计费模式与全局配额默认值只读（改 env 须重启后端，无热开关）+ 账号池 CRUD（含每号声明的上游工具面上限）+ 每成员运行态（冷却 / 月耗尽 / 封禁，带恢复时间与触发的限流窗名）与一键解封。**每用户**配额覆盖仍在「用户」、Go 三窗口用量仍在「分析 · 成本」，此页不重渲染。号池卡不依赖 `/admin/system`，那份快照挂了仍能换号。
  - **公告**：产品全局 Notice 的唯一运营入口（列表 / 草稿编辑 / **套用模板** / **复制为草稿** / 发布 / 归档）；消费端在桌面壳，不在此渲染。模板与文案 → [产品公告文案模板](/docs/05-平台与运维/产品公告文案模板.md)。
  - **内测群**：任命/撤销群管理员（`chat_members.role=admin`）；**不是**升平台 admin。IM 内踢人/禁言/公告由管理员或平台 admin 操作 → [消息 IM](/docs/05-平台与运维/消息IM.md)。
