## 三、工具审批与 PermissionAxes ✅

**问题**：布尔 `approval_required` → 批量写文件审批疲劳。

**两态**（工具固有属性）：`never`（只读/纯计算）/ `grantable`（局部可控副作用）。原 `always` 已删。`git` schema 可 `NEVER`，写入子命令运行时升格。`run` schema `GRANTABLE`（`action=read|stop|list` 免审）。用户 pty **不设边界**；AI 可读不可停不可写。

**PermissionAxes**（会话单一真相源；用户 AutonomyPolicy 仅种子配方）：

| 轴 | 取值 | 语义 |
|---|---|---|
| `file_write` | `ask` / `session` | 可逆写逐次审 / 会话信任 |
| `command` | `ask` / `auto` | 不预授执行 / 免审执行 |
| `host` | `off` / `ask` / `session` | 本机 Host 整面关 / GRANTABLE **action**（`shell` / `open_settings` / `set_audio` / `restart_service`；**⏳ 含未来 Computer Use**）逐次审 / 会话信任（熔断与**恒确认**除外） |

非法：`command=auto` ∧ `file_write=ask`。`host` 与 `command` **正交**：单一 `host` 工具**不**挂 `execution_class`，**不**吃 `command=auto` 静默授。schema 为 `NEVER`，GRANTABLE **action** 运行时升 `host` 轴（同 `git` 写入）。CEO 持 `host` / `run`，审批仍走轴 / GRANTABLE / 恒确认（装包、push）——不因角色另造闸。`run` schema `GRANTABLE`（`action=read|stop|list` 免审；启动吃 `command` 轴，`command=auto` 静默放行；云桌 guest / 本机）。动作表 → [工具 · Host](/docs/03-AI核心/工具与能力系统.md)；分集 → [编排器 · 核心定位](/docs/03-AI核心/编排器与CEO主Agent.md)。`command=auto` 静默放行整类 `execution_class`（含 `run` / `browser`）与低风险 `desktop_notify`（不挂 Host 轴）；永久删 / MCP / Host GRANTABLE / 熔断与 FORCE 不变。配方默认：谨慎=`file_write=ask` + `command=ask` + `host=off`；全放行（展示名；id `less_interrupt`）=托管=`session` + `auto` + `host=session`（三档 id 仍在，后两档轴值相同）。徽章「全放行」= **已授权根内**免审；未加入本对话的目录仍不能改。**否决**扫用户原文「所有权限」切模式。fuse / 敏感路径 / 装软件恒确认 **不**因全放行或 `attach_rw` 放宽。`command=kickoff` 已退役：API 再发 → 422；库内旧 JSON 靠迁移写改写，读侧不再并档。旧 `team_kickoff` 当未知键丢掉。深度研究自治只认会话显式旗标，配方不再蕴含。`host=off` 只关 Host 面，**不**等价于禁工作区 `run`。账户默认入口：桌面对话权限徽章「设为新会话默认」（仅三配方）；自定义轴不可存为用户默认。`ask_user` / `plan_review` / 熔断与敏感读**不可被 PermissionAxes / 配方静默覆盖**（敏感读本轮放行例外见下节）。

**⏳ Computer Use（本机 GUI · 蓝图已确认未落地）**：复用 `host` 轴，**不**新开第五轴。主路径 = **指定窗口**的控件树 `ref` 操作（非坐标）；**整屏**须轴外额外 grant（`host=session` 信任窗口 **≠** 整屏）。密码框键入硬拒——按控件 `IsPassword` 属性判定（**结构化可证明**条件，属硬闸白名单；不得扩成「看着像密码框」的启发式面），对齐 `browser` 的 DOM 属性纪律。控件树读不到时**诚实失败**，禁止盲点坐标冒充已执行。**CEO+worker** 同形（档位 1），审批走 `host` 轴，不因角色卸权。Computer Use 仍走 `host` 轴，不并进 `browser`。产品边界 → [工具 · Computer Use](/docs/03-AI核心/工具与能力系统.md#computer-use)。

**沙箱→审批**：本地 subprocess 需授权（`command=auto` 除外，见上）；云 gVisor 自动放行执行类；无沙箱不注册。**写文件类**：本地 worker 始终走审批门；云端 worker 对服务器沙箱侧工具免逐次卡，但 **`file_write=ask`（谨慎）优先**——云端可逆写（`file_write` / `str_replace` 等文件变更类及同类 `git` 写）仍弹确认；`file_write=session` 时云端写文件仍免逐次卡。MCP / Host 本机面无论云/本地都弹。CEO / captain 的 GRANTABLE 始终走门，不因 `location=server` 免审。这张「云端 worker 该不该跳卡」表是**唯一真相源**（`runtime/sandbox_approval`），收口点之外不得另起判断。

**审批收口点（单一不可绕过 · fail closed）**：「这次调用要不要人批」只在 `runtime/engine/tool_exec_gates` 判一次，且**分两步不合并**——① 按工具属性（GRANTABLE / 运行时升格 / 恒确认 / 熔断 FORCE）减去上表豁免算出「要不要审批」，这一步**不读** `ApprovalGate` 是否存在；② 再看「有没有人可问」。**上游不预判**：delegate / debate 分发 worker 时一律把本回合的 gate 原样传下去，不按 `location` 提前吞成 `None`——那等于在 `sandbox_approval` 之外另抄一张表，同一根因已漏过三次（恒确认曾整类失效；`file_write=ask` 的云端实现长期执行不到；`ceiling` 漏传）。因此 `approval_gate=None` 现在只剩**一个**含义：这条路根本没有可询问的用户（无人值守作业 / 评测 harness）。此时若该调用需要审批 → **拒绝执行**并留可测 `status`（`tool.execute_end` 的 `grantable_no_gate` / `always_confirm_no_gate` / `circuit_breaker_no_gate`），不再「gate 缺席即放行」。签名层面 `approval_gate` **一律无默认值**，漏传是 `TypeError` 而非静默放行；「这条路确实没人可问」必须显式写出来。→ 见代码: `agentcore/runtime/engine/tool_exec_gates.py`

**熔断（现状）**：`safety_breaker` 对毁灭启发式（格式化磁盘、`rm -rf /`、shutdown 等）默认 `FORCE_APPROVAL`；**例外**：① `host(action=shell)` 路径上与执行侧 fuse **已重叠**的毁灭形（rm 根/家、格式化/写块设备、关机重启）breaker 直接 **`DENY`**（方案 C，消「批了仍被 fuse 打回」）；② `run` / `host(action=shell)` 命令文本命中 force（含 force-with-lease）→ `main|master` 亦直接 **`DENY`**（与结构化 `git` 同口径；fuse 仍不扫 git）；③ `host(action=shell)` 命中**静默安装**启发（msiexec /quiet、Setup /S、Start-Process quiet 等）→ fuse 硬拒 + breaker **`DENY`**（`host.silent_install`；文案诚实「启发式兜底，并非完整拦截」；装软件主路径 = `host(action=install_package)`）。`shell` fuse 本身仍硬拒、不可批可跑。长驻启服命令硬拒（导向 `run` `background`）。**工作区脚本破坏（回滚主、窄闸辅）**：静态启发扫 `shutil.rmtree` / `rm -rf` / `Remove-Item -Recurse` 等；Local 无可用回合 zip 基线 → `FORCE_APPROVAL`（`destructive.no_turn_baseline`）；顶层整棵工作区树 → `FORCE_APPROVAL`（`destructive.workspace_top_tree`，白名单清理目录放行）；**不**与 fuse 同条件叠第二张卡。常规 `maybe_capture_turn_baseline` 仍失败不阻断。主路径仍是基线/软删可逆，熔断是辅。结构化 `git` 工具：普通 push / `create_pr` **始终弹确认**（不吃 `file_write=session` / 「本轮文件类放行」短路），force/保护分支硬拒；**结构化 `host(action=install_package)` 同口径恒确认**（不吃 `host=session` / kickoff / turn grant——少打断默认否则会零卡装软件）；**敏感路径三态**（模板放行 / 凭据读 `FORCE_APPROVAL` / 私钥类读 `DENY`；写盘 Ask|Deny 类路径仍硬拒）——PermissionAxes / 开工**不可静默覆盖** FORCE/DENY；毁灭 / 无基线 / 顶层整树等真熔断 FORCE **仍不可**「本轮放行」；**仅** `sensitive.path_read_ask` 人批后可本轮同工具 turn grant（按工具名，非按路径；非 PermissionAxes）。启发式黑名单是兜底、非完整边界——真熔断文案须诚实「启发式兜底，并非完整拦截」；工具读闸不覆盖 shell `cat` 旁路（诚实缺口）。fuse⊆DENY 对照 → `fuse_aligned_deny_rule_ids` + `test_safety_breaker` 样本表；脚本破坏 → `destructive_fs` + `test_destructive_fs`。

### ✅ 敏感路径三态（模板放行 / 凭据 Ask / 私钥 Deny）

- **现状**：模板（`.env.example` 等）放行；真凭据读给人批（首卡后可本轮同工具放行）；私钥材料硬拒。写侧（敏感路径 + Key 形正文）硬拒。
- **分级**：`classify_sensitive_path` → `NONE`（`.example`/`.sample`/`.template`/`.dist`）/ `ASK`（`.env`、`.env.local`、`credentials.json`、`.aws`…）/ `DENY`（`id_rsa`、`.pem`/`.key`、`.ssh`/`.gnupg`…）。读：`file_read`/`grep`/`code_search` 上 ASK→`FORCE_APPROVAL`（`sensitive.path_read_ask`）、DENY→`DENY`（`sensitive.path_read`）。写：Ask|Deny 路径均 `DENY`。
- **合法通道**：人批读（进模型上下文且审计）；首卡后允许「本轮内都允许」按**工具名** turn grant（同轮后续同工具敏感读免卡；不覆盖 `grep`/`code_search` 互授）。Ask 卡可附 **键名预览（无值）**（dotenv / 浅 JSON；桌面 / 手机同渲）；**不用**「安全熔断升格审批」套话（与真熔断卡分轨；机读 `rule_id` / `force_one_shot`）。设置页凭据 / 本机环境变量；**禁止**文案劝「把密钥贴进对话」。
- **边界**：不把敏感读并进 PermissionAxes / 开工静默放行；真熔断 FORCE 卡隐藏无效「本轮都允许」（仅允许一次）；不扩 shell 文本闸（旁路诚实缺口，二期可选对齐）；不做独立 `env_keys_summary` 工具（卡预览已覆盖主路径）。
- **误伤面**（可接受）：故意把真密钥放进名为 `.env.example` 的文件 → 可读；本轮 grant 按工具名 → 批一次 `.env` 后同轮其它凭据路径同工具可读。→ 见代码: `agentcore/runtime/safety_breaker.py` · `credential_preview.py`

### ✅ host(action=shell) 毁灭启发式 · fuse 已覆盖改 DENY（方案 C）

- **现状**：`host(action=shell)` 上 fuse **已覆盖**的毁灭形，`safety_breaker` 直接 **`DENY`**，不走 `FORCE_APPROVAL`（消除「人批了仍被 fuse 打回」）。灾难硬拒保留；文案诚实「启发式兜底，并非完整拦截」。
- **边界**：只改 breaker 对 fuse 已覆盖毁灭形的裁决。**不**改 fuse 为可批可跑；**不**借机扩毁灭正则面。fuse 独有形是否前置 breaker `DENY` → ⏳。git force 口径 → 下节。
- **否决**：改 fuse 为可批可跑（B）；仅改文案当终案（D）。落地对照：`FUSE_ALIGNED_DENY_RULE_IDS` / `fuse_aligned_deny_rule_ids()` + 样本表（fuse ⊆ DENY）。→ 见代码: `agentcore/runtime/safety_breaker.py`

### ✅ git force→保护分支 · 结构化与 shell 文本统一 DENY

- **现状**：`run` / `host(action=shell)` 命令文本命中 `git push --force`（及 force-with-lease / `-f`）且指向 `main|master` 时，breaker 与结构化 `git` 同为 **`DENY`**（规则 id `destructive.git_force_push_protected`；不入 `FUSE_ALIGNED_DENY_RULE_IDS`——fuse 仍不扫 git）。普通功能分支 force 文本未点名保护分支 → 不命中（维持既有启发式样本表）。结构化 `git` force/保护分支硬拒不变；普通 `git push` / `create_pr` 仍恒确认。
- **误伤面**（已确认可接受）：故意经 shell 强推主干且愿点批的路径取消——须改分支策略或人工在仓外操作。
- **边界**：不扩其它毁灭正则；不改 `GIT_FORBIDDEN_SUBCOMMANDS`；不借机加意图分类器。→ 见代码: `agentcore/runtime/safety_breaker.py` · [工具 · Git 闭环](/docs/03-AI核心/工具与能力系统.md#git-闭环)

**「本轮内都允许」**：turn 级 · 按类操作 · 整棵 DAG 共享 · 新轮清场。

**否决** 永久 allowlist、按 Agent 放行、两卡串联、超时自动开做。编制确认 → [检查点 · §二](/docs/03-AI核心/检查点与开工卡.md)。

## 五、代码执行沙箱

云端多租 → 真隔离。**云执行默认开**（`gvisor_enabled=true`）。紧急关闭：机上 `GVISOR_ENABLED=false`。执行面不可用 → API 仍起、执行类诚实不装配（fail-safe，**不**回落 subprocess / DesktopBridge / 本机冒充云）。

### 隔离不变量（✅ 切流后仍成立）

每张云桌（工作区）一台长寿命 gVisor guest（非 rootless `--network=sandbox` + 容器内 netns）。只 bind **当前工作区**为 `/workspace`（禁止整份 `DATA_DIR`）。guest uid/gid ≡ 文件侧 `app`（禁止 nobody、禁止 chmod 工作区、禁止 guest root）。`run` 向该 guest `exec`（短执行 / 验证）或在同一 guest 内起长驻进程（按 **对话** 记账；盘仍按文件夹共享），产物直接落盘。出站经包装源 **allowlist chokepoint**。空闲桌 **reap**（杀 guest、拆包装源 netns；盘保留）：无在飞 exec、无 running 的长驻进程登记、无活的沙箱 browser 会话，且超过 idle TTL。禁止 freeze/pause 当容量阀；禁止假装进程还在（登记清空，旧 `process_id` 诚实失败）。`run=` / `package_install=` / 云端 `browser=` **同一装配谓词**。`browser` 云端是这台 guest 里的 Chromium（stdio `exec` 进桌，按对话记账），**不是**第二套 runsc jail；关浏览器 ≠ 关桌。公网出站仍走 SSRF 过滤代理；guest loopback（桌上 vite 等）不得进该代理。本机仍走 DesktopBridge。裸 subprocess 云执行（`CODE_EXECUTE_CLOUD_ENABLED`）仍默认关 + SEC-005 ack。本机 Host / 装本机软件仍须 `host=`（桌面在线）。sidecar 不装配云隔离。勿把样例 `GVISOR_TIMEOUT_MAX_SECONDS=60` 照抄进生产（默认 ≥1230）。部署面 → [部署拓扑 · 云端执行](/docs/05-平台与运维/部署拓扑与环境.md#云端执行gvisor)。

开机 / 执行失败走 `exec_env_sandbox_unavailable`（对用户说云端隔离，不说本机），不是本机 `launcher_unavailable`。浏览器文案走隔离浏览器，不说「代码执行环境启动失败」。

### 拓扑（第一刀 ✅ · 第二刀 ⏳；切流替换，不留兼容层）

**电脑是一等资源，不是 API 里的一次 RPC。** 控制面（对话 / LLM / 编排）≠ 执行面（guest / `runsc` / 装包 netns / 云端 Chromium）。

| 刀 | 内容 | 完成态 |
|---|---|---|
| **第一刀** | 独立沙箱服务持有 guest；API 只 RPC。开通在 prepare / resume。装配谓词目标 = **这张桌能 exec**，不是「sandboxd ping 过」。`run` / `execute` **不准**开机。电脑没好时空气泡「正在准备云端环境」（禁空 Thinking… 冒充）。云端对话第一句必须能跑代码；机房真挂才诚实失败。禁止用落盘冒充测过代码。闲置 reap 后同一场再开口应秒级就绪 | ✅ 独立 `sandboxd`；prepare / resume 开通；`run` / `execute` 不 `start-detach`。guest running 即成功。单桌超时不关整机闸。缺桌不装配 `run`。`desk_provision_wait` 诚实等待。用户说「测云端代码」：能跑则 `run` 在，不能跑则未装配 / 环境失败 |
| **第二刀** | 长驻进程一条**已鉴权、按对话切开**的用户预览入口 | 「做个小软件」用户可自己打开正在跑的东西。Agent 云端浏览器留下，**不**代替用户预览。⏳ 须生产配独立 origin 并用上才算落地；应用内用户页未交 |

**代码现状**：独立 `sandboxd` 容器持有 guest / runsc / netns / 装包代理；API 只经 Unix socket RPC。开通在 prepare / resume（及 browser / 长驻 attach）；聊天路径 `run` 不 `start-detach`。开机以 **guest 已 running** 为成功（禁止空等父进程退出再杀活桌）。单桌 `start-detach` 超时 **不** 关整机健康闸。装配谓词 = host 健康 ∧ **这张桌已注册**。缺桌不装配 `run` / 云端 `browser`，空气泡走 `desk_provision_wait`「正在准备云端环境」（禁空 Thinking 冒充开机）。空闲 reap 杀 guest、盘保留；下一句 prepare **秒级再开**（进程 / 浏览器不续命）。subprocess 逃生口仍只跟配置 / 健康。换票（mint）与 sandboxd 预览 HTTP 存在：未配置公开 preview origin 则 mint 503。首交为换票 + 系统浏览器；Agent 右坞 jpeg 仍是队员看页，不代替用户预览。应用内用户页未交。⏳ 第二刀须在生产配独立 origin 并真正用上才算落地。部署旋钮 → [部署拓扑与环境 · 云端执行](/docs/05-平台与运维/部署拓扑与环境.md#云端执行gvisor)。

**切流**：替换，不是双轨。不保留 in-API guest 回落；不用特性开关静默走旧拓扑；执行面挂了禁止再在 API 进程里懒拉起。自托管无 KVM 仍用 gVisor——B 锁的是单位，不是 Firecracker / E2B。多机调度与快照秒启不在本定案。

#### 第二刀 · 用户预览（⏳ 蓝图已确认）

完成态：云端长驻起来之后，用户**自己点、填、用**那个程序。Agent 沙箱浏览器（右坞 SSE jpeg）是队员看页。本机传统已有 localhost + `workspace://`，本刀只补 `location=server`。

| 锁 | 定案 |
|---|---|
| **入口** | 产品按钮（进程卡 / 聊天）。点击用当前登录换票再打开。密钥不进模型上下文、不进聊天正文、不进 journal 明文。模型只说「预览已就绪，点打开」；**禁止**把 guest `http://127.0.0.1:<port>` 说成用户能打开的地址 |
| **打开面** | 同一条 URL，不是双轨拓扑。Web / 手机：系统浏览器或应用内 iframe。桌面：现有 BrowserPanel 增加一种**用户页**（真 HTTP）；「在系统浏览器打开」仍走现有 http(s) 白名单。可先交货换票 + 系统浏览器，再补右坞用户页 |
| **流量** | sandboxd 反代（执行面）。API 只验会话、发票、返回 URL，不把 HTTP 流接到聊天 worker。须过 WebSocket 升级（vite HMR）。任意 TCP / SSH / 数据库端口不进本刀 |
| **端口** | 从该长驻 `wait_for` 就绪输出解析 HTTP 端口；解析不到 → 没有按钮。不扫 guest 监听表。没就绪或进程已死 → 无入口；已发出的 URL 立刻 502，登记清空。同一对话多端口则列出，不猜「那一个」。同文件夹另一对话看不见（记账已按 `conversation_id`） |
| **票** | 预览独立 origin + 短时票；用已有 access session 换，不另开登录 |

**不是本刀**：静态 HTML / `workspace://` 完整预览；Sandbox `browser(navigate)` 相对 HTML（仍诚实失败 → [工具 · 沙箱](/docs/03-AI核心/工具与能力系统.md)）；公开分享或自定义域名（那是发布）；本机引擎 localhost。

**否决（回潮）**：加长 `start-detach` / 提示词禁止重试 `run` 当产品修复；为「平滑过渡」留旧拓扑兼容层；用 Agent 浏览器冒充用户预览；再立一套 Playwright / CDP；API 进程同步反代；给每个对话在宿主 `docker publish` 端口；未鉴权公网随机子域；密钥 URL 进模型或气泡；重做云工作区或再引入实时同步。

**诚实降级（已在云 ≠ 再导入）**：会话已是云工作区但沙箱/netns 未装配时，缺口 / 交付 action / 委派软提示须说明「沙箱不可用」并给稍后重试 · `export_to_local` · 本机传统；**禁止**把「Composer 导入到云」当作修复（工程已在云）。导入/连 Git 仅适用于工程尚在本机、需进云执行的路径。→ 见代码: `runtime/delegate/exec_env_remediation.py`

**已删、禁止回流**：per-call staging copy-in/out；OCI uid 65534；`ExecutionRequest.registry_egress` 独立 execute 模式；形状 A `--rootless` 当执行/健康主路径；独立 `family=browser` netns / `run stdio` 第二套 jail；`browser_netns_health` 第二套装配门。装包白名单与拒改源旗仍在工具层。护栏：并发 exec 位 + 有界等待 + 内存/时长 + **空闲桌 reap**。**不为云执行新增配额维**。部署前置 → [部署拓扑 · 云端执行](/docs/05-平台与运维/部署拓扑与环境.md#云端执行gvisor)。

## 七、凭据加密 ✅

AES-256-GCM；明文永不落库/不回前端。`billing_mode=byok` → 缺密钥生产 fail-closed；`platform` → fail-safe。交叉 → [成本 §〇·五](/docs/05-平台与运维/成本配额与计费.md)。**同口径**：账户级 Git PAT（`user_git_credentials`）与**平台额度账号池**（`platform_credentials`）亦走 `KeyEncryptor`；工具永不收密码参数。云 clone/push/fetch/pull 服务端注入 PAT；`create_pr` **云与 Local 均优先账户 PAT**，再回落 `GH_TOKEN`/`GITHUB_TOKEN` / Local `gh auth token`；Local 结构化 `git` 网络命令（非 PR）仍继承 OS credential helper，不注入 PAT。→ [工具 · Git 闭环](/docs/03-AI核心/工具与能力系统.md#git-闭环)

### 七·a 密钥轮换与 production.env 灾备

> **密钥值不入仓、不入 chat、不入 PR/Issue**。机上真相源 = `$DEPLOY_DIR/config/production.env`（默认 `$AGENTCORE_HOME/repo/deploy/config/production.env`；由 `production.env.example` 复制填值；compose `env_file` 同路径）。根 `$AGENTCORE_HOME/.env` 仅 ACR 登录凭据，**不含** JWT / 加密主密钥 / SMTP 密码。模板字段名 → `deploy/config/production.env.example`（`JWT_SECRET_KEY` / `ENCRYPTION_KEY` / **SMTP 七项** 等）。

#### A. `JWT_SECRET_KEY` 轮换

| # | 检查项 |
|---|---|
| 1 | 维护窗口公告：轮换后**全部** access/refresh 失效，用户须重新登录 |
| 2 | 备份当前 `production.env` 到机外安全位置（见 C；**勿**提交 git） |
| 3 | 生成新密钥（长度足够的随机串；勿用示例占位符） |
| 4 | 仅在机上改 `JWT_SECRET_KEY=…`；保存文件权限仅运维可读 |
| 5 | 重启 api（`finish-server.sh <当前 sha>` 或 compose recreate api——**不要**顺手升到未验证 SHA） |
| 6 | 验收：旧 cookie/Bearer → 401；新登录成功；Admin MFA 会话须重新过 MFA（若启用） |

#### B. `ENCRYPTION_KEY` 轮换（高风险）

| # | 检查项 |
|---|---|
| 1 | **先读清**：该键加密用户 BYOK API Key、平台额度账号池、Git PAT 等落库密文。换键且未先重加密 → 已存凭据**无法解密**（设置页表现为绑 key 失败 / MFA 相关能力异常；平台池选钥回落 env 或不可用）。`production.env.example` 亦注明「一经启用切勿随意更换」 |
| 2 | 确认是否有用户 BYOK / 依赖该键的密文；无存量密文时等同首次配置，直接写入新键并重启即可 |
| 3 | **有存量时**（当前无可照抄的一键 migrate 脚本）：维护窗口 → 导出/记录需重绑的用户范围 → 写入新 `ENCRYPTION_KEY` → 重启 → 通知用户重新绑定 API Key（或按维护者私有流程做离线重加密——**过程中密钥仍不入仓**） |
| 4 | `billing_mode=byok` 生产缺键会 fail-closed；`platform` 可启动但 BYOK 功能死——验收模型配置页与 MFA（若用加密存 TOTP） |

#### C. `production.env` 灾备 checklist

| # | 检查项 |
|---|---|
| 1 | 首次上线：自 `production.env.example` 生成 `$DEPLOY_DIR/config/production.env`；真实值**只**留在服务器与批准的密钥保管处；**开放注册**须填齐 SMTP 七项并跑 `verify_smtp.py`（步骤 → [部署拓扑 · §8.2](/docs/05-平台与运维/部署拓扑与环境.md#82-环境变量分层)） |
| 2 | 每次改密钥 / LLM Key / CORS / **SMTP** 前：拷贝 `production.env` → 加密介质或密钥保管柜（文件名含日期；**禁止**进仓库、Slack、邮件明文） |
| 3 | 机损恢复：新机摆好 compose 布局 → 从保管处回写 `production.env` + 根 `.env`（ACR 凭据）→ `finish-server.sh <已知好 sha>` → `/readyz` + 登录烟测 + 注册发码烟测 |
| 4 | 与 DB 备份正交：[发布与门禁 §7.7](/docs/05-平台与运维/发布与门禁.md#77-备份与恢复策略) `backup.sh` 只管 PostgreSQL；**不**替代 env 备份。丢 env ≠ 丢库，但服务起不来 |
| 5 | 泄露应急：视为 A/B 都需轮换 + 轮换上游 LLM Key；审计谁曾接触备份副本 |

镜像/桌面回滚步骤 → [发布与门禁 §7.7a](/docs/05-平台与运维/发布与门禁.md#77a-回滚-runbook可照做)。

## 八、治理边界 ✅
