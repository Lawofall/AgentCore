## 三、工具审批与开工授权 ✅

**问题**：布尔 `approval_required` → 批量写文件审批疲劳。

**两态**（工具固有属性）：`never`（只读/纯计算）/ `grantable`（局部可控副作用）。原 `always` 已删。`git`/`terminal` schema 可 `NEVER`，写入/start 子命令运行时升格。用户 pty **不设边界**；AI 可读不可停不可写。

**PermissionAxes**（会话单一真相源；用户 AutonomyPolicy 仅种子配方）：

| 轴 | 取值 | 语义 |
|---|---|---|
| `file_write` | `ask` / `session` | 可逆写逐次审 / 会话信任 |
| `command` | `ask` / `kickoff` / `auto` | 不预授执行 / 开工卡授 / 免审执行 |
| `team_kickoff` | `always` / `rules` / `skip` | 总挂组团卡 / 现行跳过规则 / 跳卡 |
| `host` | `off` / `ask` / `session` | 本机 Host 整面关 / GRANTABLE Host（L2+L3+`host_shell`；**⏳ 含未来 Computer Use GUI 子面**）逐次审 / 会话信任（熔断与**恒确认**除外） |

非法：`command=auto` ∧ `file_write=ask`。`host` 与 `command` **正交**：Host 工具**不**挂 `execution_class`，**不**吃开工卡/`command=auto` 静默授。CEO **唯一**可持的 GRANTABLE schema 为 `host_shell`（L2/L3 仍仅 worker）；本地 `terminal` 亦 CEO 可持，但 schema 为 `NEVER`（`start` 运行时升审批路径；`command=auto` 静默放行）。`command=auto` 静默放行整类 `execution_class`（含 `code_execute` / `test_run` / `terminal` / `browser_*`）与低风险 `desktop_notify`（不挂 Host 轴）；永久删 / MCP / Host GRANTABLE / 熔断与 FORCE 不变。配方默认 `host`：谨慎=`off`；少打断=`session`；托管=`session`（少打断与托管本机轴相同，差在 `team_kickoff`）。配方默认 `team_kickoff`：谨慎/少打断=`rules`；托管=`skip`（少打断减工具审批疲劳，仍按规则弹组队确认卡）。`host=off` 只关 Host 面，**不**等价于禁工作区 `terminal`。账户默认入口：桌面对话权限徽章「设为新会话默认」（仅三配方）；自定义轴不可存为用户默认。`ask_user` / `plan_review` / 熔断与敏感读**不可被 PermissionAxes / 开工静默覆盖**（敏感读本轮放行例外见下节）。

**⏳ Computer Use（本机 GUI · 蓝图已确认未落地）**：复用 `host` 轴，**不**新开第五轴。主路径 = **指定窗口**的控件树 `ref` 操作（非坐标）；**整屏**须轴外额外 grant（`host=session` 信任窗口 **≠** 整屏）。密码框键入硬拒——按控件 `IsPassword` 属性判定（**结构化可证明**条件，属硬闸白名单；不得扩成「看着像密码框」的启发式面），对齐 `browser_*` 的 DOM 属性纪律。控件树读不到时**诚实失败**，禁止盲点坐标冒充已执行。默认仅 worker 持点击/键入。产品边界 → [工具 · Computer Use](/docs/03-AI核心/工具与能力系统.md#computer-use)。

**沙箱→审批**：本地 subprocess 需授权（`command=auto` 除外，见上）；云 gVisor 自动放行执行类；无沙箱不注册。**写文件类**：本地 worker 始终走审批门；云端 worker 对服务器沙箱侧工具免逐次卡，但 **`file_write=ask`（谨慎）优先**——云端可逆写（`file_write` / `str_replace` / `write_section` 等文件变更类及同类 `git` 写）仍弹确认；`file_write=session` 时云端写文件仍免逐次卡。MCP / Host 本机面无论云/本地都弹。CEO / captain 的 GRANTABLE 始终走门，不因 `location=server` 免审。这张「云端 worker 该不该跳卡」表是**唯一真相源**（`runtime/sandbox_approval`），收口点之外不得另起判断。

**审批收口点（单一不可绕过 · fail closed）**：「这次调用要不要人批」只在 `runtime/engine/tool_exec_gates` 判一次，且**分两步不合并**——① 按工具属性（GRANTABLE / 运行时升格 / 恒确认 / 熔断 FORCE）减去上表豁免算出「要不要审批」，这一步**不读** `ApprovalGate` 是否存在；② 再看「有没有人可问」。**上游不预判**：delegate / debate 分发 worker 时一律把本回合的 gate 原样传下去，不按 `location` 提前吞成 `None`——那等于在 `sandbox_approval` 之外另抄一张表，同一根因已漏过三次（恒确认曾整类失效；`file_write=ask` 的云端实现长期执行不到；`ceiling` 漏传）。因此 `approval_gate=None` 现在只剩**一个**含义：这条路根本没有可询问的用户（无人值守作业 / 评测 harness / 小镇模拟）。此时若该调用需要审批 → **拒绝执行**并留可测 `status`（`tool.execute_end` 的 `grantable_no_gate` / `always_confirm_no_gate` / `circuit_breaker_no_gate`），不再「gate 缺席即放行」。签名层面 `approval_gate` **一律无默认值**，漏传是 `TypeError` 而非静默放行；「这条路确实没人可问」必须显式写出来。→ 见代码: `agentcore/runtime/engine/tool_exec_gates.py`

**熔断（P3 · 现状）**：`safety_breaker` 对毁灭启发式（格式化磁盘、`rm -rf /`、shutdown 等）默认 `FORCE_APPROVAL`；**例外**：① `host_shell` 路径上与执行侧 fuse **已重叠**的毁灭形（rm 根/家、格式化/写块设备、关机重启）breaker 直接 **`DENY`**（方案 C，消「批了仍被 fuse 打回」）；② `terminal` / `code_execute` / `test_run` / `host_shell` 命令文本命中 force（含 force-with-lease）→ `main|master` 亦直接 **`DENY`**（与结构化 `git` 同口径；fuse 仍不扫 git）；③ `host_shell` 命中**静默安装**启发（msiexec /quiet、Setup /S、Start-Process quiet 等）→ fuse 硬拒 + breaker **`DENY`**（`host_shell.silent_install`；文案诚实「启发式兜底，并非完整拦截」；装软件主路径 = 结构化 `host_package_install`）。`host_shell` fuse 本身仍硬拒、不可批可跑。长驻启服命令硬拒（导向 `terminal`）。**工作区脚本破坏（回滚主、窄闸辅）**：静态启发扫 `shutil.rmtree` / `rm -rf` / `Remove-Item -Recurse` 等；Local 无可用回合 zip 基线 → `FORCE_APPROVAL`（`destructive.no_turn_baseline`）；顶层整棵工作区树 → `FORCE_APPROVAL`（`destructive.workspace_top_tree`，白名单清理目录放行）；**不**与 fuse 同条件叠第二张卡。常规 `maybe_capture_turn_baseline` 仍失败不阻断。主路径仍是基线/软删可逆，熔断是辅。结构化 `git` 工具：普通 push / `create_pr` **始终弹确认**（不吃 `file_write=session` / 开工授权 / 「本轮文件类放行」短路），force/保护分支硬拒；**结构化 `host_package_install` 同口径恒确认**（不吃 `host=session` / kickoff / turn grant——少打断默认否则会零卡装软件）；**敏感路径三态**（模板放行 / 凭据读 `FORCE_APPROVAL` / 私钥类读 `DENY`；写盘 Ask|Deny 类路径仍硬拒）——PermissionAxes / 开工**不可静默覆盖** FORCE/DENY；毁灭 / 无基线 / 顶层整树等真熔断 FORCE **仍不可**「本轮放行」；**仅** `sensitive.path_read_ask` 人批后可本轮同工具 turn grant（按工具名，非按路径；非 PermissionAxes）。启发式黑名单是兜底、非完整边界——真熔断文案须诚实「启发式兜底，并非完整拦截」；工具读闸不覆盖 shell `cat` 旁路（诚实缺口）。fuse⊆DENY 对照 → `fuse_aligned_deny_rule_ids` + `test_safety_breaker` 样本表；脚本破坏 → `destructive_fs` + `test_destructive_fs`。

### ✅ 敏感路径三态（模板放行 / 凭据 Ask / 私钥 Deny）

- **目标**：对齐行业 deny/ask/allow——修 `.env.example` 等模板误伤；真凭据读给人批通道（首卡后可本轮同工具放行）；私钥材料仍硬拒。写侧（敏感路径 + Key 形正文）保持硬拒。
- **分级**：`classify_sensitive_path` → `NONE`（`.example`/`.sample`/`.template`/`.dist`）/ `ASK`（`.env`、`.env.local`、`credentials.json`、`.aws`…）/ `DENY`（`id_rsa`、`.pem`/`.key`、`.ssh`/`.gnupg`…）。读：`file_read`/`grep`/`code_search` 上 ASK→`FORCE_APPROVAL`（`sensitive.path_read_ask`）、DENY→`DENY`（`sensitive.path_read`）。写：Ask|Deny 路径均 `DENY`。
- **合法通道**：人批读（进模型上下文且审计）；首卡后允许「本轮内都允许」按**工具名** turn grant（同轮后续同工具敏感读免卡；不覆盖 `grep`/`code_search` 互授）。Ask 卡可附 **键名预览（无值）**（dotenv / 浅 JSON；桌面 / 手机同渲）；**不用**「安全熔断升格审批」套话（与真熔断卡分轨；机读 `rule_id` / `force_one_shot`）。设置页凭据 / 本机环境变量；**禁止**文案劝「把密钥贴进对话」。
- **边界**：不把敏感读并进 PermissionAxes / 开工静默放行；真熔断 FORCE 卡隐藏无效「本轮都允许」（仅允许一次）；不扩 shell 文本闸（旁路诚实缺口，二期可选对齐）；不做独立 `env_keys_summary` 工具（卡预览已覆盖主路径）。
- **误伤面**（可接受）：故意把真密钥放进名为 `.env.example` 的文件 → 可读；本轮 grant 按工具名 → 批一次 `.env` 后同轮其它凭据路径同工具可读。
- **验收**：`.env.example` 读写放行；`.env` 读弹敏感读升格卡（可含键名预览、可本轮放行）；同工具二次读可免卡；`id_rsa`/`.pem` 读硬拒；`.env` 写仍硬拒；真熔断卡无本轮按钮。→ 见代码: `agentcore/runtime/safety_breaker.py` · `credential_preview.py`

### ✅ host_shell 毁灭启发式 · fuse 已覆盖改 DENY（方案 C）

- **目标**：对 `host_shell` fuse **已覆盖**的毁灭启发式，`safety_breaker` 改为直接 **`DENY`**，不走 `FORCE_APPROVAL`，消除「人批了仍被 fuse 打回」的误导。灾难硬拒保留；文案继续诚实「启发式兜底，并非完整拦截」。
- **边界**：仅改 breaker 对 **fuse 已覆盖**毁灭形的裁决（`FORCE_APPROVAL`→`DENY`）。**不**改 fuse 本身为可批可跑；**不**借机扩毁灭正则面。fuse 独有形是否前置 breaker `DENY` → **二期**。git force 口径 → 下节「统一 DENY」（本方案 C 原文曾留「可另开」，已由 Git 闭环定案收口）。
- **关键取舍**：选方案 **C**（breaker 对齐 fuse 硬拒）。**否决 B**：改 fuse 为可批可跑（削弱执行侧灾难闸）。**否决 D 当终案**：仅改文案（可作过渡，不可替代 C）。落地对照：`FUSE_ALIGNED_DENY_RULE_IDS` / `fuse_aligned_deny_rule_ids()` + `test_host_shell_fuse_covered_destructive_denies` 样本表（fuse ⊆ DENY）。
- **验收**：fuse 已覆盖的毁灭形经 `host_shell` 路径直接 `DENY`、不再弹可批卡；批了仍失败路径消失。文案仍含诚实启发式声明。→ 见代码: `agentcore/runtime/safety_breaker.py`

### ✅ git force→保护分支 · 结构化与 shell 文本统一 DENY

- **现状**：`terminal` / `code_execute` / `test_run` / `host_shell` 命令文本命中 `git push --force`（及 force-with-lease / `-f`）且指向 `main|master` 时，breaker 与结构化 `git` 同为 **`DENY`**（规则 id `destructive.git_force_push_protected`；不入 `FUSE_ALIGNED_DENY_RULE_IDS`——fuse 仍不扫 git）。普通功能分支 force 文本未点名保护分支 → 不命中（维持既有启发式样本表）。结构化 `git` force/保护分支硬拒不变；普通 `git push` / `create_pr` 仍恒确认。
- **误伤面**（已确认可接受）：故意经 shell 强推主干且愿点批的路径取消——须改分支策略或人工在仓外操作。
- **边界**：不扩其它毁灭正则；不改 `GIT_FORBIDDEN_SUBCOMMANDS`；不借机加意图分类器。→ 见代码: `agentcore/runtime/safety_breaker.py` · [工具 · Git 闭环](/docs/03-AI核心/工具与能力系统.md#git-闭环)

**「本轮内都允许」**：turn 级 · 按类操作 · 整棵 DAG 共享 · 新轮清场。

**开工卡**：`team_preview`∪授权合一；delegate/debate 共用；`team_kickoff=skip` 不弹。被否：永久 allowlist、按 Agent 放行、两卡串联。演进：可回滚写入 → 降为 `never`。

## 五、代码执行沙箱 ✅

云端多租 → 真隔离。**云执行默认开**（`gvisor_enabled=true`；deploy 默认叠 sandbox）。紧急关闭：机上 `GVISOR_ENABLED=false`。健康探测失败 → 整类不装配（fail-safe 不拒启）。**开齐口径**：健康探测通过 → 能力行 `code_execute=已装配`；**装包另需**容器内 netns 探针 / `registry_egress` → `package_install=已装配`（能跑代码 ≠ 能装依赖；与 `browser=` 同探针）。裸 subprocess 云执行（`CODE_EXECUTE_CLOUD_ENABLED`）仍默认关 + SEC-005 ack。本机 Host / 装本机软件仍须 `host=`（桌面在线）。`terminal` 云缺席。勿把样例 `GVISOR_TIMEOUT_MAX_SECONDS=60` 照抄进生产（默认 ≥1230）。部署细节 → [部署拓扑 · 云端执行](/docs/05-平台与运维/部署拓扑与环境.md#云端执行gvisor)。

**诚实降级（已在云 ≠ 再导入）**：会话已是云工作区但沙箱/netns 未装配时，能力行 / 交付 action / 委派软提示须说明「沙箱不可用」并给稍后重试 · `export_to_local` · 本机传统；**禁止**把「Composer 导入到云」当作修复（工程已在云）。导入/连 Git 仅适用于工程尚在本机、需进云执行的路径。→ 见代码: `runtime/delegate/exec_env_remediation.py`

**产物写回**：默认 staging copy-in/out（tmpfs + 有界写回）；超时不写回；删不回传。**装包例外**：`registry_egress` 时 rw-bind 持久工作区，跳过 staging/整树 base64，`node_modules` / `.venv` 直接落盘（短命沙箱只跑命令；Python 装包白名单 uv/pip/poetry，与 JS npm/pnpm/yarn 同纪律，非 shell 替代）。被替代：ro overlay（产物取不出）。护栏：并发位 + 有界等待 + 内存/时长/写回限额。**不为云执行新增配额维**。部署前置 → [部署拓扑与环境 · 云端执行灰度](/docs/05-平台与运维/部署拓扑与环境.md)。

## 七、凭据加密 ✅

AES-256-GCM；明文永不落库/不回前端。`billing_mode=byok` → 缺密钥生产 fail-closed；`platform` → fail-safe。交叉 → [成本 §〇·五](/docs/05-平台与运维/成本配额与计费.md)。**同口径**：账户级 Git PAT（G3 · `user_git_credentials`）与**平台额度账号池**（`platform_credentials`）亦走 `KeyEncryptor`；工具永不收密码参数。云 clone/push/fetch/pull 服务端注入 PAT；`create_pr` **云与 Local 均优先账户 PAT**，再回落 `GH_TOKEN`/`GITHUB_TOKEN` / Local `gh auth token`；Local 结构化 `git` 网络命令（非 PR）仍继承 OS credential helper，不注入 PAT。→ [工具 · G3/G4](/docs/03-AI核心/工具与能力系统.md#git-闭环)

### 七·a 密钥轮换与 production.env 灾备

> **密钥值不入仓、不入 chat、不入 PR/Issue**。机上真相源 = `$DEPLOY_DIR/config/production.env`（默认 `$AGENTCORE_HOME/repo/deploy/config/production.env`；由 `production.env.example` 复制填值；compose `env_file` 同路径）。根 `$AGENTCORE_HOME/.env` 仅 ACR 登录凭据，**不含** JWT / 加密主密钥 / SMTP 密码。模板字段名 → `deploy/config/production.env.example`（`JWT_SECRET_KEY` / `ENCRYPTION_KEY` / **SMTP 七项** 等）。

#### A. `JWT_SECRET_KEY` 轮换

| # | 检查项 |
|---|---|
| 1 | 维护窗口公告：轮换后**全部** access/refresh 失效，用户须重新登录 |
| 2 | 备份当前 `production.env` 到机外安全位置（见 C；**勿**提交 git） |
| 3 | 生成新密钥（长度足够的随机串；勿用示例占位符） |
| 4 | 仅在机上改 `JWT_SECRET_KEY=…`；保存文件权限仅运维可读 |
| 5 | 重启 api（`finish-server.sh <当前 sha>` 或 compose recreate api——**不要**顺手升到未验证 SHA） |
| 6 | 验收：旧 cookie/Bearer → 401；新登录成功；Admin MFA 会话须重新过 MFA（若启用） |

#### B. `ENCRYPTION_KEY` 轮换（高风险）

| # | 检查项 |
|---|---|
| 1 | **先读清**：该键加密用户 BYOK API Key、平台额度账号池、Git PAT 等落库密文。换键且未先重加密 → 已存凭据**无法解密**（设置页表现为绑 key 失败 / MFA 相关能力异常；平台池选钥回落 env 或不可用）。`production.env.example` 亦注明「一经启用切勿随意更换」 |
| 2 | 确认是否有用户 BYOK / 依赖该键的密文；无存量密文时等同首次配置，直接写入新键并重启即可 |
| 3 | **有存量时**（当前无可照抄的一键 migrate 脚本）：维护窗口 → 导出/记录需重绑的用户范围 → 写入新 `ENCRYPTION_KEY` → 重启 → 通知用户重新绑定 API Key（或按维护者私有流程做离线重加密——**过程中密钥仍不入仓**） |
| 4 | `billing_mode=byok` 生产缺键会 fail-closed；`platform` 可启动但 BYOK 功能死——验收模型配置页与 MFA（若用加密存 TOTP） |

#### C. `production.env` 灾备 checklist

| # | 检查项 |
|---|---|
| 1 | 首次上线：自 `production.env.example` 生成 `$DEPLOY_DIR/config/production.env`；真实值**只**留在服务器与批准的密钥保管处；**开放注册**须填齐 SMTP 七项并跑 `verify_smtp.py`（步骤 → [部署拓扑 · §8.2](/docs/05-平台与运维/部署拓扑与环境.md#82-环境变量分层)） |
| 2 | 每次改密钥 / LLM Key / CORS / **SMTP** 前：拷贝 `production.env` → 加密介质或密钥保管柜（文件名含日期；**禁止**进仓库、Slack、邮件明文） |
| 3 | 机损恢复：新机摆好 compose 布局 → 从保管处回写 `production.env` + 根 `.env`（ACR 凭据）→ `finish-server.sh <已知好 sha>` → `/readyz` + 登录烟测 + 注册发码烟测 |
| 4 | 与 DB 备份正交：[发布与门禁 §7.7](/docs/05-平台与运维/发布与门禁.md#77-备份与恢复策略) `backup.sh` 只管 PostgreSQL；**不**替代 env 备份。丢 env ≠ 丢库，但服务起不来 |
| 5 | 泄露应急：视为 A/B 都需轮换 + 轮换上游 LLM Key；审计谁曾接触备份副本 |

镜像/桌面回滚步骤 → [发布与门禁 §7.7a](/docs/05-平台与运维/发布与门禁.md#77a-回滚-runbook可照做)。

## 八、治理边界 ✅

一受众一应用（admin 独立）。管理操作 → append-only `admin_audit_logs`。

**Agent 行为审计**：专表 `agent_audit_events`（投影非第二事实源）；默认仅 delegate 回合；`command=auto`（少打断/托管配方）全回合副作用；审批 force 落盘。telemetry 独立池 + 异步 flush。C 端不设通用时间线——场景化：inject 入边 / 协作图高亮 / 权限配方 chip。**文件反查 C 端暂不挂**（产物卡 / 预览已撤；「谁写的」走协作图 · 过程时间线 ·「改动」tab），仅保留 `GET …/audit/file` 与表。被否：扩 `turn_journal`、热路径 emit、全文副本、把残缺审计链挂回「收」的主路径。未落地尾巴 → 远期（详细提案不在公开仓）。

## 十、已坐实不变量

| 面 | 不变量 |
|---|---|
| 凭据 | AES-GCM；响应仅掩码；prod 拒占位密钥 |
| IDOR | 路由 scoped + 仓储 `user_id` 必填（SEC-002） |
| 注入 | SQL 参数化；`resolve_safe_path`；命令 argv 无 shell |
| SSRF | `core/net.py` + `PinnedIPTransport`；**不**为 dev fake-ip 放宽 |
| CSRF | 放行仅四类：开关关（prod 大声告警但仍启动）、安全方法、豁免前缀、无可解码 access cookie（纯 Bearer 手机端）。带 cookie 时即使有 Bearer 也必验（SEC-003）。令牌只在登录/续期/被拒那条 403 上下发 |
| 提示注入 | `<untrusted_content>` 框定工具/网页/文件为数据 |
| XSS / Electron | CSP `script-src 'self'`；`connect-src` 收窄；sandbox + openExternal 白名单 |
| 预览 / 浏览器 | ✅ 统一 BrowserSession；partition 按 `conversation_id`；密码不进模型。产品/壳权威 → [前端技术 §9.12](/docs/04-前端/前端技术与架构.md)；本文只钉安全不变量 |
| 沙箱 | **gVisor 云执行默认开**；健康失败 → 整类不装配。裸 subprocess 云执行（`CODE_EXECUTE_CLOUD_ENABLED`）默认关，无 SEC-005 ack 拒启动——勿与 gVisor 默认开混称 |
